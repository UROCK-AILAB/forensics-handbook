# 카빙 (Carving)

파일 시스템 메타데이터를 거치지 않고 원시 영역의 바이트에서 파일 시그니처나 구조의 특징을 찾아 파일과 조각을 꺼내는 방법, 그리고 macOS 에서 이 방법이 통하는 조건을 다룹니다.

## 언제 쓰나

파일 시스템이 망가졌거나 다시 포맷됐거나, 지운 파일의 메타데이터가 옛 체크포인트·스냅샷에도 남아 있지 않을 때 마지막으로 씁니다. 파일 시스템 구조로 되찾을 수 있는지는 [APFS에서 지운 파일 (APFS)](apfs-deleted-files.md) 에서 먼저 확인하고, 살아 있는 SQLite 파일 안의 지운 레코드는 [SQLite 레코드 되살리기 (SQLite)](sqlite-records.md) 에서 다룹니다.

Apple 실리콘·T2 Mac 의 내장 저장소는 FileVault 가 꺼져 있어도 볼륨이 암호화돼 있어서 [5], 내장 디스크의 원시 이미지를 그대로 카빙하면 파일 시그니처가 보이지 않는다고 봅니다(보안 가이드에서 끌어낸 판단입니다). 그래서 카빙은 복호된 상태로 확보한 볼륨이나 암호화되지 않은 외장 매체에 씁니다. 저장 매체에 따라 무엇을 기대할 수 있는지는 [트림과 복구 한계 (TRIM)](trim.md) 에 정리돼 있고, 외장 매체 연결 기록은 [USB 저장 장치 (USB Storage)](../../../02-artifacts/external-devices/usb/index.md) 에서 봅니다.

## 원리

카빙 도구는 파일 시스템을 무시하고 그 밑의 데이터를 뒤져서 파일 시스템이 망가졌거나 다시 포맷된 매체에서도 동작합니다 [1]. 공개 도구 PhotoRec 을 예로 들면, 먼저 블록 크기를 정하는데, ext2/3/4 는 수퍼블록에서, FAT·NTFS 는 볼륨 부트 레코드에서 읽고, 파일 시스템이 망가졌으면 처음 찾은 파일 10개의 위치로 추정합니다 [1]. 그다음 블록 단위로 파일 시그니처 목록과 비교하고(예: JPEG 는 블록이 0xff 0xd8 0xff 로 시작하고 넷째 바이트가 0xe0·0xe1·0xfe 가운데 하나) [1], 조각난 파일은 앞 블록들을 확인하며 여러 번 시도해 일부를 되살립니다 [1].

PhotoRec 은 적어도 FAT, NTFS, exFAT, ext2/3/4, HFS+ 에서 잃어버린 파일을 되찾을 수 있고, 지원 목록에 APFS 는 없습니다 [1]. 그래서 블록 크기를 수퍼블록이나 볼륨 부트 레코드에서 읽지 못하는 APFS 에서는 추정값을 쓰게 될 가능성이 있으므로, APFS 의 기본이자 최소 블록 크기가 4096 바이트라는 점을 [2] 비교 기준으로 삼을 수 있습니다. 어느 경우든 원래 파일 이름과 경로는 되살리지 못합니다 [1].

## 찾을 수 있는 대상

파일 내용 말고도 macOS 조사에서 쓸모 있는 구조를 원시 영역에서 찾을 수 있습니다.

| 대상 | 찾는 단서 | 검증 방법 | 자세히 |
|---|---|---|---|
| 일반 파일 | 파일 형식 시그니처(예: JPEG 0xff 0xd8 0xff 0xe0·0xe1·0xfe) [1] | 형식에 맞게 열리는지 | 이 페이지 |
| APFS 객체(수퍼블록·B-트리 노드) | 객체 머리 obj_phys_t 의 모양 [2] | 첫 8바이트 Fletcher 64 체크섬이 나머지와 맞는지 [2] | [APFS에서 지운 파일](apfs-deleted-files.md) |
| SQLite WAL | 매직 0x377f0682 또는 0x377f0683 [4] | 형식 버전·페이지 크기 칸, 프레임 salt [4] | [SQLite 레코드 되살리기](sqlite-records.md) |
| SQLite 롤백 저널 | 매직 0xd9d505f920a163d7 [4] | 헤더의 페이지 크기·섹터 크기 칸 [4] | 위와 같음 |
| SQLite B-트리 페이지 | 첫 바이트 0x02, 0x05, 0x0a, 0x0d [4] | 머리의 셀 개수·셀 영역 시작이 페이지 크기 안인지 | 위와 같음 |

APFS 는 모든 객체가 체크섬·객체 ID·트랜잭션 ID·종류를 담은 같은 머리로 시작해서 [2], 원시 영역에서 APFS 노드 후보를 찾고 체크섬으로 거짓 양성을 걸러 낼 수 있습니다(명세에서 끌어낸 판단입니다). 공개 도구 afro 의 출력 폴더 이름에 carve_apsb 가 보여서 [3] 볼륨 수퍼블록을 카빙하는 것으로 짐작되고(폴더 이름에서 끌어낸 판단입니다), 이렇게 찾은 옛 수퍼블록과 노드는 파일 시스템 트리를 거슬러 가는 입구가 됩니다.

SQLite B-트리 페이지 종류는 한 바이트라서 단독으로는 거짓 양성이 많을 수 있으므로, 페이지 크기 경계에 맞는 자리인지와 머리의 다른 칸이 말이 되는지를 함께 봅니다.

## 절차

1. **대상을 정합니다.** 복호된 상태로 확보한 볼륨 이미지인지, 암호화되지 않은 외장 매체인지 확인합니다. 암호화된 내장 저장소의 원시 이미지라면 [암호화된 증거 다루기 (Encrypted Evidence)](../encrypted-evidence/index.md) 로 먼저 복호할 방법을 찾습니다. 확보 방법은 [맥 증거 확보 (Acquisition)](../../process-acquisition/evidence-acquisition/index.md) 를 따릅니다.
2. **파일 시스템 수준 복구를 먼저 끝냅니다.** 옛 체크포인트와 스냅샷에서 찾을 수 있는 파일은 이름·경로·시각까지 함께 나와서, 카빙은 그 뒤에 남은 것을 찾는 단계로 둡니다.
3. **사본에서 작업합니다.** 이미지 해시를 적어 두고 사본을 읽기 전용으로 엽니다.
4. **찾을 형식을 고릅니다.** 조사 질문에 필요한 파일 형식과 위 표의 구조 가운데 무엇을 찾을지 정하고, 모든 형식을 한꺼번에 켜서 결과가 넘치지 않게 합니다.
5. **카빙을 돌립니다.** 공개 도구(예: PhotoRec)로 파일을 꺼내고, APFS·SQLite 구조는 시그니처 검색 뒤 표의 검증 방법으로 걸러 냅니다.
6. **결과를 검증합니다.** 꺼낸 파일이 형식에 맞게 열리는지, 크기가 그럴듯한지, 중간에 다른 파일의 블록이 섞이지 않았는지 봅니다. 조각난 파일은 일부만 되살아날 수 있습니다 [1].
7. **위치와 해시를 기록합니다.** 결과마다 이미지 안의 시작 오프셋, 크기, 해시, 찾은 도구와 버전을 적어 둡니다. 이름이 없어서 이 기록이 결과를 가리키는 유일한 근거가 됩니다.

## 함정과 한계

카빙 결과에는 원래 이름·경로가 없고 [1], 파일 시스템 시각도 함께 나오지 않습니다. 조각난 파일은 일부만 되살아나거나 다른 파일의 블록이 섞일 수 있어서 [1], 결과 파일이 온전하다고 가정하지 않습니다.

APFS 는 고친 객체를 늘 새 위치에 써서 [2], 빈 공간에서 찾은 파일이 지운 파일이 아니라 지금도 살아 있는 파일의 옛 버전일 수 있습니다(명세에서 끌어낸 판단입니다). 결과를 지운 파일로 보고하기 전에 같은 내용이 현재 파일 시스템에 있는지 해시로 확인합니다. 내장 SSD 에서는 TRIM 과 상시 암호화 때문에 원시 영역에 남는 것이 적을 수 있고, 그 조건은 [트림과 복구 한계 (TRIM)](trim.md) 에서 봅니다. 도구마다 시그니처 목록과 조각 처리 방식이 달라서 [도구 검증 (Tool Validation)](../../reporting/tool-validation.md) 에 따라 알려진 파일을 넣은 시험 이미지로 먼저 확인합니다.

## 결과를 어떻게 해석하나

카빙한 파일은 "이미지의 이 오프셋에 이 형식의 바이트가 있었다" 를 말해 줍니다. 그 파일을 누가 만들었는지, 언제 지웠는지, 지운 파일인지 옛 사본인지는 카빙 결과만으로 알 수 없어서 [지운 파일의 흔적 찾기 (Deleted File Traces)](../../../04-scenarios/activity/deleted-file-traces.md) 의 이름·경로 흔적과 맞춰 봅니다. 사진이라면 파일 안의 메타데이터를 [사진 메타데이터 (EXIF·HEIC)](../../../02-artifacts/embedded-metadata/exif-heic.md) 로 읽어 촬영 기기와 시각을 따로 확인할 수 있습니다.

보고서에는 "복호한 데이터 볼륨 이미지의 빈 공간에서 JPEG 시그니처로 시작하는 파일을 꺼냈고, 현재 파일 시스템에는 같은 해시의 파일이 없다" 처럼 어디서 어떤 단서로 꺼냈는지와 무엇을 확인했는지를 함께 적습니다.
