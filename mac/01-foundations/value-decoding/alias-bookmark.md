# 파일 참조 데이터 (Alias·Bookmark)

## 한 줄 요약

Alias 레코드와 북마크 데이터(Bookmark)는 앱이 파일 위치를 기억하려고 저장해 두는 바이너리 덩어리이고, 대상 파일의 경로·이름·CNID·생성 시각에 더해 그 파일이 있던 볼륨의 이름·UUID·크기·마운트 지점까지 담을 수 있어서, 대상 파일이 지워졌거나 외장 볼륨을 뗀 뒤에도 당시 위치를 알려 줍니다.

## 이 형식을 쓰는 아티팩트

두 형식은 따로 떨어진 파일이 아니라 다른 파일 안에 값으로 넣어 두는 데이터라서, plist 값 같은 곳에서 바이트 덩어리로 만납니다. 최근 항목, 파인더 설정, 로그인 항목 등이 이런 값을 담는 후보이고, 어느 아티팩트의 어느 키에 어느 형식이 들어 있는지와 macOS 버전에 따라 어느 형식을 쓰는지는 검체에서 확인합니다. 각 아티팩트는 [최근 항목](../../02-artifacts/file-folder-usage/recent-items/index.md), [파인더 설정과 기록](../../02-artifacts/file-folder-usage/finder-plist.md), [로그인 항목](../../02-artifacts/persistence/login-items.md), [실행 에이전트·데몬](../../02-artifacts/persistence/launchd/index.md) 에서 다룹니다. plist 에서 바이트 값을 꺼내는 법은 [속성 목록 파일](../data-formats/plist/index.md)에서 다룹니다.

| 형식 | 첫 바이트로 알아보기 | 엔디언 | 이 페이지의 출처 |
|---|---|---|---|
| 북마크 데이터 | 오프셋 0 매직 `book` 또는 `alis` | 리틀엔디언 (날짜만 빅엔디언) | mac_alias 문서, Mac Bookmark Format |
| Alias 레코드 | 고정 매직 없음, 오프셋 6 버전이 2 또는 3 | 전체 빅엔디언 | mac_alias 문서, Mac Alias Format |

북마크 매직은 `book`·`alis` 두 가지인데 [1], `alis` 로 시작하는 북마크가 무엇이고 Alias 레코드와 어떤 관계인지는 공개된 분석 자료가 없습니다. 파인더에서 "가상본 만들기" 로 만든 파일 안의 구조도 검체에서 확인해야 합니다.

## 구조

### 북마크 데이터

따로 적지 않은 값은 모두 리틀엔디언이고, 데이터 안에 적힌 오프셋은 모두 헤더 끝(오프셋 48)부터 셉니다 [1].

| 오프셋 | 크기 | 내용 |
|---|---|---|
| 0 | 4 | 매직 `book` 또는 `alis` |
| 4 | 4 | 전체 크기 |
| 8 | 4 | `0x10040000` (뜻이 알려지지 않음) |
| 12 | 4 | 헤더 크기 (48) |
| 16 | 32 | 예약 |
| 48 | 4 | 첫 TOC 까지의 오프셋 (헤더 끝, 곧 오프셋 48 기준) |

데이터 안에는 목차(TOC)가 하나 이상 있고, TOC 마다 다음 TOC 의 오프셋을 적어 사슬처럼 잇습니다.

| TOC 오프셋 | 내용 |
|---|---|
| 0 | TOC 크기 − 8 |
| 4 | 매직 `0xfffffffe` |
| 8 | 식별자 |
| 12 | 다음 TOC 오프셋 (없으면 0) |
| 16 | 항목 수 |
| 그 뒤 | (키, 오프셋, 예약) 항목 배열, 이진 탐색을 할 수 있게 키 순으로 정렬 |

항목의 오프셋이 가리키는 값은 형식 코드에 따라 읽습니다.

| 형식 코드 | 값 |
|---|---|
| 0x0101 | 문자열 (UTF-8) |
| 0x0201 | 바이트 |
| 0x0301 ~ 0x0304 | 부호 있는 정수 (8·16·32·64비트) |
| 0x0305 ~ 0x0306 | 실수 (32·64비트) |
| 0x0400 | 날짜 (빅엔디언 double, 2001-01-01 00:00:00 UTC 기준 초) |
| 0x0500, 0x0501 | 참거짓 |
| 0x0601 | 배열 |
| 0x0701 | 딕셔너리 |
| 0x0801 | UUID |
| 0x0901 | URL |
| 0x0902 | 상대 URL |

키는 대상 파일, 볼륨, 만든 사람, 표시 정보로 나뉩니다.

| 키 | 뜻 | 키 | 뜻 |
|---|---|---|---|
| 0x1003 | 대상 URL | 0x2030 | 루트 볼륨 여부 |
| 0x1004 | 대상 경로 (경로 조각 배열) | 0x2040 | 볼륨 북마크 |
| 0x1005 | 대상 CNID 경로 | 0x2050 | 볼륨 마운트 지점 |
| 0x1010 | 대상 플래그 | 0xc001 | 포함 폴더 인덱스 |
| 0x1020 | 대상 파일 이름 | 0xc011 | 만든 사용자 이름 |
| 0x1030 | 대상 CNID | 0xc012 | 만든 사용자 UID |
| 0x1040 | 대상 생성 시각 | 0xd001 | 파일 참조 플래그 |
| 0x2000 | TOC 경로 | 0xd010 | 생성 옵션 |
| 0x2002 | 볼륨 경로 | 0xe003 | URL 길이 배열 |
| 0x2005 | 볼륨 URL | 0xf017 | 표시 이름 |
| 0x2010 | 볼륨 이름 | 0xf020 | 아이콘 데이터 (icns) |
| 0x2011 | 볼륨 UUID | 0xf021 | 아이콘 이미지 |
| 0x2012 | 볼륨 크기 | 0xf022 | 형식 연결 정보 |
| 0x2013 | 볼륨 생성 시각 | 0xf030 | 북마크 생성 시각 |
| 0x2020 | 볼륨 플래그 | 0xf080 | 샌드박스 읽기쓰기 확장 |
| | | 0xf081 | 샌드박스 읽기 전용 확장 |

볼륨 UUID(0x2011)는 UUID 형식(0x0801)이 아니라 문자열(0x0101)로 들어 있습니다 [1]. 그래도 읽을 때는 형식 코드를 먼저 봅니다.

### Alias 레코드

Alias 레코드의 값은 모두 빅엔디언입니다 [2]. 앞 8바이트는 두 버전이 같습니다.

| 오프셋 | 크기 | 내용 |
|---|---|---|
| 0 | 4 | 앱 전용 4글자 코드 |
| 4 | 2 | 레코드 크기 (최소 150) |
| 6 | 2 | 버전 (2 또는 3) |

버전 2 는 그 뒤가 아래처럼 이어집니다. 날짜는 1904-01-01 00:00:00 UTC 부터 센 값입니다 [2].

| 오프셋 | 크기 | 내용 |
|---|---|---|
| 8 | 2 | 종류 (0 파일, 1 폴더) |
| 10 | 28 | 볼륨 이름 (파스칼 문자열) |
| 38 | 4 | 볼륨 날짜 (1904 기준 초) |
| 42 | 2 | 파일 시스템 종류 (HFS+ 는 `H+`) |
| 44 | 2 | 디스크 종류 (0~5) |
| 46 | 4 | 포함 폴더 CNID |
| 50 | 64 | 대상 이름 (파스칼 문자열) |
| 114 | 4 | 대상 CNID |
| 118 | 4 | 대상 생성 날짜 (1904 기준 초) |
| 122 | 4 | 대상 크리에이터 코드 |
| 126 | 4 | 대상 타입 코드 |
| 130 | 2 | 별칭에서 루트까지 단계 수 |
| 132 | 2 | 루트에서 대상까지 단계 수 |
| 134 | 4 | 볼륨 속성 |
| 138 | 2 | 볼륨 파일 시스템 ID |
| 140 | 10 | 예약 |

버전 3 은 자리가 다릅니다. 오프셋 10 에 볼륨 날짜가 8바이트(1904 기준 1/65536초)로 오고, 18 에 파일 시스템 종류가 4바이트(HFS+ 는 `H+00`), 22 에 디스크 종류, 24 에 포함 폴더 CNID, 28 에 대상 CNID, 32 에 대상 생성 날짜가 8바이트(1/65536초), 40 에 볼륨 속성이 오고 44 부터 14바이트가 예약입니다.

고정 부분 뒤에는 추가 데이터가 태그(2바이트)·길이(2바이트)·값 순서로 이어지고, 길이가 홀수면 채움 바이트 하나로 짝수를 맞춥니다.

| 태그 | 내용 | 태그 | 내용 |
|---|---|---|---|
| −1 | 끝 | 14 | 유니코드 파일 이름 |
| 0 | 카본 폴더 이름 | 15 | 유니코드 볼륨 이름 |
| 1 | CNID 경로 | 16 ~ 17 | 고해상도 날짜 |
| 2 | 카본 경로 | 18 | POSIX 경로 |
| 3 ~ 6 | AppleShare·드라이버 정보 | 19 | POSIX 마운트 지점 |
| 9 ~ 10 | 네트워크·전화 접속 정보 | 20 | 재귀 별칭 |
| | | 21 | 홈 폴더까지 단계 수 |

두 형식의 날짜 값을 사람이 읽는 시각으로 바꾸는 식은 [맥의 시각 값](mac-time-values.md)에 있습니다.

## 읽는 법

아래 헥스는 명세로 만든 예시이고, 특정 검체에서 나온 값이 아닙니다. `NN` 은 값이 들어갈 자리를 뜻합니다.

```text
북마크 데이터 앞부분
오프셋  00 01 02 03  04 05 06 07  08 09 0A 0B  0C 0D 0E 0F
0000    62 6F 6F 6B  NN NN NN NN  00 00 04 10  30 00 00 00
        "b  o  o  k" 전체 크기     0x10040000    헤더 크기 48
                     (리틀엔디언)
0010    00 00 00 00 ...  (예약 32바이트, 오프셋 0x2F 까지)
0030    NN NN NN NN      첫 TOC 까지의 오프셋 (0x30 부터 셈)

Alias 레코드 v2 앞부분
오프셋  00 01 02 03  04 05  06 07  08 09  0A  0B ...
0000    NN NN NN NN  00 96  00 02  00 00  0C  4D 61 63 69 6E 74 6F 73 68 20 48 44 ...
        앱 코드       크기150 버전2  파일   길이 "Macintosh HD" (볼륨 이름, 28바이트 칸)
```

북마크는 다음 순서로 읽습니다.

1. 오프셋 0 이 `book`(또는 `alis`)인지, 오프셋 8 이 리틀엔디언 `0x10040000` 인지 봅니다.
2. 오프셋 48 에서 첫 TOC 까지의 오프셋을 읽고, 그 값에 48 을 더한 자리로 갑니다. 도착한 곳 4바이트 뒤가 `FE FF FF FF`(매직 `0xfffffffe`)이면 맞게 온 것입니다.
3. TOC 의 항목 수만큼 (키, 오프셋) 쌍을 읽고, 0x1004 대상 경로, 0x1030 대상 CNID, 0x2010 볼륨 이름, 0x2011 볼륨 UUID, 0xc012 만든 사용자 UID 처럼 필요한 키를 찾습니다.
4. 키의 오프셋에 48 을 더한 자리에서 값을 형식 코드에 맞춰 읽습니다. 날짜(0x0400)만 빅엔디언 double 로 읽습니다.
5. 다음 TOC 오프셋이 0 이 아니면 그 TOC 로 가서 3단계를 되풀이합니다.

Alias 레코드는 오프셋 6 의 버전을 먼저 읽고, 버전 2 면 위 v2 표대로, 버전 3 이면 v3 자리대로 고정 부분을 읽습니다. 그다음 레코드 끝까지 태그·길이·값을 차례로 읽다가 태그 −1(`FF FF`)을 만나면 멈추고, POSIX 형태의 경로가 필요하면 태그 18 POSIX 경로와 19 POSIX 마운트 지점을 먼저 봅니다.

## 포렌식에서 중요한 점

북마크 하나에서 대상 경로·파일 이름·CNID·생성 시각과 볼륨 이름·UUID·크기·마운트 지점을 함께 얻을 수 있어서, 대상 파일이 지워졌거나 외장 볼륨이 지금 연결되어 있지 않아도 북마크를 만들 당시의 위치 정보가 남아 있을 수 있습니다. 볼륨 이름과 크기, 루트 볼륨 여부(0x2030)를 함께 보면 파일이 내장 디스크에 있었는지 다른 볼륨에 있었는지 가늠할 수 있고, 외장 장치 쪽 흐름은 [USB 저장 장치](../../02-artifacts/external-devices/usb/index.md)에서 다룹니다.

북마크 안에는 시각이 세 가지 들어갈 수 있고, 뜻이 서로 다릅니다. 0x1040 은 대상 파일의 생성 시각, 0x2013 은 볼륨의 생성 시각, 0xf030 은 북마크 자체를 만든 시각이라서, 파일을 연 시각으로 읽으면 안 됩니다. 앱이 북마크를 언제 만들고 언제 다시 만드는지는 공개된 분석 자료가 없어서, 북마크 생성 시각 하나로 "이때 열었다" 고 쓰지 않습니다. 파일을 연 시점을 좁히는 흐름은 [이 파일을 누가 언제 열었나](../../04-scenarios/activity/file-access.md)에서 다룹니다.

만든 사용자 이름(0xc011)과 UID(0xc012)는 북마크를 만든 계정을 알려 줍니다. 샌드박스 확장(0xf080·0xf081)은 이름으로 보아 샌드박스 앱의 파일 접근과 관련된 값이지만, 안에 무엇이 들어 있는지는 검체에서 확인해야 합니다. 대상 CNID 는 [식별자 읽기](uuid-uid.md)에서 다루는 대로 볼륨과 함께 적어야 뜻이 생깁니다.

지운 파일 영역에서 이 데이터를 찾을 때는 북마크의 매직 `book` 과 TOC 매직 `FE FF FF FF` 를 표시로 삼아 찾습니다. Alias 레코드는 고정 매직이 없어서, 오프셋 4 의 크기가 150 이상이고 오프셋 6 이 `00 02`·`00 03` 인 자리를 후보로 잡고, HFS+ 볼륨을 가리키는 레코드라면 파일 시스템 종류 칸(v2 오프셋 42, v3 오프셋 18)에 `H+` 가 있는지로 걸러 낼 수 있습니다. 카빙 절차는 [삭제 데이터 복구](../../03-techniques/analysis/data-recovery/index.md)에서 다룹니다.

## 함정

북마크는 대부분 리틀엔디언인데 날짜만 빅엔디언이라서, 도구가 날짜를 이상하게 보여 주면 바이트 순서부터 의심합니다. Alias 레코드는 전체가 빅엔디언이라서 북마크를 읽던 습관대로 읽으면 크기와 CNID 가 모두 틀립니다.

Alias v3 은 v2 와 필드 자리가 달라서, 버전을 보지 않고 v2 표를 대면 볼륨 이름 자리에 v3 의 볼륨 날짜가 읽히는 식으로 필드가 모두 어긋납니다. v3 의 날짜는 1/65536초 단위라는 점도 따로 챙깁니다.

북마크에 적힌 경로는 북마크를 만들 때의 경로라서, 그 뒤 파일을 옮기거나 이름을 바꿨다면 지금 디스크의 경로와 다를 수 있습니다. 경로가 다르면 대상 CNID 와 볼륨 UUID 로 같은 파일인지 다시 맞춰 봅니다.

## 도구

| 도구 | 쓰임 |
|---|---|
| mac_alias (파이썬 라이브러리) | Alias·북마크 구조 문서 [1][2]를 낸 공개 라이브러리이고, 구조를 확인할 때 기준으로 삼습니다 |
| 헥스 편집기 | 위 순서대로 매직·TOC·키를 직접 따라가 도구 결과를 확인합니다 |

도구가 키를 다른 이름으로 보여 주면 이 페이지의 키 번호와 맞춰 보고, 도구 결과를 검증하는 방법은 [도구 검증](../../03-techniques/reporting/tool-validation.md)에서 다룹니다.
