# 예전 시스템 로그 (ASL·syslog)

Apple 시스템 로그 (Apple System Log, ASL)는 통합 로그가 나오기 전의 macOS 로그 체계이고, `syslogd` 가 받은 메시지를 `/etc/asl.conf` 규칙에 따라 빅엔디언 바이너리 파일(`.asl`)이나 텍스트 로그 파일에 쓰며 `aslmanager` 가 오래된 파일을 순환·압축·삭제합니다. 이 페이지는 설정 파일을 읽는 법, `.asl` 파일 구조, 보존·순환 규칙이 증거에 남기는 흔적을 다룹니다.

## 이 형식을 쓰는 아티팩트

macOS 10.12 Sierra에서 통합 로그가 ASL의 자리를 넘겨받았고, 그 경위와 통합 로그의 형식은 [통합 로그 형식 (Unified Log)](unified-log/index.md)에서 다룹니다. 이 핸드북이 주로 다루는 macOS 10.15 Catalina 이후에도 `/var/log/asl/` 에 `.asl` 파일이 계속 쌓이는지, `/var/log/system.log` 가 남아 있는지는 실제 기기에서 확인합니다. 이 페이지의 내용은 옛 macOS 이미지를 볼 때, 그리고 요즘 이미지에서 이런 파일이 나왔을 때 해석하는 기준으로 씁니다.

| macOS 버전 | 주된 로그 체계 | ASL·텍스트 로그 |
|---|---|---|
| 10.11 이전 | ASL | ASL 데이터베이스 기본 경로는 `/var/log/asl` [2] |
| 10.12 ~ 10.14 | 통합 로그 | 공개 문서 없음. 실제 기기에서 확인 |
| 10.15 이후 | 통합 로그 | 공개 문서 없음. 실제 기기에서 `/var/log/asl/`·`/var/log/system.log` 의 유무와 수정 시각을 확인 |

아래 설정과 보존 규칙은 2008년 판 `asl.conf(5)` 매뉴얼 기준이라 요즘 macOS 에서는 다를 수 있으니, 실제 기기의 설정 파일로 확인합니다 [2]. 설치 기록(`/var/log/install.log`)은 [설치 로그 (install.log)](../../02-artifacts/logs/install-log.md)에서 다룹니다.

## 구조

### 설정 파일 `/etc/asl.conf` 와 `/etc/asl` 폴더

`syslogd` 는 시작할 때 `/etc/asl.conf` 를 읽고 HUP 신호를 받으면 다시 읽으며, `aslmanager` 데몬도 시작할 때 이 파일을 읽습니다 [2]. `/etc/asl` 폴더가 있으면 그 안의 파일을 하나씩 읽는데, 파일 하나가 모듈 하나이고 파일 이름이 곧 모듈 이름입니다 [2]. `/etc/asl.conf` 자체는 `com.apple.asl` 모듈이라고도 부릅니다 [2].

줄의 종류는 첫 글자로 나뉩니다 [2].

| 첫 글자 | 줄의 뜻 |
|---|---|
| `=` | 설정값 |
| `?` | 조건과 동작을 묶은 규칙 |
| `>` | 출력 파일·폴더 설정 |
| `#` | 주석 |

규칙이 조건에 맞는 메시지에 적용하는 동작은 아래와 같습니다 [2].

| 동작 | 뜻 |
|---|---|
| `store` | ASL 데이터베이스에 저장 |
| `file` | 텍스트 로그 파일에 씀 |
| `directory` | ASL 형식 저장소 폴더에 씀. 하루에 파일 하나씩 `yyyy.mm.dd.asl` 이름으로 쌓임 |
| `claim` | 이 모듈이 메시지를 가져감. 가져간 메시지는 `/etc/asl.conf` 규칙으로 처리하지 않지만 다른 모듈은 볼 수 있음 |
| `notify`, `skip`, `access`, `broadcast`, `ignore` | 그 밖의 동작 |

`/etc/asl.conf` 에 `store` 규칙이 하나도 없으면 `syslogd` 는 받은 메시지를 모두 ASL 데이터베이스에 저장합니다 [2]. `file` 경로가 절대 경로가 아니면 `/etc/asl.conf` 의 규칙은 `/var/log` 아래로, 다른 모듈의 규칙은 `/var/log/module/모듈이름` 아래로 보고, 만든 파일은 기본으로 root 소유이며 admin 그룹이 읽을 수 있습니다 [2].

모듈은 `= enable 0` 으로 끄고, 파일이 있는지나 plist 값이 무엇인지를 조건으로 켜고 끌 수도 있으며, `sudo syslog -module` 명령으로도 바꿀 수 있지만 root만 바꿀 수 있습니다 [2].

```
= enable 0
= enable [File /a/b/c]
= enable [Plist 경로] [= 키 값]
sudo syslog -module <이름> enable 0
```

### 출력 형식

`format=` 값에 따라 같은 메시지가 다른 모양으로 파일에 들어갑니다 [2].

| 값 | 모양 |
|---|---|
| `bsd` | `syslogd` 가 `/var/log/system.log` 같은 시스템 로그 파일에 쓰는 형식 |
| `std` | 기본값. `bsd` 와 비슷하지만 우선순위 수준이 들어감 |
| `raw` | 키와 값 전부. 시각은 epoch 초 |
| `xml` | plist |
| `asl` | ASL 저장소 파일 형식. `syslog -f 경로` 로 읽음 |

`bsd`·`std` 형식은 30초 안에 시각만 다른 같은 메시지가 오면 하나로 합치고 `--- last message repeated N times ---` 줄을 남기며, 이 중복 합치기(coalesce)는 기본으로 켜져 있습니다(`coalesce=1`) [2]. 로그 수준 문자열은 emergency, alert, critical, error, warning, notice, info, debug입니다 [2].

### `.asl` 파일 헤더 (80바이트)

`.asl` 파일은 빅엔디언이고 파일 헤더는 80바이트입니다 [1].

| 오프셋 | 크기 | 내용 |
|---|---|---|
| 0 | 12 | 시그니처 `"ASL DB\x00\x00\x00\x00\x00\x00"` |
| 12 | 4 | 형식 버전 = 2 |
| 16 | 8 | 첫 기록 오프셋(파일 처음 기준) |
| 24 | 8 | 생성 시각, POSIX(유닉스) 시각 |
| 32 | 4 | 미상(캐시 크기로 추정) |
| 36 | 8 | 마지막 기록 오프셋 |
| 44 | 36 | 미상 |

### 기록 (log entry)

기록 하나는 문자열 0개 이상이 앞에 오고 기록 서술부가 뒤에 오는 모양이고, 서술부의 필드는 아래와 같습니다 [1].

| 오프셋 | 크기 | 내용 |
|---|---|---|
| 0 | 2 | 0x0000 (데이터 종류로 추정) |
| 2 | 4 | 데이터 크기 |
| 6 | 8 | 다음 기록 오프셋 |
| 14 | 8 | 미상(메시지 ID로 추정) |
| 22 | 8 | 기록 시각(written time), POSIX 시각 |
| 30 | 4 | 기록 시각의 나노초 |
| 34 | 2 | 경고 수준(alert level) |
| 36 | 2 | 미상(플래그로 추정) |
| 38 | 4 | PID |
| 42 | 4 | UID |
| 46 | 4 | GID |
| 50 | 4 | 읽기 허용 UID |
| 54 | 4 | 읽기 허용 GID |
| 58 | 8 | 미상(참조 PID로 추정) |
| 66 | 8 | 호스트 이름 문자열 오프셋 |
| 74 | 8 | 보낸 프로세스(Sender) 문자열 오프셋 |
| 82 | 8 | 퍼실리티(Facility) 문자열 오프셋 |
| 90 | 8 | 메시지 본문 문자열 오프셋 |
| 98 | 16 × n | 추가 필드 배열. 항목마다 이름 문자열 오프셋 8 + 값 문자열 오프셋 8 |
| 끝 8바이트 | 8 | 이전 기록 오프셋 |

기록마다 다음 기록과 이전 기록의 오프셋이 함께 들어 있어서, 기록들은 앞뒤로 이어진 목록을 이룹니다 [1]. 경고 수준 값은 0 EMERGENCY, 1 ALERT, 2 CRITICAL, 3 ERROR, 4 WARNING, 5 NOTICE, 6 INFO, 7 DEBUG이고 [1], 설정 파일의 수준 문자열과 순서가 같습니다.

### 문자열

문자열 오프셋 필드 8바이트는 두 가지로 읽습니다 [1]. 문자열이 6바이트 이하이면 첫 바이트의 상위 4비트가 0x8이라서 인라인 문자열임을 알 수 있고, 하위 4비트가 길이이며 나머지 7바이트에 끝 표시 없는 UTF-8 문자열이 들어갑니다. 그보다 길면 이 필드는 파일 처음부터 문자열까지의 오프셋이고, 그 자리에 따로 저장된 문자열은 아래 모양입니다 [1].

| 오프셋 | 크기 | 내용 |
|---|---|---|
| 0 | 2 | 0x0001 |
| 2 | 4 | 크기 |
| 6 | 가변 | UTF-8 문자열(끝 표시 있음) |

이 구조는 아직 완성되지 않은 공개 명세를 따른 것이라 미상 필드가 많습니다 [1].

## 읽는 법

아래 헥스는 위 표대로 만든 예시이고 실제 데이터에서 나온 값이 아닙니다. `??` 는 명세에 뜻이 적히지 않은 미상 바이트입니다.

```
00000000: 41 53 4C 20 44 42 00 00 00 00 00 00 00 00 00 02  ASL DB..........
00000010: 00 00 00 00 00 00 00 80 00 00 00 00 5F 5E 10 00  ............_^..
00000020: ?? ?? ?? ?? 00 00 00 00 00 00 01 00 ?? ?? ?? ??  ................
```

1. 오프셋 0의 12바이트가 `ASL DB` 와 0 여섯 바이트인지, 오프셋 12의 버전이 `00 00 00 02` 인지 봅니다.
2. 오프셋 16의 8바이트(예시 0x80)가 첫 기록 오프셋이고, 오프셋 36의 8바이트(예시 0x100)가 마지막 기록 오프셋입니다.
3. 오프셋 24의 생성 시각은 예시에서 0x5F5E1000 = 1600000000이고, 유닉스 시각으로 풀면 2020-09-13 12:26:40 UTC입니다.
4. 첫 기록으로 가서 서술부의 고정 필드를 읽고, 호스트 이름·보낸 프로세스·퍼실리티·본문 필드마다 첫 바이트의 상위 4비트가 0x8인지 봐서 인라인 문자열인지 오프셋인지 구분합니다. 예를 들어 `kernel` (6바이트)이 인라인으로 들어가면 첫 바이트는 0x86이고 뒤에 `6B 65 72 6E 65 6C` 가 옵니다. 남는 1바이트의 값은 참고 문헌에 적혀 있지 않습니다.
5. 다음 기록 오프셋을 따라 끝까지 가고, 중간이 깨졌으면 헤더의 마지막 기록 오프셋에서 출발해 기록 끝의 이전 기록 오프셋을 따라 거꾸로 읽습니다.
텍스트 로그는 설정 파일의 `format=` 값으로 모양이 정해지니, 먼저 `/etc/asl.conf` 와 `/etc/asl/` 안의 모듈 파일을 읽어 어떤 파일에 어떤 형식으로 쓰도록 되어 있었는지 확인하고 나서 로그 파일을 해석합니다.

## 포렌식에서 중요한 점

### 보존 기간과 크기 한도

ASL 데이터베이스는 오래 두는 저장소가 아니라서, 기본 설정대로라면 조사 시점보다 한참 앞선 메시지는 남아 있지 않다고 보고 시작합니다 [2].

| 설정 | 뜻 | 기본값 [2] |
|---|---|---|
| `store_ttl` | ASL 데이터베이스 메시지 보존 일수 | 7일 |
| `max_store_size` | ASL 데이터베이스 최대 크기 | 150000000바이트 |
| `max_file_size` | ASL 데이터베이스 파일 하나의 최대 크기 | 25600000바이트 |
| `store_path` | `aslmanager` 가 쓰는 데이터베이스 경로(`syslogd` 는 무시) | `/var/log/asl` |
| `archive` | 켜면 지운 파일을 보관 폴더로 옮김 | 보관 폴더 `/var/log/asl.archive`, 보관 파일 권한 0400(root만 읽기) |
| `utmp_ttl` | utmp·wtmp·lastlog용 메시지 보존 기간 | 31622400초(약 1년) |
| `mps_limit` | 커널 메시지 초당 한도 | 500. 사용자 프로세스는 시간당 36000개 |
| `dup_delay` | 중복 판정 간격 | 30초 |
| `mark_time` | mark 메시지 간격 | 0(만들지 않음) |

`archive` 가 켜져 있었다면 7일이 지난 메시지도 `/var/log/asl.archive` 에 남아 있을 수 있어서, 설정 파일에서 이 값을 먼저 확인합니다. `utmp_ttl` 은 로그인 기록 계열 메시지를 따로 1년 가까이 두는 설정이라서, 일반 메시지는 지워졌어도 로그인 관련 메시지는 더 오래 남았을 수 있습니다. 짧은 시간에 메시지가 몰린 구간에서 기록이 비어 보이면 이 한도를 먼저 떠올립니다. `debug` 를 켜면 `syslogd` 자신의 디버그 메시지가 `/var/log/syslogd.log` 에 쓰입니다 [2].

### 순환과 압축

`syslogd` 는 자정이 되거나(잠자기·꺼짐 뒤라면 새 날의 첫 메시지를 받을 때) 파일이 `file_max` 를 넘으면 파일을 닫고 생성 시각을 넣은 이름으로 바꾸고, 이 동작을 checkpoint 라고 합니다 [2]. 이름 바꾸기, `dest=` 로 지정한 곳으로 옮기기, gzip 압축, `ttl=` 을 넘긴 파일 삭제, `all_max` 를 넘긴 파일 삭제는 `aslmanager` 가 맡고, `aslmanager` 는 보통 부팅 때 한 번과 매일 자정 직후 한 번 돕니다 [2].

순환한 파일 이름에 붙는 시각은 방식마다 모양이 다릅니다 [2].

| 방식 | 이름 예 |
|---|---|
| `sec` | `example.log.T1340607600` (epoch 초). `rotate` 에 값이 없으면 이 방식 |
| `utc` | `example.log.2012-06-24T07:00:00Z` |
| `utc-basic` | `example.log.20120624T070000Z` |
| `local`, `lcl` | `example.log.2012-06-24T07:00:00-7` (현지 시각 + 오프셋) |
| `local-basic`, `lcl-basic` | 현지 시각의 기본 표기 |
| `seq` | `example.log.0` (0이 가장 최근) |

`compress` 를 켜면 순환 파일 이름에 `.gz` 가 붙고, ASL 폴더 출력이면 자정 뒤에 데이터 파일을 압축합니다 [2]. 압축된 파일의 메시지는 풀기 전에는 `syslog -d` 나 asl API로 볼 수 없어서 [2], 도구가 폴더를 읽고 결과를 내놓았더라도 `.gz` 파일 안의 메시지가 빠졌을 수 있습니다.

### 설정 변경과 기록 공백

`?` 규칙의 `ignore`·`skip`·`claim` 이나 `= enable 0` 은 특정 메시지를 저장하지 않게 만들 수 있고, 이 설정은 root만 바꿀 수 있습니다 [2]. 로그가 특정 기간이나 특정 보낸 프로세스에서만 비어 있다면, `/etc/asl.conf` 와 `/etc/asl/` 모듈 파일의 내용과 파일 시스템 시각을 확인해 설정이 바뀐 흔적이 있는지 봅니다. 로그를 지우거나 설정을 바꿔 흔적을 줄이려 한 사례를 조사하는 흐름은 [증거를 없애려 했나 (Anti-Forensics)](../../04-scenarios/activity/anti-forensics/index.md)에서 다룹니다.

### 지운 파일과 손상

`aslmanager` 가 보존 기간을 넘긴 파일을 지우면 파일 시스템에서 사라지지만, 헤더 시그니처 `ASL DB` 가 고정 문자열이라서 비할당 영역에서 이 문자열로 조각을 찾아볼 수 있습니다. 조각을 찾은 뒤에는 헤더의 첫 기록·마지막 기록 오프셋이 조각 크기 안에 들어오는지 따져 끝이 잘렸는지를 확인합니다. 삭제 데이터를 되살리는 일반 절차는 [삭제 데이터 복구 (Data Recovery)](../../03-techniques/analysis/data-recovery/index.md)에 있습니다.

## 함정

- **중복 합치기**: `bsd`·`std` 텍스트 로그의 `--- last message repeated N times ---` 줄은 같은 메시지 N개를 한 줄로 합친 것이라서 [2], 줄 수로 사건 수를 세면 적게 셉니다. 합쳐진 메시지 각각의 시각은 이 줄에 남지 않습니다.
- **파일 이름의 시각**: 순환 파일 이름의 시각은 파일 생성 시각이고 `aslmanager` 는 파일 나이를 이 이름으로 판단합니다 [2]. 현지 시각으로 이름을 붙이면 시간대가 바뀌는 기기에서 나이 계산이 틀어질 수 있어서 [2], 이름의 시각을 메시지 시각으로 쓰지 않고 시간대 기록과 맞춰 봅니다. 시간대 설정은 [시간대와 시계 설정 (Time Zone·NTP)](../../02-artifacts/system-account/time-zone.md)에서 봅니다.
- **시각 기준**: `.asl` 파일의 생성 시각과 기록 시각은 POSIX 시각이고 [1], `raw` 형식의 시각은 epoch 초입니다 [2]. `bsd`·`std` 텍스트 줄의 시각이 현지 시각인지 UTC인지는 공개 자료에 적혀 있지 않으니, 같은 사건이 다른 기록에 남아 있으면 그 시각과 맞춰 봅니다. 시각 값을 푸는 법은 [맥의 시각 값 (Mac Absolute Time·Unix·HFS)](../value-decoding/mac-time-values.md)에 있습니다.
- **UID와 읽기 허용 UID**: 기록에는 보낸 프로세스의 UID·GID와 별도로 읽기 허용 UID·GID가 있어서 [1], 두 값을 섞어 읽으면 누가 메시지를 보냈는지를 잘못 적게 됩니다.
- **매뉴얼의 판**: 설정 이름과 기본값은 2008년 날짜의 매뉴얼 기준입니다 [2]. 실제 기기의 `/etc/asl.conf` 에 적힌 값이 기본값보다 우선하니, 기본값으로 단정하지 않고 설정 파일을 먼저 읽습니다.

## 도구

ASL 형식 파일은 `syslog -f 경로` 로 읽고 [2], 압축된 ASL 폴더 파일은 `syslog -d` 로 볼 수 없습니다 [2]. 분석용 맥에 이 명령이 없으면 위 표대로 헥스를 직접 읽거나 명세 문서 [1]를 기준으로 파서를 짭니다. 어느 도구를 쓰든 결과에서 기록 몇 개를 골라 헤더와 기록 오프셋을 헥스로 맞춰 보고, 도구를 검증하는 방법은 [도구 검증 (Tool Validation)](../../03-techniques/reporting/tool-validation.md)을 따릅니다. 이 로그를 다른 기록과 한 시간축에 놓는 방법은 [타임라인 작성 (Timeline)](../../03-techniques/analysis/timeline/index.md)에서 다룹니다.
