# 삭제 도구 (Wiping Tools)

## 조사 질문

누군가 파일이나 디스크의 빈 공간을 덮어써 지운 파일을 되살리지 못하게 하려 했는지, 했다면 어떤 수단으로 어느 범위를 지웠는지를 묻습니다. 삭제 도구는 지운 내용보다 도구를 쓴 흔적과 덮어쓴 자리의 모양으로 드러나는 경우가 많아서, 이 페이지는 macOS 기본 명령이 실제로 무엇을 하는지와 그 흔적을 어디서 찾는지를 다룹니다.

## 먼저 확인할 것

가장 먼저 저장 장치 종류를 확인합니다. 디스크 유틸리티의 보안 지우기 옵션은 일부 저장 장치에서만 나오고 SSD 에서는 아예 없어서 [3], SSD 맥에서 "디스크 유틸리티로 보안 지우기를 했다" 는 진술이나 추정은 먼저 의심해 봅니다. 이 내용은 macOS Catalina 10.15 부터 최신 버전까지 같습니다 [3].

다음으로 macOS 버전과 수집 범위를 확인합니다. 빈 공간을 덮어썼는지 보려면 논리 파일만 모은 확보본으로는 부족하고 볼륨 전체를 담은 이미지가 필요해서, 확보 방식을 [맥 증거 확보 (Acquisition)](../../../03-techniques/process-acquisition/evidence-acquisition/index.md)에서 먼저 맞춰 봅니다. 파일볼트나 하드웨어 암호화가 걸린 볼륨이라면 [암호화된 증거 다루기 (Encrypted Evidence)](../../../03-techniques/analysis/encrypted-evidence/index.md)도 함께 봅니다.

## macOS 기본 수단이 실제로 하는 일

| 수단 | 하는 일 | 흔적 해석에 주는 뜻 |
|---|---|---|
| `rm -P` | 아무 효과가 없고, 4.4BSD-Lite2 와의 호환을 위해 남겨 둔 옵션 [1] | 이 옵션을 쓴 기록이 있어도 파일을 덮어쓰지 않은 일반 삭제와 같습니다 |
| `diskutil secureErase` | 디스크 전체(모든 파티션 포함), 또는 마운트된 볼륨의 빈 공간만 보안 방식으로 지움 [2] | 빈 공간만 지우면 파티션은 그대로 있고 지운 파일의 복구만 막습니다 [2] |
| `diskutil zeroDisk` | 디스크 전체를 0으로 덮음, 다시 파티션하기 전엔 쓸 수 없음 [2] | 디스크 전체가 0 으로 채워진 모양 |
| `diskutil randomDisk` | 디스크 전체에 무작위 값을 씀(반복 횟수 지정 가능), 다시 파티션해야 함 [2] | 디스크 전체가 무작위 값으로 채워진 모양 |
| `diskutil eraseDisk` / `eraseVolume` | 볼륨을 지우고 새 파일 시스템을 씀 [2] | 새로 만든 파일 시스템만 보입니다 |
| `diskutil apfs deleteVolume` | 볼륨을 없애고 데이터가 사라짐 [2] | 컨테이너에서 볼륨 하나가 빠진 모양 |
| 디스크 유틸리티 보안 옵션 | 슬라이더로 덮어쓰기 횟수를 고름 [3] | SSD 에서는 이 옵션이 없습니다 [3] |

`secureErase` 는 수준 값에 따라 덮어쓰는 방식이 다르고 [2], 마지막으로 쓴 값이 디스크에 남기 때문에 빈 공간의 모양을 해석할 때 아래 표를 씁니다.

| 수준 | 방식 [2] | 마지막으로 남는 값 |
|---|---|---|
| 0 | 0으로 한 번 채움 | 0 |
| 1 | 무작위 값으로 한 번 채움 | 무작위 값 |
| 2 | 미 국방부(DoD) 7회, 0 채움·1 채움 뒤 마지막에 무작위 채움 | 무작위 값 |
| 3 | Gutmann 35회 | — |
| 4 | 미 에너지부(DoE) 3회, 무작위 두 번 뒤 마지막에 0 채움 | 0 |

Gutmann 방식에서 마지막으로 남는 값은 공개 자료에 나오지 않아 검체에서 확인합니다.

## 볼 아티팩트와 순서

| 순서 | 아티팩트 | 알려 주는 것 | 링크 |
|---|---|---|---|
| 1 | 터미널 명령 기록 | `diskutil`·`rm` 같은 명령을 입력한 흔적 | [터미널 명령 기록 (zsh_history·bash_sessions)](../../../02-artifacts/execution/shell-history.md) |
| 2 | 격리 속성 | 제3자 삭제 도구를 내려받은 흔적 | [격리 속성과 다운로드 기록 (Quarantine)](../../../02-artifacts/filesystem/quarantine/index.md) |
| 3 | 설치한 앱과 영수증 | 삭제 도구가 설치돼 있었는지 | [설치한 앱과 영수증 (Applications·Receipts)](../../../02-artifacts/system-account/installed-apps-receipts.md) |
| 4 | 통합 로그의 프로세스 기록 | 삭제 도구를 실행한 흔적 | [통합 로그의 프로세스 실행 기록 (Process Events)](../../../02-artifacts/execution/unified-log-process.md) |
| 5 | 파일 시스템 이벤트 | 지운 파일과 폴더, 지운 시기 | [파일 시스템 이벤트 (FSEvents)](../../../02-artifacts/filesystem/fsevents/index.md) |
| 6 | 빈 공간 내용 | 빈 공간이 한 가지 값으로 고르게 채워졌는지 | [삭제 데이터 복구 (Data Recovery)](../../../03-techniques/analysis/data-recovery/index.md) |

`diskutil` 이나 `rm` 을 실행한 사실이 통합 로그에 남는지, 남는다면 어느 서브시스템인지는 공개된 분석 자료가 없어 검체로 확인해야 합니다. 그래서 macOS 기본 명령은 주로 명령 기록으로 찾고, 제3자 도구는 내려받기·설치·실행의 일반적인 흔적으로 찾습니다.

## 분석 흐름

1. 저장 장치 종류와 수집 범위를 확인해 빈 공간을 볼 수 있는 확보본인지 정합니다.
2. 명령 기록에서 `diskutil` 이나 `rm` 을 쓴 줄을 찾습니다. `rm -P` 가 보이면 덮어쓰기 시도로 기록하되, 이 옵션은 효과가 없으므로 [1] 지운 파일의 흔적은 일반 삭제와 같은 방법으로 찾습니다.
3. 격리 속성, 설치한 앱 목록, 통합 로그의 프로세스 기록에서 제3자 삭제 도구를 내려받고 설치하고 실행한 흔적을 찾고, 시각을 이어 붙입니다.
4. 파일 시스템 이벤트에서 도구 실행 전후에 무엇이 지워졌는지 확인합니다.
5. 볼륨 전체 이미지가 있으면 빈 공간을 표본 삼아 훑어, 넓은 구간이 0 이나 무작위 값으로 고르게 채워졌는지 봅니다. 고르게 채워진 모양은 빈 공간 지우기를 의심할 단서지만, APFS 나 SSD 에서 빈 공간이 원래 0 으로 읽힐 수 있는지는 알려진 자료가 없어 단서로만 씁니다.
6. 파티션이 그대로인데 빈 공간만 채워진 모양이면 `secureErase` 의 빈 공간 지우기와 들어맞는지, 파티션 구성 자체가 새로 만들어진 모양이면 디스크 전체 지우기와 들어맞는지 견주고 [2], 디스크 전체를 지운 경우는 [초기화·재설치 (Erase·Reinstall)](erase-reinstall.md)와 함께 봅니다.

> 그림 자리: 정상 볼륨의 빈 공간(남은 파일 조각이 섞인 모양)과 빈 공간 지우기 뒤(한 가지 값으로 고르게 채워진 모양)를 나란히 놓은 헥스 화면. 명세로 만든 예시로 그린다.

## 흔한 오판

명령 기록에 `rm -P` 가 있다고 해서 파일을 복구할 수 없다고 판단하는 경우가 있습니다. 이 옵션은 지금 macOS 에서 효과가 없어서 [1], 덮어쓰려 한 의도는 보여 줄 수 있어도 실제로 덮어썼다는 근거는 되지 않습니다.

빈 공간이 0 으로 채워진 모양을 곧바로 삭제 도구 사용으로 보는 것도 조심합니다. 저장 장치와 파일 시스템의 동작만으로 0 이 읽힐 수 있는지는 알려진 자료가 없어서, 도구를 쓴 흔적이 함께 나올 때에 판단의 무게가 실립니다.

반대로 지운 파일을 되살리지 못했다고 해서 삭제 도구를 썼다고 결론 내리지도 않습니다. 복구가 안 되는 이유는 여러 가지일 수 있어서, 도구를 쓴 흔적이나 덮어쓴 자리의 모양 같은 직접 근거가 있을 때만 삭제 도구 사용을 적습니다.

## 보고서 문장 예

- "사용자의 명령 기록에 `rm -P` 를 실행한 줄이 있습니다. 이 옵션은 현재 macOS 에서 덮어쓰기를 하지 않으므로, 이 기록은 덮어쓰기를 시도했을 가능성을 보여 줄 뿐 실제로 덮어썼다는 근거는 아닙니다."
- "데이터 볼륨의 빈 공간 가운데 조사한 구간은 모두 0 으로 채워져 있습니다. 삭제 도구를 실행한 기록은 찾지 못해, 이 모양만으로 빈 공간을 지웠다고 판단하지 않았습니다."
