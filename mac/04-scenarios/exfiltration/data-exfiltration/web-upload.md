# 웹 업로드로 (Web Upload)

## 조사 질문

이 맥의 브라우저로 웹메일·클라우드 저장소·파일 공유 사이트 같은 웹 서비스에 자료를 올렸는지 묻습니다. 브라우저가 업로드한 파일 이름을 따로 적어 두는 기록은 이 핸드북이 확인한 공개 자료에서 찾지 못했습니다. 그래서 업로드할 수 있는 사이트를 방문한 시각, 그 시간대에 파일을 다룬 흔적, 앱이 내보낸 데이터 양을 모아 정황으로 맞춰 보는 방식으로 조사하고, 이 흐름은 공개 자료에서 확인한 절차가 아니라 필자가 정리한 방법입니다. 경로마다 공통으로 쓰는 판단 원칙은 [자료를 밖으로 빼돌렸나](index.md) 허브에 있습니다.

메일 앱 대신 브라우저로 웹메일을 쓴 경우와 클라우드 서비스의 웹 화면으로 파일을 올린 경우를 이 페이지에서 다룹니다. 메일 앱으로 보낸 경우는 [메일로](email.md), 동기화 앱의 폴더에 넣어 올린 경우는 [클라우드로](cloud.md) 페이지를 봅니다.

## 먼저 확인할 것

OS 버전과 시간대는 [OS 버전과 설치 기록](../../../02-artifacts/system-account/os-version-install-history.md)과 [시간대와 시계 설정](../../../02-artifacts/system-account/time-zone.md)에서 먼저 확인합니다. 브라우저 기록과 파일 흔적은 시각을 적는 기준이 서로 다를 수 있어서, 모든 시각을 한 기준으로 바꿔 적어 두어야 뒤에서 대조할 수 있습니다([맥의 시각 값](../../../01-foundations/value-decoding/mac-time-values.md)).

사용자 범위를 정할 때는 브라우저도 함께 정합니다. 브라우저 기록은 사용자 홈 아래 브라우저마다 따로 쌓여서, 이 맥에 어떤 브라우저가 있었는지 [설치한 앱과 영수증](../../../02-artifacts/system-account/installed-apps-receipts.md)에서 먼저 보고 사용자마다, 브라우저마다 기록을 모읍니다. 개인 정보 보호 브라우징을 썼다면 기록이 어떻게 달라지는지는 [개인 정보 보호 브라우징으로 무엇을 했나](../../activity/private-browsing.md)에서 다룹니다.

수집 범위에는 브라우저 프로필 폴더와 함께 앱별 네트워크 사용량 기록이 들어 있는지 확인합니다. 네트워크 사용량은 업로드했을 법한 시간대를 좁히는 데 쓰는 보조 흔적이고, 수집 방법은 [맥 증거 확보](../../../03-techniques/process-acquisition/evidence-acquisition/index.md)를 따릅니다.

## 볼 아티팩트와 순서

| 순서 | 아티팩트 | 알려 주는 것 | 링크 |
|---|---|---|---|
| 1 | 사파리 방문 기록 | 업로드할 수 있는 사이트를 방문한 주소와 시각 | [사파리](../../../02-artifacts/browsers/safari/index.md) |
| 1 | 크롬·엣지·웨일 방문 기록 | 같음 | [크롬·엣지·웨일](../../../02-artifacts/browsers/chromium/index.md) |
| 1 | 파이어폭스 방문 기록 | 같음 | [파이어폭스](../../../02-artifacts/browsers/firefox.md) |
| 2 | 최근 항목 | 같은 시간대에 이 사용자가 연 파일 | [최근 항목](../../../02-artifacts/file-folder-usage/recent-items/index.md) |
| 3 | 파일 시스템 이벤트 | 같은 시간대에 만들어지거나 이름이 바뀐 파일 | [파일 시스템 이벤트](../../../02-artifacts/filesystem/fsevents/index.md) |
| 4 | KnowledgeC·바이옴 | 같은 시간대에 쓴 앱 | [KnowledgeC](../../../02-artifacts/execution/knowledgec/index.md), [바이옴](../../../02-artifacts/execution/biome/index.md) |
| 5 | 앱별 네트워크 사용량 | 브라우저가 내보낸 데이터 양 | [앱별 네트워크 사용량](../../../02-artifacts/network/netusage.md) |

파일 선택 창에서 고른 파일이 최근 항목·FSEvents·KnowledgeC에 남는지는 이 핸드북에서 확인하지 못했습니다. 그래서 2~4번 흔적은 "업로드할 때 고른 파일"이 아니라 "같은 시간대에 다룬 파일과 앱"으로만 읽습니다. 네트워크 사용량은 mac_apt에 `netusage` 플러그인이 있다는 것까지 확인했고 [1], 데이터베이스 경로와 표 구조는 [앱별 네트워크 사용량](../../../02-artifacts/network/netusage.md) 페이지를 따릅니다.

## 분석 흐름

1. 조사할 시간대와 대상 파일을 정합니다. 다른 경로를 조사하며 나온 시각이나 신고 내용에서 출발합니다.
2. 브라우저마다 방문 기록에서 웹메일·클라우드 저장소·파일 공유 사이트 주소를 찾아 방문 시각을 뽑습니다. 찾을 주소 목록은 사건과 조직 환경에 맞춰 정하고, 방문 기록 읽는 법은 [웹 사용 행위 재구성](../../activity/web-activity.md)을 따릅니다.
3. 2단계 시각 앞뒤로 대상 파일을 열거나 옮긴 흔적을 최근 항목과 FSEvents에서 찾습니다. 올리기 전에 파일을 압축하거나 이름을 바꿨을 수 있어서, 같은 폴더에 새로 생긴 압축 파일이나 이름이 바뀐 파일도 함께 봅니다.
4. 같은 시간대에 브라우저를 쓰고 있었는지 KnowledgeC·바이옴으로 확인하고, 네트워크 사용량에서 브라우저가 내보낸 양이 대상 파일 크기와 어울리는지 봅니다.
5. 1~4단계의 시각을 한 [타임라인](../../../03-techniques/analysis/timeline/index.md)에 올려, 사이트 방문·파일 접근·송신량이 한 시간대에 겹치는지 봅니다.

## 흔한 오판

- **업로드 사이트를 방문한 기록만으로 "올렸다"고 쓰는 경우.** 방문 기록은 그 주소를 열었다는 사실까지만 말하고, 파일을 올렸는지는 말하지 않습니다. 웹메일은 받은 메일을 읽으려고도 열고, 클라우드 사이트는 내려받으려고도 엽니다.
- **다운로드 기록을 업로드 흔적으로 읽는 경우.** 브라우저 다운로드 기록과 격리 속성은 밖에서 이 맥으로 들어온 파일의 흔적이라 방향이 반대입니다. 들어온 파일을 추적하는 방법은 [이 파일은 어디서 왔나](../../activity/file-origin.md)에 있습니다.
- **송신량이 크면 대상 파일을 보냈다고 보는 경우.** 송신량은 앱 단위 숫자라서 어떤 파일을 보냈는지와 이어지지 않고, 같은 시간대의 영상 통화나 동기화와도 섞입니다.
- **방문 기록이 없으면 올리지 않았다고 보는 경우.** 다른 브라우저나 다른 사용자 계정을 썼을 수 있고, 기록을 지웠을 수도 있습니다. 지운 흔적은 [증거를 없애려 했나](../../activity/anti-forensics/index.md)의 방법으로 따로 찾습니다.

## 보고서 문장 예

> 사용자 ○○의 사파리 방문 기록에 ○○○○년 ○월 ○일 ○시 ○분(UTC로 바꾼 시각) 파일 공유 사이트 "○○"의 업로드 화면 주소를 연 기록이 있고, 같은 사용자의 최근 항목에는 그보다 ○분 앞서 "○○.xlsx" 파일을 연 기록이 있습니다. 이 기록들은 두 행위가 같은 시간대에 있었다는 사실까지만 보여 주며, 이 파일을 그 사이트에 올렸는지는 이 맥의 기록만으로 정할 수 없습니다.
