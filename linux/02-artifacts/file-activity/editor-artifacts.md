# 편집기 흔적 (vim·nano·less)

터미널 편집기와 페이저는 사용자 홈에 기록 파일을 남기고, vim 은 편집 중인 파일 옆에 스왑 파일까지 만들어서, 어떤 계정이 어떤 파일을 열었고 무엇을 검색·입력했는지 알려 줍니다.

## 무엇을 기록하나 · 왜 생기나

서버를 다루는 사람은 설정 파일을 대개 `vim`·`nano` 로 고치고 로그는 `less` 로 봅니다. 세 프로그램 모두 다음 실행 때 편하도록 지난 작업을 파일에 저장해 두고, 이 편의 기능이 그대로 흔적이 됩니다. 셸 기록에는 `vim /etc/hosts` 처럼 명령줄만 남지만, 편집기 기록에는 그 안에서 입력한 명령·검색어·커서 위치가 남습니다.

| 프로그램 | 흔적 | 담는 것 | 기본으로 남나 |
|---|---|---|---|
| Vim | viminfo (`~/.viminfo`) | 명령줄 기록, 검색 문자열 기록, 입력줄 기록, 레지스터 내용, 파일별 마크, 파일 마크, 마지막 검색·치환 패턴, 버퍼 목록, 전역 변수[1] | 켜짐(Vim 기본값일 때)[2] |
| Vim | 스왑 파일 (`.이름.swp`) | 편집 중인 내용과 사용자·호스트·PID·파일 이름[3][5] | 켜짐, 편집을 마치면 지움[3] |
| Vim | 백업 (`이름~`)·undo 파일 (`.이름.un~`) | 이전 판 내용, 되돌리기 기록[2] | 꺼짐[2] |
| Neovim | ShaDa (`main.shada`) | viminfo 와 같은 종류의 정보[6] | `'shada'` 가 비어 있지 않을 때[6] |
| nano | `search_history`·`filepos_history` | 검색·치환·실행 명령 기록, 최근 200개 파일의 커서 위치[7] | 꺼짐(`-H`·`-P` 또는 nanorc 설정)[7] |
| nano | 비상 저장 (`이름.save`)·잠금 파일 (`.이름.swp`) | 편집 중인 내용, 잠금 정보[7] | 비상 저장은 켜짐, 잠금은 꺼짐[7] |
| less | lesshst | 검색 패턴, 셸 명령, 저장한 마크[8] | 켜짐[8] |

## 위치와 버전별 차이

위치는 배포판이 아니라 프로그램과 그 판이 정합니다. Ubuntu 24.04 와 RHEL 9 도 같은 규칙을 따르므로, 분석 대상에서는 `vim --version`, `nano --version`, `less --version` 이나 패키지 기록으로 판을 먼저 확인합니다.

### Vim·Neovim

viminfo 기본 위치는 `$HOME/.viminfo` 입니다[1]. `'viminfo'` 옵션의 `n` 플래그, 실행 인자 `-i 파일`, `'viminfofile'` 옵션으로 위치를 바꿀 수 있고, `-i NONE` 이면 읽지도 쓰지도 않습니다[1]. 옵션 기본값은 Vim 기본값이 `'100,<50,s10,h`(마크를 기억할 파일 100개, 레지스터마다 50줄, 10KB 넘는 레지스터 제외)이고 Vi 기본값은 빈 문자열입니다[2]. 그래서 호환 모드 (compatible) 로 도는 Vim 은 viminfo 를 쓰지 않습니다[2]. 명령줄·검색 기록 개수는 `'history'` 를 따르며 Vim 기본값은 200 입니다[2]. 버퍼 목록은 `'viminfo'` 에 `%` 가 있을 때만 저장하므로 기본값에서는 남지 않습니다[2].

스왑 파일은 편집 중인 파일과 같은 폴더에 `.이름.swp` 로 생기고, 그 이름이 이미 있으면 `.swo`, `.swn` 처럼 마지막 글자를 줄여 가며 이름을 고릅니다[3]. 스왑 폴더 기본값 `'directory'` 는 `.,~/tmp,/var/tmp,/tmp` 라서, 편집 폴더에 쓸 수 없으면 `/var/tmp`·`/tmp` 에 생길 수 있습니다[2]. 백업은 `'backup'` 이 기본 꺼짐이고, `'writebackup'` 은 켜져 있지만 저장이 끝나면 백업을 지웁니다[2]. 백업 폴더 기본값은 `.,~/tmp,~/`, 확장자는 `~` 입니다[2]. undo 파일은 `'undofile'` 을 켰을 때만 `.이름.un~` 으로 생깁니다[2].

Neovim 은 viminfo 대신 ShaDa (shared data) 파일을 씁니다. 기본 위치는 `$XDG_STATE_HOME/nvim/shada/main.shada` 이고, 보통 `~/.local/state/nvim/shada/main.shada` 입니다[6].

### nano

nano 는 기록 폴더를 아래 순서로 고르고, `~/.nano/` 가 없을 때 2나 3에서 고른 폴더가 없으면 권한 0700 으로 만듭니다[7].

| 순서 | 폴더 | 조건 |
|---|---|---|
| 1 | `~/.nano/` | 이 폴더가 이미 있을 때 |
| 2 | `$XDG_DATA_HOME/nano/` | 환경 변수가 있을 때 |
| 3 | `~/.local/share/nano/` | 그 밖의 경우 |

이 폴더 안에 `search_history`(`-H`, `--historylog`, nanorc 의 `set historylog`)와 `filepos_history`(`-P`, `--positionlog`, `set positionlog`)가 생깁니다[7]. 설정 파일은 시스템 `/etc/nanorc` 와 사용자 `~/.nanorc`, `$XDG_CONFIG_HOME/nano/nanorc`, `~/.config/nano/nanorc` 입니다[7]. 기록 설정은 주로 이 파일에 들어 있으므로 기록 파일과 함께 봅니다.

### less

less 는 기록 파일 lesshst 를 `$XDG_STATE_HOME/lesshst` → `$HOME/.local/state/lesshst` → `$XDG_DATA_HOME/lesshst` → `$HOME/.lesshst` 순서로 찾고, 저장할 때 이미 있는 파일이 있으면 그 파일을 씁니다[8]. 환경 변수 `LESSHISTFILE` 로 위치를 정할 수 있고, 값이 `-` 나 `/dev/null` 이면 기록을 쓰지 않습니다[8].

| less 판 | 기록 파일 위치 |
|---|---|
| 581 까지 | `$HOME/.lesshst` |
| 590 부터 | `XDG_DATA_HOME` 이 있으면 `$XDG_DATA_HOME/lesshst`[8] |
| 608 부터 | `$XDG_STATE_HOME`·`$HOME/.local/state` 가 앞 순서로 추가됨[8] |

## 구조

### viminfo

viminfo 는 사람이 읽을 수 있는 텍스트 파일입니다. `#` 로 시작하는 줄은 절 제목이고, Vim 8 이후 형식은 옛 형식 줄 바로 뒤에 `|` 로 시작하는 막대 줄 (bar line) 을 덧붙여 시각을 적습니다[4]. 막대 줄의 첫 숫자는 종류로, 1 은 판, 2 는 기록, 3 은 레지스터, 4 는 마크이고 현재 판 번호는 4 입니다[4].

```text
|2,{기록 종류},{시각},{구분자},"내용"                              기록 한 줄
|3,{플래그},{이름},{형식},{줄 수},{너비},{시각},"줄1","줄2"        레지스터
|4,{마크 이름},{줄},{열},{시각},"파일 이름"                        파일 마크·점프
```

기록 종류는 0 명령줄, 1 검색, 2 식, 3 입력줄, 4 디버그입니다[4]. 옛 형식 줄은 앞 글자로 종류를 나타내고(`:` 명령줄, `?` 검색, `=` 식, 그 밖은 `@`), 검색 기록은 둘째 글자에 구분자를 둡니다[4]. 마크 이름은 문자 코드 숫자로 적힙니다(`'0` 이면 48)[4].

파일별 마크는 `# History of marks within files (newest to oldest):` 절에 있습니다. 한 파일은 `> ` 뒤에 경로를 적은 줄로 시작하고, 홈 폴더 경로는 `~` 로 줄여 적습니다[4]. 그 아래 탭으로 들여 쓴 줄마다 마크 하나를 적는데, 첫 줄 `*` 는 실제 마크가 아니라 줄 번호 자리에 그 파일 버퍼에 마지막으로 들어간 시각을 넣은 것입니다[4]. 이어서 `"`(마지막 커서), `^`(마지막 입력), `.`(마지막 변경), `+`(변경 목록, 오래된 것부터), `a`~`z`(이름 붙인 마크)가 옵니다[4].

아래는 형식에 맞춰 만든 예시입니다(만든 예시, 사용자·경로·값 모두 지어낸 것).

```text
# This viminfo file was generated by Vim 9.1.
# You may edit it if you're careful!

# Viminfo version
|1,4

# Value of 'encoding' when this file was written
*encoding=utf-8

# Command Line History (newest to oldest):
:wq
|2,0,1767226500,,"wq"
:%s/192.0.2.10/192.0.2.20/g
|2,0,1767226400,,"%s/192.0.2.10/192.0.2.20/g"

# Search String History (newest to oldest):
?/192.0.2.10
|2,1,1767226300,47,"192.0.2.10"

# File marks:
'0  3  0  /etc/hosts
|4,48,3,0,1767226500,"/etc/hosts"

# Jumplist (newest first):
-'  3  0  /etc/hosts
|4,39,3,0,1767226500,"/etc/hosts"

# History of marks within files (newest to oldest):

> /etc/hosts
	*	1767226200	0
	"	3	0
	.	3	14
	+	3	14
```

`'0` 은 viminfo 를 쓸 때(종료나 `:wviminfo`) 현재 커서가 있던 파일과 위치이고, 이전 `'0` 은 `'1` 로, `'1` 은 `'2` 로 밀립니다[1]. 그래서 `'0`~`'9` 는 최근 Vim 을 끝낸 자리 열 곳의 목록으로 읽을 수 있습니다.

### Vim 스왑 파일의 첫 블록

스왑 파일 첫 블록 (block 0) 에는 누가 어디서 어떤 파일을 편집했는지 적혀 있습니다[5]. 4바이트 숫자는 기계와 상관없이 낮은 바이트부터 저장합니다[5].

| 오프셋 | 크기 | 내용 |
|---|---|---|
| 0 | 2 | `b0`. 암호화한 스왑은 둘째 바이트가 `c`·`C`·`d`·`S`·`s`[5] |
| 2 | 10 | `VIM ` 뒤에 Vim 판 문자열[5] |
| 12 | 4 | 페이지 크기[5] |
| 16 | 4 | 편집 중인 원본 파일의 수정 시각 (mtime), 원본이 없으면 0[5] |
| 20 | 4 | 원본 파일의 아이노드 번호, 원본이 없으면 0[5] |
| 24 | 4 | 스왑을 만든 프로세스 ID[5] |
| 28 | 40 | 사용자 이름(없으면 UID)[5] |
| 68 | 40 | 호스트 이름[5] |
| 108 | 900 | 편집 중인 파일 이름. 홈 폴더 파일은 `~사용자/…` 형식[5] |
| 1006 | 1 | 플래그[5] |
| 1007 | 1 | `0x55` 면 저장하지 않은 변경이 있음[5] |

파일 이름 필드 끝부분에는 파일 인코딩도 들어갈 수 있습니다[5]. 첫 블록 뒤에는 편집 중인 본문이 블록 단위로 들어 있어서, `vim -r 파일` 로 저장하지 않은 변경을 되살릴 수 있습니다[3].

### nano 기록과 잠금 파일

`search_history` 는 검색 문자열, 빈 줄, 치환 문자열, 빈 줄, 실행 명령 순서로 오래된 것부터 한 줄에 하나씩 적고, 문자열 안의 줄바꿈은 NUL 바이트로 바꿔 적습니다[7]. `filepos_history` 는 한 줄에 `경로 줄 열` 을 적고, 앵커 (anchor) 를 둔 줄이 있으면 그 줄 번호들을 경로 앞에 붙입니다[7]. 두 파일 모두 권한을 0600 으로 바꾸고, 항목별 시각은 없습니다[7].

`-G`·`set locking` 을 켜면 nano 도 vim 식 잠금 파일 `.이름.swp` 를 1024바이트로 만듭니다[7]. 0~1 바이트 `62 30`, 2~11 바이트 `nano` 와 판, 24~27 바이트 PID(작은 끝 순서), 28 바이트부터 사용자 이름(최대 16바이트), 68 바이트부터 호스트 이름(최대 32바이트), 108 바이트부터 파일 이름(최대 768바이트)이 오고, 1007 바이트가 `0x55` 면 수정된 상태입니다[7]. Vim 과 달리 페이지 크기·원본 mtime·아이노드는 적지 않습니다[7].

### lesshst

첫 줄은 `.less-history-file:` 이고, `.search`(검색 패턴), `.shell`(`!` 셸 명령), `.mark`(마크) 절이 이어집니다[8]. 기록 한 줄은 `"` 로 시작하고, 마크 줄은 `m 글자 화면줄 위치 파일이름` 형식입니다[8]. `.search`·`.shell` 절은 기본 100개(`LESSHISTSIZE`)까지 남기고, 항목별 시각은 없습니다[8]. 마크는 `--save-marks` 로 실행했거나 이전에 저장된 마크가 있을 때만 적힙니다[8].

```text
.less-history-file:
.search
"Failed password
"203.0.113.7
.shell
"grep -c sshd /var/log/auth.log
.mark
m a 1 20480 /var/log/auth.log
```

위는 형식에 맞춰 만든 예시입니다.

## 증거로서 의미

**증명하는 것**

- viminfo 의 `>` 블록·파일 마크·점프 목록에 경로가 있으면, 이 viminfo 를 쓴 Vim 이 그 경로의 파일을 버퍼로 열었던 적이 있다는 것.
- 막대 줄의 시각은 그 명령줄·검색어를 입력하거나 레지스터·마크를 설정한 시각이라는 것. 명령 하나하나에 시각이 붙어 있어 셸 기록보다 촘촘한 타임라인을 만들 수 있습니다[4].
- `:%s/…/…/` 같은 치환 명령, `:!` 로 실행한 외부 명령, 레지스터에 남은 복사·삭제 텍스트는 편집 의도를 보여 주는 문자열 그대로라는 것.
- 스왑 파일이 남아 있으면, 첫 블록의 사용자·호스트·PID 로 그 파일을 편집하던 Vim 이 비정상 종료했거나 수집 시점에 아직 편집 중이었다는 것[3][5]. 1007 바이트가 `0x55` 면 저장하지 않은 변경이 있었습니다.
- nano `filepos_history`·less `.mark` 에 경로가 있으면 그 파일을 열었던 적이 있다는 것.

**증명하지 못하는 것**

- 파일을 저장했다거나 내용을 바꿨다는 것. `.` 마크와 치환 명령으로 추정할 수 있을 뿐이고, 파일 쪽 시각과 맞춰 봐야 합니다.
- 기록이 전부라는 것. viminfo 는 개수 제한으로 오래된 항목이 밀려나고, `r` 플래그로 지정한 경로는 마크를 저장하지 않으며, `-i NONE` 으로 실행한 세션은 아무것도 남기지 않습니다[1][2].
- 기록 파일 소유자 본인이 입력했다는 것. `su`·`sudo` 뒤에는 어느 계정의 파일에 쓰는지가 `$HOME` 에 따라 달라집니다(함정 절 참고).
- nano·less 기록의 항목이 언제 생겼는지. 항목별 시각이 없습니다[7][8].

보고서에는 "`/root/.viminfo` 에 2026-01-01 00:11:40(UTC) 에 `192.0.2.10` 을 검색한 기록이 있다" 처럼 기록으로 확인되는 만큼만 씁니다(만든 예시).

## 시각 해석

| 값 | 뜻 | 기준 |
|---|---|---|
| viminfo 막대 줄의 시각 | 기록·레지스터·마크를 만든 시각 | `time(NULL)` 값, 유닉스 시각 (epoch) 초, UTC[4] |
| viminfo `*` 줄의 값 | 그 파일 버퍼에 마지막으로 들어간 시각 | 같음[4] |
| viminfo 파일의 mtime | 마지막으로 viminfo 를 쓴 시각, 보통 Vim 을 끝낸 시각 | 파일 시스템 시각[1] |
| 스왑 첫 블록 16 바이트 | 편집 대상 원본 파일의 mtime(스왑을 만든 시각이 아님) | epoch 초, 4바이트[5] |
| 스왑 파일 자신의 mtime | 마지막으로 스왑을 갱신한 시각. 변경이 있을 때 200글자 입력 또는 4초 멈춤마다 갱신 | 파일 시스템 시각[3] |
| nano·less 기록 파일의 mtime | 마지막으로 기록을 저장한 시각 | 파일 시스템 시각 |

epoch 초를 읽는 법은 [Linux 의 시각 값](../../01-foundations/value-decoding/time-values.md) 에 있습니다. viminfo 는 여러 세션 내용을 합쳐 쓰므로 파일 mtime 은 마지막 세션만 가리키고, 개별 항목 시각은 막대 줄에서 읽어야 합니다[1]. 막대 줄이 없는 항목은 시각 기능이 들어가기 전(Vim 8.0 전)의 판이 남긴 것일 가능성이 있습니다[1]. 스왑 첫 블록의 시각 필드는 4바이트라 큰 값은 잘립니다[5].

## 함정과 한계

- **여러 세션이 합쳐집니다.** Vim 은 끝날 때 기존 viminfo 를 읽어 합쳐 쓰고, 시각이 붙은 항목은 새것을 남깁니다[1]. 한 파일 안의 순서가 한 세션의 순서라고 보면 안 됩니다.
- **root 로 편집한 흔적은 두 곳을 봅니다.** Vim 은 현재 실제 (real) 사용자가 쓸 수 없는 viminfo 를 덮어쓰지 않습니다[1]. 다만 현재 코드는 실제 UID 가 root 이면 이 검사를 건너뛰고, 새로 쓴 viminfo 의 소유자를 원래 소유자로 되돌립니다[4]. 그래서 `su` 로 root 가 됐는데 `$HOME` 이 원래 사용자 홈이면 root 로 한 편집 기록이 그 사용자의 `~/.viminfo` 에 섞일 수 있고, `$HOME` 이 `/root` 면 `/root/.viminfo` 에 남습니다. sudo 의 `$HOME` 처리는 [sudo 설정](../../01-foundations/users-auth/sudoers.md) 을 봅니다.
- **viminfo 는 임시 파일을 거쳐 바뀝니다.** viminfo 가 이미 있으면 Vim 은 같은 폴더에 임시 파일을 O_EXCL 로 만들어(권한은 기존 파일 권한에 0600 을 더한 값) 쓴 뒤 이름을 바꿉니다[4]. 그래서 viminfo 의 아이노드 번호는 쓸 때마다 바뀌고, 비정상 종료 뒤에는 `~/.viminf*` 형식의 임시 파일이 남을 수 있습니다[1]. viminfo 는 심볼릭 링크일 수 없습니다[1].
- **Vim 저장이 원본 아이노드를 바꿀 수 있습니다.** `'backupcopy'` 기본값 `auto` 는 문제가 없으면 원본 이름을 바꿔 백업으로 두고 새 파일을 씁니다[2]. 편집한 파일의 아이노드가 바뀌므로 아이노드 기준 타임라인과 [감사 로그의 파일 감시](auditd-watches.md) 를 해석할 때 고려합니다. 옛 아이노드 쪽 시각은 [ext4](../../01-foundations/filesystem/ext4/index.md) 에서 찾습니다.
- **스왑 파일은 정상 종료 때 지워집니다.** 편집을 마치면 바로 지우므로[3], 남아 있는 스왑은 예외 상황의 흔적입니다. 지워진 스왑은 `b0VIM ` 서명으로 빈 공간을 찾아볼 수 있습니다. `/tmp` 에 생긴 스왑은 재부팅 때 사라질 수 있습니다([임시 폴더와 메모리 파일 시스템](tmp-shm.md)).
- **`.swp` 라고 모두 Vim 것은 아닙니다.** nano 잠금 파일도 같은 이름·같은 `b0` 서명을 씁니다[7]. 2바이트 뒤가 `VIM ` 인지 `nano ` 인지로 가릅니다.
- **nano 기록이 없는 것이 보통입니다.** 기록은 기본으로 꺼져 있으므로[7], 없다고 지웠다고 볼 수 없습니다. nanorc 에 `set historylog` 가 있는데 기록 파일이 없으면 그때 의심합니다.
- **도구 정의가 모으는 위치가 코드와 다릅니다.** ForensicArtifacts 와 UAC 는 nano 기록으로 `~/.nano_history` 를 모으지만[9][10], 현재 nano 코드는 `~/.nano/`·`~/.local/share/nano/` 의 `search_history`·`filepos_history` 를 씁니다[7]. less 도 ForensicArtifacts 는 `~/.lesshst` 만 모으고[9], UAC 는 `~/.local/state/lesshst`·`~/.local/share/lesshst` 까지 모읍니다[10]. Vim 스왑·ShaDa 는 두 정의 모두 모으지 않습니다[9][10]. 수집 목록에 기대지 말고 홈 폴더를 직접 살펴봅니다.
- **기록을 끄는 설정은 셸 시작 파일에 있습니다.** `LESSHISTFILE=-`, `alias vim='vim -i NONE'` 같은 줄이 있으면 기록이 없는 이유가 됩니다. [셸 시작 파일](../persistence/shell-startup.md) 을 함께 봅니다. less 는 보안 모드 (secure mode) 에서는 기록을 읽거나 쓰지 않습니다[8].
- **손으로 고칠 수 있습니다.** viminfo 는 평문 텍스트이고[1] 머리에 `You may edit it if you're careful!` 라고 적혀 있습니다[4]. lesshst 도 텍스트입니다[8]. 기록 파일 mtime 과 마지막 막대 줄 시각이 크게 어긋나면 살펴볼 만합니다.

## 직접 분석해 보기

### 헥스로 한 번 — Vim 스왑 첫 블록

아래는 위 오프셋 표로 만든 예시입니다(명세로 만든 예시). 사용자 `user1`, 호스트 `host01`, 파일 `~user1/notes.txt`, PID 4242, 원본 mtime 2026-01-01 00:00:00 UTC 를 가정했고, 적지 않은 줄은 모두 0 입니다.

```text
00000000  62 30 56 49 4d 20 39 2e 31 00 00 00 00 10 00 00  b0VIM 9.1.......
00000010  00 b9 55 69 01 35 0c 00 92 10 00 00 75 73 65 72  ..Ui.5......user
00000020  31 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00  1...............
00000040  00 00 00 00 68 6f 73 74 30 31 00 00 00 00 00 00  ....host01......
00000060  00 00 00 00 00 00 00 00 00 00 00 00 7e 75 73 65  ............~use
00000070  72 31 2f 6e 6f 74 65 73 2e 74 78 74 00 00 00 00  r1/notes.txt....
000003e0  00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 55  ...............U
```

1. 0x00 의 `62 30` 이 `b0`, 0x02 부터 `VIM 9.1` 이 Vim 판입니다.
2. 0x0C `00 10 00 00` 을 낮은 바이트부터 읽으면 0x1000, 페이지 크기 4096 입니다.
3. 0x10 `00 b9 55 69` 는 0x6955B900 = 1767225600 이고, 원본 파일의 mtime 2026-01-01 00:00:00 UTC 입니다.
4. 0x14 `01 35 0c 00` 은 아이노드 800001, 0x18 `92 10 00 00` 은 PID 4242 입니다.
5. 0x1C 부터 사용자 이름, 0x44(68) 부터 호스트 이름, 0x6C(108) 부터 파일 이름을 읽습니다.
6. 0x3EF(1007) 가 `55` 이므로 저장하지 않은 변경이 있던 상태입니다.

### 공개 도구로 한 번

- plaso 의 `viminfo` 파서는 명령줄·검색·식·입력줄·디버그 기록, 레지스터, 파일 마크, 점프 목록의 막대 줄 시각을 사건으로 뽑습니다[11]. 파일별 마크 절(`History of marks within files`)은 아직 읽지 않으므로[11] `>` 블록과 `*` 시각은 직접 읽습니다.
- Vim 자체도 도구가 됩니다. 사본에서 `vim -r` 을 실행하면 찾은 스왑 파일 목록과 각 파일의 사용자·호스트·PID·수정 여부를 보여 줍니다[1][5]. 원본 증거물이 아닌 사본 폴더에서 실행합니다.
- ShaDa 는 MessagePack 항목을 이어 붙인 파일입니다. 항목마다 종류(1 Header, 2 SearchPattern, 3 SubString, 4 HistoryEntry, 5 Register, 6 Variable, 7 GlobalMark, 8 Jump, 9 BufferList, 10 LocalMark, 11 Change), 타임스탬프, 길이, 데이터 네 값이 있으므로[6] MessagePack 을 읽는 라이브러리로 풀어 봅니다. 타임스탬프 단위는 풀어 낸 값을 파일 mtime 과 비교해 확인합니다.
- nano·less 기록과 viminfo 는 텍스트라서 `cat -A` 로 NUL·탭을 드러내 읽으면 됩니다.

## 실습

공개 Linux 시험 데이터(NIST CFReDS 등)나 직접 만든 가상 머신 이미지로 아래 질문을 풀어 봅니다.

1. 모든 사용자 홈과 `/root` 에 `.viminfo`, `.local/state/nvim/shada/main.shada`, `.nano/`, `.local/share/nano/`, lesshst 네 위치 가운데 무엇이 있는가?
2. `.viminfo` 의 명령줄 기록에서 `:w`·`:wq`·`:%s` 가 있는 줄의 막대 줄 시각을 UTC 로 바꾸면, 셸 기록·인증 로그의 로그인 시간대 안에 드는가?
3. `> ` 블록에 적힌 경로 가운데 `/etc` 아래 파일은 무엇이고, 그 파일들의 mtime 은 `*` 시각 뒤에 있는가?
4. 파일 시스템 전체에서 `.swp`·`.swo` 로 끝나는 파일을 찾아 첫 16바이트를 보면, Vim 이 만든 것과 nano 가 만든 것은 각각 몇 개인가? Vim 것이라면 사용자·호스트·수정 여부는?
5. 빈 공간에서 `b0VIM ` 서명을 검색하면 지워진 스왑 첫 블록이 나오는가? 나온다면 파일 이름 필드는 어떤 파일을 가리키는가?
