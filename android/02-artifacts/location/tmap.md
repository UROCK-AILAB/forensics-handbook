# 티맵 (TMAP)

티맵 (TMAP, 패키지 com.skt.tmap.ku) 은 국내에서 많이 쓰는 내비게이션·지도 앱이고, 앱 데이터를 모두 평문으로 저장해서 앱 폴더를 확보하면 범용 도구로 바로 읽을 수 있습니다 [2][3]. 공개 도구 ALEAPP 에는 이 앱을 읽는 모듈이 없어서 [1], 이 페이지는 티맵 기록을 찾고 해석할 때 챙길 점을 정리합니다.

## 무엇을 기록하나 · 왜 생기나

내비게이션 앱을 쓰면 사용자가 이동한 경로와 목적지의 위치 정보가 시간 정보와 함께 남고, 이 기록으로 사용자가 언제 어디로 가려 했는지를 추적할 수 있습니다 [2]. 티맵은 이런 데이터를 평문으로 저장해서, 사용자 동작에 따라 생기는 기록을 앱 폴더에서 바로 읽을 수 있습니다 [2].

앱에는 자동차 길 안내 말고도 대중교통·도보 길 안내, 맛집·장소 검색, 가고 싶은 장소를 그룹으로 모으는 "저장", 자주 가는 경로를 저장하는 "즐겨찾는 경로" 가 있습니다 [3]. 즐겨찾는 경로는 사용자가 저장한 것뿐 아니라, 이동했던 경로 가운데 자주 다닌 길을 앱이 자동으로 만들어 추천하기도 합니다 [3]. 그 밖에 매일 쌓이는 운전 데이터로 매기는 운전 점수, 카메라를 쓰는 블랙박스 기능, 주행 중 사고·공사를 알리는 소셜 제보, 대리운전·주차·전기차 충전·렌터카·바이크와 결제 기능이 있습니다 [3]. 이 기능 목록은 어떤 흔적을 찾아볼지 정하는 데 쓰고, 기기에 그 기록이 파일로 남았다는 근거로 쓰지 않습니다.

접근 권한 가운데 위치와 전화가 필수입니다 [3]. 위치 권한은 현재 위치 표시와 경로 안내에 쓰고, 전화 권한은 로그인할 때 본인을 확인하려고 전화번호를 인증하고 저장하는 데 씁니다 [3]. 선택 권한으로는 알림(공지·이벤트, 다른 시간 출발 알림, 신호등 정보), 마이크(음성 인식), 신체 활동(길 안내 정확도), SMS(주행 중 문자 주고받기), 주소록(음성 전화 걸기), 통화 기록(전화 다시 걸기, 연락처 표시), 카메라(블랙박스·카드/QR 스캔·사진), 파일 및 미디어(프로필·리뷰 사진 올리기), 다른 앱 위에 그리기(다른 앱을 쓰는 중 방향 표지판 표시), 근처 기기(NUGU 블루투스 연동), 알림 접근(길 안내 중 전화 받기), 차량 정보(연비·연료 정보 연동)가 있습니다 [3].

## 위치와 버전별 차이

| 항목 | 내용 | 근거 |
|---|---|---|
| 패키지 이름 | com.skt.tmap.ku, 개발자 TMAP MOBILITY CO.(티맵모빌리티) | Play 상세 페이지 [3] |
| 지원 Android 버전 | 최신 판은 Android 11.0 이상 | Play 상세 페이지 [3] |
| 저장 방식 | 모든 데이터를 평문으로 저장 | 2022년 분석 [2] |
| DB 파일 이름·표·열 | 앱 판마다 바뀔 수 있어 실제 데이터로 확인 | — |
| ALEAPP 전용 모듈 | 없음(2026-09-28 main 가지의 모듈 목록 기준) | [1] |

평문 저장은 2022년 논문이 그 무렵의 앱을 분석한 결과라서 [2], 다른 판을 다룰 때는 파일 앞머리가 `SQLite format 3\000` 인지 보고 다시 확인합니다. 앱을 처음 설치하면 필수 파일 30~50MB 를 따로 내려받으므로 [3], 앱 폴더에는 사용자 기록 말고도 지도·안내에 쓰는 큰 파일이 함께 있을 수 있습니다. 앱 데이터 영역의 짜임새는 [앱 데이터 폴더 구조](../../01-foundations/storage/app-data-layout.md) 페이지에서 다룹니다. 블랙박스 기능이나 사진 올리기를 썼다면 영상·사진이 [공용 저장 공간 (Shared Storage·/sdcard)](../../01-foundations/storage/shared-storage.md) 에 남았을 가능성이 있으니 그쪽도 살핍니다.

## 구조

앱 폴더를 직접 살펴 구조를 찾는 순서는 [네이버 지도 (NAVER Map)](naver-map.md) 페이지의 "구조 — 직접 찾는 절차" 와 같습니다. 여기서는 티맵에서 달라지는 점만 적습니다.

먼저 설치된 앱 목록에서 com.skt.tmap.ku 를 찾고, APK 의 앱 이름과 서명자를 확인합니다. 앱 목록은 [설치된 앱 (packages.xml)](../app-usage/packages/index.md), APK 이름과 서명 읽기는 [APK 정보 (AndroidManifest·서명)](../embedded-metadata/apk.md) 페이지에 있습니다.

데이터가 평문이라 [2], 찾은 폴더의 SQLite 파일은 SQLite 브라우저로 바로 열립니다. 표 목록과 `PRAGMA table_info` 결과를 적어 두고, 검색어·장소 이름·좌표·시각이 들어 있을 만한 표를 고릅니다. 지도 데이터처럼 크기가 큰 파일은 사용자 기록과 따로 분류해 두면 살펴볼 파일이 줄어듭니다. 그다음 시험 기기에서 목적지 검색, 길 안내 시작, 장소 저장, 경로 즐겨찾기를 하나씩 해 본 전후를 비교해 어느 표가 어느 동작 때 바뀌는지 확인합니다. 이 확인 전에는 표의 뜻을 보고서에 쓰지 않습니다.

## 증거로서 의미

**증명하는 것**

시험 기기로 뜻을 확인한 기록이라면, 그 시각에 어느 목적지를 검색했는지, 어디로 가는 길 안내를 받으려 했는지, 어떤 장소나 경로를 저장했는지를 알려 줄 수 있습니다. 확인하지 않은 기록은 "이 앱 폴더에 이런 문자열과 좌표가 있다" 는 사실만 증명합니다.

**증명하지 못하는 것**

목적지 검색이나 길 안내 기록은 그곳에 실제로 도착했다는 증거가 아닙니다. 길 안내를 시작했다가 중간에 멈췄을 수 있고, 다른 사람이 그 기기로 길을 찾았을 수도 있습니다. 즐겨찾는 경로에는 앱이 자동으로 만든 경로가 섞일 수 있어서 [3], 경로가 있다는 것만으로 사용자가 직접 저장했다고 단정하지 않습니다. 저장한 장소 그룹은 친구와 공유할 수 있으니 [3], 다른 사람이 만든 목록일 가능성도 따져 봅니다.

## 시각 해석

시각 필드의 단위는 표마다 다를 수 있습니다. 자릿수로 초·밀리초·마이크로초를 어림하고 앱 설치 시각과 수집 시각 사이에 들어오는지 맞춰 보는 방법은 [네이버 지도 (NAVER Map)](naver-map.md) 페이지의 시각 해석과 같습니다. 유닉스 시각은 UTC 기준이라 보고서에는 현지 시각으로 옮겨 적습니다. 값을 바꾸는 일반 방법은 [시각 값](../../01-foundations/value-decoding/time-values.md), 현지 시각 기준은 [시간대와 시각 설정 (Time Zone)](../system-account/time-zone.md) 페이지에 있습니다.

길 안내 기록에 시각이 여러 개 있으면, 검색한 때·안내를 시작한 때·안내가 끝난 때 가운데 어느 것인지 시험 기기로 구분합니다. 한 행의 시각 하나만 보고 "그 시각에 출발했다" 고 쓰지 않습니다.

## 함정과 한계

첫째, 공개 도구 결과에 티맵 항목이 없다고 해서 기록이 없는 것이 아닙니다. ALEAPP 에는 이 앱을 읽는 모듈이 없습니다 [1].

둘째, 같은 국내 지도 앱이라도 저장 방식이 다릅니다. 티맵과 [카카오맵 (KakaoMap)](kakaomap.md) 은 평문으로 저장하지만, [네이버 지도 (NAVER Map)](naver-map.md) 는 주요 DB 를 암호화합니다 [2]. 앱 판이 바뀌면 티맵의 저장 방식도 달라질 수 있으니 파일 앞머리부터 확인합니다.

셋째, 운전 점수의 바탕인 운전 데이터나 주행 기록이 기기에 파일로 남는지, 서버에만 있는지는 시험 기기로 확인합니다. 서버에 남는 기록은 기기 분석으로 얻을 수 없고, 클라우드 쪽 확보 절차는 [클라우드 데이터 (Google Takeout 등)](../../03-techniques/acquisition/cloud-data.md) 페이지에서 다룹니다.

## 직접 분석해 보기

### 헥스로 한 번

찾은 파일을 헥스 편집기로 열어 맨 앞 16바이트가 `SQLite format 3\000` 인지 봅니다. 좌표로 보이는 정수는 10^6·10^7 로 나눠 국내 위도·경도 범위에 들어오는지 확인합니다. 예시 계산과 형식별 페이지 링크는 [네이버 지도 (NAVER Map)](naver-map.md) 페이지의 "헥스로 한 번" 에 있습니다.

### 공개 도구로 한 번

전용 모듈이 없으니 SQLite 브라우저나 프로토콜 버퍼 디코더 같은 범용 도구로 파일을 하나씩 엽니다. 폴더 전체에서 목적지 이름이나 주소를 찾을 때는 [콘텐츠 검색 (Content Search)](../../03-techniques/analysis/content-search.md) 방법을 쓰고, 앱 폴더를 살피는 일반 절차는 [앱 데이터 분석 (App Data Analysis)](../../03-techniques/analysis/app-data-analysis/index.md) 페이지에 있습니다.

## 실습

공개 이미지에 티맵이 들어 있는 경우는 드물 수 있으니, 필요하면 직접 준비한 시험 기기로 풀어 봅니다.

1. 설치된 앱 목록에서 com.skt.tmap.ku 의 앱 이름, 서명자, 앱 버전은 무엇입니까?
2. 앱 데이터 폴더의 SQLite 파일은 몇 개이고, 모두 `SQLite format 3\000` 으로 시작합니까?
3. 시험 기기에서 목적지 하나를 검색하고 길 안내를 시작한 전후로, 어느 파일의 어느 표에 행이 늘었습니까?
4. 3번 행의 시각 값은 몇 자리이고, 단위를 골라 바꾼 현지 시각이 실제로 길 안내를 시작한 시각과 맞습니까?
5. 같은 시간대의 usagestats 와 블루투스 연결 기록이 3번의 시각과 겹칩니까?
