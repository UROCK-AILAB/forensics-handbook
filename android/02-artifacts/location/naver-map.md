# 네이버 지도 (NAVER Map)

## 한 줄 요약

네이버 지도 (NAVER Map) 는 국내 검체에서 자주 보이는 지도 앱이지만, 공개 도구 ALEAPP 에 전용 모듈이 없고 [1] 저장 경로와 표 구조를 공개 자료로 확인하지 못해서, 이 페이지는 확정된 구조 대신 앱 폴더를 직접 살펴 위치 기록을 찾는 절차를 다룹니다.

## 무엇을 기록하나 · 왜 생기나

지도 앱에서 찾아볼 만한 기록은 보통 최근 검색, 즐겨찾기(저장한 장소), 길찾기 기록이고, [구글 지도 (Google Maps)](google-maps.md) 에서는 이 세 가지가 실제로 앱 폴더에 남는 것을 공개 도구 코드로 확인할 수 있습니다. 네이버 지도가 이런 기록을 기기에 남기는지, 남긴다면 어느 파일에 어떤 모양으로 남기는지는 이번에 확인하지 못했습니다. 네이버 계정과 서버 사이에 무엇을 동기화하는지, 네이버 쪽에서 기록을 어떻게 조회하고 지우는지도 확인하지 못했습니다.

그래서 이 페이지에는 경로·파일 이름·표 이름을 적지 않습니다. 추측으로 적은 경로가 보고서로 옮겨지면 검체에 없는 파일을 찾거나, 다른 파일을 네이버 지도 기록으로 오해하게 됩니다.

## 위치와 버전별 차이

| 항목 | 상태 |
|---|---|
| 패키지 이름 | 확인하지 못함 |
| 앱 데이터 경로·DB 파일 이름 | 확인하지 못함 |
| 최근 검색·즐겨찾기·길찾기 기록의 표와 칸 | 확인하지 못함 |
| 시각 단위 | 확인하지 못함 |
| ALEAPP 전용 모듈 | 없음(2026-09-25 main 가지의 모듈 목록 기준) [1] |
| 관찰 기기의 앱 데이터 | 보지 못함 |

앱 버전이나 Android 버전, 삼성 One UI 여부에 따라 무엇이 달라지는지도 확인하지 못했습니다. 앱 데이터 영역은 루팅되지 않은 기기에서 adb 일반 권한으로 읽을 수 없는 곳이고, 짜임새는 [앱 데이터 폴더 구조](../../01-foundations/storage/app-data-layout.md) 페이지에서 다룹니다. 공용 저장 공간 쪽에 이 앱이 파일을 남기는지도 확인하지 못했으니, [공용 저장 공간 (Shared Storage·/sdcard)](../../01-foundations/storage/shared-storage.md) 도 함께 살핍니다.

## 구조 — 직접 찾는 절차

확인된 구조가 없으니, 검체마다 아래 순서로 앱 폴더를 살펴 구조를 직접 기록합니다. 일반 절차는 [앱 데이터 분석 (App Data Analysis)](../../03-techniques/analysis/app-data-analysis/index.md) 페이지에 있습니다.

1. 패키지를 찾습니다. 설치된 앱 목록에서 후보 패키지를 고르고, 그 APK 의 앱 이름과 서명자를 확인해 네이버 지도가 맞는지 가립니다. 앱 목록은 [설치된 앱 (packages.xml)](../app-usage/packages/index.md), APK 이름과 서명 읽기는 [APK 정보 (AndroidManifest·서명)](../embedded-metadata/apk.md) 페이지에서 다룹니다. 패키지 이름을 기억에 기대어 정하지 않습니다.
2. 그 패키지의 앱 데이터 폴더에서 `databases`, `shared_prefs`, `files`, `cache` 같은 하위 폴더를 훑고, 파일마다 크기와 수정 시각을 적어 둡니다.
3. 파일 앞머리 바이트로 형식을 가립니다. SQLite, 설정 XML, 프로토콜 버퍼, LevelDB 가운데 무엇인지에 따라 읽는 도구가 달라집니다.
4. SQLite 파일이면 표 목록을 뽑고, 이름이나 칸에 검색어·장소 이름·좌표·시각이 들어 있을 만한 표를 고릅니다.
5. 고른 표에서 좌표로 보이는 칸과 시각으로 보이는 칸을 찾아 아래 "시각 해석" 과 "직접 분석해 보기" 대로 단위를 가립니다.
6. 앱 안에서 직접 검색·즐겨찾기·길찾기를 해 본 시험 기기와 비교해, 어느 표가 어느 동작 때 바뀌는지 확인한 뒤에야 보고서에 표의 뜻을 씁니다.

6단계를 거치지 않은 해석은 "이 표에 이런 값이 있다" 까지만 씁니다. 시험 기기를 이용해 도구와 해석을 확인하는 방법은 [도구 검증 (Tool Validation)](../../03-techniques/reporting/tool-validation.md) 페이지에 있습니다.

## 증거로서 의미

**증명하는 것**

6단계까지 확인한 표라면, 검색 기록은 그 시각에 앱에서 무엇을 찾아봤는지, 즐겨찾기는 어떤 장소를 저장했는지, 길찾기 기록은 어디로 가는 길을 찾았는지를 알려 줄 수 있습니다. 확인하지 못한 표는 "이 앱 폴더에 이런 문자열과 좌표가 있다" 는 사실만 증명합니다.

**증명하지 못하는 것**

검색하거나 길을 찾은 기록은 그곳에 실제로 갔다는 증거가 아닙니다. 즐겨찾기가 계정 동기화로 다른 기기에서 넘어왔을 수 있는지도 확인하지 못했으니, 이 기기에서 저장했다고 단정하지 않습니다. 기록이 없다는 사실도 앱을 쓰지 않았다는 뜻이 아니고, 이 앱이 그런 기록을 기기에 남기지 않을 가능성이 있습니다.

## 시각 해석

시각 칸의 단위는 확인하지 못했으니, 값의 자릿수로 먼저 어림합니다. 요즘 날짜를 유닉스 시각으로 적으면 초는 10자리, 밀리초는 13자리, 마이크로초는 16자리쯤 됩니다. 자릿수로 고른 단위로 바꾼 날짜가 앱 설치 시각과 수집 시각 사이에 들어오는지 맞춰 보고, 문자열로 적힌 날짜라면 시간대 표기가 붙어 있는지 확인합니다. 값을 바꾸는 법은 [시각 값](../../01-foundations/value-decoding/time-values.md), 현지 시각으로 옮기는 기준은 [시간대와 시각 설정 (Time Zone)](../system-account/time-zone.md) 페이지에 있습니다.

## 함정과 한계

첫째, 공개 도구 결과에 네이버 지도 항목이 없다고 해서 기록이 없는 것이 아닙니다. ALEAPP 에는 이 앱을 읽는 모듈이 없습니다 [1].

둘째, 인터넷에 떠도는 경로나 표 이름을 확인 없이 옮기지 않습니다. 앱 판마다 저장 방식이 바뀔 수 있고, 이 페이지도 그 이름을 확인하지 못했습니다.

셋째, 네이버 앱이나 네이버 계정을 쓰는 다른 앱에서 지도를 연 기록은 네이버 지도 앱 폴더에 없을 수 있습니다. 네이버 앱 쪽은 [네이버 앱 (NAVER)](../browsers/naver.md) 페이지에서 다룹니다.

넷째, 서버에 남는 기록은 기기 분석으로 얻을 수 없고, 무엇이 서버에 남는지도 확인하지 못했습니다. 클라우드 쪽 확보 절차는 [클라우드 데이터 (Google Takeout 등)](../../03-techniques/acquisition/cloud-data.md) 페이지에서 다룹니다.

## 직접 분석해 보기

### 헥스로 한 번

위 3단계에서 파일을 헥스 편집기로 열어 앞머리를 보고 형식을 가립니다. 형식별 앞머리 모양은 [SQLite 데이터베이스](../../01-foundations/data-formats/sqlite/index.md), [설정 XML과 SharedPreferences](../../01-foundations/data-formats/shared-preferences.md), [프로토콜 버퍼 (Protocol Buffers)](../../01-foundations/data-formats/protobuf.md), [LevelDB와 IndexedDB](../../01-foundations/data-formats/leveldb-indexeddb.md) 페이지에 있습니다.

좌표 칸으로 보이는 정수가 있으면, 국내 좌표인지로 단위를 가릴 수 있습니다. 아래는 계산으로 만든 예시이고 실제 검체에서 나온 값이 아닙니다.

```
37566500     → ÷ 10^6 = 37.566500    (E6 로 읽으면 국내 위도 범위)
375665000    → ÷ 10^7 = 37.5665000   (E7 로 읽으면 국내 위도 범위)
37.5665      → 실수 그대로 도 단위
```

같은 칸의 값을 여러 개 바꿔 봤을 때 국내 위도(대략 33~39도)와 경도(대략 124~132도) 안으로 들어오는 나눗수가 그 칸의 단위일 가능성이 높지만, 도 단위가 아닌 다른 좌표계일 수도 있어서 시험 기기로 확인합니다.

### 공개 도구로 한 번

전용 모듈이 없으니 SQLite 브라우저나 프로토콜 버퍼 디코더 같은 범용 도구로 파일을 하나씩 엽니다. 여러 파일에서 좌표·검색어를 한꺼번에 찾을 때는 [콘텐츠 검색 (Content Search)](../../03-techniques/analysis/content-search.md) 방법을 씁니다.

## 실습

공개 검체에 네이버 지도가 들어 있는 경우는 드물 수 있으니, 필요하면 직접 준비한 시험 기기로 풀어 봅니다.

1. 설치된 앱 목록에서 네이버 지도의 패키지를 어떻게 찾았고, 앱 이름과 서명자는 무엇입니까?
2. 그 패키지의 앱 데이터 폴더에 SQLite 파일은 몇 개이고, 표 이름에 검색·장소·경로를 뜻하는 말이 들어간 표가 있습니까?
3. 시험 기기에서 장소 하나를 검색한 전후로 어느 파일의 크기나 수정 시각이 바뀌었습니까?
4. 시각으로 보이는 칸의 자릿수로 단위를 어림한 뒤, 바꾼 시각이 실제로 검색한 시각과 맞습니까?
