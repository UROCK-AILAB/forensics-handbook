# 파일시스템 기반 복구 (Undelete: NTFS·FAT)

## 한 줄 요약

파일을 지워도 매체의 데이터는 대개 그대로 남고, OS 는 파일 위치를 가리키는 디렉터리 자료에 삭제 표시만 남깁니다. 그 공간은 빈 공간으로 취급되어 언제든 덮어쓸 수 있습니다. 파일시스템 기반 복구 (Undelete) 는 남은 디렉터리 자료에서 이름·크기·데이터 위치를 읽어 파일을 되살리는 방법입니다. 되살린 내용이 원래 파일의 것인지는 따로 확인합니다.

이 페이지는 [삭제 데이터 복구 (Data Recovery)](index.md) 의 하위 주제입니다. NTFS 와 FAT 계열(FAT12·FAT16·FAT32·exFAT)을 다룹니다. 구조 전체는 [NTFS 구조](../../../01-foundations/disk-volume/ntfs/index.md) 와 [FAT·exFAT 구조](../../../01-foundations/disk-volume/fat-exfat.md) 에 있습니다. 클러스터가 비어 있는지 판단하는 자리는 [비할당 영역과 슬랙 (Unallocated·Slack Space)](unallocated-slack-space.md) 에 정리했습니다.

## 언제 쓰나

- 지운 파일의 이름·크기·시각을 내용과 함께 되살려야 할 때 씁니다. [파일 카빙 (File Carving)](file-carving.md) 결과에는 이런 정보가 붙지 않습니다.
- 볼륨에 있다가 지워진 파일의 목록을 만들 때 씁니다. 조사 흐름은 [지운 파일의 흔적 찾기](../../../04-scenarios/activity/deleted-file-traces.md) 에 있습니다.
- 휴지통에 없는 파일을 찾을 때 씁니다. 휴지통에 남은 파일은 [휴지통](../../../02-artifacts/file-folder-usage/recycle-bin.md) 에서 먼저 봅니다.

디렉터리 자료까지 없어졌거나 망가졌다면 이 방법을 쓸 수 없습니다. 그때는 파일 카빙이나 [레코드 카빙 (Record Carving)](record-carving.md) 으로 넘어갑니다.

## 판단에 쓰는 값

### NTFS — MFT 레코드

NTFS 에서는 MFT 레코드를 쓰는 중인지 두 곳에서 봅니다. 하나는 레코드 안의 플래그이고, 다른 하나는 $MFT 의 $BITMAP 속성입니다.

| 자리 | 크기 | 값 | 복구에서 쓰는 법 |
|---|---|---|---|
| 레코드 오프셋 16 | 2바이트 | 순번 (Sequence Number). 레코드가 해제될 때마다 1씩 늘어납니다. 쓴 적 없는 레코드는 0 입니다. | 다른 기록에 남은 파일 참조와 맞춰 봅니다. |
| 레코드 오프셋 22 | 2바이트 | 플래그. 0x0001 사용 중, 0x0002 $I30 색인 있음(폴더), 0x0004 $Extend 안의 레코드, 0x0008 뷰 색인 | 0x0001 이 꺼진 레코드를 지운 항목 후보로 고릅니다. 0x0002 로 폴더와 파일을 나눕니다. |
| 레코드 오프셋 32 | 8바이트 | 기본 레코드 참조. 0 이 아니면 다른 레코드의 속성을 이어 담는 확장 레코드입니다. | 확장 레코드를 기본 레코드에 묶습니다. |
| $MFT 의 $BITMAP 속성 | 레코드마다 1비트 | 1 은 할당, 0 은 비할당입니다. 바이트 안에서는 최하위 비트가 첫 레코드입니다. | 플래그와 함께 봅니다. |

순번은 파일 참조에도 들어갑니다. 파일 참조는 레코드 번호와 순번을 함께 적은 값입니다. 다른 기록에 남은 참조의 순번이 지금 레코드의 순번과 다르면, 그 참조는 옛 파일을 가리킵니다. 순번은 해제될 때마다 1씩 늘어나므로 차이가 2 이상이면 그 사이에 레코드가 한 번 넘게 풀렸다고 봅니다. 다시 풀리려면 그 전에 다른 파일이 그 레코드를 썼어야 합니다.

### NTFS — 데이터 런

데이터가 레코드 밖 클러스터에 있으면 위치는 데이터 런 (Data Run) 에 적혀 있습니다.

첫 바이트의 아래 4비트는 클러스터 개수 필드의 크기이고, 위 4비트는 시작 위치 필드의 크기입니다. 첫 런의 위치는 절대 클러스터 번호이고, 다음 런부터는 앞 런을 기준으로 한 상대값입니다. 위치 필드 크기가 0 인 런은 희소 (Sparse) 런이며, 이 구간은 0 으로 채워 읽습니다.

데이터가 레코드 안에 있는지 밖에 있는지(상주·비상주)는 [NTFS 구조](../../../01-foundations/disk-volume/ntfs/index.md) 에서 다룹니다.

### FAT12·FAT16·FAT32 — 디렉터리 항목

디렉터리 항목 하나는 32바이트입니다.

| 오프셋 | 크기 | 내용 |
|---|---|---|
| 0 | 8 | 짧은 이름. 남는 자리는 공백으로 채웁니다. 첫 바이트는 항목 상태도 나타냅니다. |
| 8 | 3 | 확장자. 남는 자리는 공백으로 채웁니다. |
| 11 | 1 | 속성. 0x0F 이면 긴 이름 (LFN) 항목입니다. |
| 13 | 1 | 만든 시각의 10ms 단위 값 |
| 14 | 2 | 만든 시각 |
| 16 | 2 | 만든 날짜 |
| 18 | 2 | 마지막 접근 날짜(날짜만) |
| 22 | 2 | 수정 시각 |
| 24 | 2 | 수정 날짜 |
| 26 | 2 | 데이터 시작 클러스터 |
| 28 | 4 | 파일 크기 |

첫 바이트는 다음 값을 씁니다.

| 값 | 뜻 |
|---|---|
| 0x00 | 끝 항목 |
| 0xE5 | 할당 안 된 항목 |
| 0x05 | 해제 대기 표시(DOS 3.0 부터 쓰지 않음). 또는 이름 첫 글자가 실제로 0xE5 일 때 대신 쓰는 값 |

긴 이름 항목은 오프셋 0 이 순서 번호이고, 아래 5비트가 번호입니다. FAT32 에서 시작 클러스터 값을 읽는 방법은 [FAT·exFAT 구조](../../../01-foundations/disk-volume/fat-exfat.md) 에서 확인합니다.

### FAT12·FAT16·FAT32 — FAT 표

| 뜻 | FAT12 | FAT16 | FAT32 |
|---|---|---|---|
| 빈 클러스터 | 0x000 | 0x0000 | 0x00000000 |
| 불량 클러스터 | 0xFF7 | 0xFFF7 | 0x0FFFFFF7 |
| 체인 끝 | 0xFF8~0xFFF | 0xFFF8~0xFFFF | 0x0FFFFFF8~0x0FFFFFFF |

### exFAT — 디렉터리 항목

exFAT 는 항목 종류 (EntryType) 바이트의 bit 7 을 InUse 로 씁니다. 1 이면 쓰는 항목이고, 0 이면 쓰지 않는 항목입니다.

| 항목 종류 값 | 뜻 |
|---|---|
| 0x00 | 디렉터리 끝 표시. 뒤 항목도 모두 끝 표시입니다. |
| 0x01~0x7F | 쓰지 않는 항목. 구현이 덮어써도 됩니다. |
| 0x80 | 무효 |
| 0x81~0xFF | 쓰는 항목. 0x81 할당 비트맵, 0x85 파일, 0xC0 스트림 확장, 0xC1 파일 이름 |

스트림 확장 항목(0xC0)에서 볼 값은 셋입니다.

| 오프셋 | 크기 | 내용 |
|---|---|---|
| 1 | 1 | GeneralSecondaryFlags. bit 0 은 AllocationPossible(1 이면 클러스터 할당 있음), bit 1 은 NoFatChain |
| 20 | 4 | FirstCluster |
| 24 | 8 | DataLength |

NoFatChain 이 1 이면 클러스터가 연속으로 붙어 있습니다. 이때 FAT 항목은 무효라서 클러스터 수는 DataLength 로 계산합니다.

exFAT 명세에는 파일을 지우는 절차가 정해져 있지 않습니다. 그래서 지운 파일의 항목이 어떤 값으로 남는지는 명세만으로 알 수 없습니다. 0x85 에서 InUse 비트만 빼면 0x05 이고, 같은 방식으로 0xC0 은 0x40, 0xC1 은 0x41 이 됩니다. 이 모양의 항목이 이어져 있으면 예전 파일 항목 묶음의 후보로 봅니다.

## 절차

### NTFS

1. 원본의 해시를 구하고 이미지 사본에서 작업합니다. 이미지를 뜨는 법은 [증거 획득](../../process-acquisition/evidence-acquisition/index.md) 에 있습니다.
2. $MFT 를 레코드 단위로 읽습니다. 레코드마다 fix-up 을 먼저 되돌립니다. fix-up 은 [레코드 카빙](record-carving.md) 에서 설명합니다.
3. 플래그 0x0001 이 꺼진 레코드를 고릅니다. $MFT 의 $BITMAP 에서 같은 레코드의 비트가 0 인지도 봅니다.
4. 기본 레코드 참조가 0 이 아닌 레코드는 확장 레코드입니다. 기본 레코드와 묶은 뒤에 이름과 속성을 읽습니다.
5. 이름은 $FILE_NAME 속성에서 읽습니다. 경로를 되살리는 법은 [NTFS 구조](../../../01-foundations/disk-volume/ntfs/index.md) 에서 다룹니다.
6. 데이터가 레코드 밖에 있으면 데이터 런을 풀어 클러스터 목록을 만듭니다.
7. 목록의 클러스터가 지금 비할당인지 봅니다. 볼륨 비트맵을 읽는 법은 [비할당 영역과 슬랙](unallocated-slack-space.md) 에 있습니다.
8. 지금 할당된 클러스터가 섞여 있으면 그 부분의 내용은 다른 파일의 것일 수 있다고 표시합니다.
9. 파일을 뽑고 해시를 구합니다. 레코드 번호, 순번, 클러스터 범위, 희소 구간 처리 방식을 함께 적습니다.

### FAT12·FAT16·FAT32

1. 디렉터리 클러스터를 32바이트씩 읽습니다.
2. 첫 바이트가 0xE5 인 항목을 고릅니다.
3. 시작 클러스터와 파일 크기를 읽습니다.
4. 파일 크기를 클러스터 크기로 나누고 올림하면 필요한 클러스터 수가 나옵니다.
5. FAT 표에서 시작 클러스터의 값을 봅니다. 0 이면 빈 클러스터입니다.
6. 체인을 따라갈 수 없으면 시작 클러스터부터 필요한 수만큼 이어서 읽습니다. 이 방법은 파일이 조각나지 않았다고 가정합니다. 결과에 이 가정을 적습니다.

### exFAT

1. InUse 비트가 꺼진 0x05·0x40·0x41 묶음을 찾습니다.
2. 0x40 항목에서 플래그, FirstCluster, DataLength 를 읽습니다.
3. NoFatChain 비트가 1 이면 FirstCluster 부터 DataLength 로 계산한 클러스터 수만큼 이어서 읽습니다.
4. NoFatChain 비트가 0 이면 FAT 체인을 따라야 합니다. 체인을 따라갈 수 없으면 FAT12·FAT16·FAT32 와 같은 가정을 씁니다.
5. 그 클러스터가 지금 비어 있는지 할당 비트맵에서 봅니다.

## 헥스로 한 번 따라가기

아래 예시는 명세로 만든 예시입니다. 실제 디스크에서 떠낸 바이트가 아닙니다. `??` 는 이 설명에 쓰지 않는 바이트입니다. 여러 바이트 값은 리틀 엔디언으로 읽습니다.

### MFT 레코드 머리

```
오프셋    00 01 02 03 04 05 06 07  08 09 0A 0B 0C 0D 0E 0F
00000000  46 49 4C 45 ?? ?? ?? ??  ?? ?? ?? ?? ?? ?? ?? ??   FILE
00000010  06 00 ?? ?? ?? ?? 00 00  ?? ?? ?? ?? ?? ?? ?? ??
00000020  00 00 00 00 00 00 00 00  ?? ?? ?? ?? ?? ?? ?? ??
```

오프셋 0x10 의 순번은 6 이고, 오프셋 0x16 의 플래그는 0x0000 이라서 사용 중 비트와 폴더 비트가 모두 꺼진, 쓰지 않는 파일 레코드입니다. 오프셋 0x20 의 기본 레코드 참조는 0 이므로 이 레코드는 기본 레코드입니다. 다른 기록에 이 레코드를 순번 5 로 가리키는 참조가 있다고 가정하면 차이가 1 이므로, 그 파일이 풀린 뒤 다른 파일이 이 레코드를 쓴 흔적은 순번에 없습니다.

같은 레코드의 데이터 런이 `21 18 34 56` 으로 시작한다고 가정합니다.

첫 바이트 0x21 의 아래 4비트는 1 이라서 개수 필드는 1바이트이고 값은 0x18(24) 입니다. 위 4비트는 2 이므로 위치 필드는 2바이트이고 값은 0x5634(22,068) 입니다. 첫 런이라서 22,068 은 절대 클러스터 번호이고, 데이터는 클러스터 22,068~22,091 에 있었습니다. 이 24개 클러스터가 볼륨 비트맵에서 모두 0 이면 지금 비할당입니다.

### FAT 디렉터리 항목

```
오프셋    00 01 02 03 04 05 06 07  08 09 0A 0B 0C 0D 0E 0F
00000000  E5 45 50 4F 52 54 20 20  54 58 54 ?? ?? ?? ?? ??   .EPORT  TXT
00000010  ?? ?? ?? ?? ?? ?? ?? ??  ?? ?? 25 00 00 30 00 00
```

오프셋 0 이 0xE5 이므로 할당 안 된 항목입니다. 첫 바이트가 곧 이름의 첫 글자 자리라서 원래 첫 글자는 이 항목에 없고, 이름은 "?EPORT.TXT" 처럼 첫 글자를 모르는 채로 적습니다. 오프셋 0x1A(26) 의 시작 클러스터는 0x0025(37) 이고, 오프셋 0x1C(28) 의 파일 크기는 0x00003000(12,288바이트) 입니다. 클러스터가 4,096바이트라고 가정하면 클러스터 3개가 필요합니다. FAT 표에서 37 의 값이 0 이면 빈 클러스터이고, 체인이 없으면 연속 가정으로 클러스터 37·38·39 를 읽습니다.

## 도구

- 헥스 편집기로 위 값을 직접 읽어 도구 결과를 확인합니다.
- 값의 뜻은 libyal 의 libfsntfs·libfsfat 형식 문서와 Microsoft 의 exFAT 명세를 기준으로 삼습니다.
- 복구 도구 두 가지 이상의 결과가 다르면 [도구 결과 교차 검증](../../reporting/tool-validation.md) 을 따릅니다.

## 함정과 한계

- 이름을 되살려도 내용은 다른 파일의 것일 수 있는데, 빈 공간은 언제든 다시 쓰이기 때문입니다. 지금 할당된 클러스터가 섞였는지 꼭 봅니다.
- MFT 레코드가 $ATTRIBUTE_LIST 로 확장 레코드를 쓰면 Win32 긴 이름($FILE_NAME)이 확장 레코드에만 있을 수 있습니다. 기본 레코드만 보면 8.3 짧은 이름만 보입니다. 확장 레코드는 대개 기본 레코드와 멀리 떨어져 있습니다(현장 관찰). 지운 파일에 이름을 붙일 때도 짧은 이름으로 나올 수 있습니다.
- 희소 구간을 건너뛰고 뽑으면 뒤 내용이 앞으로 밀립니다. 0 으로 채웠는지 건너뛰었는지에 따라 크기와 해시가 다릅니다(현장 관찰). 어떻게 뽑았는지 적습니다.
- FAT 의 연속 가정은 조각난 파일에서 틀립니다. 앞부분만 맞고 뒷부분은 다른 데이터일 수 있습니다.
- 0xE5 항목의 첫 글자를 도구가 채워 넣었다면 원래 글자가 아닙니다.
- 폴더 색인($I30)의 남는 공간은 [비할당 영역과 슬랙](unallocated-slack-space.md) 과 [폴더 인덱스와 슬랙](../../../02-artifacts/filesystem/i30.md) 에서 다룹니다.
- SSD 에서는 파일시스템 기록이 남아 있어도 데이터 자리가 이미 비워졌을 수 있습니다. [SSD TRIM과 복구 한계 (SSD·TRIM)](ssd-trim.md) 를 봅니다.
- 볼륨 섀도 복사본이 있으면 [섀도 복사본 활용](../volume-shadow-copy-analysis.md) 도 함께 봅니다.

## 결과를 어떻게 해석하나

### 증명하는 것과 증명하지 못하는 것

**증명하는 것**

- 그 이름과 크기의 파일 항목이 볼륨에 있었다는 것
- 그 항목을 지금은 쓰지 않는다는 것
- 데이터가 있던 클러스터 가운데 어느 것이 지금 비할당인지

**증명하지 못하는 것**

- 언제 지웠는지. FAT·exFAT 항목의 시각 필드는 만든·수정·접근 시각입니다. 지운 시점은 [USN 변경 저널](../../../02-artifacts/filesystem/usnjrnl.md) 같은 다른 기록과 맞춰 봅니다. NTFS 레코드의 시각은 [마스터 파일 테이블](../../../02-artifacts/filesystem/mft.md) 에서 다룹니다.
- 누가 지웠는지
- 뽑은 내용이 원래 파일과 같은지. 지금 할당된 클러스터가 섞였거나 연속 가정을 썼다면 더 그렇습니다. 원래 파일의 해시를 알면 [해시셋 대조와 유사 해시](../hash-set-fuzzy-hash.md) 로 맞춰 봅니다.

### 시각 해석

FAT12·FAT16·FAT32 항목에는 시간대 필드가 없어서 어느 시간대 기준으로 적었는지는 항목만으로 알 수 없으므로 [시간대 설정](../../../02-artifacts/system-account/time-zone.md) 과 함께 봅니다. FAT 의 마지막 접근 값은 날짜만 있고, 만든 시각에는 10ms 단위 값이 따로 있습니다.

exFAT 파일 항목(0x85)에는 시각이 셋 있습니다. CreateTimestamp(오프셋 8), LastModifiedTimestamp(12), LastAccessedTimestamp(16) 이고 각 4바이트입니다. 만든 시각과 수정 시각에는 10ms 증분 필드(오프셋 20·21)를 따로 두고, 세 시각마다 UtcOffset 필드(오프셋 22·23·24)을 둡니다. UtcOffset 은 UTC 와의 차이를 15분 단위로 적고, 최상위 비트가 켜져 있어야 값이 유효합니다. 시각 값의 형식은 [시각 값 형식](../../../01-foundations/value-decoding/filetime-unix-webkit-dos-ole.md) 에서 봅니다.

### 보고서 문장 예

"MFT 레코드 N번(순번 S)은 사용 중 표시가 꺼져 있다. 이 레코드의 $FILE_NAME 에는 이름 X 가 남아 있다. 데이터 런이 가리키는 클러스터 가운데 k개는 지금 할당된 상태이므로, 그 부분의 내용은 원래 파일의 것이라고 볼 수 없다. 이 파일을 언제 지웠는지는 이 레코드에 기록이 없다."
