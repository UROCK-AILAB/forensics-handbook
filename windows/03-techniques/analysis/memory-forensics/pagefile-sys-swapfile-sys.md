# 페이지 파일 (pagefile.sys·swapfile.sys)

> 상위 허브: [메모리 분석 (Memory Forensics)](index.md)

## 한 줄 요약

페이지 파일 (Page File) 은 Windows 가 물리 메모리에서 내보낸 페이지를 담아 두는 디스크 파일입니다.
파일 이름은 보통 pagefile.sys 이며, 물리 메모리 이미지에 없는 메모리 조각이 이 파일에 남을 수 있습니다.

## 언제 쓰나

- 전원이 꺼진 PC 에서 메모리 조각을 찾을 때 씁니다.
- 메모리 이미지에서 프로세스의 명령줄이나 DLL 목록이 비어 나올 때 씁니다. 그 부분이 페이지 파일로 나가 있었을 수 있습니다. [프로세스와 DLL 분석](process-analysis.md) 을 봅니다.
- 키워드·주소·명령 조각을 넓게 찾을 때 씁니다.

## 무엇을 담나

아래 내용은 Windows 10 기준입니다 [1].

- 페이지 파일은 디스크에 두는 숨김 시스템 파일이고, 선택 사항이라 두지 않을 수도 있습니다.
- Windows 는 자주 쓰지 않는 수정된 페이지를 물리 메모리에서 빼내 여기에 둡니다.
- 시스템 크래시 덤프를 남길 때도 페이지 파일을 씁니다. 필요한 크기는 [크래시 덤프](memory-dmp-minidump.md) 에 있습니다.
- 시스템 커밋 한도 (Commit Limit) 는 물리 메모리와 모든 페이지 파일을 더한 크기입니다.
- 도메인 컨트롤러, DFS-R 서버, 인증서 서버, ADAM/LDS 서버에는 페이지 파일이 필요합니다.

### 크기

시스템이 관리하는 페이지 파일은 커밋 사용량이 한도의 90% 에 이르면 늘어납니다 [1].
늘어나는 상한은 물리 메모리의 3배와 4GB 가운데 큰 값이지만 볼륨 크기의 1/8 을 넘지 않습니다 [1].
그래서 파일 크기는 PC 마다 다르고, 같은 PC 에서도 때에 따라 다를 수 있습니다.

## 위치와 설정

- 파일 위치는 PC 마다 다를 수 있어 디스크 이미지의 모든 볼륨에서 이름으로 찾습니다.
- 페이지 파일 설정은 `HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\Memory Management` 키의 `PagingFiles` 값에 있습니다 [2].
- 값을 읽어 시스템 볼륨 말고 다른 볼륨에도 페이지 파일을 두었는지 확인합니다.
- 디스크 이미지에서 떼어 낸 SYSTEM 하이브를 읽을 때는 경로의 `CurrentControlSet` 부분을 실제로 쓰던 제어 집합으로 바꿔 읽습니다. 방법은 [레지스트리 하이브 구조](../../../01-foundations/database-log-formats/registry-hive/index.md) 에 있습니다.
- 종료할 때 페이지 파일을 비우는 설정과 페이지 파일을 암호화하는 설정이 있다고 알려져 있습니다. 설정 이름과 값은 분석 대상의 레지스트리에서 확인합니다.

## swapfile.sys

swapfile.sys 는 pagefile.sys 와 같은 부류로 흔히 묶는 파일이며, 스토어 (UWP) 앱의 메모리를 통째로 내보낼 때 쓰는 별도 파일로 알려져 있습니다.
이 파일이 생기는 Windows 버전, 위치, 크기는 실제 기기에서 확인합니다.
이 파일을 찾았다면 페이지 파일과 같은 방법으로 검색해 봅니다.

## 절차

1. 디스크 이미지의 모든 볼륨에서 pagefile.sys 와 swapfile.sys 를 찾습니다.
2. 파일을 꺼내고, 꺼낸 도구·방법과 해시를 적습니다. 방법은 [증거 획득](../../process-acquisition/evidence-acquisition/index.md) 에 있습니다.
3. SYSTEM 하이브에서 `PagingFiles` 값을 읽습니다. 설정에 나온 페이지 파일과 실제로 찾은 파일을 맞대 봅니다.
4. 파일 앞부분과 몇 군데를 헥스로 봅니다. 모두 0 이면 종료할 때 비웠을 수 있습니다.
5. 키워드를 ASCII 와 UTF-16LE 로 둘 다 검색합니다. 키워드를 정하고 결과를 정리하는 법은 [파일 내용 검색](../content-search/index.md) 에 있습니다.
6. 패턴으로 찾을 것이 있으면 YARA 규칙을 씁니다. 규칙을 쓰는 법은 [의심 실행 파일 선별](../code-signing-yara.md) 에 있습니다.
7. 이미지·문서·실행 파일 조각은 카빙으로 꺼냅니다. [삭제 데이터 복구](../data-recovery/index.md) 를 봅니다.
8. 찾은 조각을 디스크 기록과 맞대 봅니다. 조각에 나온 파일 이름은 [마스터 파일 테이블](../../../02-artifacts/filesystem/mft.md) 에서, 웹 주소는 [웹 사용 행위 재구성](../../../04-scenarios/activity/web-activity.md) 에서 이어 봅니다.

## 헥스로 보기

페이지 파일에서 문자열을 찾을 때는 같은 글자가 두 가지 바이트 모양으로 있을 수 있다고 생각합니다.
아래는 인코딩 규칙으로 만든 예시입니다.
실제 데이터에서 뜬 값이 아닙니다.

```
ASCII     68 74 74 70 73 3A 2F 2F                            https://
UTF-16LE  68 00 74 00 74 00 70 00 73 00 3A 00 2F 00 2F 00    h.t.t.p.s.:././
```

- UTF-16LE 에서는 영문 한 글자마다 뒤에 `00` 이 붙습니다.
- 한 가지 인코딩으로만 검색하면 다른 쪽을 놓칩니다.
- 한글처럼 영문이 아닌 글자는 인코딩마다 바이트가 다릅니다. [문자 인코딩](../../../01-foundations/value-decoding/utf-16le-utf-8-cp949.md) 을 봅니다.

## 도구

아래 도구는 예로만 듭니다.

| 도구 | 쓰임 |
|---|---|
| 헥스 편집기 | 파일 앞부분과 빈 영역을 직접 봅니다 |
| 문자열 추출·검색 도구 | ASCII 와 UTF-16LE 문자열을 뽑고 키워드를 찾습니다 |
| YARA (공개) | 패턴을 규칙으로 적어 검색합니다 |
| 카빙 도구 | 파일 조각을 서명으로 찾아 꺼냅니다 |

## 함정과 한계

- **어느 프로세스의 조각인지 모릅니다.** 페이지 파일 안의 페이지는 순서가 섞여 있고, 가상 주소를 잇는 정보가 없다고 알려져 있습니다. 그래서 흔히 문자열 검색·카빙·YARA 로 봅니다. 긴 문자열이나 파일이 중간에 끊겨 나올 수도 있습니다.
- **언제의 조각인지 모릅니다.** 페이지 파일에는 페이지를 써 넣은 시각을 담는 필드가 없는 것으로 보입니다.
- **압축된 페이지는 문자열 검색에 걸리지 않을 수 있습니다.** 메모리 압축을 쓰는 Windows 에서는 압축한 페이지가 페이지 파일에 들어간다고 알려져 있습니다.
- **크기로 사용량을 추정하지 않습니다.** 시스템이 관리하는 페이지 파일은 필요하면 늘어납니다 [1].
- **비어 있을 수 있습니다.** 종료할 때 비우는 설정을 켰다면 내용이 0 일 수 있습니다. 비어 있다고 해서 누가 일부러 지웠다고 단정하지 않습니다.
- **없을 수도 있습니다.** 페이지 파일은 선택 사항입니다 [1]. 파일이 없으면 먼저 `PagingFiles` 설정을 봅니다.
- **물리 메모리 이미지와 함께 봅니다.** 페이지 파일만으로는 어느 페이지가 어느 프로세스의 것인지 알기 어렵습니다. 메모리 이미지 분석은 [메모리 분석](index.md) 의 하위 페이지를 따릅니다.

## 결과를 어떻게 해석하나

- 페이지 파일에서 찾은 조각은 어느 시점엔가 물리 메모리에 있다가 디스크로 나간 내용으로 봅니다.
- 조각 하나로는 어느 프로그램이 언제 그 내용을 썼는지 정할 수 없습니다.
- 조각을 찾지 못했다고 해서 그 내용이 메모리에 없었다는 뜻은 아닙니다. 그 페이지가 밖으로 나가지 않았거나, 다른 내용으로 덮였을 수 있습니다.
- 조각만으로 행위를 적지 않습니다. 다른 아티팩트와 이어 본 결과를 함께 적습니다.

보고서 문장 예입니다.

- 쓰지 않을 문장: "피조사자가 ○○ 사이트에 접속했습니다."
- 쓸 문장: "디스크 이미지의 pagefile.sys (SHA-256 ○○) 오프셋 ○○ 에 문자열 ○○ 가 UTF-16LE 로 있습니다. 이 기록은 이 문자열이 어느 시점엔가 메모리에 있다가 페이지 파일로 나갔음을 보여 줍니다. 어느 프로그램이 언제 이 문자열을 썼는지는 이 기록만으로 정할 수 없습니다."
