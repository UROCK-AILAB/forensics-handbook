# 실행 중 시스템 이미징 (Live Imaging)

## 한 줄 요약

켜진 시스템의 디스크나 볼륨을 끄지 않고 복사합니다. 켜진 물리 디스크 전체를 비트 단위로 복사하는 것은 일반적으로 권하지 않습니다. 복사하는 동안 디스크가 계속 바뀌어 검증할 수 없기 때문입니다. 볼륨 같은 논리 영역을 비트 단위로 복사하면 끝내고 검증할 수 있습니다. 잠금 해제된 BitLocker 볼륨은 볼륨 경로로 읽으면 풀린 내용이 나옵니다.

## 언제 쓰나

- 시스템을 내릴 수 없을 때 씁니다. NIST SP 800-86 은 수백 명이 쓰는 서버를 한 사용자 폴더 때문에 내릴 필요는 없다고 적습니다.
- 암호화 볼륨이 잠금 해제된 채로 켜져 있을 때 씁니다. 아래 "암호화 볼륨" 을 봅니다.
- 필요한 파일이 정해져 있고, 시스템 전체가 필요하지 않을 때 씁니다.

NIST 는 어떤 파일이 필요한지, 얼마나 정확하고 완전해야 하는지, 시스템이 얼마나 중요한지 보고 정하라고 적습니다. 휘발성 데이터는 이미징보다 먼저 모읍니다. 순서는 [수집 순서와 원칙](/03-techniques/process-acquisition/live-response/order-of-volatility.md)에서 다룹니다. 끈 시스템의 디스크를 복사하는 일반 방법은 [증거 획득](/03-techniques/process-acquisition/evidence-acquisition/index.md)에서 다룹니다.

## 켜진 시스템에서 복사할 때의 문제

아래는 NIST SP 800-86 의 판단입니다.

| 방식 | NIST 의 판단 | 까닭 |
|---|---|---|
| 물리 장치 전체를 비트 단위로 복사 | 일반적으로 하지 않습니다 | 파일과 메모리가 계속 바뀌어 검증할 수 없습니다. 사람이 쓰지 않아도 서비스와 프로세스가 디스크에 쓰고 있을 수 있습니다 |
| 논리 영역을 비트 단위로 복사 | 끝내고 검증할 수 있습니다 | — |
| 논리 백업 (파일 단위 복사) | 되도록 피합니다 | 복사하는 동안 파일이 바뀝니다. 프로세스가 연 파일은 복사하기 어렵습니다. 시작과 검증 사이에 일부 파일이 바뀔 가능성이 높습니다 |

논리 백업에는 두 가지 한계가 더 있습니다.

- 지운 파일과 슬랙 공간을 담지 않습니다.
- 일부 도구의 논리 백업은 파일 생성 시각을 바꿀 수 있습니다. 파일 시각이 중요하면 비트 단위 이미징을 씁니다.

NIST 는 원본을 이미징하기 전과 뒤에 해시를 구해 비교하라고 적습니다.

## 절차

1. **휘발성 데이터를 먼저 모읍니다.**
2. **무엇을 복사할지 정합니다.** 물리 디스크 전체, 볼륨, 필요한 파일 가운데 고릅니다. 고른 까닭을 적습니다.
3. **볼륨과 물리 디스크의 관계를 확인합니다.** 볼륨 하나가 여러 디스크에 걸칠 수 있습니다. 아래 "디스크와 볼륨을 직접 여는 방법" 을 봅니다.
4. **암호화 여부를 확인합니다.** 잠금 해제된 BitLocker 볼륨은 어느 경로로 읽느냐에 따라 풀린 내용과 암호문이 갈립니다.
5. **읽기로만 엽니다.** 결과는 대상 시스템이 아닌 외장 매체나 원격 시스템에 씁니다.
6. **해시를 구하고 적습니다.** 이미지 파일의 해시, 도구 이름과 버전, 입력한 명령, 시작·끝 시각을 적습니다.

## 디스크와 볼륨을 직접 여는 방법

Windows 에서 디스크와 볼륨은 `CreateFile` 함수로 직접 엽니다. 아래는 Microsoft 문서의 "Physical Disks and Volumes" 절 내용입니다.

| 대상 | 경로 | 비고 |
|---|---|---|
| 물리 디스크 | `\\.\PhysicalDriveX` | X 는 0 부터 세는 번호 |
| 볼륨 | `\\.\X:` | X 는 드라이브 문자 |
| 볼륨의 파일 시스템 | `\\.\X:\` | 끝에 `\` 를 붙이면 볼륨이 아니라 루트 폴더를 엽니다 |
| 볼륨 (이름으로) | 볼륨 GUID 경로 | 볼륨 이름으로도 열 수 있습니다 |

- 열려면 관리자 권한이 있어야 합니다.
- 여는 방식은 `OPEN_EXISTING` 이어야 합니다.
- 볼륨을 열 때는 공유 모드에 `FILE_SHARE_WRITE` 가 들어 있어야 합니다.
- 디스크와 볼륨에 직접 접근하는 일은 제한됩니다. Windows Server 2003 과 XP 에는 이런 제한이 없었습니다.
- 볼륨 핸들은 캐시 없이 열린다고 봐야 합니다. 버퍼 정렬 같은 비캐시 I/O 제약이 볼륨에도 걸립니다.
- 볼륨의 마지막 몇 섹터를 읽으려면 `DeviceIoControl` 로 `FSCTL_ALLOW_EXTENDED_DASD_IO` 를 먼저 보냅니다.
- 볼륨이 어느 물리 디스크의 어디에 있는지는 `IOCTL_VOLUME_GET_VOLUME_DISK_EXTENTS` 로 얻습니다.
- 문서는 잘못 쓰면 OS 가 디스크를 못 읽게 될 수 있다고 경고합니다. 수집할 때는 읽기로만 엽니다.

파티션이 디스크의 어디서 시작하는지 읽는 법은 [파티션 구조](/01-foundations/disk-volume/mbr-gpt.md)에서 다룹니다.

## 암호화 볼륨

BitLocker 가 켜진 PC 한 대에서 같은 자리를 두 경로로 읽었습니다 (확인 범위: Windows 11 Home 10.0.26200, PC 한 대). C: 는 사용한 공간만 암호화, XTS-AES 128, 보호 켜짐, 잠금 해제 상태였습니다.

| 읽은 경로 | 볼륨 첫 섹터의 OEM ID |
|---|---|
| `\\.\C:` 의 첫 섹터 | `NTFS    ` |
| `\\.\PhysicalDrive0` 의 파티션 시작 오프셋 | `-FVE-FS-` |

아래 바이트는 두 글자열을 ASCII 로 옮긴 것입니다. 검체에서 뽑은 덤프가 아닙니다.

```
"NTFS    "  → 4E 54 46 53 20 20 20 20
"-FVE-FS-"  → 2D 46 56 45 2D 46 53 2D
```

볼륨 경로로 읽으면 풀린 내용이 나오고, 물리 디스크로 읽으면 암호문이 나왔습니다. 그래서 켜진 상태에서 볼륨 단위로 이미징하면 복호된 이미지를 얻습니다. 암호화된 증거를 다루는 법은 [암호화 증거 다루기](/03-techniques/analysis/encrypted-evidence/index.md)에서, NTFS 부트 섹터는 [NTFS 구조](/01-foundations/disk-volume/ntfs/index.md)에서 다룹니다.

## 볼륨 섀도 복사본

볼륨 섀도 복사본 서비스 (VSS) 는 특정 시점의 읽기 전용 복사본을 만듭니다. 앱이 도는 중에 백업하면 파일이 열려 있거나 내용이 서로 맞지 않을 수 있습니다. VSS 는 이 문제를 풀려고 만든 기능입니다. 켜진 시스템에서 열린 파일을 복사해야 할 때 후보가 됩니다.

### 만들 때 일어나는 일

- 복사본을 만드는 동안 앱의 쓰기를 잠시 멈춥니다. 멈춤은 60초를 넘을 수 없습니다.
- 복사본을 확정하는 단계는 10초를 넘지 않습니다. 그동안 파일 시스템 쓰기가 모두 멈춥니다.
- Windows 기본 공급자는 쓰기 시 복사 (copy-on-write) 방식입니다. 블록이 바뀌기 직전에 원래 블록을 차이 영역 (diff area) 으로 옮겨 둡니다.
- 차이 영역은 같은 볼륨에 있을 수도 있습니다. 차이 영역은 NTFS 볼륨이어야 합니다.
- 페이징 파일 같은 임시 파일은 복사본에서 저절로 빠집니다.
- 공간이 모자라면 가장 오래된 섀도 복사본부터 지웁니다.

아래 두 가지는 문서 내용에서 끌어낸 추론입니다.

- 섀도 복사본을 만들면 차이 영역에 데이터를 씁니다. 차이 영역이 증거 볼륨에 있으면 그 볼륨이 바뀝니다.
- 공간이 모자라면 새 복사본 때문에 기존의 오래된 섀도 복사본이 지워질 수 있습니다. 기존 섀도 복사본도 증거입니다.

섀도 복사본의 저장 구조는 [볼륨 섀도 복사본 구조](/01-foundations/disk-volume/volume-shadow-copy.md)에서, 이미 있는 복사본을 분석하는 법은 [섀도 복사본 활용](/03-techniques/analysis/volume-shadow-copy-analysis.md)에서 다룹니다.

### 만드는 도구

| 도구 | 문서 | 확인한 것 |
|---|---|---|
| DiskShadow | Windows Server 에만 있습니다. 클라이언트에는 없습니다 | — |
| VssAdmin | VSS 개요 문서는 클라이언트와 서버 모두에 있고 `create shadow` 명령이 있다고 적습니다. `vssadmin` 명령 참조 문서의 목록에는 `create shadow` 가 없습니다 | Windows 11 Home 에서 `vssadmin create shadow` 는 "Error: Invalid command." 였습니다 |

`vssadmin` 명령 참조 문서는 클라이언트와 서버 모두에서 쓸 수 있는 명령으로 Delete Shadows, List Providers, List Shadows, List ShadowStorage, List Volumes, List Writers, Resize ShadowStorage 를 듭니다. 그 PC 의 VssAdmin 도 같은 명령만 보여 줬습니다 (확인 범위: Windows 11 Home 10.0.26200, PC 한 대). 클라이언트 Windows 에서 VssAdmin 으로는 복사본을 만들 수 없다고 보고, 현장에 가기 전에 대상 판에서 쓸 수 있는 방법을 확인해 둡니다.

## 도구

- RFC 3227 은 비트 복사 도구의 예로 `dd` 를, 체크섬 도구의 예로 `sha1sum` 을 듭니다. 둘 다 유닉스 명령입니다.
- 어떤 도구든 위의 `\\.\PhysicalDriveX`, `\\.\X:` 경로를 읽기로 엽니다.
- 이미지 파일 형식은 [증거 이미지·가상 디스크 형식](/01-foundations/disk-volume/e01-raw-aff4-vhdx-vmdk.md)에서 다룹니다.
- 도구가 볼륨 끝까지 읽었는지는 볼륨 크기와 이미지 크기를 비교해 확인합니다. 결과를 검증하는 법은 [도구 결과 교차 검증](/03-techniques/reporting/tool-validation.md)에서 다룹니다.

## 함정과 한계

1. **켜진 물리 디스크의 전후 해시가 같기를 기대합니다.** 복사하는 동안 디스크가 계속 바뀝니다. NIST 가 검증할 수 없다고 적은 까닭입니다.
2. **`\\.\C:\` 로 엽니다.** 끝에 `\` 가 붙으면 볼륨이 아니라 파일 시스템의 루트 폴더를 엽니다.
3. **볼륨 끝 몇 섹터를 빠뜨립니다.** `FSCTL_ALLOW_EXTENDED_DASD_IO` 를 보내지 않으면 마지막 몇 섹터를 읽지 못합니다.
4. **볼륨 하나가 디스크 하나에 있다고 봅니다.** 볼륨은 여러 디스크에 걸칠 수 있습니다.
5. **물리 디스크 이미지로 BitLocker 볼륨을 읽으려 합니다.** 켜진 상태에서도 물리 디스크 경로로 읽으면 암호문이 나왔습니다.
6. **파일 복사로 충분하다고 봅니다.** 논리 백업에는 지운 파일과 슬랙 공간이 없습니다. 파일 생성 시각이 바뀔 수도 있습니다.
7. **어디서나 `vssadmin create shadow` 가 된다고 봅니다.** `vssadmin` 명령 참조 문서의 클라이언트 명령 목록에 없고, Windows 11 Home 한 대에서도 되지 않았습니다.
8. **섀도 복사본을 만들어도 증거가 그대로라고 봅니다.** 차이 영역이 증거 볼륨에 있으면 그 볼륨에 데이터를 씁니다.
9. **희소 스트림을 뽑은 방법을 적지 않습니다.** `$UsnJrnl:$J` 같은 희소 스트림은 빈 구간을 0 으로 채우느냐 건너뛰느냐에 따라 크기와 해시가 달라집니다 (확인 범위: 압수 이미지에서 추출). 켜진 시스템에서 파일 단위로 뽑을 때도 어떻게 뽑았는지 적습니다. 저널 자체는 [USN 변경 저널](/02-artifacts/filesystem/usnjrnl.md)에서 다룹니다.

## 결과를 어떻게 해석하나

- 켜진 채로 만든 이미지는 한 시점의 모습이 아닙니다. 복사하는 동안 바뀐 디스크를 담습니다.
- 이미지 파일의 해시는 그 뒤로 이미지가 바뀌지 않았음을 보여 줍니다. 원본과 같다는 증명은 되지 못합니다.
- 볼륨 단위 이미지는 복호된 내용을 담을 수 있습니다. 보고서에는 어느 경로로 읽었는지, 잠금 해제 상태였는지 적습니다.
- 섀도 복사본을 새로 만들어 복사했다면 그 사실과 시각을 적습니다. 새 복사본이 생긴 흔적이 나중 분석에서 조사 대상의 행위로 읽히지 않게 하기 위해서입니다.

### 증명하는 것 / 증명하지 못하는 것

| 증명하는 것 | 증명하지 못하는 것 |
|---|---|
| 적어 둔 시각 동안 이 경로에서 읽은 내용 | 복사 시작 순간의 디스크 전체 모습 |
| 이미지를 만든 뒤로 이미지 파일이 바뀌지 않았다는 것 (해시) | 원본과 비트 단위로 같다는 것 |
| 잠금 해제 상태의 볼륨에 이 파일이 있었다는 것 | 전원을 끈 뒤에도 같은 방법으로 읽을 수 있다는 것 |

아래 보고서 문장의 값은 설명을 위해 만든 예입니다.

- 쓸 수 있는 문장: "대상 시스템이 켜진 상태에서 2025-03-14 10:40 부터 11:55 (KST) 까지 `\\.\C:` 볼륨을 읽기로 열어 이미지를 만들었습니다. 볼륨은 BitLocker 잠금 해제 상태였고, 이미지는 복호된 내용을 담고 있습니다."
- 쓰면 안 되는 문장: "원본 디스크와 같은 이미지를 확보했습니다."
