# 디스크 이미징 (Disk Imaging)

> 상위 허브: [증거 획득 (Evidence Acquisition)](index.md)

## 한 줄 요약

디스크 이미징은 원본 저장 매체를 비트 단위로 빠짐없이 복사하는 일입니다.
이 사본에는 파일뿐 아니라 빈 공간과 슬랙 공간 (Slack Space) 도 들어갑니다.
분석은 사본으로 하고, 원본은 표시를 붙여 따로 보관합니다.

## 언제 쓰나

NIST SP 800-86 은 매체에서 데이터를 복사하는 방식을 둘로 나눕니다.

| | 논리 백업 (Logical Backup) | 비트 스트림 이미징 (Bit Stream Imaging) |
|---|---|---|
| 복사하는 것 | 논리 볼륨의 폴더와 파일 | 원본 매체의 모든 비트 |
| 지운 파일, 슬랙 공간의 잔여 데이터 | 들어가지 않습니다 | 빈 공간·슬랙 공간과 함께 들어갑니다 |
| 저장 공간과 시간 | 이미징보다 덜 듭니다 | 저장 공간이 더 들고 시간이 더 걸립니다 |

아래와 같을 때 비트 스트림 이미지를 만듭니다.

- **증거로 쓸 가능성이 있을 때.** 법적·징계 절차에 쓸지는 데이터를 모으기 전에 정합니다. 보존할지 분명하지 않으면 보존하는 쪽을 기본으로 삼습니다.
- **파일 시각이 중요할 때.** 일부 도구로 논리 백업을 하면 복사하면서 파일 생성 시각이 바뀔 수 있습니다.
- **지운 파일과 슬랙 공간을 살펴야 할 때.** 복구하는 법은 [삭제 데이터 복구](../../analysis/data-recovery/index.md) 에서 다룹니다.

중요한 서버를 멈출 수 없어서 필요한 파일만 가져와야 할 때는 [선별 수집](triage-collection.md) 을 봅니다.
가상 머신과 클라우드 디스크는 [가상 머신·클라우드 디스크 확보](vm-cloud-disk.md) 에서 다룹니다.

## 이미지를 만드는 두 가지 방법

| | 디스크→디스크 (disk-to-disk) | 디스크→파일 (disk-to-file) |
|---|---|---|
| 결과물 | 원본을 옮겨 담은 두 번째 매체 | 이미지 파일 |
| 좋은 점 | 사본 매체를 컴퓨터에 바로 붙여 볼 수 있습니다 | 옮기고 백업하기 쉽습니다 |
| 불편한 점 | 원본과 비슷한 매체가 하나 더 있어야 합니다 | 내용을 보려면 이미지를 매체에 다시 풀거나 이미지를 읽는 프로그램을 써야 합니다 |

어느 방법이든 사본을 담을 매체는 기존 데이터를 지운 깨끗한 상태여야 합니다.
용량도 복사할 데이터보다 커야 합니다.

## 절차

SP 800-86 은 데이터 획득을 계획 세우기, 획득, 무결성 검증의 세 단계로 나눕니다.
아래 단계도 이 순서를 따릅니다.

1. **시스템이 켜져 있으면 끌지부터 정합니다.** 판단 기준은 아래 "켜진 시스템에서" 절에 있습니다.
2. **사본을 담을 매체를 준비합니다.** 기존 데이터를 지우고 용량이 충분한지 확인합니다.
3. **원본에 쓰기 방지를 겁니다.** 연결 순서는 [쓰기 방지](write-blocker.md) 에 있습니다.
4. **원본의 해시를 계산해 적습니다.**
5. **비트 스트림 이미지를 뜹니다.** 디스크→디스크와 디스크→파일 가운데 하나를 고릅니다.
6. **사본의 해시를 원본 값과 비교합니다.** 이미징 뒤에 원본 해시를 다시 계산하는 까닭과 알고리즘 고르는 법은 [해시로 무결성 검증](hash-verification.md) 에 있습니다.
7. **모든 단계를 기록합니다.** 아래 목록을 빠짐없이 적습니다.
8. **원본에 표시를 붙여 안전하게 보관합니다.** 이후 분석은 사본으로만 합니다. 원본은 필요할 때 사본을 다시 만들 수 있게 남겨 둡니다.

7단계에서 적을 것은 다음과 같습니다.

- 원본 하드 드라이브의 모델, 일련번호, 용량
- 이미징 소프트웨어의 이름, 버전, 라이선스 정보
- 이미징 하드웨어의 이름, 버전, 라이선스 정보
- 이미지를 만든 모든 단계

모든 단계와 쓴 도구를 자세히 적어 두면 다른 분석가가 나중에 같은 과정을 되풀이할 수 있습니다.
원본과 사본을 누가 언제 맡았는지 적는 법은 [증거 보관 연속성](chain-of-custody.md) 에서 다룹니다.

## 켜진 시스템에서

- 켜진 시스템에서 물리 장치 전체를 비트 단위로 뜨는 방법은 권하지 않습니다. 뜨는 동안 파일과 메모리가 계속 바뀌어서 결과를 검증할 수 없습니다.
- 켜진 시스템이라도 논리 영역은 비트 단위로 뜨고 검증할 수 있습니다.
- 사용자가 아무것도 하지 않아도 서비스와 프로세스가 하드 드라이브에 쓰고 있을 수 있습니다.
- 메모리처럼 먼저 사라지는 데이터를 어떻게 모을지는 [라이브 응답](../live-response/index.md) 에서 다룹니다.

### 끌 것인가, 어떻게 끌 것인가

비휘발성 데이터를 모으기 전에 시스템을 끌지 정합니다.
SP 800-86 은 끄는 방법을 둘로 나눕니다.

| | 정상 종료 (Graceful OS Shutdown) | 전원 제거 (Remove Power) |
|---|---|---|
| 일어나는 일 | 운영체제가 열린 파일을 닫고 임시 파일을 지웁니다. 스왑 파일을 비울 수도 있습니다 | 스왑 파일과 임시 파일을 보존할 수 있습니다 |
| 잃을 수 있는 것 | 메모리에만 있던 루트킷이 사라질 수 있습니다. 트로이 목마가 흔적을 지울 수도 있습니다 | 일부 운영체제에서는 열린 파일 같은 데이터가 손상될 수 있습니다 |

- 전원을 뺄 때 벽 콘센트에서 뽑는 방법은 권하지 않습니다. 컴퓨터가 무정전 전원 장치 (UPS) 에 꽂혀 있을 수 있기 때문입니다.
- RFC 3227 은 증거 수집을 마치기 전에는 시스템을 끄지 말라고 합니다.
- 공격자가 시작·종료 스크립트를 바꿔 두어서, 끄는 순간 증거가 지워질 수 있기 때문입니다.

## 숨은 영역과 RAID

- 호스트 보호 영역 (Host Protected Area, HPA) 은 일부 하드 드라이브에서 제조사만 쓰도록 정한 영역입니다.
- SP 800-86 은 HPA 가 데이터를 숨기는 곳이 될 수 있다고 적었습니다.
- 스트라이핑 RAID (RAID-0·RAID-5) 는 디스크마다 따로 이미지를 뜹니다. 그다음 분석 시스템에서 RAID 구성을 다시 만듭니다.
- RAID-5 는 디스크 하나를 빼고 나머지를 모두 이미징해도 볼륨을 볼 수 있습니다.

이미지 안의 파티션을 읽는 법은 [파티션 구조](../../../01-foundations/disk-volume/mbr-gpt.md) 에 있습니다.

## E01 (EWF) 로 뜰 때 알아 둘 것

EWF (Expert Witness Compression Format) 는 디스크→파일 방식에서 쓰는 이미지 형식 가운데 하나입니다.
첫 세그먼트 파일의 확장자가 .E01 이라서 흔히 E01 이라고 부릅니다.
섹션 구조와 청크 압축 같은 형식 전체는 [증거 이미지·가상 디스크 형식](../../../01-foundations/disk-volume/e01-raw-aff4-vhdx-vmdk.md) 에서 다룹니다.
여기서는 이미지를 뜨거나 넘겨받을 때 확인할 것만 봅니다.

### 세그먼트 파일은 모두 함께 옮깁니다

이미지 하나가 여러 세그먼트 파일로 나뉠 수 있습니다.
파일 이름은 아래 순서로 이어집니다.

| 형식 | 확장자 순서 |
|---|---|
| EWF-E01 (디스크 이미지) | .E01~.E99 → .EAA~.EZZ → .FAA~.ZZZ |
| EWF-L01 (논리 증거 파일) | .L01~.L99 → .LAA~.LZZ → .MAA~.ZZZ |
| EWF2 (EnCase 7) | .Ex01, .Lx01 |

- 섹션 가운데 next 는 다음 세그먼트가 있다는 표시입니다.
- done 섹션은 이미지의 끝을 알립니다.
- 넘겨줄 때는 세그먼트 파일 수를 적고 모두 함께 옮깁니다.

### 파일 머리를 헥스로 확인합니다

아래 바이트는 **명세로 만든 예시**입니다. 실제 검체에서 나온 값이 아닙니다.

```
첫 세그먼트 파일(.E01), 오프셋 0x00 (명세로 만든 예시)
00000000  45 56 46 09 0D 0A FF 00  01 01 00 00 00           EVF..........
```

| 오프셋 | 크기 | 예시 값 | 뜻 |
|---|---|---|---|
| 0 | 8 | `45 56 46 09 0D 0A FF 00` | 시그니처 "EVF\x09\x0d\x0a\xff\x00" |
| 8 | 1 | `01` | 필드 시작 |
| 9 | 2 | `01 00` | 세그먼트 번호. 이 예시는 첫 세그먼트라서 1 입니다 |
| 11 | 2 | `00 00` | 필드 끝 |

- 파일 머리는 모두 13바이트입니다.
- 두 번째 세그먼트 파일이면 세그먼트 번호 칸이 2 입니다.
- 시그니처가 맞지 않으면 EWF-E01 세그먼트 파일이 아닙니다.

### 머리 정보에 무엇이 들어가는지 봅니다

header 섹션에는 사건 정보와 획득 정보가 압축한 ASCII 문자열로 들어갑니다.
EnCase 4 부터는 같은 정보를 UTF-16 으로 적은 header2 섹션도 씁니다.

| 식별자 | 뜻 |
|---|---|
| c | 사건 번호 |
| n | 증거 번호 |
| a | 설명 |
| e | 조사자 이름 |
| t | 메모 |
| m | 획득 일시 |
| u | 시스템 일시 |
| av | 획득 프로그램 버전 (EnCase 는 11자까지) |
| ov | 플랫폼·운영체제 (EnCase 는 23자까지) |
| p | 암호 해시 |
| r | 압축 수준 (b·f·n) |
| md | 매체 모델 (EnCase 6 이상) |
| sn | 매체 일련번호 (EnCase 6 이상) |

사건 번호와 증거 번호, 조사자 이름은 [증거 보관 연속성](chain-of-custody.md) 기록과 맞춰 봅니다.

날짜를 적는 방식은 이미지를 만든 도구마다 다릅니다.
EnCase 와 linen 은 둘 다 EWF 를 만드는 획득 도구입니다.

| 만든 도구 | 날짜 표기 | 시간대 |
|---|---|---|
| EnCase | "2002 3 4 10 19 59" 같은 문자열 | 형식 명세에 나오지 않습니다 |
| linen 6.19 이전 | POSIX 32비트 초 값 | 획득 일시·시스템 일시 모두 현지 시각 |
| linen 6.19 부터 | POSIX 32비트 초 값 | 획득 일시는 UTC, 시스템 일시는 현지 시각 |

그래서 획득 일시를 보고서에 옮길 때는 만든 도구와 버전을 먼저 확인합니다.
시각 값을 바꾸는 법은 [시각 값 형식](../../../01-foundations/value-decoding/filetime-unix-webkit-dos-ole.md) 에 있습니다.

### 읽기 오류 구간을 확인합니다

- error2 섹션은 읽기 오류가 난 섹터의 시작 섹터와 개수를 적습니다.
- EnCase 는 획득할 때 이 섹터를 0 으로 채웁니다.
- 그래서 이미지 안의 이 구간은 원본 내용이 아니라 채운 값입니다.

## 도구

아래는 예로만 듭니다. 한 도구의 결과에만 기대지 않습니다.

- NIST CFTT (Computer Forensics Tool Testing) 프로젝트가 디스크 이미징 도구를 검증하는 절차를 만들었습니다.
- libyal/libewf 는 EWF 형식 명세 문서를 공개한 오픈 소스 라이브러리입니다. 한 도구로 만든 E01 을 다른 구현으로 읽어 볼 때 예로 들 수 있습니다.
- 어떤 도구를 썼든 이름과 버전을 절차 7단계대로 기록합니다.

두 도구의 결과를 맞춰 보는 법은 [도구 결과 교차 검증](../../reporting/tool-validation.md) 에 있습니다.

## 함정과 한계

- **켜진 시스템의 물리 장치 전체를 뜨고 검증을 마쳤다고 적습니다.** 뜨는 동안 계속 바뀌는 장치라서 검증할 수 없는 이미지입니다.
- **파일 복사로 이미징을 대신합니다.** 지운 파일과 슬랙 공간이 빠집니다. 파일 생성 시각이 바뀔 수도 있습니다.
- **사본 매체를 지우지 않고 씁니다.** 복사 대상 매체는 복사 전에 기존 데이터를 지운 깨끗한 상태여야 합니다.
- **RAID 디스크 하나만 뜹니다.** 스트라이핑 RAID 는 디스크마다 이미지를 떠야 구성을 다시 만들 수 있습니다.
- **E01 세그먼트 일부만 넘깁니다.** next 와 done 섹션으로 마지막 세그먼트까지 있는지 확인합니다.
- **머리 정보의 획득 일시를 UTC 로 가정합니다.** 만든 도구와 버전에 따라 현지 시각일 수 있습니다.
- **0 으로 채운 구간을 원래 비어 있던 곳으로 읽습니다.** error2 섹션에 적힌 구간이면 읽기 오류로 채운 값입니다.

## 결과를 어떻게 해석하나

- **말해 주는 것**: 해시가 일치하는 이미지는 이미징 시점에 원본 매체에 있던 비트를 담습니다.
- **말해 주는 것**: 머리 정보와 기록지는 누가 어떤 도구로 언제 이미지를 만들었는지 보여 줍니다.
- **말해 주지 못하는 것**: 이미징 전에 매체가 어떻게 바뀌었는지.
- **말해 주지 못하는 것**: 메모리에만 있던 데이터. 디스크 이미지에는 들어가지 않습니다.
- **말해 주지 못하는 것**: 읽기 오류로 0 을 채운 구간의 원래 내용.

보고서에는 절차와 결과를 기록이 말하는 만큼만 씁니다.

> 증거 번호 `<번호>` 매체(모델 `<모델>`, 일련번호 `<번호>`)를 쓰기 방지 장치에 연결해 `<날짜 시각, 시간대>` 에 비트 스트림 이미지로 복사했다. 이미징 전후에 계산한 원본 해시와 사본 해시(`<알고리즘>`)가 같았다. 읽기 오류 구간은 `<없음 / 섹터 범위>` 이다.
