# 셸 아이템 (Shell Item·PIDL)

## 한 줄 요약

셸 아이템 (Shell Item) 은 Windows 셸이 파일·폴더·가상 객체 하나를 가리킬 때 쓰는 작은 이진 구조입니다. 셸 아이템을 차례로 이어 붙이고 끝에 0 두 바이트를 둔 것이 항목 ID 목록 (ITEMIDLIST) 입니다. 이 목록을 흔히 PIDL 이라고 부릅니다. 바로가기 파일과 셸백은 이 목록을 그대로 저장합니다. 파일 항목 셸 아이템에는 이름, 크기, 시각 세 개, NTFS 파일 참조가 들어갈 수 있습니다.

## 이 형식을 쓰는 아티팩트

libfwsi 문서는 바로가기 파일 (LNK), Windows 7 의 셸백 (BagMRU), 열기·저장 대화상자의 최근 폴더 기록에서 셸 아이템을 보았다고 적습니다.

| 아티팩트 | 셸 아이템이 있는 곳 | 페이지 |
|---|---|---|
| 바로가기 파일 | 링크 대상 식별자 (LinkTargetIDList) | [바로가기 형식](/01-foundations/shell-document-formats/shell-link-lnk.md), [바로가기 파일](/02-artifacts/file-folder-usage/lnk.md) |
| 바로가기 파일 | 추가 데이터 블록 0xa000000c (셸 아이템 목록 블록) | [바로가기 형식](/01-foundations/shell-document-formats/shell-link-lnk.md) |
| 점프리스트 | 번호 스트림에 든 LNK 데이터 | [점프리스트](/02-artifacts/file-folder-usage/jump-lists.md) |
| 셸백 | BagMRU 아래 값 | [셸백](/02-artifacts/file-folder-usage/shellbags/index.md) |
| 열기·저장 대화상자 기록 | 최근 폴더 기록 값 | [열기·저장 대화상자 기록](/02-artifacts/file-folder-usage/comdlg32-opensavepidlmru-lastvisitedpidlmru-cids.md) |

libfwsi 문서에는 라이브러리 정의 파일 (.library-ms, XML) 안에도 이 데이터를 직렬화해 넣는다는 주석이 있습니다.

### Windows 버전

셸 아이템 형식은 셸 내부용입니다. 그래서 공개 문서가 없고, Windows 버전마다 다릅니다.

| Windows | 근거 |
|---|---|
| 95·98·NT4·2000·XP·2003·Vista·2008·7·8·8.1·10 | libfwsi 문서가 시험한 버전입니다 |
| 11 | libfwsi 목록에 없습니다. PC 한 대에서 읽어 본 결과는 아래와 같습니다 |

Windows 11 PC 한 대에서 시작 메뉴 LNK 를 읽어 보았습니다 (확인 범위: Windows 11 Home 10.0.26200, PC 한 대).

- 링크 대상 식별자가 있는 LNK 는 86개였습니다. 86개 모두 첫 셸 아이템이 뿌리 폴더 (0x1f) 였습니다.
- 그 안의 파일 항목 셸 아이템은 357개였습니다. 357개 모두 확장 블록 0xbeef0004 의 버전이 9 였습니다.
- 볼륨 아이템은 44개였습니다. 종류 표시에 0x70 을 AND 한 값이 0x70 인 아이템 (0x71 제어판 등) 은 34개였습니다.

## 구조

### 셸 이름 공간과 PIDL

아래는 Microsoft 문서의 설명입니다.

- 셸 이름 공간 (Shell Namespace) 은 파일 시스템과 셸이 다루는 다른 객체를 나무 하나로 묶은 것입니다.
- 나무의 뿌리는 바탕 화면입니다.
- 파일이 아닌 가상 객체도 이 나무에 들어갑니다. 네트워크 프린터, 네트워크의 다른 컴퓨터, 제어판 앱, 휴지통이 그 예입니다.
- 바탕 화면 바로 아래에 내 컴퓨터·휴지통 같은 가상 폴더가 있습니다.
- 각 디스크 드라이브의 파일 시스템 뿌리는 내 컴퓨터 아래 폴더입니다.
- 경로 문자열로는 가상 객체를 가리킬 수 없습니다. 그래서 셸은 항목 ID (Item ID) 로 객체를 가리킵니다.

항목 ID 는 SHITEMID 구조체입니다. 앞의 `cb` 2바이트는 구조체 전체 크기입니다. 그 뒤의 `abID` 는 내용입니다. `abID` 의 길이와 내용은 그 객체를 담은 폴더가 정합니다. 표준 정의가 없어서 그 폴더만 내용의 뜻을 압니다.

PIDL 은 "항목 ID 목록을 가리키는 포인터" 의 줄임말입니다. 문서에서는 목록 자체를 흔히 PIDL 이라고 부릅니다. 이 글도 그렇게 씁니다.

| 종류 | 뿌리 | 객체 하나를 유일하게 가리키나 |
|---|---|---|
| 전체 PIDL (절대 PIDL) | 바탕 화면. 중간 폴더의 항목 ID 를 모두 담습니다 | 예 |
| 상대 PIDL | 바탕 화면이 아닌 어떤 폴더 | 아니요 |
| 단일 수준 PIDL | 부모 폴더. 항목 ID 하나와 끝 표시만 담습니다 | 아니요. 다만 바탕 화면에 있는 객체라면 전체 PIDL 이기도 합니다 |

### 목록과 아이템

값은 모두 리틀 엔디언입니다. 오프셋은 셸 아이템 시작에서 센 10진 바이트 수입니다.

| 오프셋 | 크기 | 뜻 |
|---|---|---|
| 0 | 2 | 아이템 크기. 크기 칸 2바이트를 포함합니다 |
| 2 | 1 | 종류 표시 (Class Type Indicator) |
| 3 | 가변 | 종류별 데이터 |

- 목록은 셸 아이템을 이어 놓고, 크기 값이 0 인 2바이트로 끝납니다.
- 아이템 순서가 경로 역할을 합니다.

### 종류 표시

| 값 | 종류 |
|---|---|
| 0x1f | 뿌리 폴더 (Root Folder) |
| 0x20–0x2f | 볼륨 (Volume) |
| 0x30–0x3f | 파일 항목 (File Entry). 0x80 이 더 켜진 0xb1 도 libfwsi 문서에 있습니다 |
| 0x40–0x4f | 네트워크 위치 (Network Location) |
| 0x61 | URI |
| 0x71 | 제어판 (Control Panel) |

- 볼륨·파일 항목·네트워크 위치는 종류 표시에 0x70 을 AND 한 값으로 가립니다. 결과는 0x20·0x30·0x40 입니다. 그래서 0xb1 도 파일 항목입니다.
- libfwsi 는 나머지 비트를 하위 종류나 플래그로 추정합니다.
- 종류 표시 바이트는 확실한 기준이 아닙니다. libfwsi 는 셸 아이템을 세 갈래로 나눕니다.
  - 종류 표시로 가리는 아이템
  - 서명 (Signature) 으로 가리는 아이템
  - 앞 아이템 (Ancestor) 을 보고 가리는 아이템
- 사용자 속성 보기 (Users Property View) 아이템이 그 예입니다. libfwsi 는 이 아이템의 종류 표시가 0x00 이었다고 적습니다. 이 아이템은 Users Libraries (`031e4825-…`) 나 Users (`59031a47-…`) 뿌리 폴더 뒤에 옵니다.
- 압축 폴더 (ZIP), MTP 저장 장치, 제어판 CPL, 위임 (Delegate) 폴더 같은 서명 기반 아이템도 libfwsi 문서에 따로 있습니다.

### 뿌리 폴더 (0x1f)

| 오프셋 | 크기 | 뜻 |
|---|---|---|
| 3 | 1 | 정렬 순번 (Sort Index) |
| 4 | 16 | 셸 폴더 GUID |

정렬 순번 값의 예는 아래와 같습니다.

| 값 | 폴더 |
|---|---|
| 0x42 | 라이브러리 |
| 0x44 | 사용자 |
| 0x48 | 내 문서 |
| 0x50 | 내 컴퓨터 |
| 0x58 | 네트워크 |
| 0x60 | 휴지통 |
| 0x80 | My Games |

- GUID `20d04fe0-3aea-1069-a2d8-08002b30309d` 는 XP 에서 "My Computer" 로, Windows 10 에서 "This PC" 로 보입니다.
- 표시 이름은 레지스트리의 그 CLSID 키에 있습니다.
- GUID 를 바이트에서 읽는 법은 [윈도 식별자 형식](/01-foundations/value-decoding/sid-guid-clsid-known-folder-id.md) 에서 다룹니다.

### 볼륨 (0x2X)

- 플래그 0x01 이 켜져 있으면 오프셋 3 에 볼륨 이름 20바이트가 있습니다.
- 볼륨 이름은 ASCII 이고 끝에 NULL 이 옵니다. 남는 바이트는 0 입니다.
- libfwsi 는 플래그 0x08 을 이동식 매체로 적습니다.

### 파일 항목 (0x3X)

종류 표시의 아래 비트는 플래그입니다.

| 플래그 | 뜻 |
|---|---|
| 0x01 | 디렉터리 |
| 0x02 | 파일 |
| 0x04 | 유니코드 문자열 |
| 0x80 | 클래스 식별자가 있음 |

XP 이후 파일 항목의 구조는 아래와 같습니다.

| 오프셋 | 크기 | 뜻 |
|---|---|---|
| 4 | 4 | 파일 크기 |
| 8 | 4 | 마지막 수정 시각 (FAT 날짜·시각, UTC) |
| 12 | 2 | 파일 속성의 아래 16비트 |
| 14 | 가변 | 기본 이름 (Primary Name) |
| 그 뒤 | 가변 | 확장 블록 0xbeef0004 |

- 기본 이름은 대개 짧은 이름 (8.3) 입니다. 플래그 0x04 가 켜져 있으면 긴 이름일 수도 있습니다.
- XP 이후에는 ASCII 이름 뒤에 16비트 경계를 맞추는 0 바이트가 하나 더 붙을 수 있습니다.
- XP 이전 (95·NT4·2000) 파일 항목에는 확장 블록 대신 두 번째 이름 (짧은 이름) 이 있습니다.
- libfwsi 는 날짜·시각 값이 늘 채워지지는 않는 것 같다고 적습니다.
- 파일 크기 칸은 4바이트입니다. 4GB 를 넘는 파일을 이 칸에 어떻게 적는지는 libfwsi 문서에도 확인되지 않은 채로 남아 있습니다.

### 네트워크 위치 (0x4X)

| 아래 4비트 값 | 뜻 |
|---|---|
| 0x01 | 도메인·작업 그룹 |
| 0x02 | 서버 UNC 경로 |
| 0x03 | 공유 UNC 경로 |
| 0x06 | Microsoft Windows Network |
| 0x07 | 전체 네트워크 |

### 확장 블록

확장 블록 (Extension Block) 은 셸 아이템 뒤쪽에 붙는 부가 정보입니다. 공통 구조는 아래와 같습니다. 오프셋은 블록 시작에서 셉니다.

| 오프셋 | 크기 | 뜻 |
|---|---|---|
| 0 | 2 | 블록 크기 |
| 2 | 2 | 버전 |
| 4 | 4 | 서명 |
| 블록 끝 2바이트 | 2 | 첫 확장 블록 위치 (셸 아이템 시작 기준) |

서명은 늘 0xbeef 뒤에 블록 종류를 나타내는 16비트 값이 붙는 모양입니다. libfwsi 문서에는 0xbeef0000 부터 0xbeef0029 까지 있습니다.

파일 항목에 붙는 블록은 0xbeef0004 입니다.

| 오프셋 | 크기 | 뜻 |
|---|---|---|
| 8 | 4 | 만든 시각 (FAT 날짜·시각, UTC) |
| 12 | 4 | 마지막 접근 시각 (FAT 날짜·시각, UTC) |
| 16 | 2 | 긴 이름 위치 (블록 시작 기준) |
| 버전 7 이상 | 8 | NTFS 파일 참조. 앞 6바이트는 MFT 항목 번호, 뒤 2바이트는 시퀀스 번호입니다 |
| 버전 3 이상 | 가변 | 긴 이름 (UTF-16LE) 과 지역화 이름 (예: `@shell32.dll,-21781`) |

파일 참조와 이름이 들어가는 정확한 자리는 블록 버전에 따라 다릅니다. 읽을 때는 libfwsi 문서의 버전별 표를 따릅니다.

| 블록 버전 | Windows (libfwsi 문서) |
|---|---|
| 3 | XP·2003 |
| 7 | Vista (SP0) |
| 8 | 2008·7·8.0 |
| 9 | 8.1·10. 위의 Windows 11 PC 한 대에서도 9 였습니다 |

- libfwsi 는 파일 참조 칸이 늘 파일 참조는 아닐 수 있다고 표시합니다.
- 이름 문자열에는 짝 없는 서로게이트 (Unpaired Surrogate, 예: U+D800) 가 들어갈 수 있습니다. 그래서 엄격한 UTF-16 이 아닙니다. 문자열 변환은 [문자 인코딩](/01-foundations/value-decoding/utf-16le-utf-8-cp949.md) 에서 다룹니다.

## 읽는 법

1. 목록 시작에서 크기 2바이트를 읽습니다. 값이 0 이면 목록이 끝났습니다.
2. 오프셋 2 의 종류 표시를 읽습니다. 0x1f 이면 뿌리 폴더입니다. 아니면 0x70 을 AND 해서 볼륨·파일 항목·네트워크 위치인지 봅니다.
3. 표에 없는 값이면 서명 기반 아이템인지, 앞 아이템이 무엇인지 봅니다.
4. 파일 항목이면 아이템 끝 2바이트에서 첫 확장 블록 위치를 읽습니다. 그 자리에서 서명 0xbeef0004 와 블록 버전을 확인합니다.
5. 아이템 크기만큼 건너뛰어 다음 아이템으로 갑니다. 아이템 안에 풀지 못한 바이트가 있어도 다음 아이템 위치는 크기 칸으로 정해집니다.
6. 아이템마다 얻은 이름을 순서대로 이으면 경로가 됩니다.

### 헥스로 한 번

아래는 libfwsi 문서와 Microsoft 문서를 보고 만든 예시입니다. 실제 검체에서 뽑은 값이 아닙니다. 오프셋은 목록 시작에서 셉니다. `..` 은 설명하지 않는 바이트를 줄인 것입니다.

```
오프셋  00 01 02 03 04 05 06 07 08 09 0A 0B 0C 0D 0E 0F
0x00    14 00 1F 50 E0 4F D0 20 EA 3A 69 10 A2 D8 08 00
0x10    2B 30 30 9D 17 00 21 43 3A 5C 00 00 00 00 00 00
0x20    00 00 00 00 00 00 00 00 00 00 00 4E 00 31 00 00
0x30    00 00 00 6A 5A 94 49 10 00 57 6F 72 6B 00 00 3A
0x40    00 09 00 04 00 EF BE 6A 5A 94 49 6E 5A 82 52 ..
0x50    .. .. .. .. .. .. .. .. .. .. .. .. .. .. .. ..
0x60    .. .. .. .. .. .. .. .. .. .. .. .. .. .. .. ..
0x70    .. .. .. .. .. .. .. 14 00 00 00
```

**첫째 아이템: 뿌리 폴더**

1. 0x00 의 `14 00` 은 크기 20 입니다. 첫째 아이템은 0x00~0x13 입니다.
2. 0x02 의 `1F` 는 뿌리 폴더입니다.
3. 0x03 의 `50` 은 정렬 순번 0x50 입니다. 내 컴퓨터입니다.
4. 0x04~0x13 의 16바이트는 GUID `20d04fe0-3aea-1069-a2d8-08002b30309d` 입니다.

**둘째 아이템: 볼륨**

5. 0x14 의 `17 00` 은 크기 23 입니다. 둘째 아이템은 0x14~0x2A 입니다.
6. 0x16 의 `21` 에 0x70 을 AND 하면 0x20 입니다. 그래서 볼륨 아이템입니다.
7. 0x01 비트가 켜져 있습니다. 그래서 0x17 (아이템 +3) 부터 20바이트가 볼륨 이름입니다. ASCII 로 읽으면 `C:\` 입니다. 0x08 비트 (이동식 매체) 는 꺼져 있습니다.

**셋째 아이템: 파일 항목**

8. 0x2B 의 `4E 00` 은 크기 78 입니다. 셋째 아이템은 0x2B~0x78 입니다.
9. 0x2D 의 `31` 에 0x70 을 AND 하면 0x30 입니다. 그래서 파일 항목입니다. 0x01 비트가 켜져 있으므로 디렉터리입니다.
10. 0x2F (아이템 +4) 의 `00 00 00 00` 은 파일 크기 0 입니다.
11. 0x33 (아이템 +8) 의 `6A 5A 94 49` 는 마지막 수정 시각입니다. FAT 날짜·시각을 푸는 법은 [시각 값 형식](/01-foundations/value-decoding/filetime-unix-webkit-dos-ole.md) 에서 다룹니다.
12. 0x37 (아이템 +12) 의 `10 00` 은 파일 속성의 아래 16비트입니다.
13. 0x39 (아이템 +14) 부터 기본 이름 `Work` 와 NULL 이 옵니다.
14. 0x3E 의 `00` 은 16비트 경계를 맞추는 바이트입니다.
15. 아이템 끝 2바이트인 0x77 의 `14 00` 은 20 입니다. 첫 확장 블록은 아이템 시작 0x2B 에서 20바이트 뒤인 0x3F 에 있습니다.

**확장 블록**

16. 0x3F 의 `3A 00` 은 블록 크기 58 입니다. 블록은 0x3F~0x78 이고, 셋째 아이템 끝과 맞습니다.
17. 0x41 의 `09 00` 은 블록 버전 9 입니다.
18. 0x43 의 `04 00 EF BE` 는 서명 0xbeef0004 입니다.
19. 0x47 (블록 +8) 의 `6A 5A 94 49` 는 만든 시각입니다.
20. 0x4B (블록 +12) 의 `6E 5A 82 52` 는 마지막 접근 시각입니다.
21. 0x4F (블록 +16) 부터는 긴 이름 위치, 파일 참조, 긴 이름이 옵니다. 칸 자리가 블록 버전마다 달라 이 예시에서는 줄였습니다.

**목록 끝**

22. 0x79 의 `00 00` 은 크기 0 입니다. 목록이 여기서 끝납니다.

세 아이템을 이으면 내 컴퓨터 → `C:\` → `Work` 입니다. 이 목록은 `C:\Work` 폴더를 가리키는 전체 PIDL 입니다.

> 그림 자리: 위 예시 목록을 세 아이템으로 나누고, 각 아이템의 크기 칸이 다음 아이템 시작을 가리키는 화살표와 파일 항목 끝 2바이트가 확장 블록 시작을 가리키는 화살표를 보여 주는 그림

## 포렌식에서 중요한 점

### 셸 아이템에 남는 시각

| 시각 | 자리 | 형식 |
|---|---|---|
| 마지막 수정 | 파일 항목 +8 | FAT 날짜·시각, UTC (libfwsi) |
| 만든 시각 | 0xbeef0004 블록 +8 | FAT 날짜·시각, UTC (libfwsi) |
| 마지막 접근 | 0xbeef0004 블록 +12 | FAT 날짜·시각, UTC (libfwsi) |

- 세 시각 모두 FILETIME 이 아니라 4바이트 FAT 날짜·시각입니다.
- 시각이 채워지지 않은 아이템도 있습니다.
- 셸이 이 시각을 언제 채우고 언제 다시 쓰는지는 형식 문서에 없습니다. 그래서 대상 파일의 지금 시각과 다를 수 있습니다.
- 시각을 증거로 읽는 법은 아티팩트마다 다릅니다. [셸백](/02-artifacts/file-folder-usage/shellbags/index.md) 과 [바로가기 파일](/02-artifacts/file-folder-usage/lnk.md) 페이지를 봅니다.

### NTFS 파일 참조

- 버전 7 이상 블록에는 MFT 항목 번호 6바이트와 시퀀스 번호 2바이트가 있습니다.
- 파일 참조의 구조는 [NTFS 구조](/01-foundations/disk-volume/ntfs/index.md) 에서 다룹니다.
- libfwsi 는 이 칸이 늘 파일 참조는 아닐 수 있다고 표시합니다. 번호 하나만으로 결론을 내리지 않습니다. 같은 아이템의 이름도 함께 봅니다.
- 이 번호를 $MFT 와 맞춰 보는 절차는 [셸백](/02-artifacts/file-folder-usage/shellbags/index.md) 페이지에서 다룹니다.

### 지운 대상

- 셸 아이템은 대상 파일 안이 아니라 LNK 파일이나 셸백 같은 다른 기록 안에 있습니다.
- 그래서 대상을 지워도 그 기록을 지우지 않으면 셸 아이템은 남습니다.
- 대상이 지금 없다면 셸 아이템의 이름·크기·시각·파일 참조가 대상의 흔적을 알려 주는 단서가 됩니다([지운 파일의 흔적 찾기](/04-scenarios/activity/deleted-file-traces.md)).

### 손상과 낯선 값

- 모르는 종류의 아이템이 나와도 크기 칸으로 건너뛰면 다음 아이템을 읽을 수 있습니다.
- 이름에 짝 없는 서로게이트가 들어 있으면 엄격한 UTF-16 변환기는 그 글자에서 오류를 내거나 다른 글자로 바꿀 수 있습니다. 원본 바이트를 함께 적어 둡니다.
- XP 이전 파일 항목을 XP 이후 틀로 읽으면 두 번째 이름을 확장 블록으로 잘못 읽습니다.

## 함정

1. **종류 표시 하나로 종류를 정합니다.** 서명이나 앞 아이템을 보고서야 가려지는 아이템이 있습니다. 사용자 속성 보기 아이템은 종류 표시가 0x00 입니다.
2. **기본 이름을 파일 이름으로 씁니다.** 기본 이름은 대개 짧은 이름 (8.3) 입니다. 긴 이름은 확장 블록에서 읽습니다.
3. **폴더 아이템이 있으면 디스크에 폴더가 있었다고 봅니다.** ZIP 은 디렉터리를 따로 저장하지 않습니다. 그래서 셸이 디렉터리용 셸 아이템을 흉내 내어 만듭니다. 압축 파일 안을 탐색한 흔적일 수 있습니다.
4. **파일 크기를 그대로 씁니다.** 크기 칸은 4바이트입니다. 4GB 를 넘는 파일의 값은 믿기 어렵습니다.
5. **FAT 시각을 FILETIME 으로 읽습니다.** 셸 아이템 시각은 4바이트 FAT 날짜·시각입니다. 8바이트 FILETIME 틀로 읽으면 엉뚱한 날짜가 나옵니다.
6. **버전 표를 Windows 11 에 그대로 씁니다.** libfwsi 문서는 Windows 10 까지만 시험했습니다. Windows 11 PC 한 대에서 버전 9 를 보았지만, 모든 PC 에 맞는다고 보장하지 못합니다.
7. **블록 버전을 보지 않고 칸을 읽습니다.** 파일 참조는 버전 7 이상, 긴 이름은 버전 3 이상에만 있습니다. 칸 자리도 버전마다 다릅니다.
8. **뿌리 폴더 이름을 도구 표시 그대로 옮깁니다.** 같은 GUID 가 XP 에서는 "My Computer", Windows 10 에서는 "This PC" 로 보입니다. 보고서에는 GUID 를 함께 적습니다.

## 도구

- 이 글이 따른 형식 문서는 libyal 의 libfwsi 저장소에 있습니다.
- 셸 아이템은 따로 떨어진 파일로 나오지 않습니다. LNK·셸백 파서가 안쪽의 셸 아이템을 함께 풉니다. 도구 예는 [바로가기 파일](/02-artifacts/file-folder-usage/lnk.md) 과 [셸백](/02-artifacts/file-folder-usage/shellbags/index.md) 페이지에 있습니다.

도구를 쓸 때는 다음을 확인합니다.

- 확장 블록의 버전과 파일 참조를 보여 주는지 확인합니다.
- 기본 이름과 긴 이름을 나눠 보여 주는지 확인합니다.
- FAT 시각을 UTC 그대로 보여 주는지, 분석 PC 의 현지 시각으로 바꿔 보여 주는지 확인합니다.
- 모르는 종류의 아이템을 건너뛰는지, 원본 바이트를 보여 주는지 확인합니다.
- 아이템 몇 개는 헥스로 읽은 값과 맞춰 봅니다. 방법은 [도구 결과 교차 검증](/03-techniques/reporting/tool-validation.md) 을 봅니다.
