# 도메인 백업 키 (Domain Backup Key)

> 위치: [DPAPI 구조 (Data Protection API)](index.md) > 도메인 백업 키

## 한 줄 요약

도메인 계정의 마스터키는 만들 때 도메인 컨트롤러 (Domain Controller, DC) 의 공개키로 한 벌 더 암호화해 둡니다.
사용자 암호로 마스터키를 못 풀 때, 이 백업본을 DC 가 대신 풀어 줍니다.
그래서 DC 의 백업 개인키가 있으면 사용자 암호 없이도 마스터키가 풀립니다.

> 마스터키가 무엇이고 사용자 암호로 어떻게 풀리는지는 [마스터키 파일](master-key-protect-sid.md) 에 있습니다.
> 이 글은 사용자 암호가 아닌 두 번째 복호 경로, 곧 도메인 백업을 다룹니다.

## 왜 생기나

사용자가 암호를 잊으면 사용자 암호로 감싼 마스터키를 풀 수 없고, 그러면 그 마스터키로 보호한 데이터도 모두 잃습니다. 도메인 환경은 이 손실을 막으려고 마스터키를 DC 의 키로 한 번 더 감싸므로, 도메인 계정의 마스터키에는 사용자 암호 말고도 풀 길이 하나 더 있습니다.

## 어떻게 도나

도메인 백업은 마스터키를 만드는 순간과 마스터키를 푸는 순간에 각각 한 번씩 DC 와 통신합니다.

### 마스터키를 만들 때

1. DC 에는 DPAPI 전용 공개키·개인키가 한 쌍 있습니다. 도메인 전체가 이 키쌍을 함께 씁니다.
2. 클라이언트는 상호 인증하고 기밀을 지키는 RPC 로 DC 의 공개키를 받습니다.
3. 클라이언트는 마스터키를 그 공개키로 한 번 더 암호화합니다.
4. 이 백업본을 사용자 암호로 감싼 본과 함께 마스터키 파일에 둡니다. 역공학 자료는 이 칸을 도메인 키 (DomainKey) 로 부릅니다.

### 마스터키를 풀 때

1. 먼저 사용자 암호로 마스터키를 풉니다.
2. 사용자 암호로 못 풀면, 공개키로 감싼 백업본을 상호 인증·기밀 RPC 로 DC 에 보냅니다.
3. DC 는 자기 개인키로 백업본을 풀어 마스터키를 돌려줍니다.
4. 이 RPC 는 도청으로 마스터키가 새지 않게 보호합니다.

- 도메인 전체가 같은 백업 키쌍을 쓰므로, 이 개인키 하나로 그 도메인 계정들의 마스터키를 모두 풀 수 있습니다.
- 이 통신 규약은 MS-BKRP (BackupKey Remote Protocol) 로 알려져 있습니다. 이 글은 그 명세를 직접 열어 보지 못했습니다.
- 그래서 세부 메서드와 GUID 값은 적지 않습니다.

## 스탠드얼론·워크그룹 PC 는 다릅니다

도메인에 가입하지 않은 PC 에는 이 도메인 백업이 없고, 도메인 가입 PC 라도 로컬 계정의 마스터키는 DC 로 백업하지 않습니다. 대신 암호 재설정 디스크 (Password Reset Disk, PRD) 를 만들면 복구 길이 생깁니다. PRD 는 2048비트 RSA 키쌍을 복구 키로 쓰며, PRD 로 암호를 재설정하면 그 사용자의 모든 마스터키를 새 암호로 다시 감쌉니다.

## 블롭의 마스터키 ID 여러 개와의 관계

[DPAPI 블롭](dpapi-blob.md) 의 arrKeys 필드는 마스터키 ID 를 여럿 담을 수 있습니다. 한 역공학 자료는 이 여러 자리가 도메인 백업 키나 호환 키를 위한 것으로 짐작하지만 직접 검증하지는 못했다고 밝혔으므로, arrKeys 의 정확한 쓰임은 아직 확정하지 못했습니다.

## 포렌식에서 중요한 점

- 도메인 계정은 사용자 암호를 몰라도 마스터키를 풀 길이 있습니다. 그 길이 도메인 백업 개인키입니다.
- 이 개인키가 DC 밖으로 새면, 그 도메인 계정들의 마스터키가 사용자 암호 없이 풀립니다.
- 그래서 도메인 사건에서는 조직이 보관한 백업 키를 복호 재료로 쓸 수 있는지, 그리고 이 키가 밖으로 샌 흔적이 있는지 함께 살핍니다.
- 오프라인 복호에서 이 백업 키를 어떻게 재료로 쓰는지는 [오프라인 복호 재료와 절차](nt.md) 에 있습니다.
- **말해 주는 것**: 마스터키 파일에 도메인 키 칸이 차 있으면, 그 마스터키를 만들 때 도메인 계정이었고 두 번째 복호 경로가 있다는 것.
- **말해 주지 못하는 것**: 백업 개인키 자체. 이 키는 클라이언트 PC 가 아니라 DC 에 있습니다.
- **말해 주지 못하는 것**: 마스터키를 실제로 언제 백업했는지. 이 통신은 마스터키를 만들 때 일어나지만, 그 시각을 알려 주는 신뢰할 칸은 없습니다.

## 함정

- **클라이언트 PC 에서 백업 개인키를 찾습니다.** 개인키는 클라이언트가 아니라 DC 에 있습니다. 클라이언트에는 공개키로 감싼 백업본만 있습니다.
- **워크그룹 PC 나 로컬 계정에 도메인 백업이 있다고 봅니다.** 도메인 계정의 마스터키에만 이 백업본이 있습니다.
- **PRD 복구 키와 도메인 백업 키를 같게 봅니다.** PRD 는 로컬 계정용 RSA 복구 키이고, 도메인 백업 키는 DC 가 쥔 도메인 공용 키쌍입니다.
- **arrKeys 의 여러 마스터키 ID 를 확정 사실로 씁니다.** 이 쓰임은 아직 짐작 단계입니다.
