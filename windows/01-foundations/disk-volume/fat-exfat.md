# FAT·exFAT 구조 (FAT·exFAT)

> 위치: 기반 구조 > 디스크·볼륨

## 한 줄 요약

FAT (File Allocation Table) 파일시스템은 파일이 쓰는 클러스터를 FAT 표에 사슬처럼 이어 적습니다. 파일 이름·크기·시각은 32바이트 디렉터리 항목에 적습니다. FAT12·FAT16·FAT32 는 FAT 표 항목의 크기가 다르고, exFAT 는 빈 클러스터를 비트맵으로 찾습니다.

## 구조

### 형식과 나온 때

| 형식 | 나온 때 |
|---|---|
| FAT12 | 1980년 |
| FAT16 | 1984년 (PC DOS 3.0) |
| FAT32 | 1996년 8월 (Windows 95 OSR2) |
| exFAT | 2006년 11월 (Windows Embedded CE 6.0) |

- FAT16B 와 FAT32 에서 파일 하나의 최대 크기는 4,294,967,295바이트 (4 GB − 1) 입니다.
- 헤더와 FAT 표의 여러 바이트 정수는 리틀 엔디언 (little-endian) 입니다.

### 볼륨의 네 영역

| 영역 | 내용 |
|---|---|
| 예약 영역 | 첫 섹터가 부트 섹터 (VBR, Volume Boot Record) 입니다. 이 섹터에 BPB (BIOS Parameter Block) 가 들어 있습니다. |
| FAT 영역 | FAT 표 사본이 보통 2개 있습니다. |
| 루트 디렉터리 영역 | FAT12·FAT16 에만 있습니다. 크기가 고정입니다. |
| 데이터 영역 | 파일과 디렉터리가 들어갑니다. FAT32 는 루트 디렉터리도 여기에 둡니다. |

- FAT32 의 예약 영역은 보통 32섹터입니다.
- FAT32 는 예약 영역의 섹터 1 에 FS 정보 섹터를, 섹터 6 에 백업 부트 섹터를 둡니다.
- FAT32 의 루트 디렉터리는 보통 클러스터 2 에서 시작합니다.
- 두 FAT 사본은 평소에 같은 내용으로 맞춰 둡니다. 읽을 때는 첫 사본에 오류가 있을 때만 둘째 사본을 씁니다.

### 부트 섹터와 BPB

오프셋은 부트 섹터 첫 바이트 기준입니다.

| 오프셋 | 크기 | 필드 | 설명 |
|---|---|---|---|
| 0x000 | 3 | 점프 명령 | |
| 0x003 | 8 | OEM 이름 | 포맷한 시스템의 이름입니다. |
| 0x00B | 2 | 섹터당 바이트 수 | 흔히 512 입니다. |
| 0x00D | 1 | 클러스터당 섹터 수 | 1·2·4·…·128 |
| 0x00E | 2 | 예약 섹터 수 | 첫 FAT 앞까지의 섹터 수입니다. |
| 0x010 | 1 | FAT 개수 | 거의 늘 2 입니다. |
| 0x011 | 2 | 루트 디렉터리 항목 수 | FAT32 는 0 입니다. |
| 0x013 | 2 | 전체 섹터 수 | FAT32 는 0 이고 0x020 의 값을 씁니다. |
| 0x015 | 1 | 매체 설명자 | |
| 0x016 | 2 | FAT 하나의 섹터 수 (FAT12/16) | FAT32 는 0 이고 0x024 의 값을 씁니다. |
| 0x018 | 2 | 트랙당 섹터 | |
| 0x01A | 2 | 헤드 수 | |
| 0x01C | 4 | 숨은 섹터 수 | 파티션 앞의 섹터 수입니다. |
| 0x020 | 4 | 전체 섹터 수 | |
| 0x1FE | 2 | 서명 | `55 AA` |

### FAT12·FAT16 확장 BPB

| 오프셋 | 크기 | 필드 | 설명 |
|---|---|---|---|
| 0x024 | 1 | 드라이브 번호 | |
| 0x025 | 1 | 예약 | Windows NT 는 CHKDSK 표시로 씁니다. 비트 0 은 "제대로 마운트 해제되지 않음 (dirty)", 비트 1 은 "디스크 입출력 오류가 있었음" 입니다. |
| 0x026 | 1 | 확장 서명 | 0x29 |
| 0x027 | 4 | 볼륨 일련번호 | |
| 0x02B | 11 | 볼륨 레이블 | |
| 0x036 | 8 | 파일 시스템 이름 | "FAT12␠␠␠" 같은 값입니다. 보여 주기용입니다. |

### FAT32 확장 BPB

| 오프셋 | 크기 | 필드 | 설명 |
|---|---|---|---|
| 0x024 | 4 | FAT 하나의 섹터 수 | |
| 0x028 | 2 | 미러링 플래그 | 비트 7 이 켜지면 비트 0~3 이 가리키는 FAT 하나만 씁니다. |
| 0x02A | 2 | 판 | 0.0 |
| 0x02C | 4 | 루트 디렉터리 시작 클러스터 | 보통 2 |
| 0x030 | 2 | FS 정보 섹터 위치 | 보통 1 |
| 0x032 | 2 | 백업 부트 섹터 위치 | 보통 6 |
| 0x040 | 1 | 드라이브 번호 | |
| 0x041 | 1 | 예약 | FAT12/16 의 0x025 와 쓰임이 같습니다. |
| 0x042 | 1 | 확장 서명 | 0x29 |
| 0x043 | 4 | 볼륨 일련번호 | |
| 0x047 | 11 | 볼륨 레이블 | |
| 0x052 | 8 | 파일 시스템 이름 | "FAT32␠␠␠" |

### FAT32 FS 정보 섹터

| 오프셋 | 크기 | 필드 | 설명 |
|---|---|---|---|
| 0x000 | 4 | 서명 1 | "RRaA" |
| 0x1E4 | 4 | 서명 2 | "rrAa" |
| 0x1E8 | 4 | 빈 클러스터 수 | 마지막으로 알려진 값입니다. 모르면 0xFFFFFFFF 입니다. |
| 0x1EC | 4 | 마지막으로 할당한 클러스터 | 다음 할당을 찾기 시작하는 자리입니다. |
| 0x1FC | 4 | 서명 3 | `00 00 55 AA` |

- 세 서명이 모두 맞아야 이 섹터를 믿습니다.
- 모든 OS 가 이 섹터를 고치지는 않습니다. 그래서 값이 실제와 다를 수 있습니다.

### FAT 종류 가리기

- FAT 종류는 클러스터 개수로 가립니다. 아래 기준은 Microsoft EFI FAT32 명세의 규칙입니다(Wikipedia 해설의 인용).

| 클러스터 개수 | 종류 |
|---|---|
| 4,085개 미만 | FAT12 |
| 65,525개 미만 | FAT16 |
| 그 이상 | FAT32 |

- 클러스터 개수는 데이터 영역의 섹터 수를 클러스터당 섹터 수로 나눈 몫입니다.
- 0x036·0x052 의 파일 시스템 이름은 보여 주기용입니다. 종류를 가리는 데 쓰면 안 됩니다.

### 클러스터 위치 계산

데이터 영역의 첫 섹터 (SSA) 는 이렇게 구합니다.

```
SSA = 예약 섹터 수 + FAT 개수 × FAT 하나의 섹터 수 + ceil(32 × 루트 디렉터리 항목 수 ÷ 섹터 크기)
클러스터의 첫 섹터 = SSA + (클러스터 번호 − 2) × 클러스터당 섹터 수
```

- 이 식의 섹터 번호는 볼륨 기준입니다. 디스크 전체 이미지에서는 파티션 시작 위치를 더합니다([파티션 구조](mbr-gpt.md)).

### FAT 표 값

FAT 표에는 클러스터마다 항목이 하나 있습니다. 항목 값은 그 클러스터 다음에 올 클러스터를 가리킵니다.

| 값 (FAT32 표기) | 뜻 |
|---|---|
| 0 | 빈 클러스터 |
| 1 | 예약 |
| 2 ~ 0x?FFFFFEF | 다음 클러스터 번호 |
| 0x?FFFFFF7 | 불량 클러스터. FAT12 는 0xFF7, FAT16 은 0xFFF7 입니다. |
| 0x?FFFFFF8 ~ 0x?FFFFFFF | 파일의 마지막 클러스터 (EOC) |

- FAT32 의 클러스터 번호는 28비트만 씁니다. 위 4비트는 예약이라 표에서 `?` 로 적었습니다.
- 클러스터 0 항목에는 FAT ID 가 있습니다. 매체 설명자 (0x015) 와 같은 값입니다.
- 클러스터 1 항목에는 끝 표시 값이 있습니다.
- DOS 7.1 부터는 클러스터 1 항목의 비트 15 (FAT16) 나 비트 27 (FAT32) 이 꺼져 있으면 제대로 마운트 해제되지 않은 볼륨입니다.
- 같은 항목의 비트 14 (FAT16) 나 비트 26 (FAT32) 이 꺼져 있으면 입출력 오류가 있었던 볼륨입니다.
- 모든 OS 가 이 두 표시를 지원하지는 않습니다.

### 디렉터리 항목 (32바이트)

| 오프셋 | 크기 | 필드 | 설명 |
|---|---|---|---|
| 0x00 | 8 | 짧은 이름 | 첫 바이트는 항목 상태도 나타냅니다(아래). |
| 0x08 | 3 | 확장자 | |
| 0x0B | 1 | 속성 | 아래 표 |
| 0x0C | 1 | 대소문자 정보 | Windows NT 이후가 비트 3·4 에 적습니다. |
| 0x0D | 1 | 만든 시각의 10 ms 단위 값 | 0~199 |
| 0x0E | 2 | 만든 시각 | |
| 0x10 | 2 | 만든 날짜 | |
| 0x12 | 2 | 마지막 접근 날짜 | 날짜만 있습니다. |
| 0x14 | 2 | 첫 클러스터 번호의 위 2바이트 | FAT32 |
| 0x16 | 2 | 수정 시각 | |
| 0x18 | 2 | 수정 날짜 | |
| 0x1A | 2 | 첫 클러스터 번호 | FAT12/16 은 전체 번호, FAT32 는 아래 2바이트 |
| 0x1C | 4 | 파일 크기 | 디렉터리는 0 입니다. |

- FAT32 의 첫 클러스터 번호는 0x14 의 2바이트를 위에, 0x1A 의 2바이트를 아래에 놓아 만듭니다.

첫 바이트에는 특별한 값이 있습니다.

| 첫 바이트 | 뜻 |
|---|---|
| 0x00 | 빈 항목이고, 뒤에도 쓰는 항목이 없습니다 (디렉터리 끝). |
| 0xE5 | 지운 항목 (또는 빈 항목) 입니다. |
| 0x05 | 이름의 첫 글자가 실제로는 0xE5 입니다. |
| 0x2E | "." 또는 ".." 항목입니다. |

| 속성 비트 | 뜻 |
|---|---|
| 0x01 | 읽기 전용 |
| 0x02 | 숨김 |
| 0x04 | 시스템 |
| 0x08 | 볼륨 레이블 |
| 0x10 | 디렉터리 |
| 0x20 | 보관 (archive) |

- 0x0F (읽기 전용 + 숨김 + 시스템 + 볼륨 레이블) 조합은 긴 파일 이름 항목을 뜻합니다.

### 날짜·시각 형식

| 값 | 비트 | 내용 |
|---|---|---|
| 시각 (2바이트) | 15~11 | 시 |
| | 10~5 | 분 |
| | 4~0 | 초 ÷ 2 |
| 날짜 (2바이트) | 15~9 | 연도 (0 = 1980년) |
| | 8~5 | 월 |
| | 4~0 | 일 |

- 초는 2초 단위입니다.
- 만든 시각만 0x0D 의 값으로 10 ms 단위까지 더 나타냅니다.
- 마지막 접근은 날짜만 있고 시각이 없습니다.
- 디렉터리 항목에는 시간대를 적는 칸이 없습니다. 적힌 값이 UTC 인지 현지 시각인지는 이 페이지의 참고 자료로 확인하지 못했습니다.

### 긴 파일 이름 (VFAT LFN)

- 긴 파일 이름 (LFN, Long File Name) 항목은 짧은 이름 항목 바로 앞에 붙습니다.
- 항목 하나에 UCS-2 글자 13개가 들어갑니다.
- 항목을 최대 20개 이어 255글자까지 씁니다.
- 이름의 끝 부분 항목이 먼저 나오고, 순번은 줄어드는 순서입니다.

| 오프셋 | 크기 | 필드 | 설명 |
|---|---|---|---|
| 0x00 | 1 | 순번 | 비트 6 (0x40) 이 켜진 항목이 마지막 조각입니다. |
| 0x01 | 10 | 글자 5개 | |
| 0x0B | 1 | 속성 | 늘 0x0F |
| 0x0C | 1 | 종류 | 0 |
| 0x0D | 1 | 짧은 이름 체크섬 | |
| 0x0E | 12 | 글자 6개 | |
| 0x1A | 2 | 첫 클러스터 | 늘 0 |
| 0x1C | 4 | 글자 2개 | |

- 글자 인코딩은 [문자 인코딩](../value-decoding/utf-16le-utf-8-cp949.md)을 봅니다.

### exFAT

이 페이지의 참고 자료로 확인한 exFAT 사실은 아래까지입니다.

- 부트 섹터 0x003 의 OEM 이름은 "EXFAT␠␠␠" 입니다.
- exFAT 의 BPB 는 섹터 오프셋 0x040~0x077 에 있습니다.
- 0x00B~0x03F 는 보통 0 입니다. 그래서 FAT 의 BPB 표로 exFAT 부트 섹터를 읽으면 안 됩니다.
- exFAT 는 FAT 표를 훑는 대신 빈 공간 비트맵으로 빈 클러스터를 찾습니다.
- MBR 파티션 종류 값은 NTFS 와 같은 0x07 입니다([파티션 구조](mbr-gpt.md)).
- exFAT 의 디렉터리 항목 구조와 시각 칸은 이 페이지에서 다루지 않습니다. exFAT 에서 지운 파일을 찾는 방법은 [삭제 데이터 복구](../../03-techniques/analysis/data-recovery/index.md)에서 다룹니다.

## 읽는 법

### 디렉터리 항목 하나 풀기

> 아래 바이트는 명세(Wikipedia 의 FAT 해설)대로 만든 예시입니다. 실제 검체에서 뽑은 값이 아닙니다.

```
오프셋    00 01 02 03 04 05 06 07  08 09 0A 0B 0C 0D 0E 0F
00000000  52 45 50 4F 52 54 20 20  44 4F 43 20 00 64 CA 73   REPORT  DOC .d.s
00000010  2F 5D 34 5D 01 00 A4 85  2F 5D 45 23 00 CE 00 00   /]4]..../]E#....
```

| 오프셋 | 바이트 | 값 | 뜻 |
|---|---|---|---|
| 0x00 | `52 45 50 4F 52 54 20 20` | "REPORT␠␠" | 짧은 이름입니다. 남는 자리는 공백입니다. |
| 0x08 | `44 4F 43` | "DOC" | 확장자입니다. 짧은 이름은 REPORT.DOC 입니다. |
| 0x0B | `20` | 0x20 | 보관 속성입니다. |
| 0x0C | `00` | 0 | 대소문자 정보가 없습니다. |
| 0x0D | `64` | 100 | 만든 시각에 100 × 10 ms = 1.00초를 더합니다. |
| 0x0E | `CA 73` | 0x73CA | 14:30:20 입니다. 0x0D 를 더하면 만든 시각은 14:30:21.00 입니다. |
| 0x10 | `2F 5D` | 0x5D2F | 만든 날짜 2026-09-15 입니다. |
| 0x12 | `34 5D` | 0x5D34 | 마지막 접근 날짜 2026-09-20 입니다. 시각은 없습니다. |
| 0x14 | `01 00` | 0x0001 | 첫 클러스터 번호의 위 2바이트입니다. |
| 0x16 | `A4 85` | 0x85A4 | 수정 시각 16:45:08 입니다. |
| 0x18 | `2F 5D` | 0x5D2F | 수정 날짜 2026-09-15 입니다. |
| 0x1A | `45 23` | 0x2345 | 첫 클러스터 번호의 아래 2바이트입니다. |
| 0x1C | `00 CE 00 00` | 52,736 | 파일 크기 (바이트) 입니다. |

값을 비트로 나누면 이렇습니다.

- 수정 시각 0x85A4 는 2진수로 `10000 101101 00100` 입니다. 앞 5비트 16 이 시, 가운데 6비트 45 가 분입니다. 뒤 5비트 4 에 2 를 곱한 8 이 초입니다.
- 만든 날짜 0x5D2F 는 2진수로 `0101110 1001 01111` 입니다. 앞 7비트 46 에 1980 을 더한 2026 이 연도입니다. 가운데 4비트 9 가 월, 뒤 5비트 15 가 일입니다.
- 첫 클러스터 번호는 0x0001 을 위에, 0x2345 를 아래에 놓은 0x00012345, 곧 74,565 입니다.

### 클러스터 위치 구하기

같은 예시 볼륨의 BPB 값을 아래처럼 둡니다(명세로 만든 예시 값).

| 필드 | 값 |
|---|---|
| 섹터당 바이트 수 (0x00B) | 512 |
| 클러스터당 섹터 수 (0x00D) | 8 |
| 예약 섹터 수 (0x00E) | 32 |
| FAT 개수 (0x010) | 2 |
| 루트 디렉터리 항목 수 (0x011) | 0 (FAT32) |
| FAT 하나의 섹터 수 (0x024) | 15,360 |

1. SSA = 32 + 2 × 15,360 + 0 = 30,752 입니다.
2. 클러스터 74,565 의 첫 섹터 = 30,752 + (74,565 − 2) × 8 = 627,256 입니다.
3. 볼륨 안 오프셋은 627,256 × 512 = 321,155,072 (0x13247000) 입니다.
4. 디스크 전체 이미지라면 파티션 시작 바이트를 더합니다.
5. 다음 클러스터는 FAT 표에서 찾습니다. FAT32 항목은 4바이트이므로 클러스터 74,565 의 항목은 첫 FAT 시작에서 74,565 × 4 = 298,260바이트 뒤에 있습니다.
6. 첫 FAT 는 예약 섹터 32개 뒤, 곧 볼륨 안 16,384바이트에서 시작합니다. 그래서 그 항목은 볼륨 안 314,644바이트에 있습니다.
7. 항목 값에서 위 4비트를 지우고 읽습니다. 끝 표시 (0x?FFFFFF8 이상) 가 나올 때까지 사슬을 따라갑니다.
8. 클러스터 하나는 512 × 8 = 4,096바이트입니다. 파일 크기 52,736바이트는 클러스터 13개를 씁니다. 사슬에 클러스터가 13개인지 맞춰 봅니다.

### 지운 항목 알아보기

- 위 항목을 지우면 첫 바이트가 0xE5 로 바뀌어 `E5 45 50 4F 52 54 20 20` 이 됩니다.
- 원래 첫 글자 "R" 은 항목에서 사라집니다. 되살리는 도구는 이 글자를 다른 글자로 바꿔 넣어야 합니다.
- 나머지 칸(시각·첫 클러스터·크기)은 다른 항목이 이 자리를 다시 쓰기 전까지 남아 있을 수 있습니다.

## 포렌식에서 중요한 점

### 지운 파일

- 파일을 지우면 디렉터리 항목 첫 바이트가 0xE5 로 바뀝니다.
- Wikipedia 해설에 따르면 DOS 5.0 이후는 안 쓴 항목을 다 쓴 다음에야 지운 항목의 자리를 다시 씁니다.
- DOS 3.0 이후는 지운 파일의 공간을 바로 다시 쓰지 않고, 안 쓴 공간부터 찾습니다.
- 위 세 동작이 Windows 에서도 같은지는 이 페이지의 참고 자료로 확인하지 못했습니다.
- 지운 파일의 클러스터 사슬을 따라가다 0 이 나오면 끝 표시처럼 다룹니다(Wikipedia 해설).
- 되살리는 절차는 [삭제 데이터 복구](../../03-techniques/analysis/data-recovery/index.md)에서 다룹니다.

### 긴 이름 항목의 흔적

- 지운 긴 이름 항목도 순번 자리가 0xE5 입니다.
- 긴 이름 항목의 체크섬이 바로 뒤 짧은 이름과 맞지 않을 수 있습니다. 파일을 지운 뒤 같은 자리에 DOS 로 새 파일을 만든 흔적일 수 있습니다.
- 이때 긴 이름은 예전 파일의 것이고, 짧은 이름 항목은 새 파일의 것일 수 있습니다. 두 이름을 한 파일로 묶어 보고하지 않습니다.

### 비정상 종료와 입출력 오류 표시

- 부트 섹터의 예약 바이트 (FAT12/16 은 0x025, FAT32 는 0x041) 비트 0 은 "제대로 마운트 해제되지 않음" 입니다. Windows NT 가 씁니다.
- 같은 바이트의 비트 1 은 "디스크 입출력 오류가 있었음" 입니다.
- FAT 표 클러스터 1 항목의 비트 15 (FAT16) 와 비트 27 (FAT32) 도 마운트 해제 상태를 나타냅니다. DOS 7.1 부터 쓰고, 모든 OS 가 지원하지는 않습니다.
- 이 표시로 볼륨을 안전하게 떼지 않은 채 뽑았을 가능성을 봅니다. 다만 표시를 지원하지 않는 OS 도 있으므로 표시가 없다는 사실만으로 정상 해제였다고 쓰지 않습니다.

### FS 정보 섹터와 두 FAT 사본

- FS 정보 섹터의 빈 클러스터 수와 마지막 할당 클러스터는 모든 OS 가 고치지 않습니다. 실제 FAT 표로 다시 셉니다.
- 두 FAT 사본이 다르면 둘 다 기록합니다. 보고서에는 어느 사본으로 해석했는지 밝힙니다.
- FAT32 미러링 플래그 (0x028) 의 비트 7 이 켜져 있으면 FAT 하나만 씁니다. 이때 다른 사본에는 예전 값이 남아 있을 수 있습니다.

### 시각

- 수정 시각은 2초 단위입니다. 만든 시각은 10 ms 단위까지 있습니다.
- 마지막 접근은 날짜만 있습니다. 같은 날 안의 순서는 이 값으로 알 수 없습니다.
- 시간대를 적는 칸이 없습니다. 다른 볼륨의 시각과 한 타임라인에 놓을 때는 [시간대 설정](../../02-artifacts/system-account/time-zone.md)과 [타임라인 작성](../../03-techniques/analysis/timeline/index.md)의 방법으로 기준을 맞춥니다.

### 볼륨 일련번호와 레이블

- 볼륨 일련번호는 FAT12/16 은 0x027, FAT32 는 0x043 의 4바이트입니다.
- 볼륨 레이블은 부트 섹터 칸 (0x02B 또는 0x047) 과, 속성이 0x08 인 디렉터리 항목 두 곳에 나옵니다.
- 일련번호는 부트 섹터 안의 바이트라 고칠 수 있습니다. 일련번호가 같다는 사실만으로 같은 볼륨이라고 쓰지 않습니다.

## 함정

1. **0x036·0x052 의 이름으로 FAT 종류를 정합니다.** 보여 주기용 값입니다. 클러스터 개수로 가립니다.
2. **FAT32 첫 클러스터를 0x1A 의 2바이트만으로 읽습니다.** 0x14 의 위 2바이트를 합쳐야 합니다.
3. **FAT32 항목의 위 4비트를 지우지 않습니다.** 예약 비트가 켜져 있으면 클러스터 번호가 틀립니다.
4. **마지막 접근 날짜에 시각을 붙여 적습니다.** 날짜만 있는 값입니다. 도구가 00:00:00 을 붙여 보여 줘도 그 시각에 접근했다는 뜻이 아닙니다.
5. **수정 시각이 짝수 초라는 점을 조작 흔적으로 봅니다.** 형식이 2초 단위라서 생기는 값입니다.
6. **첫 바이트 0x05 를 지운 항목으로 읽습니다.** 첫 글자가 0xE5 인 이름을 적는 방법입니다.
7. **FS 정보 섹터의 빈 클러스터 수를 그대로 씁니다.** 고치지 않는 OS 가 있습니다.
8. **FAT 시각을 UTC 로 가정합니다.** 시간대 칸이 없습니다. 기준을 따로 확인합니다.
9. **exFAT 부트 섹터를 FAT 의 BPB 표로 읽습니다.** exFAT 의 BPB 는 0x040 뒤에 있고 0x00B~0x03F 는 보통 0 입니다.
10. **긴 이름 항목을 나온 순서대로 이어 붙입니다.** 이름의 끝 부분이 먼저 나옵니다. 순번을 거꾸로 따라 이어 붙입니다.

## 도구

- 헥스 편집기로 위 순서를 직접 따라갈 수 있습니다. 부트 섹터의 `55 AA` 와 0x003 의 OEM 이름에서 시작합니다.
- 파일시스템을 읽는 공개 도구의 결과 가운데 몇 항목을 골라 헥스로 맞춰 봅니다. 특히 지운 항목의 첫 글자와 FAT32 첫 클러스터 번호를 확인합니다.
- 두 도구의 결과가 다르면 [도구 결과 교차 검증](../../03-techniques/reporting/tool-validation.md)의 방법을 씁니다.
