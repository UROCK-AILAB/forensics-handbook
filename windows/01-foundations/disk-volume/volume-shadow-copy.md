# 볼륨 섀도 복사본 구조 (Volume Shadow Copy)

볼륨 섀도 복사본 (Volume Shadow Copy) 은 볼륨의 한 시점 스냅숏 (Snapshot) 입니다. Windows Vista 부터 VSS 는 영구 섀도 복사본을 같은 NTFS 볼륨 안에 저장합니다. 저장소에는 볼륨 블록의 예전 내용이 16 KiB 단위로 들어 있고, 이 블록을 지금 볼륨 위에 차례로 덮으면 예전 시점의 볼륨을 다시 만들 수 있습니다.

## 이 형식을 쓰는 아티팩트

섀도 복사본은 사용자 행동을 따로 기록하지 않습니다. 볼륨의 예전 모습을 담습니다. 그래서 볼륨 위에 있는 거의 모든 아티팩트의 예전 판을 여기서 찾을 수 있습니다.

| 쓰는 곳 | 섀도 복사본에서 찾는 것 |
|---|---|
| [섀도 복사본 활용](../../03-techniques/analysis/volume-shadow-copy-analysis.md) | 섀도 복사본을 찾아 붙이고 지금 볼륨과 비교하는 절차 |
| [레지스트리 하이브 구조](../database-log-formats/registry-hive/index.md) | 예전 시점의 하이브 파일 |
| [ESE 데이터베이스](../database-log-formats/extensible-storage-engine/index.md) | 예전 시점의 데이터베이스 파일 |
| [마스터 파일 테이블](../../02-artifacts/filesystem/mft.md) | 예전 시점의 MFT 레코드 |

## 구조

### 공급자와 시험 범위

- 이 페이지의 구조는 "Microsoft Software Shadow Copy provider 1.0" (GUID b5946137-7b9f-4925-af80-51abd60b20d5) 공급자의 것입니다.
- 이 공급자는 16 KiB 블록 단위로 저장합니다.
- 여러 볼륨을 같은 순간에 찍은 섀도 복사본은 한 세트 (Set) 로 묶을 수 있습니다.
- 날짜·시각은 UTC 기준 FILETIME 입니다. 형식은 [시각 값 형식](../value-decoding/filetime-unix-webkit-dos-ole.md)에 있습니다.
- 문자열은 BOM 없는 UTF-16LE 입니다.
- 여러 바이트 정수는 리틀 엔디언 (little-endian) 입니다.

| Windows | libvshadow 문서의 시험 | 볼륨 헤더의 판 값 |
|---|---|---|
| Windows 2003 R2 | 시험함 | 볼륨 헤더에서 직접 읽어 확인 |
| Windows Vista | 시험함 | 1 |
| Windows 2008 | 시험함 | 볼륨 헤더에서 직접 읽어 확인 |
| Windows 7 | 시험함 | 1 |
| Windows 8 (Consumer Preview) | 시험함 | 2 |
| Windows 2012, Windows 10 | 아직 시험하지 않음 | 볼륨 헤더에서 직접 읽어 확인 |

- Windows 10 이후 볼륨을 다룰 때는 이 표의 시험 범위 밖이라는 점을 적어 둡니다.

### 파일 위치

VSS 는 GUID 3808876b-c176-4e48-b7ae-04046e6cc752 로 자기 파일을 표시합니다.

| 구성 | 위치 |
|---|---|
| 볼륨 헤더 | 볼륨 시작에서 7,680 (0x1E00) 바이트 |
| 카탈로그 | `System Volume Information\{3808876b-c176-4e48-b7ae-04046e6cc752}` |
| 저장소 (Store) | `System Volume Information\{GUID}{3808876b-c176-4e48-b7ae-04046e6cc752}` |

- 볼륨 헤더 자리는 NTFS 볼륨 헤더 ($Boot) 영역의 일부입니다.
- 저장소 파일 이름의 앞 GUID 는 시각과 MAC 주소로 만든 GUID 입니다. 이 GUID 는 카탈로그 항목의 저장소 GUID 와 같습니다.
- GUID 를 바이트에서 문자열로 바꾸는 법은 [윈도 식별자 형식](../value-decoding/sid-guid-clsid-known-folder-id.md)에 있습니다.

### 볼륨 헤더

| 오프셋 | 크기 | 필드 | 설명 |
|---|---|---|---|
| 0 | 16 | VSS 식별자 GUID | 3808876b-c176-4e48-b7ae-04046e6cc752 |
| 16 | | 판 | 1 = Windows Vista·7, 2 = Windows 8 |
| 20 | | 레코드 종류 | 1 |
| 24 | | 현재 위치 | 0x1E00 |
| 48 | | 카탈로그 위치 | 0 이면 카탈로그가 없습니다. |
| 56 | | 최대 크기 | 0 이면 제한이 없습니다. |
| 64 | 16 | 볼륨 GUID | |
| 80 | 16 | 섀도 복사본 저장 볼륨 GUID | |

- VSS 가 켜져 있어도 스냅숏이 없으면 카탈로그가 없습니다.

### 카탈로그

- 카탈로그는 16,384 (0x4000) 바이트 블록이 이어진 것입니다.
- 블록마다 128바이트 머리 뒤에 128바이트 항목이 줄지어 있습니다.

| 블록 머리 오프셋 | 필드 | 설명 |
|---|---|---|
| 0 | VSS 식별자 GUID | |
| 16 | 판 | 1 |
| 20 | 레코드 종류 | 2 |
| 24 | 위치 | 첫 블록 기준 |
| 32 | 현재 위치 | 볼륨 기준 |
| 40 | 다음 블록 위치 | 마지막 블록이면 0 |

| 항목 종류 | 항목 안의 오프셋과 필드 |
|---|---|
| 0x01 | 안 쓰는 항목 |
| 0x02 | 8 볼륨 크기, 16 저장소 GUID (저장소 파일 이름에 쓰임), 48 섀도 복사본을 만든 시각 (FILETIME) |
| 0x03 | 8 블록 목록 위치, 16 저장소 GUID, 32 저장소 머리 위치, 40 블록 범위 목록 위치, 48 현재 비트맵 위치, 56 NTFS 파일 참조, 72 이전 비트맵 위치 |

- 0x02 항목과 0x03 항목에는 둘 다 저장소 GUID 가 있습니다. 이 값으로 두 항목의 짝을 맞춥니다.
- 0x02 와 0x03 항목은 서로 붙어 있지 않을 수 있습니다.
- 항목은 오래된 순서로 놓이지도 않습니다.
- Windows 2003 R2 의 카탈로그에는 0x03 항목이 없습니다.

### 저장소

저장소에는 볼륨 데이터 블록의 예전 내용이 들어 있습니다. 저장소는 저장소 머리, 블록 목록, 블록 범위 목록, 비트맵, 데이터 블록으로 이뤄집니다.

저장소 안의 블록은 128바이트 머리로 시작합니다. 머리의 레코드 종류로 블록의 쓰임을 구분합니다.

| 레코드 종류 | 블록 |
|---|---|
| 1 | 볼륨 헤더 |
| 2 | 카탈로그 블록 |
| 3 | 블록 목록 |
| 4 | 저장소 머리 |
| 5 | 블록 범위 목록 |
| 6 | 비트맵 |

저장소 머리에는 저장소 정보가 있습니다.

| 저장소 정보 오프셋 | 필드 |
|---|---|
| 16 | 섀도 복사본 ID |
| 32 | 섀도 복사본 세트 ID |
| 48 | 스냅숏 문맥 (Context) |
| 56 | 속성 플래그 |
| 64 부터 | 운영 컴퓨터 이름, 서비스 컴퓨터 이름 (UTF-16) |

| 스냅숏 문맥 값 (예) | 뜻 |
|---|---|
| 0x00 | 백업 |
| 0x09 | 앱 롤백 (영구) |
| 0x0D | 기록기 (Writer) 가 참여한 읽기 전용 |
| 0x1D | 공유 폴더용 읽기 전용 |

| 속성 플래그 (예) | 뜻 |
|---|---|
| 0x01 | 영구. 재부팅 뒤에도 남습니다. |
| 0x04 | 클라이언트가 접근할 수 있음 |
| 0x08 | 자동으로 해제하지 않음 |
| 0x10 | 기록기 없음 |
| 0x20000 | 차등 (쓰기 시 복사) 방식 |

### 블록 목록

블록 목록은 32바이트 블록 설명자 (Block Descriptor) 를 줄지어 적습니다.

| 오프셋 | 크기 | 필드 | 설명 |
|---|---|---|---|
| 0 | 8 | 원래 블록 위치 | 볼륨 기준 |
| 8 | 8 | 저장소 안 상대 위치 | |
| 16 | 8 | 저장소 블록 위치 | 볼륨 기준 |
| 24 | 4 | 플래그 | 아래 표 |
| 28 | 4 | 할당 비트맵 | |

| 플래그 | 뜻 |
|---|---|
| 0x01 | 전달 (Forwarder) |
| 0x02 | 덮어쓰기 조각 (Overlay). 512바이트 단위 비트맵으로 덮을 부분을 구분합니다. |
| 0x04 | 안 씀 |

- 비트맵의 비트 하나는 16 KiB 블록 하나입니다.
- 비트가 켜져 있으면 저장소가 그 블록을 쓰지 않는다는 뜻입니다.

## 읽는 법

### 섀도 복사본이 있는지 보기

1. 볼륨 시작에서 0x1E00 바이트 위치를 엽니다. 디스크 전체 이미지라면 [파티션 구조](mbr-gpt.md)에서 구한 볼륨 시작 위치를 먼저 더합니다.
2. 오프셋 0 의 GUID 가 VSS 식별자 3808876b-c176-4e48-b7ae-04046e6cc752 인지 확인합니다.
3. 판 값으로 Windows 세대를 짐작합니다. 1 은 Vista·7, 2 는 8 입니다.
4. 카탈로그 위치 (48) 를 읽습니다. 0 이면 스냅숏이 없습니다.
5. 카탈로그 블록을 다음 블록 위치 (40) 로 따라가며 항목을 모두 읽습니다.
6. 0x02 항목에서 저장소 GUID, 볼륨 크기, 만든 시각을 적습니다.
7. 0x03 항목에서 같은 저장소 GUID 를 찾아 블록 목록·저장소 머리·비트맵 위치를 적습니다.
8. 만든 시각으로 섀도 복사본을 정렬합니다. 카탈로그 안의 순서를 시간 순서로 쓰지 않습니다.
9. 저장소 머리에서 섀도 복사본 ID, 세트 ID, 문맥, 속성, 컴퓨터 이름을 읽습니다.
10. `System Volume Information` 폴더의 저장소 파일 이름과 저장소 GUID 가 맞는지 봅니다.

### 블록 설명자 하나 풀기

> 아래 바이트는 명세대로 만든 예시입니다. 실제 데이터에서 뽑은 값이 아닙니다.

```
오프셋    00 01 02 03 04 05 06 07  08 09 0A 0B 0C 0D 0E 0F
00000000  00 00 34 12 00 00 00 00  00 80 00 00 00 00 00 00
00000010  00 00 78 56 00 00 00 00  00 00 00 00 00 00 00 00
```

| 오프셋 | 바이트 | 값 | 뜻 |
|---|---|---|---|
| 0 | `00 00 34 12 00 00 00 00` | 0x12340000 | 원래 블록은 볼륨의 0x12340000 에 있습니다. 16 KiB 블록 번호로는 0x48D0 입니다. |
| 8 | `00 80 00 00 00 00 00 00` | 0x8000 | 저장소 안 상대 위치입니다. |
| 16 | `00 00 78 56 00 00 00 00` | 0x56780000 | 예전 내용은 볼륨의 0x56780000 에 있습니다. |
| 24 | `00 00 00 00` | 0 | 표의 어떤 플래그도 켜지지 않았습니다. |
| 28 | `00 00 00 00` | 0 | 할당 비트맵입니다. |

- 이 설명자는 이렇게 읽습니다. "이 스냅숏 시점의 볼륨 0x12340000 부터 16 KiB 는 볼륨 0x56780000 부터 16 KiB 를 읽으면 된다."
- 두 위치가 모두 볼륨 기준이므로, 디스크 이미지에서는 볼륨 시작 바이트를 더합니다.

### 예전 시점 다시 만들기

오래된 스냅숏을 보려면 가장 최근 저장소부터 차례로 지금 볼륨 위에 덮어 갑니다. 저장소가 3개이고 가장 오래된 1번을 보려면 3 → 2 → 1 순서로 덮습니다. 나중에 덮은 저장소의 블록이 앞의 것을 대신합니다.

아래는 이 규칙을 보이려고 만든 예시입니다(명세로 만든 예시, 블록 4개).

| 볼륨 블록 | 저장소 3 (최신) | 저장소 2 | 저장소 1 (가장 오래됨) | 스냅숏 1 시점의 내용 | 스냅숏 3 시점의 내용 |
|---|---|---|---|---|---|
| 0x0000 | — | 설명자 있음 | — | 저장소 2 의 블록 | 지금 볼륨 |
| 0x4000 | 설명자 있음 | 설명자 있음 | — | 저장소 2 의 블록 | 저장소 3 의 블록 |
| 0x8000 | — | — | 설명자 있음 | 저장소 1 의 블록 | 지금 볼륨 |
| 0xC000 | — | — | — | 지금 볼륨 | 지금 볼륨 |

1. 보려는 스냅숏과 그보다 새로운 스냅숏의 저장소를 모두 고릅니다.
2. 가장 새로운 저장소의 블록 목록부터 지금 볼륨 위에 덮습니다.
3. 보려는 스냅숏의 저장소를 마지막으로 덮습니다.
4. 어느 저장소에도 설명자가 없는 블록은 지금 볼륨에서 읽습니다.
5. 다시 만든 볼륨은 섹터 크기의 배수로만 읽습니다.
6. 다시 만든 볼륨을 [NTFS 구조](ntfs/index.md)대로 읽어 예전 판 파일을 꺼냅니다.

## 포렌식에서 중요한 점

### 예전 판을 되찾기

스냅숏 뒤에 덮어쓴 블록의 예전 내용은 저장소에 남으므로, 지금 볼륨에서 바뀌거나 지운 파일도 스냅숏 시점의 모습으로 다시 볼 수 있습니다. 여러 스냅숏을 차례로 다시 만들면 같은 파일이 시점마다 어떻게 바뀌었는지 비교할 수 있습니다. 비교 절차는 [섀도 복사본 활용](../../03-techniques/analysis/volume-shadow-copy-analysis.md)에 있습니다.

### 만든 시각과 순서

- 0x02 항목의 만든 시각은 UTC 기준 FILETIME 입니다.
- 카탈로그 항목은 오래된 순서로 놓이지 않습니다. 시점 순서는 만든 시각으로 정합니다.
- 이 시각으로는 "이 시점의 볼륨 모습이 남아 있다" 는 사실을 알 수 있습니다. 그 시각에 사용자가 무엇을 했는지는 알 수 없습니다.

### 어떤 방식으로 만들었나

- 저장소 정보의 스냅숏 문맥과 속성 플래그는 섀도 복사본의 종류를 알려 줍니다. 백업용인지, 영구인지, 기록기가 참여했는지를 봅니다.
- 저장소 정보에는 운영 컴퓨터 이름과 서비스 컴퓨터 이름이 있습니다. 어느 쪽이 무엇을 뜻하는지 단정할 수 없으므로 둘 다 적습니다.
- 여러 볼륨을 한 세트로 찍었으면 세트 ID 가 같습니다. 같은 세트의 볼륨은 같은 순간의 모습입니다.

### 범위 스냅숏

Windows 8·Server 2012 부터 있는 범위 스냅숏 (Scoped Snapshot) 은 업데이트에 관계된 파일만 쓰기 시 복사를 하므로, 스냅숏 안의 다른 파일 내용이 그 시점의 내용과 다를 수 있습니다.

설정 자리는 `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\SystemRestore` 의 `ScopeSnapshots` 값입니다. 오프라인 이미지에서는 SOFTWARE 하이브에서 읽습니다([레지스트리 하이브 구조](../database-log-formats/registry-hive/index.md)).

### 쓰지 않는 블록과 손상

비트맵에서 저장소가 쓰지 않는 블록을 Windows 가 읽을 때의 결과는 정해져 있지 않습니다. libvshadow 는 이런 블록을 0 으로 채우지만 다른 도구는 다르게 처리할 수 있어서, 같은 스냅숏도 도구마다 결과가 조금 다를 수 있습니다.

카탈로그 항목의 볼륨 크기가 실제 볼륨보다 큰 사례가 있습니다. libvshadow 는 이때 NTFS 볼륨 헤더로 볼륨 크기를 구합니다.

### 섀도 복사본이 없을 때

- 카탈로그 위치가 0 이면 VSS 는 켜져 있지만 스냅숏이 없는 상태입니다.
- 스냅숏이 없다는 사실만으로 누가 지웠다고 쓰지 않습니다. 지운 흔적은 다른 기록으로 확인합니다([증거를 없애려 했나](../../04-scenarios/activity/anti-forensics/index.md)).

## 함정

1. **가장 오래된 저장소 하나만 덮습니다.** 그보다 새로운 저장소를 먼저 차례로 덮어야 그 시점이 맞게 나옵니다.
2. **카탈로그 안의 순서를 시간 순서로 씁니다.** 항목은 오래된 순서로 놓이지 않습니다. 만든 시각으로 정렬합니다.
3. **만든 시각을 현지 시각으로 읽습니다.** UTC 기준 FILETIME 입니다.
4. **범위 스냅숏에서 꺼낸 파일을 그 시점의 내용으로 단정합니다.** 업데이트에 관계된 파일만 쓰기 시 복사를 했을 수 있습니다.
5. **카탈로그의 볼륨 크기를 그대로 씁니다.** 실제보다 큰 사례가 있습니다. NTFS 볼륨 헤더와 맞춰 봅니다.
6. **0 으로 채운 블록을 원래 0 이었다고 봅니다.** 저장소가 쓰지 않는 블록을 도구가 0 으로 채운 것일 수 있습니다.
7. **섹터 크기의 배수가 아닌 크기로 읽습니다.** 섀도 복사본 장치는 섹터 크기의 배수로만 읽을 수 있습니다.
8. **Windows 2003 R2 카탈로그에서 0x03 항목을 찾습니다.** 이 버전에는 없습니다.
9. **저장소 GUID 와 섀도 복사본 ID 를 섞어 적습니다.** 두 값은 다른 필드에 있습니다. 보고서에는 어느 필드의 값인지 밝힙니다.
10. **시험 범위 밖의 Windows 에서 나온 결과를 그대로 믿습니다.** Windows 2012·10 은 libvshadow 문서의 시험 범위 밖입니다. 두 도구로 맞춰 봅니다.

## 도구

- 헥스 편집기로 볼륨 헤더 (0x1E00), 카탈로그, 블록 목록을 직접 따라갈 수 있습니다.
- libyal 의 libvshadow 는 섀도 복사본을 읽는 오픈 소스 라이브러리이고, VSS 형식 문서도 함께 공개합니다. 저장소가 쓰지 않는 블록을 0 으로 채운다는 점을 알고 씁니다.
- 실행 중인 Windows 에서 섀도 복사본을 찾고 붙이는 방법은 [섀도 복사본 활용](../../03-techniques/analysis/volume-shadow-copy-analysis.md)에서 다룹니다. 조사 대상 시스템에서 명령을 실행하면 [라이브 응답](../../03-techniques/process-acquisition/live-response/index.md) 원칙에 따라 기록을 남깁니다.
- 두 도구의 결과가 다르면 [도구 결과 교차 검증](../../03-techniques/reporting/tool-validation.md)의 방법으로 헥스와 맞춰 봅니다.
