# 부트 섹터와 클러스터 (Boot Sector·Cluster)

> 위치: 기반 구조 > 디스크·볼륨 > [NTFS 구조](index.md)

## 한 줄 요약

NTFS 볼륨의 첫 섹터에는 섹터 크기, 클러스터 크기, $MFT 위치, 볼륨 일련번호가 적혀 있습니다. 이 값을 알아야 볼륨 안의 위치를 바이트 오프셋으로 바꿀 수 있습니다.

## 이 형식을 쓰는 아티팩트

부트 섹터 (Boot Sector) 자체는 사용자의 행동을 기록하지 않습니다. 그 대신 NTFS 위의 거의 모든 분석이 이 섹터의 값에서 시작합니다.

| 쓰는 곳 | 부트 섹터에서 가져오는 값 |
|---|---|
| [마스터 파일 테이블 ($MFT)](../../../02-artifacts/filesystem/mft.md) | $MFT 시작 위치, MFT 레코드 크기 |
| [데이터 런](data-run-resident-non-resident.md) | 클러스터 크기 (클러스터 번호를 바이트로 바꿀 때) |
| [폴더 인덱스 ($I30)](../../../02-artifacts/filesystem/i30.md) | 인덱스 레코드 크기 |
| [$Bitmap](bitmap-secure-extend.md) | 클러스터 크기 (할당 표가 클러스터 단위) |
| [LNK](../../../02-artifacts/file-folder-usage/lnk.md)·[프리페치](../../../02-artifacts/execution/prefetch/index.md) | 볼륨 일련번호의 아래 32비트 |
| [비할당 영역과 슬랙](../../../03-techniques/analysis/data-recovery/unallocated-slack-space.md) | 클러스터 크기 (파일 끝 뒤에 남는 공간의 크기) |

## 구조

### 섹터와 클러스터

섹터 (Sector)는 디스크가 한 번에 읽고 쓰는 가장 작은 단위이고, 크기는 흔히 512바이트나 4,096바이트입니다. 클러스터 (Cluster)는 NTFS 가 파일에 공간을 나눠 주는 가장 작은 단위이며, 섹터 여러 개를 묶은 것입니다.

논리 클러스터 번호 (LCN, Logical Cluster Number)는 볼륨의 첫 클러스터를 0 으로 센 번호이고, 가상 클러스터 번호 (VCN, Virtual Cluster Number)는 파일 안에서 첫 클러스터를 0 으로 센 번호입니다. 파일의 VCN 을 볼륨의 LCN 으로 잇는 일은 [데이터 런](data-run-resident-non-resident.md)이 맡습니다. 클러스터 0 은 볼륨의 첫 바이트에서 시작하므로 볼륨 안 바이트 오프셋은 "LCN × 클러스터 크기" 입니다.

클러스터 크기의 범위는 다음과 같습니다.

| 항목 | Windows 버전 | 값 |
|---|---|---|
| 기본값 | (버전 구분 없음) | 4 KB |
| 최솟값 | 공통 | 512바이트 |
| 최댓값 | Windows 10 1703 이하, Windows Server 2016 이하 | 64 KB |
| 최댓값 | Windows 10 1709 이상, Windows Server 2019 이상 | 2 MB |

Windows 10 1903 에서 128 KB~2 MB 클러스터를 쓰려면 파티션이 클러스터 크기에 맞춰 정렬돼 있어야 합니다. NTFS 압축은 클러스터가 4 KB 이하인 볼륨에서만 되며, 자세한 내용은 [압축·희소 파일](compressed-sparse.md)에 있습니다.

### 부트 영역과 백업

부트 섹터는 볼륨의 첫 섹터이고, MFT 레코드 7번인 `$Boot` 가 이 영역을 파일처럼 가리킵니다. `$Boot` 의 데이터는 클러스터 0 에 있으며 이 파일은 다른 곳으로 옮길 수 없습니다. 포맷할 때 첫 16섹터를 부트 섹터와 부트 코드 몫으로 잡습니다.

볼륨 끝에는 주 부트 섹터와 거의 같은 사본인 백업 부트 섹터 (Backup Boot Sector)가 있습니다. 볼륨 크기(총 섹터 수)에는 백업 부트 섹터가 들어가지 않습니다.

| 항목 | Windows 버전 | 위치 |
|---|---|---|
| 백업 부트 섹터 | Windows NT 3.51 | 볼륨의 논리적 가운데 |
| 백업 부트 섹터 | 그 뒤 버전 | 볼륨 끝 |

백업은 볼륨의 마지막 클러스터 다음 클러스터의 마지막 섹터에 있습니다. 흔히 볼륨 마지막 섹터 바로 다음 섹터지만, 언제나 그렇지는 않습니다.

### 필드 표

오프셋은 부트 섹터 첫 바이트 기준입니다. 여러 바이트 숫자는 작은 쪽 바이트가 앞에 오는 순서(리틀 엔디언, little-endian)로 저장됩니다.

| 오프셋 | 크기 | 필드 | 설명 |
|---|---|---|---|
| 0x00 | 3 | 점프 명령 | 부트 코드로 건너뛰는 x86 명령입니다. 흔히 `EB 52 90` 입니다. |
| 0x03 | 8 | OEM ID | `NTFS` 뒤에 공백 4칸이 붙은 `4E 54 46 53 20 20 20 20` 입니다. |
| 0x0B | 2 | 섹터당 바이트 | 섹터 크기입니다. |
| 0x0D | 1 | 클러스터당 섹터 | 아래 "크기 값 읽기" 를 봅니다. |
| 0x0E | 2 | 예약 섹터 | 0 입니다. |
| 0x10 | 3 | (FAT 용 칸) | 늘 0 입니다. |
| 0x13 | 2 | (NTFS 가 안 씀) | |
| 0x15 | 1 | 미디어 설명자 | 하드 디스크는 `F8` 입니다. |
| 0x16 | 2 | (FAT 용 칸) | 늘 0 입니다. |
| 0x18 | 2 | 트랙당 섹터 | 옛 디스크 구조 값입니다. 해석에 쓰지 않습니다. |
| 0x1A | 2 | 헤드 수 | 옛 디스크 구조 값입니다. 해석에 쓰지 않습니다. |
| 0x1C | 4 | 숨은 섹터 | 볼륨 앞의 섹터 수를 적는 칸이지만, NTFS 는 이 값을 쓰지 않습니다. |
| 0x20 | 4 | (NTFS 가 안 씀) | |
| 0x24 | 4 | (NTFS 가 안 씀) | |
| 0x28 | 8 | 총 섹터 수 | 볼륨의 섹터 수입니다. |
| 0x30 | 8 | $MFT 시작 LCN | $MFT 의 첫 클러스터 번호입니다. |
| 0x38 | 8 | $MFTMirr 시작 LCN | $MFT 앞 레코드 4개의 사본이 있는 곳입니다. |
| 0x40 | 1 | MFT 레코드 크기 | 뒤 3바이트는 쓰지 않습니다. |
| 0x44 | 1 | 인덱스 레코드 크기 | 뒤 3바이트는 쓰지 않습니다. |
| 0x48 | 8 | 볼륨 일련번호 | 64비트 값입니다. |
| 0x50 | 4 | 체크섬 | 쓰지 않습니다. |
| 0x54 | 426 | 부트 코드 | 운영체제를 시작하는 코드입니다. |
| 0x1FE | 2 | 끝 표시 | `55 AA` 입니다. |

Microsoft 문서는 0x40 과 0x44 를 4바이트 칸으로 적지만, libyal 명세는 첫 1바이트만 값으로 읽고 나머지 3바이트를 쓰지 않는 칸으로 적습니다.

### 크기 값 읽기

세 필드는 작은 값과 큰 값을 적는 방식이 다릅니다.

| 필드 | 값의 범위 | 뜻 | 예 |
|---|---|---|---|
| 클러스터당 섹터 (0x0D) | 0x01~0x80 | 그대로 섹터 수 | `08` → 8섹터 |
| 클러스터당 섹터 (0x0D) | 0xF4~0xFF | 2^(256 − 값) 섹터 | `F4` → 2^12 = 4,096섹터 |
| MFT 레코드·인덱스 레코드 크기 | 0x00~0x7F | 클러스터 수 | `01` → 1클러스터 |
| MFT 레코드·인덱스 레코드 크기 | 0x80~0xFF | 2^(256 − 값) 바이트 | `F6` → 2^10 = 1,024바이트 |

2^(256 − 값) 은 그 바이트를 부호 있는 1바이트로 읽은 음수 n 으로 2^(−n) 을 계산한 것과 같습니다. 클러스터당 섹터의 0x80 은 음수가 아니라 128섹터입니다. 512바이트 섹터에서 2 MB 클러스터는 4,096섹터인데, 1바이트에 4,096 을 넣을 수 없어서 `F4` 로 적습니다.

MFT 레코드는 흔히 1,024바이트입니다. 인덱스 레코드 크기도 짐작하지 말고 0x44 에서 읽습니다.

## 읽는 법

> 아래 바이트는 명세(libyal·Microsoft 문서)대로 만든 예시입니다. 실제 검체에서 뽑은 값이 아닙니다.

```
오프셋    00 01 02 03 04 05 06 07  08 09 0A 0B 0C 0D 0E 0F
00000000  EB 52 90 4E 54 46 53 20  20 20 20 00 02 08 00 00   .R.NTFS    .....
00000010  00 00 00 00 00 F8 00 00  3F 00 FF 00 00 08 00 00   ........?.......
00000020  00 00 00 00 80 00 80 00  FF FF 7F 0C 00 00 00 00   ................
00000030  00 00 0C 00 00 00 00 00  02 00 00 00 00 00 00 00   ................
00000040  F6 00 00 00 01 00 00 00  1A 2B 3C 4D 5E 6F 70 81   .........+<M^op.
00000050  00 00 00 00 (0x54 부터 부트 코드)
  ...
000001F0                                             55 AA
```

| 필드 | 바이트 | 값 | 뜻 |
|---|---|---|---|
| 섹터당 바이트 | `00 02` | 512 | 섹터 하나가 512바이트입니다. |
| 클러스터당 섹터 | `08` | 8 | 클러스터 하나가 512 × 8 = 4,096바이트입니다. |
| 숨은 섹터 | `00 08 00 00` | 2,048 | 파티션 표의 시작 위치와 맞춰 봅니다. |
| 총 섹터 수 | `FF FF 7F 0C 00 00 00 00` | 209,715,199 | 볼륨 크기는 107,374,181,888바이트입니다. |
| $MFT 시작 LCN | `00 00 0C 00 00 00 00 00` | 786,432 | 볼륨 안 오프셋은 786,432 × 4,096 = 3,221,225,472 (0xC0000000)입니다. |
| $MFTMirr 시작 LCN | `02 00 00 00 00 00 00 00` | 2 | 볼륨 안 오프셋은 8,192 (0x2000)입니다. |
| MFT 레코드 크기 | `F6` | −10 | 2^10 = 1,024바이트입니다. |
| 인덱스 레코드 크기 | `01` | 1 | 1클러스터 = 4,096바이트입니다. |
| 볼륨 일련번호 | `1A 2B 3C 4D 5E 6F 70 81` | 0x81706F5E4D3C2B1A | 아래 32비트는 0x4D3C2B1A 입니다. |

순서는 이렇습니다.

1. 디스크 전체 이미지라면 파티션 시작 위치를 [파티션 표](../mbr-gpt.md)에서 구합니다. 이 예시에서는 2,048섹터, 곧 1,048,576바이트로 둡니다.
2. 그 위치의 섹터에서 오프셋 0x03 의 `NTFS    ` 와 오프셋 0x1FE 의 `55 AA` 를 확인합니다.
3. 섹터당 바이트와 클러스터당 섹터로 클러스터 크기를 구합니다.
4. 이미지 안 절대 오프셋은 "파티션 시작 바이트 + LCN × 클러스터 크기" 입니다. 이 예시의 $MFT 는 1,048,576 + 3,221,225,472 = 3,222,274,048바이트에 있습니다.
5. 그 자리에서 MFT 레코드 서명 `FILE` 을 확인합니다. 레코드 구조는 [MFT 레코드와 속성](file-record-attribute.md)에 있습니다.
6. 백업 부트 섹터를 찾습니다. 이 예시에서는 볼륨 기준 209,715,199번 섹터(총 섹터 수와 같은 번호)입니다. 볼륨 안 오프셋은 209,715,199 × 512 = 107,374,181,888바이트입니다.
7. 주 부트 섹터와 백업의 필드 값을 비교합니다.

## 포렌식에서 중요한 점

### 지운 볼륨·잃어버린 볼륨 찾기

파티션 표가 지워져도 부트 섹터가 남아 있으면 볼륨을 다시 찾을 수 있습니다. 섹터 경계마다 오프셋 0x03 의 `NTFS    ` 와 오프셋 0x1FE 의 `55 AA` 를 함께 찾고, 찾은 부트 섹터의 총 섹터 수로 볼륨이 어디서 끝나는지 알 수 있습니다.

앞쪽 부트 섹터가 덮어써졌으면 볼륨 끝의 백업 부트 섹터를 찾습니다. 백업 위치에서 "총 섹터 수 × 섹터 크기" 를 빼면 볼륨 시작 위치를 거꾸로 짐작할 수 있는데, 백업 위치가 늘 같지는 않으므로 짐작한 자리의 부트 섹터나 `FILE` 서명으로 확인합니다. 복구 절차 전체는 [파일시스템 기반 복구](../../../03-techniques/analysis/data-recovery/undelete-ntfs-fat.md)에 있습니다.

### 주 부트 섹터와 백업이 다를 때

두 섹터의 필드 값이 다르면 손상이나 수정을 의심하고, 두 값을 모두 기록합니다. 보고서에는 어느 쪽 값으로 해석했는지 밝힙니다.

$MFT 앞부분이 망가졌을 때는 $MFTMirr 에 있는 앞 레코드 4개의 사본으로 $MFT 자신의 위치를 다시 구할 수 있습니다.

### 볼륨 일련번호로 볼륨 잇기

부트 섹터의 볼륨 일련번호 (Volume Serial Number)는 8바이트입니다. Windows API 가 돌려주는 일련번호는 이 값의 아래 32비트이고, `vol`·`dir` 명령이 보여 주는 `XXXX-XXXX` 도 이 32비트 값이어서 예시 값이면 `4D3C-2B1A` 로 보입니다. [LNK](../../../02-artifacts/file-folder-usage/lnk.md)와 [프리페치](../../../02-artifacts/execution/prefetch/index.md)에 남는 볼륨 일련번호도 이 32비트 값입니다.

그래서 LNK 대상 파일이 어느 볼륨에 있었는지를 부트 섹터 값과 맞춰 볼 수 있습니다. 외부 저장장치 조사에서도 같은 방식으로 씁니다([USB 저장장치 흔적](../../../02-artifacts/external-devices/usb-storage-artifacts/index.md)).
일련번호는 포맷할 때 정해지며, 다시 포맷한 볼륨은 값이 달라집니다. 또 부트 섹터 안의 바이트 몇 개일 뿐이라 고칠 수 있습니다. 일련번호가 같다는 사실만으로 같은 볼륨이라고 쓰지 않습니다. 볼륨 크기, 볼륨 이름 같은 다른 값과 함께 봅니다.

### 볼륨 뒤에 남는 공간

파티션 크기와 "볼륨 크기 + 백업 부트 섹터" 를 비교합니다. 파티션이 더 크면 그 차이는 NTFS 가 관리하지 않는 공간이고, 파일 목록에 나타나지 않으므로 이미지에서 바이트를 직접 봐야 합니다.

### 클러스터와 슬랙

파일은 클러스터 단위로 공간을 받고, 마지막 클러스터에서 파일 끝 뒤에 남는 부분이 파일 슬랙 (File Slack)입니다. 클러스터가 클수록 파일 하나에 생길 수 있는 슬랙도 커집니다. MFT 레코드 안에 바로 들어가는 작은 파일(상주 데이터)은 클러스터를 받지 않아서 클러스터 슬랙이 없습니다. 슬랙을 다루는 방법은 [비할당 영역과 슬랙](../../../03-techniques/analysis/data-recovery/unallocated-slack-space.md)에 있습니다.

### 부트 코드

오프셋 0x54 뒤의 부트 코드와 이어지는 부트 영역은 운영체제 시작에 쓰입니다. 부팅 과정을 노리는 악성코드를 조사할 때는 이 영역을 같은 Windows 버전의 정상 부트 영역과 비교합니다.

## 함정

1. **섹터를 512바이트로 가정합니다.** 4,096바이트 섹터 디스크의 이미지라면 계산이 모두 틀어집니다. 섹터당 바이트(0x0B)를 먼저 읽습니다.
2. **LCN 에 파티션 시작 위치를 빼먹습니다.** LCN 은 볼륨 기준입니다. 디스크 전체 이미지에서는 파티션 시작 바이트를 더해야 합니다. 볼륨만 뜬 이미지에서는 더하지 않습니다.
3. **숨은 섹터(0x1C)를 파티션 시작으로 믿습니다.** NTFS 는 이 값을 쓰지 않습니다. 파티션 시작은 파티션 표에서 구합니다.
4. **크기 필드를 부호 없는 숫자로 읽습니다.** `F6` 을 246클러스터로 읽으면 MFT 레코드 크기가 틀립니다. 512바이트 섹터에서 64 KB 보다 큰 클러스터는 0x0D 도 2의 거듭제곱 방식으로 적힙니다.
5. **일련번호의 바이트 순서를 뒤집지 않습니다.** 0x48~0x4B 의 4바이트를 리틀 엔디언으로 읽어야 LNK·프리페치의 32비트 값과 맞습니다.
6. **백업 부트 섹터가 늘 파티션 마지막 섹터라고 가정합니다.** 흔히 그렇지만 언제나 그렇지는 않습니다. 총 섹터 수로 위치를 구하고 서명을 확인합니다.
7. **NTFS 서명만 찾습니다.** BitLocker 로 암호화된 볼륨은 오프셋 0x03 에 `-FVE-FS-` 가 있습니다. FAT32 위의 BitLocker To Go 볼륨은 `MSWIN4.1` 을 씁니다. 이런 볼륨은 [BitLocker 볼륨 구조와 풀기](../../../03-techniques/analysis/encrypted-evidence/bitlocker.md)를 봅니다.

## 도구

- 헥스 편집기로 위 순서를 직접 따라갈 수 있습니다.
- The Sleuth Kit 같은 공개 도구는 파티션 시작 위치(`mmls`)와 부트 섹터 값 요약(`fsstat`)을 보여 줍니다. `$Boot` 는 MFT 레코드 7번이므로 레코드 번호로 뽑을 수 있습니다.
- 실행 중인 Windows 에서는 `fsutil fsinfo ntfsinfo` 가 일련번호, 섹터 수, 클러스터 수를 보여 줍니다. `fsutil fsinfo sectorinfo` 는 디스크의 섹터 크기를 보여 줍니다. 이 명령은 조사 대상 시스템에서 실행되므로 [라이브 응답](../../../03-techniques/process-acquisition/live-response/index.md) 원칙에 따라 기록을 남깁니다.
- 도구마다 결과가 다르면 [도구 결과 교차 검증](../../../03-techniques/reporting/tool-validation.md)의 방법으로 헥스와 맞춰 봅니다.
