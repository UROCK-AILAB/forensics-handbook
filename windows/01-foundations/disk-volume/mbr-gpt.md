# 파티션 구조 (MBR·GPT)

> 위치: 기반 구조 > 디스크·볼륨

## 한 줄 요약

디스크 앞쪽의 파티션 표 (Partition Table) 는 디스크를 몇 개의 파티션으로 나눴는지, 파티션마다 어느 섹터에서 시작해 어디서 끝나는지 적습니다. 이 페이지는 MBR 과 GPT 두 형식을 다룹니다. 디스크 전체 이미지에서 볼륨을 읽으려면 먼저 이 표에서 파티션 시작 위치를 구합니다.

## 이 형식을 쓰는 아티팩트

파티션 표는 사용자 행동을 기록하지 않습니다. 그 대신 디스크 이미지 위의 모든 분석이 이 표의 값에서 시작합니다.

| 쓰는 곳 | 파티션 표에서 가져오는 값 |
|---|---|
| [NTFS 구조](ntfs/index.md) | 파티션 시작 LBA. 볼륨 안 오프셋을 디스크 오프셋으로 바꿀 때 더합니다. |
| [FAT·exFAT 구조](fat-exfat.md) | 파티션 시작 LBA와 파티션 종류 값 |
| [USB 저장장치 흔적](../../02-artifacts/external-devices/usb-storage-artifacts/index.md) | MBR 디스크 서명, GPT 디스크 GUID·파티션 GUID. 다른 기록과 맞춰 볼 값입니다. |
| [암호화 증거 다루기](../../03-techniques/analysis/encrypted-evidence/index.md) | 파티션마다 시작 위치와 크기 |
| [삭제 데이터 복구](../../03-techniques/analysis/data-recovery/index.md) | 어느 파티션에도 속하지 않은 섹터 |

- 디스크 이미지 파일(E01·VHDX·VMDK)을 먼저 풀어야 첫 섹터를 읽을 수 있습니다. 이미지 형식은 [증거 이미지·가상 디스크 형식](e01-raw-aff4-vhdx-vmdk.md)에 있습니다.

## 구조

### 섹터와 LBA

섹터 크기는 전통적으로 512바이트이고, 요즘 하드디스크는 4,096바이트도 씁니다. LBA (Logical Block Address) 는 디스크 첫 섹터를 0 으로 센 섹터 번호이며, 디스크 안 바이트 오프셋은 "LBA × 섹터 크기" 입니다.

MBR 은 서명 위치만으로는 섹터 크기를 알 수 없어서 첫 EPR 의 서명이나 알려진 파티션 내용을 보고 짐작합니다. GPT 는 헤더가 LBA 1 에 있으므로 헤더 서명의 위치로 섹터 크기를 알 수 있습니다. 서명이 0x200 에 있으면 512바이트 섹터이고, 0x1000 에 있으면 4,096바이트 섹터입니다.

여러 바이트 정수는 모두 리틀 엔디언 (little-endian) 입니다.

### MBR (512바이트)

MBR (Master Boot Record) 파티션 표는 주로 인텔 x86 계열 컴퓨터에서 씁니다. MBR 과 확장 파티션 레코드 (EPR, Extended Partition Record) 로 이뤄집니다. EPR 은 EBR 이라고도 부릅니다.

아래는 요즘 쓰는 MBR 의 모습입니다.

| 오프셋 | 16진 | 크기 | 필드 | 설명 |
|---|---|---|---|---|
| 0 | 0x000 | 440 | 부트 코드 | Windows 95·98·ME 는 그 가운데 218~223 을 따로 씁니다(아래). |
| 440 | 0x1B8 | 4 | 디스크 서명 (Disk Identity) | UEFI 와 Windows NT 이후가 씁니다. |
| 444 | 0x1BC | 2 | | 0x0000 이거나, 복사 방지 표시 0x5A5A 입니다. |
| 446 | 0x1BE | 16 | 파티션 항목 1 | |
| 462 | 0x1CE | 16 | 파티션 항목 2 | |
| 478 | 0x1DE | 16 | 파티션 항목 3 | |
| 494 | 0x1EE | 16 | 파티션 항목 4 | |
| 510 | 0x1FE | 2 | 서명 | `55 AA` |

- Windows 95·98·ME 는 218~223 에 디스크 시각(초·분·시)과 원래 드라이브 번호를 적습니다.

### MBR 파티션 항목 (16바이트)

| 오프셋 | 크기 | 필드 | 설명 |
|---|---|---|---|
| 0 | 1 | 플래그 | 0x80 이면 부팅 파티션입니다. |
| 1 | 3 | 시작 CHS 주소 | 실린더·헤드·섹터로 적은 옛 주소입니다. |
| 4 | 1 | 파티션 종류 | 아래 표 |
| 5 | 3 | 끝 CHS 주소 | |
| 8 | 4 | 시작 LBA | |
| 12 | 4 | 섹터 수 | |

- 시작 LBA 와 섹터 수는 둘 다 4바이트라서 2^32 섹터를 넘는 값을 적을 수 없습니다. 512바이트 섹터로 계산하면 2^32 × 512바이트 = 2 TiB 이며, 이 값은 칸 크기로 계산한 것입니다.
- CHS 를 LBA 로 바꾸는 식은 이렇습니다. LBA = ((실린더 × 실린더당 헤드 + 헤드) × 트랙당 섹터) + 섹터 − 1
- 예를 들어 실린더 0, 헤드 32, 섹터 33 이고 실린더당 헤드가 255, 트랙당 섹터가 63 이면 LBA = ((0 × 255 + 32) × 63) + 33 − 1 = 2,048 입니다. (식을 보이려고 만든 값입니다)

| 값 | 뜻 |

| 0x0C | FAT32 (LBA) |

| 0x27 | 제조사 복구 파티션으로 추정 (libvsmbr 문서도 확정하지 않았습니다) |

| 0x83 | Linux |

### 확장 파티션 레코드 (EPR)

기본 MBR 에는 항목이 4개뿐이라서 그보다 많은 파티션은 EPR 을 사슬처럼 이어 적습니다. 첫 EPR 의 파티션 종류는 보통 0x05 이고, Windows 98 등은 0x0F 를 씁니다.

EPR 도 512바이트입니다.

| 오프셋 | 크기 | 내용 |
|---|---|---|
| 0~445 | 446 | 비어 있어야 합니다. |
| 446 | 16 | 항목 1: 논리 파티션 |
| 462 | 16 | 항목 2: 다음 EPR 을 가리키는 확장 파티션 |
| 478 | 16 | 항목 3: 0 |
| 494 | 16 | 항목 4: 0 |
| 510 | 2 | 서명 `55 AA` |

EPR 안의 시작 LBA 는 항목마다 기준이 다릅니다(Wikipedia "Extended boot record"). 항목 1 (논리 파티션) 의 시작 LBA 는 지금 읽는 EPR 에서 잰 값이고, 항목 2 (다음 EPR) 의 시작 LBA 는 확장 파티션의 첫 EPR 에서 잰 값입니다. libvsmbr 문서는 "EPR 안의 LBA 주소는 첫 EPR 시작 기준" 이라고만 적었는데, 이 문장은 항목 2 에 맞습니다. 계산한 위치에 볼륨 부트 섹터나 다음 EPR 의 서명 `55 AA` 가 실제로 있는지 확인합니다.

### GPT 배치

GPT (GUID Partition Table) 디스크는 아래처럼 놓입니다.

| 위치 | 내용 |
|---|---|
| LBA 0 | 보호용 (Protective) MBR, 또는 혼합 (Hybrid) MBR |
| LBA 1 | GPT 헤더 |
| LBA 2~33 | 파티션 항목. 512바이트 섹터에 항목 128개일 때입니다. |
| 그 뒤 | 파티션 영역 |
| 디스크 끝 쪽 | 백업 파티션 항목. 보통 끝에서 −33 ~ −2 섹터 |
| 디스크 끝 | 백업 헤더. 보통 마지막 LBA |

- 보호용 MBR 은 종류 0xEE 파티션 하나가 디스크를 할 수 있는 만큼 덮는 MBR 입니다.
- GPT 안의 문자열은 BOM 없는 UTF-16LE 입니다.

## 읽는 법

### MBR 디스크

> 아래 바이트는 명세(libvsmbr 문서)대로 만든 예시입니다. 실제 검체에서 뽑은 값이 아닙니다.

```
오프셋    00 01 02 03 04 05 06 07  08 09 0A 0B 0C 0D 0E 0F
00000000  (0x000~0x1B7 부트 코드, 생략)
000001B0  .. .. .. .. .. .. .. ..  78 56 34 12 00 00 80 20
000001C0  21 00 07 FE FF FF 00 08  00 00 00 00 80 0C 00 00
000001D0  00 00 00 00 00 00 00 00  00 00 00 00 00 00 00 00
000001E0  00 00 00 00 00 00 00 00  00 00 00 00 00 00 00 00
000001F0  00 00 00 00 00 00 00 00  00 00 00 00 00 00 55 AA
```

| 오프셋 | 바이트 | 값 | 뜻 |
|---|---|---|---|
| 0x1B8 | `78 56 34 12` | 0x12345678 | 디스크 서명입니다. |
| 0x1BE | `80` | | 항목 1 은 부팅 파티션입니다. |
| 0x1BF | `20 21 00` | | 시작 CHS 입니다. 이 예시에서는 풀지 않고 LBA 칸을 씁니다. |
| 0x1C2 | `07` | | HPFS/NTFS 또는 exFAT 입니다. 볼륨 부트 섹터를 봐야 가릴 수 있습니다. |
| 0x1C3 | `FE FF FF` | | 끝 CHS 입니다. 풀지 않습니다. |
| 0x1C6 | `00 08 00 00` | 2,048 | 시작 LBA 입니다. 디스크 안 오프셋은 2,048 × 512 = 1,048,576 (0x100000) 입니다. |
| 0x1CA | `00 00 80 0C` | 209,715,200 | 섹터 수입니다. 크기는 107,374,182,400바이트입니다. |
| 0x1CE~0x1FD | `00 …` | | 항목 2~4 는 종류가 0x00 인 빈 항목입니다. |
| 0x1FE | `55 AA` | | MBR 서명입니다. |

순서는 이렇습니다.

1. 오프셋 0x1FE 의 `55 AA` 를 확인합니다.
2. 항목 4개를 읽습니다. 종류가 0x00 인 항목은 건너뜁니다.
3. 종류가 0xEE 인 항목이 있으면 GPT 디스크입니다. 아래 GPT 순서로 넘어갑니다.
4. 종류가 0x05 나 0x0F 인 항목이 있으면 EPR 사슬을 따라가며 논리 파티션을 모읍니다.
5. 시작 LBA 에 섹터 크기를 곱해 볼륨 시작 바이트를 구합니다.
6. 그 자리의 볼륨 부트 섹터를 확인합니다. NTFS 는 [NTFS 구조](ntfs/index.md), FAT 와 exFAT 는 [FAT·exFAT 구조](fat-exfat.md)를 봅니다.
7. 파티션 끝 LBA 를 구합니다. 이 예시에서는 2,048 + 209,715,200 − 1 = 209,717,247 입니다.
8. 파티션 사이와 마지막 파티션 뒤에 빈 섹터 구간이 있는지 적어 둡니다.

### GPT 디스크

> 아래 바이트는 명세(libvsgpt 문서)대로 만든 예시입니다. 실제 검체에서 뽑은 값이 아닙니다. CRC 자리는 `xx`·`yy`, 디스크 GUID 자리는 `gg` 로 비워 두었습니다. 예시 디스크는 512바이트 섹터 419,430,400개입니다.

```
오프셋    00 01 02 03 04 05 06 07  08 09 0A 0B 0C 0D 0E 0F
00000200  45 46 49 20 50 41 52 54  00 00 01 00 5C 00 00 00   EFI PART....\...
00000210  xx xx xx xx 00 00 00 00  01 00 00 00 00 00 00 00
00000220  FF FF FF 18 00 00 00 00  22 00 00 00 00 00 00 00
00000230  DE FF FF 18 00 00 00 00  gg gg gg gg gg gg gg gg
00000240  gg gg gg gg gg gg gg gg  02 00 00 00 00 00 00 00
00000250  80 00 00 00 80 00 00 00  yy yy yy yy
```

| 헤더 오프셋 | 바이트 | 값 | 뜻 |
|---|---|---|---|
| 0x00 | `45 46 49 20 50 41 52 54` | "EFI PART" | GPT 헤더 서명입니다. 디스크 오프셋 0x200 에 있으므로 섹터는 512바이트입니다. |
| 0x08 | `00 00 01 00` | 1.0 | 부 판 0, 주 판 1 입니다. |
| 0x0C | `5C 00 00 00` | 92 | 헤더 크기입니다. |
| 0x10 | `xx xx xx xx` | | 헤더 CRC-32 입니다. |
| 0x18 | `01 00 00 00 00 00 00 00` | 1 | 이 헤더는 LBA 1 에 있습니다. 주 헤더입니다. |
| 0x20 | `FF FF FF 18 00 00 00 00` | 419,430,399 | 백업 헤더는 마지막 LBA 에 있습니다. |
| 0x28 | `22 00 00 00 00 00 00 00` | 34 | 파티션 영역 첫 LBA 입니다. |
| 0x30 | `DE FF FF 18 00 00 00 00` | 419,430,366 | 파티션 영역 끝 LBA 입니다. |
| 0x38 | `gg …` | | 디스크 GUID 입니다. |
| 0x48 | `02 00 00 00 00 00 00 00` | 2 | 파티션 항목은 LBA 2 에서 시작합니다. |
| 0x50 | `80 00 00 00` | 128 | 항목 자리가 128개입니다. |
| 0x54 | `80 00 00 00` | 128 | 항목 하나는 128바이트입니다. |
| 0x58 | `yy yy yy yy` | | 항목 배열 CRC-32 입니다. |

- 항목 배열 크기는 128 × 128 = 16,384바이트입니다. 512바이트 섹터로 32개이므로 LBA 2~33 을 차지합니다.

LBA 2 (디스크 오프셋 0x400) 의 첫 항목을 같은 방식으로 풀면 이렇습니다(명세로 만든 예시 값).

| 항목 오프셋 | 값 | 뜻 |
|---|---|---|
| 0 | ebd0a0a2-b9e5-4433-87c0-68b6b72699c7 | 기본 데이터 파티션 |
| 16 | (파티션 고유 GUID) | |
| 32 | `00 08 00 00 00 00 00 00` → 2,048 | 시작 LBA |
| 40 | `FF F7 FF 18 00 00 00 00` → 419,428,351 | 끝 LBA (포함) |
| 48 | 0 | 속성 없음 |
| 56 | (UTF-16LE 이름) | |

- 섹터 수는 419,428,351 − 2,048 + 1 = 419,426,304 입니다.
- 크기는 419,426,304 × 512 = 214,746,267,648바이트입니다.

순서는 이렇습니다.

1. LBA 0 의 MBR 에서 종류 0xEE 항목을 확인합니다. MBR 에 0xEE 말고 다른 항목도 있으면 보호용 MBR 이 아닙니다. 혼합 MBR 일 수 있으니 MBR 항목과 GPT 항목을 둘 다 읽어 비교합니다.
2. "EFI PART" 서명을 찾아 섹터 크기를 정합니다.
3. 헤더 CRC-32 를 다시 계산합니다. 오프셋 16 의 4바이트를 0 으로 두고 헤더 크기(92바이트)만큼 계산합니다.
4. 파티션 항목 시작 LBA 에서 "항목 개수 × 항목 크기" 만큼 읽습니다. 이 배열로 항목 배열 CRC-32 를 다시 계산합니다.
5. 종류 GUID 가 전부 0 인 항목은 건너뜁니다.
6. 항목마다 종류 GUID, 고유 GUID, 시작·끝 LBA, 속성, 이름을 적습니다.
7. 백업 헤더 LBA 로 가서 백업 헤더를 읽습니다. 백업 헤더의 오프셋 72 는 백업 항목을 가리킵니다.
8. 주 헤더·항목과 백업 헤더·항목을 비교합니다.

## 포렌식에서 중요한 점

### 파티션이 가리키지 않는 공간

MBR 디스크에는 MBR 과 첫 파티션 사이, 파티션과 파티션 사이, 마지막 파티션 뒤에 파티션이 가리키지 않는 섹터가 생길 수 있습니다. GPT 디스크에서는 파티션 영역 첫 LBA 앞과 끝 LBA 뒤를 파티션이 쓸 수 없고, 파티션 영역 안에서도 항목이 가리키지 않는 구간이 생길 수 있습니다.

이 구간은 어느 파일시스템의 파일 목록에도 나오지 않으므로 이미지에서 바이트를 직접 봅니다. 이 구간을 다루는 방법은 [삭제 데이터 복구](../../03-techniques/analysis/data-recovery/index.md)에 있습니다.

### 지운 파티션과 망가진 파티션 표

- 파티션 표만 망가지고 볼륨이 남아 있으면 볼륨 부트 섹터로 파티션 위치를 다시 찾을 수 있습니다. 찾는 법은 [NTFS 구조](ntfs/index.md)와 [FAT·exFAT 구조](fat-exfat.md)에 있습니다.
- GPT 는 헤더와 항목 배열의 백업이 디스크 끝에 있어서, 주 헤더가 망가졌으면 백업 헤더로 항목 배열을 찾습니다. 주 쪽과 백업 쪽이 다르면 한쪽이 손상됐거나 바뀐 것이므로 두 값을 모두 기록하고, 보고서에는 어느 쪽으로 해석했는지 밝힙니다.
- EPR 사슬 가운데 하나가 망가지면 그 뒤의 논리 파티션은 사슬로 찾을 수 없습니다. 섹터 경계마다 `55 AA` 와 EPR 모양을 찾아 이어 붙입니다.

### CRC 로 손상과 수정 가리기

GPT 헤더와 항목 배열에는 각각 CRC-32 가 있습니다. 다시 계산한 CRC 가 적힌 값과 다르면 손상이거나, CRC 를 고치지 않고 바이트만 바꾼 것입니다. 하지만 CRC 가 맞는다고 해서 수정이 없었다는 뜻은 아닌데, 값을 바꾼 뒤 CRC 를 다시 계산해 넣을 수 있기 때문입니다.

### 숨긴 파티션과 드라이브 문자

- MBR 의 0x11·0x14·0x16·0x17·0x1B·0x1C·0x1E 는 숨긴 FAT·NTFS 파티션입니다.
- GPT 기본 데이터 파티션은 속성 비트 62 (숨김) 와 63 (드라이브 문자 없음) 을 켤 수 있습니다.
- 복구용 파티션도 있습니다. MBR 에서는 0x27 이 제조사 복구 파티션으로 추정되고, GPT 에는 Windows 복구 환경 GUID 가 있습니다.
- 사용자 화면에 드라이브가 보이지 않았다는 사실만으로 파티션이 없었다고 쓰지 않습니다. 파티션 표를 직접 읽어 확인합니다.

### 디스크와 파티션을 가리키는 값

MBR 디스크 서명 (오프셋 440, 4바이트), GPT 디스크 GUID (헤더 오프셋 56), GPT 파티션 고유 GUID (항목 오프셋 16) 는 디스크와 파티션을 가리키는 값이라서, 다른 기록에 같은 값이 남아 있으면 맞춰 볼 수 있습니다. 외부 저장장치 조사에서 쓰는 방법은 [USB 저장장치 흔적](../../02-artifacts/external-devices/usb-storage-artifacts/index.md)에서 다룹니다.

이 값들은 파티션 표 안의 바이트일 뿐이라 고칠 수 있습니다. 값이 같다는 사실만으로 같은 디스크라고 단정하지 않고, 디스크 크기, 파티션 배치 같은 다른 값과 함께 봅니다.

### 동적 디스크와 저장소 공간

MBR 종류 0x42 와 GPT 의 LDM GUID 두 개는 Windows 동적 디스크이고, GPT 의 저장소 공간 GUID 는 Storage Spaces 영역입니다. 이 페이지는 이런 파티션 안의 볼륨 구성을 다루지 않습니다.

### 옛 Windows 의 디스크 시각

Windows 95·98·ME 가 쓴 디스크라면 MBR 218~223 에 디스크 시각과 원래 드라이브 번호가 있을 수 있습니다. 이 자리는 다른 Windows 에서는 부트 코드의 일부이므로 같은 자리를 시각으로 풀지 않습니다.

## 함정

1. **섹터를 512바이트로 가정합니다.** 4,096바이트 섹터 디스크라면 모든 오프셋이 8배 어긋납니다. GPT 는 서명 위치로, MBR 은 볼륨 부트 섹터로 섹터 크기를 확인합니다.
2. **GPT 끝 LBA 로 크기를 셀 때 1 을 더하지 않습니다.** 끝 LBA 도 파티션에 들어갑니다. 섹터 수는 "끝 − 시작 + 1" 입니다.
3. **MBR 섹터 수를 끝 LBA 로 읽습니다.** MBR 항목의 둘째 숫자는 끝 위치가 아니라 섹터 수입니다.
4. **GPT 항목 개수를 파티션 개수로 읽습니다.** 헤더의 항목 개수는 자리 개수입니다. 종류 GUID 가 0 인 빈 항목을 빼고 셉니다.
5. **보호용 MBR 만 보고 파티션이 하나라고 봅니다.** 종류 0xEE 는 GPT 디스크라는 표시입니다. LBA 1 의 GPT 를 읽어야 합니다.
6. **0x07 을 NTFS 로 단정합니다.** exFAT 도 0x07 을 씁니다. 볼륨 부트 섹터로 가립니다.
7. **EPR 두 항목의 LBA 를 같은 기준으로 계산합니다.** 항목 1 은 지금 EPR 기준, 항목 2 는 첫 EPR 기준입니다. 계산한 자리에 서명이 있는지도 확인합니다.
8. **CRC 칸을 그대로 둔 채 헤더 CRC 를 계산합니다.** 오프셋 16 을 0 으로 두고 계산해야 맞습니다.
9. **백업 헤더의 오프셋 72 를 주 항목 위치로 씁니다.** 백업 헤더에서는 백업 항목 위치입니다.
10. **GUID 바이트를 그대로 읽어 문자열로 적습니다.** 바이트 순서를 [윈도 식별자 형식](../value-decoding/sid-guid-clsid-known-folder-id.md)대로 바꿉니다.

## 도구

- 헥스 편집기로 위 순서를 직접 따라갈 수 있습니다.
- libyal 의 libvsmbr 와 libvsgpt 는 이 페이지가 참고한 MBR·GPT 문서를 공개한 오픈 소스 라이브러리입니다.
- 두 도구가 보여 주는 파티션 목록이 다르면 [도구 결과 교차 검증](../../03-techniques/reporting/tool-validation.md)의 방법으로 헥스와 맞춰 봅니다. 혼합 MBR 디스크에서는 도구마다 MBR 과 GPT 가운데 어느 쪽을 읽었는지부터 확인합니다.
