# Windows 디지털 포렌식 위키

Windows 시스템에 남는 흔적을 어떻게 읽고 해석하는지 정리한 한국어 위키입니다. 포렌식을 공부하는 사람과 현업에서 사건을 분석하는 사람을 위해 작성했습니다.

아티팩트가 어디에 있는지뿐만 아니라 그 기록이 왜 생기는지, 무엇을 증명하고 무엇은 증명하지 못하는지까지 설명합니다. 보고서에 어떻게 쓸 수 있는지도 함께 다룹니다.

## 구성

모두 394쪽이며, 네 갈래로 나뉩니다.

| 갈래 | 쪽 | 다루는 것 |
|---|---:|---|
| **기반 구조** | 62 | NTFS·레지스트리 하이브·ESE·SQLite·EVTX 같은 저장 형식. 여러 아티팩트가 이 형식 위에 기록됩니다 |
| **아티팩트 사전** | 241 | 프리페치·AmCache·SRUM·셸백·USB·브라우저·메신저·이벤트 로그 등 아티팩트 하나에 한 쪽 |
| **분석 기법** | 55 | 증거 수집·라이브 대응·메모리 분석·타임라인·삭제 데이터 복구·암호화된 증거·해시와 YARA·Sigma·보고서 작성 |
| **조사 시나리오** | 36 | "자료를 밖으로 빼돌렸나" 같은 질문 하나에 여러 아티팩트를 엮어 답하는 흐름 |

큰 주제는 허브 쪽이 먼저 전체를 보여 주고, 하위 쪽이 하나씩 깊이 들어갑니다.

## 한 쪽에 담긴 것

아티팩트 쪽은 대체로 이 순서를 따릅니다.

1. 무엇을 기록하고 왜 생기는지
2. 위치와 Windows 버전별 차이
3. 구조 — 표·칸 이름·오프셋
4. 증거로서 의미 — 증명하는 것과 증명하지 못하는 것
5. 시각 해석 — 무엇이 바뀔 때 바뀌는지, UTC 인지 현지 시각인지
6. 함정과 한계 — 흔한 오해와 지우기·조작이 남기는 모양
7. 직접 분석해 보기 — 헥스로 한 번, 공개 도구로 한 번
8. 교차 검증 — 함께 볼 아티팩트
9. 실습 질문과 참고 문헌

## 읽는 법

- 처음이라면 기반 구조의 [NTFS](01-foundations/disk-volume/ntfs/index.md)와 [레지스트리 하이브](01-foundations/database-log-formats/registry-hive/index.md)부터 읽기를 권합니다.
- 사건을 앞에 두고 있다면 조사 시나리오에서 질문을 고르고, 거기서 필요한 아티팩트로 넘어가면 됩니다. 예: [어떤 프로그램을 언제 실행했나](04-scenarios/activity/program-execution.md), [자료를 밖으로 빼돌렸나](04-scenarios/exfiltration/data-exfiltration/index.md), [원격 데스크톱 침입 확인](04-scenarios/incident/rdp-intrusion.md)
- 특정 아티팩트만 궁금하다면 아래 목차에서 바로 찾으면 됩니다.

## 표기

- 명세나 공식 문서로 확인한 사실은 그대로 씁니다.
- 직접 관찰로만 알아낸 사실에는 "(확인 범위: Win10 22H2)"처럼 범위를 붙입니다.
- 확인하지 못한 것은 "확인하지 못함"이라고 밝힙니다.
- 헥스 예시는 명세를 보고 만든 예시입니다. 실제 검체에서 나온 값이 아닙니다.
- 용어는 처음 나올 때 "한국어 (English)"로 한 번 적습니다.
