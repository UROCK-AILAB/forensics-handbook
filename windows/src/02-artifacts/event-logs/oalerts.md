# 오피스 경고 (OAlerts)

## 한 줄 요약

오피스 프로그램이 띄운 경고 대화상자의 문구가 OAlerts 로그에 이벤트 300 으로 남습니다. 문구에 파일 이름이 들어 있으면 어느 문서를 다뤘는지 알 수 있습니다. 조사한 PC 에서는 추가 기능이 실행될 때 열려 있던 문서의 경로나 URL 도 남았습니다. 어느 계정이 봤는지, 사용자가 어떤 단추를 눌렀는지는 남지 않습니다. 시각은 UTC 입니다.

## 무엇을 기록하나 · 왜 생기나

공급자 이름은 "Microsoft Office 16 Alerts" 이고, 이벤트 ID 는 300 입니다. 공개 도구 EvtxECmd 의 맵 예시에는 Excel 의 "변경 내용을 저장하시겠습니까?" 대화상자 문구가 네덜란드어로 들어 있고, 문구 안에 파일 이름(`full_application_event_log.csv`)이 있으며, 그 뒤에 경고 번호(100216)와 오피스 빌드(16.0.4822.1000)가 이어집니다. 맵은 첫 줄을 "Program", 경고 문구를 "Alert" 로 뽑습니다.

조사한 PC 의 레코드는 네 종류였습니다 (확인 범위: Win11 25H2 한 대, 오피스 표시 언어 한국어).

| 종류 | 건수 | 담긴 것 |
|---|---|---|
| 대화상자 경고 | 32 | 프로그램 이름, 대화상자 문구, 경고 번호, 오피스 빌드 |
| 추가 기능 실행 ("Activated App") | 134 | 추가 기능 식별 문자열, 오피스 빌드, 그때 열려 있던 문서의 경로 또는 URL |
| 추가 기능 매니페스트 오류 | 8 | "Failed to parse element: VersionOverrides", 추가 기능 식별 문자열, 오류 코드. 수준은 오류입니다 |
| "Compositor Type: 1" | 207 | 이 문자열과 프로세스 이름(WINWORD·EXCEL·POWERPNT) 두 칸뿐 |

로그 전체는 373건이었고, 수준별로는 정보 365건, 오류 8건이었습니다. 종류별 건수는 문구로 나눠 센 것인데, 네 종류를 더한 값이 전체 건수와 맞지 않는 까닭은 확인하지 못했습니다. "Compositor Type: 1" 레코드의 뜻도 확인하지 못했습니다.

## 위치와 버전별 차이

| 항목 | 내용 |
|---|---|
| 로그 (채널) | OAlerts |
| 파일 | `%SystemRoot%\System32\Winevt\Logs\OAlerts.evtx` |
| 로그 설정 | 켜짐, 최대 1,052,672바이트(약 1MB), 순환 |
| 공급자 | Microsoft Office 16 Alerts |
| 이벤트 ID | 300 |

파일과 로그 설정은 조사한 PC 에서 본 것이고 (확인 범위: Win11 25H2 한 대), 그 PC 에는 2026-06-26\~2026-09-23, 약 3개월치가 남아 있었습니다.

EvtxECmd 맵 저장소에는 "Microsoft Office 14 Alerts", "15 Alerts", "16 Alerts" 용 맵이 따로 있어서 공급자 이름에 오피스의 주 버전 번호가 들어가는 것으로 보입니다. 14 는 Office 2010, 15 는 Office 2013, 16 은 Office 2016 이후라는 대응은 확인하지 못했으므로 검체의 공급자 이름을 먼저 봅니다. 이 로그가 오피스를 설치할 때 만들어지는지도 확인하지 못했습니다.

## 구조

### System 부분

| 칸 | 값 |
|---|---|
| Level | 4(정보) 또는 2(오류) |
| Task | 0 |
| Keywords | `0x80000000000000` |
| Security | 비어 있음(UserID 없음) |
| Execution ProcessID | 경고를 띄운 오피스 프로그램의 프로세스 ID |
| Execution ThreadID | 0 |

- Task·Keywords 는 맵 예시와 조사한 PC 가 같았습니다. 맵 예시의 Level 은 4 였습니다.
- Security 가 비어 있으므로 어느 계정의 화면에 떴는지 이 이벤트만으로는 알 수 없습니다.

### EventData 는 이름 없는 칸

조사한 PC 의 `<Data>` 요소에는 Name 속성이 없었으므로 칸 이름 대신 순서로 읽습니다. 대화상자 경고는 `<Data>` 6개로 나뉘어 있었습니다. 맵 예시는 여러 줄이 `<Data>` 하나 안에 쉼표로 이어져 있어 조사한 PC 와 모양이 다른데, 맵 예시가 도구 출력 모양을 옮긴 것일 수 있습니다.

### 종류별 칸 순서

조사한 PC 에서 본 순서입니다 (확인 범위: Win11 25H2 한 대).

| 칸 | 대화상자 경고 | 추가 기능 실행 | 매니페스트 오류 |
|---|---|---|---|
| [0] | 프로그램 표시 이름("Microsoft Excel", "Microsoft Word") | "Activated App" | "Failed to parse element: VersionOverrides" |
| [1] | 대화상자 문구(오피스 표시 언어) | 추가 기능 식별 문자열(Id=…, DisplayName=…, Provider=…, StoreType=…) | 추가 기능 식별 문자열 |
| [2] | 경고 번호 | "Apps for Office" | "Apps for Office" |
| [3] | 오피스 빌드 | 오피스 빌드 | 오피스 빌드 |
| [4] | 빈 값 | | `0x8004323E` |
| [5] | 빈 값 또는 HRESULT(예: `0x80070002`) | 그때 열려 있던 문서의 로컬 경로 또는 OneDrive·SharePoint URL | "New Document" |

### 대화상자 경고의 예

조사한 PC 에서 본 경고입니다.

| 프로그램 | 경고 번호 | 문구 (줄임) | 건수 |
|---|---|---|---|
| Word | 201452 | "이 문서에는 다른 파일을 참조하는 필드가 들어 있습니다. … 업데이트하시겠습니까?" | 16 |
| Excel | 100199 | "복사 영역과 붙여 넣을 영역의 크기가 달라서 …" | |

Excel 경고 번호 100158·100211·100536·101013·100072 도 있었습니다. 같은 경고 번호는 같은 종류의 대화상자로 보이지만, 경고 번호의 전체 목록은 확인하지 못했습니다.

### 오피스 빌드 번호

- 조사한 PC 의 레코드에는 오피스 빌드 번호가 10가지 들어 있었습니다(16.0.17328.20206 \~ 16.0.20326.20100).
- 새 빌드 번호가 처음 나오는 레코드로 오피스를 업데이트한 때를 대략 알 수 있습니다.

## 증거로서 의미

| 증명하는 것 | 증명하지 못하는 것 |
|---|---|
| 기록된 시각에 이 오피스 프로그램이 이 문구의 대화상자를 띄웠습니다 | 어느 계정의 화면에 떴는지. Security 칸이 비어 있습니다 |
| 문구 안의 파일 이름을 그 프로그램이 다뤘다는 것 | 사용자가 어떤 단추를 눌렀는지. "저장하시겠습니까?" 가 남아도 저장했는지는 알 수 없습니다 |
| 추가 기능이 실행된 시각과 그때 열려 있던 문서의 경로·URL ("Activated App") | 그 문서를 편집했다는 것 |
| 그 시기에 쓰던 오피스 빌드 | 경고가 없으니 그 문서를 열지 않았다는 것. 대화상자가 뜨지 않으면 경고도 남지 않습니다 |

### 보고서 문장

아래 시각과 경로는 설명을 위해 만든 예입니다.

- 쓸 수 있는 문장: "OAlerts 로그에는 <시각> UTC 에 Microsoft Word 의 경고 이벤트 300 이 있습니다. 경고 번호는 201452 이고, 다른 파일을 참조하는 필드를 업데이트할지 묻는 문구입니다. 같은 프로세스 ID 의 "Activated App" 레코드에는 문서 경로 `C:\…\보고서.docx` 가 있습니다."
- 쓰면 안 되는 문장: "○○ 이 보고서.docx 를 열어 고친 뒤 저장했다."

두 번째 문장은 사람, 편집, 저장을 단정합니다. 이벤트에는 프로그램과 문구, 경로만 있습니다.

## 시각 해석

레코드마다 시각은 `<TimeCreated SystemTime>` 하나뿐이고, 끝에 Z 가 붙은 UTC 값입니다. 이 시각은 경고를 기록한 시각이며 대화상자를 닫은 시각은 남지 않습니다. 현지 시각으로 바꿀 때는 [시간대 설정](../system-account/time-zone.md)을 씁니다.

## 함정과 한계

1. **영어 문구로 찾습니다.** 대화상자 문구는 오피스 표시 언어로 남습니다. 맵 예시는 네덜란드어였고, 조사한 PC 는 한국어였습니다. 경고 번호와 파일 이름으로 찾습니다.
2. **Execution ProcessID 를 사용자로 읽습니다.** 이 값은 오피스 프로그램의 프로세스 ID 이므로 사람은 그 시각의 로그온 기록으로 따로 찾습니다.
3. **칸 이름으로 찾습니다.** `<Data>` 에 이름이 없습니다. 도구마다 칸을 합치거나 이름을 붙이는 방식이 다를 수 있습니다. XML 원문의 순서로 확인합니다.
4. **"저장하시겠습니까?" 를 저장으로 읽습니다.** 누른 단추를 담은 칸이 없습니다.
5. **오래된 경고를 찾습니다.** 로그가 약 1MB 순환 방식입니다. 조사한 PC 에서는 약 3개월치가 남아 있었습니다. "Compositor Type" 레코드가 절반을 넘어서 대화상자 경고는 더 빨리 밀려날 수 있습니다.
6. **공급자 이름 하나로만 거릅니다.** 오피스 주 버전마다 공급자 이름이 다를 수 있습니다. 채널 이름 OAlerts 로 거릅니다.
7. **"Compositor Type" 레코드를 해석합니다.** 뜻을 확인하지 못한 레코드입니다. 프로그램이 실행 중이었다는 정도로만 씁니다.

### 지우기와 조작

- **로그를 지웁니다.** 지운 기록은 [이벤트 로그 삭제](1102-104.md)에서 찾습니다.
- 조작이 없어도 작은 순환 로그는 스스로 밀려납니다. 기록이 없는 기간은 "경고 없음" 이 아니라 "기록 없음" 으로 적습니다.

## 직접 분석해 보기

### 헥스로 한 번

로그 파일 안의 문자열은 UTF-16LE 로 들어 있습니다. 그래서 찾는 문구를 UTF-16LE 바이트로 바꿔 파일 전체를 찾을 수 있습니다.

아래는 조사한 PC 에서 본 문자열을 형식대로 옮긴 예시입니다. 검체에서 뽑은 바이트가 아닙니다.

```
"Activated App"  →  41 00 63 00 74 00 69 00 76 00 61 00 74 00 65 00 64 00 20 00 41 00 70 00 70 00
```

1. `OAlerts.evtx` 사본을 헥스 편집기로 엽니다.
2. 위 바이트 열을 찾습니다.
3. 찾은 자리 뒤에서 추가 기능 식별 문자열과 문서 경로·URL 을 읽습니다.
4. 파일 이름 조각도 같은 방법으로 찾습니다. 한글 파일 이름도 UTF-16LE 로 바꿔 찾습니다.
5. 도구 결과에 없는 자리에서 나왔다면, [이벤트 로그 형식](../../01-foundations/database-log-formats/evtx-evt-etl/index.md)에서 설명하는 구조로 그 자리가 레코드인지 확인합니다.

인코딩 자체는 [문자 인코딩](../../01-foundations/value-decoding/utf-16le-utf-8-cp949.md)에서 다룹니다.

### 공개 도구로 한 번

칸 이름이 없으므로 PowerShell 에서는 칸 번호로 읽습니다.

```powershell
Get-WinEvent -Path .\OAlerts.evtx -Oldest |
  ForEach-Object {
    $p = $_.Properties.Value
    [pscustomobject]@{
      TimeUtc   = $_.TimeCreated.ToUniversalTime()
      Level     = $_.Level
      ProcessId = $_.ProcessId
      D0 = $p[0]; D1 = $p[1]; D2 = $p[2]; D3 = $p[3]; D5 = $p[5]
    }
  } | Where-Object { $_.D0 -ne 'Compositor Type: 1' } | Format-List
```

- "Compositor Type" 레코드를 빼면 대화상자 경고와 추가 기능 기록만 남습니다.
- EvtxECmd 맵 저장소에는 OAlerts 용 맵이 오피스 주 버전별로 있습니다. 맵은 첫 줄을 Program, 경고 문구를 Alert 로 뽑습니다. 도구 출력은 XML 원문 한두 건과 맞춰 봅니다. 방법은 [도구 결과 교차 검증](../../03-techniques/reporting/tool-validation.md)에서 다룹니다.

## 실습

오피스를 설치한 Windows 10·11 가상 머신에서 해 봅니다. 각 단계의 시각을 UTC 로 적어 둡니다.

1. Excel 에서 새 통합 문서를 고친 뒤 저장하지 않고 닫습니다. "저장하시겠습니까?" 경고가 남는지, 문구에 파일 이름이 들어 있는지 보십시오.
2. 1번에서 "저장" 을 누른 경우와 "저장 안 함" 을 누른 경우를 비교하십시오. 두 레코드가 다른지 보십시오.
3. 추가 기능이 있는 문서를 엽니다. "Activated App" 레코드의 [5] 칸에 문서 경로가 들어 있는지 보십시오.
4. OneDrive 폴더의 문서로 3번을 되풀이합니다. 경로와 URL 가운데 무엇이 남는지 보십시오.
5. 오피스 표시 언어를 바꾼 뒤 1번을 되풀이합니다. 경고 번호는 같고 문구만 바뀌는지 보십시오.

NIST CFReDS 같은 공개 검체에서 이벤트 로그를 꺼냈다면, 먼저 OAlerts 로그가 있는지와 공급자 이름의 버전 번호를 보십시오. 그다음 대화상자 문구에 파일 이름이 든 레코드를 찾아보십시오.
