# 의심 실행 파일 선별 (Code Signing·YARA)

> 위치: 분석 기법 > 분석

## 한 줄 요약

실행 파일이 많을 때 먼저 코드 서명으로 크게 거르고, 서명이 없거나 이상한 파일을 해시와 YARA 규칙으로 좁히는 방법입니다.
이 과정에서 나오는 결과는 모두 "더 볼 파일" 을 고르는 신호일 뿐, 악성이라고 판정하는 근거가 아닙니다.
실행 파일 한 개의 헤더·버전 정보·서명 구조는 [실행 파일 메타데이터](../../02-artifacts/embedded-metadata/pe-header-version-info-digital-signature.md) 에서 다룹니다.

## 언제 쓰나

- **실행 파일이 너무 많아 하나씩 볼 수 없을 때** 씁니다. 시스템 폴더나 사용자 폴더 전체가 대상일 때입니다.
- **자동실행 위치에 등록된 파일을 확인할 때** 씁니다. 등록 위치는 [악성코드 지속성(자동실행) 찾기](../../04-scenarios/incident/persistence.md) 에서 다룹니다.
- **사건에서 찾은 악성 파일과 같은 계열을 찾을 때** 씁니다. 찾은 파일의 특징을 YARA 규칙으로 적어 다른 파일에 돌립니다.
- **실행 흔적이 남은 파일을 추릴 때** 씁니다. [프리페치](../../02-artifacts/execution/prefetch/index.md) 나 [AmCache](../../02-artifacts/execution/amcache-hve/index.md) 에 남은 경로의 파일을 먼저 봅니다.

## 절차

> 그림 자리: 전체 실행 파일 → (서명 확인) → 서명 없음·검증 실패 → (카탈로그 확인) → (해시셋 대조) → (YARA 검사) → 직접 분석할 짧은 목록. 단계마다 목록이 줄어드는 깔때기 그림

1. **실행 파일을 모읍니다.** 확장자는 믿지 않습니다. 파일 내용으로 실행 파일인지 봅니다. 방법은 [파일 내용 검색](content-search/index.md) 의 파일 형식 식별 글에 있습니다.
2. **서명을 확인합니다.** 서명이 없거나 검증에 실패한 파일을 뽑습니다. 아래 "코드 서명" 절을 봅니다.
3. **카탈로그 서명을 확인합니다.** 파일 안에 서명이 없어도 카탈로그로 서명된 파일일 수 있습니다. 오프라인 이미지라면 그 이미지의 카탈로그로 확인합니다.
4. **알려진 파일을 거릅니다.** 남은 파일의 해시를 알려진 파일 목록과 맞춥니다. 방법은 [해시셋 대조와 유사 해시](hash-set-fuzzy-hash.md) 에 있습니다.
5. **YARA 규칙으로 검사합니다.** 사건에서 얻은 특징이나 검증한 규칙 모음으로 검사합니다. 아래 "YARA" 절을 봅니다.
6. **남은 파일을 직접 봅니다.** 실행 흔적, 들어온 경로, 자동실행 등록 여부를 확인합니다.
7. **단계마다 목록을 남깁니다.** 어떤 조건으로 몇 개가 빠졌는지 적어 두어야 다른 분석가가 같은 결과를 다시 얻습니다.

## 코드 서명 (Authenticode)

### 무엇을 확인하나

Authenticode 는 Microsoft 의 코드 서명 기술입니다. 서명은 누가 게시했는지 알려 주고, 서명한 뒤로 소프트웨어가 바뀌지 않았는지도 확인해 줍니다. 게시자를 확인할 때는 서명 인증서에서 신뢰하는 루트 인증서까지 이어서 따라가는데, 이 이어진 줄을 인증서 체인 (Certificate Chain) 이라고 부릅니다. 서명은 파일의 실행 부분을 바꾸지 않습니다.

### 두 가지 방식

| 방식 | 서명이 있는 곳 | 파일만 볼 때 |
|---|---|---|
| 파일 안에 넣는 서명 (Embedded Signature) | 파일에서 실행되지 않는 부분 | 파일 안에 서명이 보입니다 |
| 서명된 카탈로그 파일 (.cat) | 여러 파일의 해시를 카탈로그에 넣고, 카탈로그를 서명합니다. 떨어져 있는 서명 (Detached Signature) 의 한 종류입니다 | 파일 안에는 서명이 없습니다 |

카탈로그로 서명된 파일은 파일만 보면 "서명 없음" 으로 잘못 볼 수 있습니다. 오프라인 이미지에서 이런 파일을 확인하려면 그 이미지의 카탈로그 파일이 필요한데, 분석하는 PC 의 카탈로그는 이미지 속 Windows 의 카탈로그와 다를 수 있습니다. 카탈로그 파일이 이미지의 어느 폴더에 있는지는 이 페이지의 자료로 확인하지 못했습니다.

- 파일 안 서명의 바이트 구조, 서명이 덮는 범위, 서명 타임스탬프는 [실행 파일 메타데이터](../../02-artifacts/embedded-metadata/pe-header-version-info-digital-signature.md) 에 있습니다.

### Sigcheck 로 서명 목록 뽑기

Sigcheck 는 Microsoft Sysinternals 의 명령줄 도구로, 파일 판 번호, 타임스탬프 정보, 인증서 체인을 포함한 디지털 서명 정보를 보여 줍니다.
현재 문서에 적힌 실행 환경은 클라이언트 Windows 11 이상, 서버 Windows Server 2019 이상입니다.

문서에 실린 사용 예입니다.

```
sigcheck -u -e c:\windows\system32
```

이 명령은 System32 에서 서명 없는 파일을 찾으며, 문서는 서명되지 않은 파일은 목적을 조사해야 한다고 적습니다.

문서에 적힌 주요 옵션입니다.

| 옵션 | 하는 일 |
|---|---|
| `-e` | 확장자와 관계없이 실행 이미지만 검사합니다 |
| `-u` | VirusTotal 검사를 끈 상태에서는 서명 없는 파일만 보여 줍니다. 켠 상태에서는 VirusTotal 이 모르는 파일이나 탐지 수가 0 이 아닌 파일을 보여 줍니다 |
| `-s` | 하위 폴더까지 검사합니다 |
| `-i` | 카탈로그 이름과 서명 체인을 보여 줍니다 |
| `-f` | 지정한 카탈로그 파일에서 서명을 찾습니다 |
| `-d` | 카탈로그 파일 내용을 덤프합니다 |
| `-h` | 파일 해시를 보여 줍니다 |
| `-a` | 확장 판 정보를 보여 줍니다. 파일 내용의 엔트로피를 바이트당 비트로 보여 줍니다 |
| `-r` | 인증서 폐기 (Revocation) 확인을 끕니다 |
| `-l` | 심볼릭 링크와 디렉터리 연결을 따라갑니다 |
| `-m` | 매니페스트를 덤프합니다 |
| `-c` / `-ct` | CSV 로 출력합니다. `-c` 는 쉼표, `-ct` 는 탭으로 나눕니다 |
| `-p` | 지정한 정책 GUID 로 서명을 검증합니다 |
| `-t[u][v]` | 인증서 저장소 내용을 덤프합니다. `-tu` 는 사용자 저장소입니다. `v` 를 붙이면 Microsoft 신뢰 루트 목록에 없는 인증서만 보여 줍니다 |
| `-v[r][s]` | 해시로 VirusTotal 을 조회합니다. `s` 를 붙이면 VirusTotal 이 모르는 파일을 올립니다 |
| `-o` | 예전에 `-h` 로 만든 CSV 의 해시로 VirusTotal 을 조회합니다. 문서는 오프라인 시스템용이라고 적습니다 |

옵션을 고를 때 세 가지를 확인합니다.

- **`-u` 의 뜻이 바뀝니다.** VirusTotal 검사를 켰는지에 따라 보여 주는 파일이 달라지므로 결과 목록에 어떤 조건으로 뽑았는지 적습니다.
- **`-vs` 는 파일 자체를 외부 서비스에 올립니다.** 사건 증거나 고객 파일이면 기밀 문제가 생기므로 해시만 보내는 `-v` 와 파일을 올리는 `-vs` 를 구분합니다.
- **오프라인 분석에서는 `-r` 을 검토합니다.** 폐기 확인은 네트워크를 타는데, 이미지를 분석하는 PC 가 네트워크에 붙지 않았다면 `-r` 로 끌 수 있습니다.

## YARA 로 좁히기

YARA 는 파일에서 찾을 문자열과 조건을 규칙으로 적어 검사하는 공개 도구이며, 아래 내용은 YARA 문서의 "Writing YARA rules" 를 따릅니다.

### 규칙의 모양

- 규칙은 `rule` 키워드와 규칙 이름으로 시작합니다.
- 규칙 이름은 영문자·숫자·밑줄로 쓰고, 최대 128자이며, 대소문자를 가립니다.
- 규칙에는 `meta`, `strings`, `condition` 절이 들어갑니다. `condition` 만 반드시 있어야 합니다.
- `meta` 값은 문자열(UTF-8), 정수, 참거짓 가운데 하나입니다.
- 규칙 이름 뒤에 `: Tag1 Tag2` 처럼 태그를 붙여 결과를 거를 수 있습니다.

### 문자열

| 종류 | 적는 법 | 예 |
|---|---|---|
| 텍스트 | 큰따옴표. 기본은 ASCII | `"example"` |
| 16진 | 중괄호 | `{ E2 34 A1 C8 23 FB }` |
| 정규식 | 빗금 | `/.../` |

16진 문자열에는 빈자리를 둘 수 있습니다.

| 적는 법 | 뜻 |
|---|---|
| `??` | 아무 바이트. 니블 단위로 `?` 하나만 써도 됩니다 |
| `[4-6]` | 4\~6바이트를 건너뜁니다 |
| `[10-]` | 10바이트 이상을 건너뜁니다 |
| `[-]` | 몇 바이트든 건너뜁니다 |
| `( 62 B4 \| 56 )` | 둘 중 하나 |

문자열 뒤에 수식어를 붙입니다.

| 수식어 | 뜻 |
|---|---|
| `nocase` | 대소문자를 가리지 않습니다 |
| `wide` | UTF-16 처럼 글자 사이에 0 바이트가 낀 형태를 찾습니다 |
| `ascii` | `wide` 와 함께 쓰면 ASCII 형태도 찾습니다 |
| `fullword` | 앞뒤가 영숫자가 아닌 문자일 때만 찾습니다 |
| `xor` | 한 바이트 XOR 로 바꾼 형태를 찾습니다 |
| `base64` | base64 로 바꾼 세 가지 형태를 찾습니다 |
| `private` | 결과 출력에서 숨깁니다 |

- `nocase` 는 `xor`·`base64` 와 함께 쓰지 못합니다.
- `xor` 는 `base64` 와 함께 쓰지 못합니다.
- `fullword` 는 `base64` 와 함께 쓰지 못합니다.

### 조건

| 적는 법 | 뜻 |
|---|---|
| `$a and $b or $c` | 문자열 일치를 논리식으로 묶습니다 |
| `#a` | `$a` 가 나온 횟수 |
| `@a[i]` | `$a` 의 i번째 위치 |
| `!a[i]` | `$a` 의 i번째 일치 길이 |
| `$a at 100` | 오프셋 100 에 있을 때 |
| `$a in (0..100)` | 0\~100 사이에 있을 때 |
| `filesize > 200KB` | 파일 크기 조건 |
| `uint16(0) == 0x5A4D` | 오프셋 0 의 2바이트 값 |
| `2 of ($a,$b,$c)` | 셋 가운데 둘 이상 |
| `any of ($foo*)` | `$foo` 로 시작하는 문자열 가운데 하나 이상 |
| `all of them` | 모든 문자열 |
| `for any of ($a*) : ( $ at pe.entry_point )` | `$a` 계열 가운데 하나가 진입점에 있을 때 |

- PE 파일인지 확인하는 조건은 문서에 `uint16(0) == 0x5A4D and uint32(uint32(0x3C)) == 0x00004550` 로 나옵니다.
- `import "pe"` 로 pe 모듈을 불러오면 `pe.entry_point`, `pe.imphash()`, `pe.sections`, `pe.number_of_sections` 등을 쓸 수 있습니다.
- 예전 변수 `entrypoint` 는 더 이상 권장하지 않습니다. `pe.entry_point` 를 씁니다.
- 모듈 변수가 맞지 않는 파일에서는 값이 정의되지 않습니다. 예를 들어 PE 가 아닌 파일에서 pe 조건은 정의되지 않은 값이 됩니다.
- `and`·`or` 는 정의되지 않은 값을 거짓으로 봅니다. 그래서 `정의 안 됨 and 참` 은 거짓이고, `정의 안 됨 or 참` 은 참입니다. 조건 전체가 정의되지 않으면 규칙은 걸리지 않습니다.
- `global` 규칙은 먼저 평가됩니다. 모든 `global` 규칙을 통과해야 나머지 규칙이 돕니다.
- `private` 규칙은 결과에 나오지 않습니다. 다른 규칙이 조건에서 참조할 수 있습니다.

### 예시 규칙

아래 규칙은 YARA 문서의 문법으로 만든 예시이며, 실제 악성 파일에서 뽑은 특징이 아닙니다.
사건에서 얻은 문자열 두 개 가운데 하나라도 들어 있는 PE 파일을 찾는 모양입니다.

```
rule Example_Case_Marker : triage example
{
    meta:
        description = "Example rule built from the YARA documentation syntax"
        is_example = true

    strings:
        $s1 = "example-marker-one" ascii wide nocase
        $s2 = "example-marker-two" fullword
        $h1 = { E2 34 ?? C8 [4-6] FB }

    condition:
        uint16(0) == 0x5A4D and
        uint32(uint32(0x3C)) == 0x00004550 and
        filesize < 500KB and
        (any of ($s*) or $h1)
}
```

- `triage`, `example` 은 태그입니다.
- `$s1` 은 대소문자와 관계없이 ASCII 형태와 UTF-16 형태를 모두 찾습니다.
- `$s2` 는 앞뒤가 영숫자가 아닐 때만 찾습니다.
- `$h1` 은 `E2 34` 다음에 아무 바이트 하나, 그다음 `C8` 이 오고, 다시 4\~6바이트를 건너뛴 곳에 `FB` 가 있으면 맞습니다.
- 조건 앞 두 줄은 PE 파일인지 확인하므로 PE 가 아닌 파일은 문자열이 있어도 걸리지 않습니다.

## 도구

아래 도구는 예로만 듭니다.

- **Sigcheck (Microsoft Sysinternals)**: 서명·카탈로그·해시·엔트로피를 한꺼번에 봅니다.
- **PowerShell**: 서명을 확인하는 명령이 있습니다. 결과 예는 [실행 파일 메타데이터](../../02-artifacts/embedded-metadata/pe-header-version-info-digital-signature.md) 에 있습니다.
- **YARA**: 규칙으로 파일을 검사합니다.
- **해시 도구**: [해시셋 대조와 유사 해시](hash-set-fuzzy-hash.md) 를 봅니다.
- 두 도구의 서명 판정이 다르면 [도구 결과 교차 검증](../reporting/tool-validation.md) 의 방법으로 맞춰 봅니다.

## 함정과 한계

- **카탈로그 서명 파일을 서명 없는 파일로 봅니다.** 파일 안에 서명이 없어도 카탈로그로 서명되었을 수 있습니다.
- **분석하는 PC 의 카탈로그로 이미지 속 파일을 판정합니다.** 이미지 속 Windows 의 카탈로그로 확인해야 합니다. Sigcheck 는 `-f` 로 카탈로그 파일을 지정할 수 있습니다.
- **서명이 있으니 안전하다고 씁니다.** 서명은 게시자와 변경 여부를 알려 줄 뿐, 그 게시자의 코드가 안전하다는 뜻은 아닙니다.
- **`-u` 결과를 조건 없이 옮깁니다.** VirusTotal 검사를 켰는지에 따라 목록의 뜻이 달라집니다.
- **증거 파일을 외부 서비스에 올립니다.** `-vs` 는 파일을 올립니다. 해시 조회와 파일 업로드를 구분합니다.
- **YARA 일치를 악성 판정으로 씁니다.** 규칙은 적힌 조건과 맞는 파일을 찾을 뿐입니다. 규칙의 출처와 뜻을 함께 적습니다.
- **YARA 불일치를 깨끗한 파일로 씁니다.** 규칙에 없는 특징은 찾지 못하고, pe 조건은 PE 가 아닌 파일에서 거짓으로 처리됩니다.
- **엔트로피만으로 판단합니다.** 엔트로피가 높다는 결과도 더 볼 파일을 고르는 신호일 뿐입니다.

## 결과를 어떻게 해석하나

| 신호 | 말해 주는 것 | 다음에 할 일 |
|---|---|---|
| 서명 없음 | 파일 안 서명도, 확인한 카탈로그의 서명도 없다는 것 | 이미지의 카탈로그로 다시 확인하고, 파일의 목적을 조사합니다 |
| 서명 검증 실패 | 서명이 있지만 검증을 통과하지 못했다는 것 | 서명 뒤로 파일이 바뀌었는지 [실행 파일 메타데이터](../../02-artifacts/embedded-metadata/pe-header-version-info-digital-signature.md) 의 방법으로 봅니다 |
| 엔트로피 높음 | 파일 내용의 바이트당 비트 수가 높다는 것 | 다른 신호와 함께 봅니다 |
| YARA 일치 | 규칙에 적힌 조건과 맞았다는 것 | 어느 문자열이 어디서 맞았는지 확인합니다 |
| 알려진 파일 목록과 일치 | 알려진 소프트웨어 파일이라는 것 | 해킹 도구도 목록에 있을 수 있으니 어떤 소프트웨어인지 봅니다 |

- 선별 결과는 "이 파일을 먼저 봐야 한다" 까지만 말합니다.
- 파일이 실행되었는지는 [어떤 프로그램을 언제 실행했나](../../04-scenarios/activity/program-execution.md) 에서 따로 확인합니다.
- 실행 중에 남는 서명·해시 기록은 [Sysmon 로그](../../02-artifacts/event-logs/sysmon/index.md) 에서 봅니다.
- 켜진 시스템에서 지금 도는 프로세스를 볼 때는 [라이브 응답](../process-acquisition/live-response/index.md) 을 봅니다.

보고서에는 어떤 조건으로 골랐는지를 씁니다.

> `<폴더>` 의 실행 이미지 `<개수>` 개 가운데, 파일 안 서명이 없고 이미지의 카탈로그에서도 서명을 찾지 못한 파일은 `<개수>` 개였다. 이 가운데 `<경로>` 는 YARA 규칙 `<규칙 이름>`(출처 `<출처>`)의 조건과 맞았다. 이 결과는 추가 분석 대상을 고른 것이며, 파일의 악성 여부를 판정한 것은 아니다.
