# 해시셋 대조와 유사 해시 (Hash Set·Fuzzy Hash)

> 위치: 분석 기법 > 분석

## 한 줄 요약

해시셋 대조는 증거 파일의 해시를 미리 모아 둔 해시 목록과 맞춰 보는 방법입니다.
이미 아는 파일을 걸러 볼 양을 줄이거나, 찾는 파일과 똑같은 파일을 찾을 때 씁니다.
유사 해시 (Fuzzy Hash) 는 똑같지는 않지만 비슷한 파일을 찾는 방법입니다.
증거 사본이 원본과 같은지 확인하는 해시 검증은 [증거 획득](../process-acquisition/evidence-acquisition/index.md) 에서 다룹니다.

## 언제 쓰나

- **운영체제·응용 프로그램 파일을 걸러 낼 때** 씁니다. 알려진 소프트웨어 파일을 빼면 사람이 볼 파일이 줄어듭니다.
- **찾는 파일의 해시를 이미 알 때** 씁니다. 유출된 문서나 사건에서 찾은 악성 파일과 똑같은 파일이 다른 곳에 있는지 찾습니다.
- **조금 고친 파일을 찾을 때** 씁니다. 내용을 일부 고친 문서나 다시 빌드한 실행 파일은 정확 일치로 찾지 못합니다. 이때 유사 해시를 씁니다.
- **아티팩트에 남은 해시를 맞춰 볼 때** 씁니다. [AmCache](../../02-artifacts/execution/amcache-hve/index.md) 에 남은 파일 해시가 그 예입니다.

## 알려진 파일 해시셋: NSRL RDS

알려진 파일 해시셋의 한 예는 NIST 의 국가 소프트웨어 참조 라이브러리 (National Software Reference Library, NSRL) 가 만드는 목록입니다.

NSRL 은 여러 곳에서 소프트웨어를 모으고, 모은 소프트웨어의 파일마다 프로필을 계산해 참조 데이터 세트 (Reference Data Set, RDS) 에 넣습니다.
NIST 는 RDS 를 "알려져 있고 출처를 따라갈 수 있는 소프트웨어의 디지털 서명 모음" 으로 설명하며, 여기서 디지털 서명은 해시를 뜻합니다. RDS 는 수사에서 파일을 식별하는 데 씁니다.
NIST 사이트 메뉴에는 "Current RDS Hash Sets", "Non-RDS Hash Sets", "RDS Query Tools" 항목이 있습니다.

RDS 에 무엇이 들어 있고 무엇이 빠져 있는지가 해석을 가릅니다.

| NIST 가 밝힌 것 | 해석 |
|---|---|
| 악성으로 볼 수 있는 응용 프로그램의 해시도 들어 있습니다. 예로 스테가노그래피 도구와 해킹 스크립트를 듭니다 | RDS 와 일치한다고 무해한 파일이 아닙니다. "알려진 소프트웨어 파일" 이라는 뜻일 뿐입니다 |
| 불법 데이터(예: 아동 학대 이미지)의 해시는 없습니다 | 불법 데이터를 찾는 목록으로 쓸 수 없습니다 |

- RDS 에 없는 파일은 "이 목록이 모르는 파일" 입니다. 의심 파일이라는 뜻이 아닙니다. 사용자가 만든 문서는 대부분 목록에 없습니다.
- RDS 가 어떤 해시 알고리즘을 담는지와 배포 형식은 이 페이지의 자료로 확인하지 못했습니다. 내려받은 판의 설명 문서를 보고, 증거 쪽에서도 같은 알고리즘으로 계산합니다.

## 정확 일치의 한계

암호 해시는 한 바이트만 달라도 전혀 다른 값이 나오는 것으로 알려져 있어서, 정확 일치 대조는 바이트가 모두 같은 파일만 찾습니다.
한 글자를 고친 문서, 다시 빌드한 실행 파일, 다른 형식으로 저장한 파일은 찾지 못하며, 이 빈틈을 채우는 방법이 아래의 유사 해시입니다.

### 해시를 뽑은 방식부터 맞춥니다

희소 (Sparse) 스트림은 구멍을 0 으로 채워 뽑느냐 건너뛰느냐에 따라 크기와 해시가 달라집니다(현장 관찰). `$UsnJrnl:$J` 가 대표적이고 희소 속성이 있는 일반 파일도 같습니다.
목록의 해시와 증거의 해시를 비교하기 전에, 두 쪽이 파일을 어떻게 뽑았는지 기록하고 맞춥니다.
뽑는 방식별 차이는 [증거 획득](../process-acquisition/evidence-acquisition/index.md) 의 해시 검증 글에 있습니다. `$UsnJrnl:$J` 자체는 [USN 변경 저널](../../02-artifacts/filesystem/usnjrnl.md) 에서 다룹니다.

## 유사 해시: ssdeep

ssdeep 은 공개된 유사 해시 도구로, 문맥 기반 조각 해시 (Context Triggered Piecewise Hashes, CTPH) 를 만듭니다.

### 출력 읽기

ssdeep 의 출력 첫 줄은 머리입니다.

```
ssdeep,1.1--blocksize:hash:hash,filename
```

그 아래로 파일마다 한 줄씩 나옵니다.
아래 줄은 ssdeep 문서에 실린 예를 그대로 옮긴 것입니다.

```
96:s4Ud1Lj96tHHlZDrwciQmA+4uy1I0G4HYuL8N3TzS8QsO/wqWXLcMSx:sF1LjEtHHlZDrJzrhuyZvHYm8tKp/RWO,"config.h"
```

| 자리 | 예의 값 | 뜻 |
|---|---|---|
| 첫째 칸 | `96` | 블록 크기 |
| 둘째 칸 | `s4Ud1Lj96t...LcMSx` | 첫째 해시 |
| 셋째 칸 | `sF1LjEtHHl...Kp/RWO` | 둘째 해시 |
| 쉼표 뒤 | `"config.h"` | 따옴표로 감싼 파일 이름 |

### 비교 결과 읽기

두 파일이 비슷하면 아래처럼 나옵니다(ssdeep 문서의 예).

```
bar.txt matches hashes.txt:foo.txt (99)
```

이 줄은 `bar.txt` 가 `hashes.txt` 에 적힌 `foo.txt` 와 비슷하다는 뜻입니다.
괄호 안 숫자는 일치 점수 (Match Score) 이고, 문서는 이 점수를 두 파일이 얼마나 비슷한지 가중해 잰 값이라고 설명합니다. 점수가 클수록 비슷합니다.
문서는 이 점수를 같은 바이트의 비율로 정의하지 않습니다. 그래서 `(99)` 를 "99% 같다" 로 옮겨 쓰지 않습니다.

### 주요 옵션

| 옵션 | 하는 일 |
|---|---|
| `-m` | 알려진 해시 목록 파일과 대조합니다 |
| `-k` | 알려진 서명 파일과 모르는 서명 파일을 대조합니다. 여러 개를 지정할 수 있습니다 |
| `-x` | 서명 파일끼리 서로 비교합니다 |
| `-d` | 입력 파일끼리 비교합니다. 해시를 저장하지 않습니다 |
| `-p` | `-d` 와 비슷하지만 양쪽 방향의 결과를 모두 보여 줍니다 |
| `-r` | 하위 폴더까지 처리합니다 |
| `-s` | 오류 메시지를 숨깁니다 |

- 사건 파일로 해시 목록을 먼저 만들고, 증거 전체를 `-m` 이나 `-k` 로 대조할 수 있습니다.
- 점수 기준값, 작은 파일에서의 동작, 블록 크기가 다른 해시끼리의 비교 규칙은 이 페이지의 자료로 확인하지 못했습니다. 쓰는 판의 문서를 확인합니다.
- TLSH·sdhash 같은 다른 유사 해시도 알려져 있습니다. 이 페이지의 자료로는 그 점수의 뜻을 확인하지 못했습니다. 그래서 도구가 다르면 점수를 서로 비교하지 않습니다.

## 실행 파일끼리 묶기: 가져오기 해시

YARA 의 pe 모듈에는 가져오기 해시 (Import Hash) 를 돌려주는 `pe.imphash()` 가 있으며, 가져오는 함수 목록이 같은 실행 파일끼리 묶는 데 씁니다.
파일 내용 해시가 달라도 가져오기 해시가 같을 수 있습니다. 그래서 다시 빌드한 실행 파일을 묶는 단서가 됩니다.
YARA 규칙을 쓰는 법은 [의심 실행 파일 선별](code-signing-yara.md) 에서 다룹니다.

## 절차

1. **대조할 목록을 정합니다.** 목록마다 출처, 판, 내려받은 날짜, 알고리즘을 적습니다.
2. **증거에서 해시를 계산합니다.** 목록과 같은 알고리즘을 씁니다. 희소 스트림처럼 뽑는 방식에 따라 값이 달라지는 파일은 방식을 기록합니다.
3. **알려진 파일을 거릅니다.** 걸러 낸 파일은 지우지 않고 "알려진 파일" 로 표시만 합니다. RDS 에는 해킹 도구 해시도 있으므로, 어떤 소프트웨어의 파일로 일치했는지도 봅니다.
4. **찾는 파일과 정확히 대조합니다.** 사건에서 모은 해시 목록으로 대조합니다.
5. **정확히 일치하지 않은 관심 파일은 유사 해시로 넓힙니다.** 사건 파일의 유사 해시 목록을 만들고 증거 전체와 대조합니다.
6. **유사 해시로 걸린 파일은 직접 엽니다.** 두 파일을 나란히 놓고 같은 부분과 다른 부분을 확인합니다.
7. **필요하면 해시로 평판을 조회합니다.** Sigcheck 의 `-h` 는 파일 해시를 보여 줍니다. `-o` 는 예전에 `-h` 로 만들어 둔 CSV 의 해시로 VirusTotal 을 조회합니다. 문서는 `-o` 를 오프라인 시스템 검사용이라고 적습니다. 파일 자체를 올리는 옵션과의 차이는 [의심 실행 파일 선별](code-signing-yara.md) 에 있습니다.

## 도구

아래 도구는 예로만 듭니다.

- **해시 계산 도구**: 어느 도구든 알고리즘과 입력 바이트가 같으면 값이 같아야 합니다. 몇 개는 두 도구로 계산해 맞춰 봅니다.
- **NSRL RDS**: NIST 사이트에서 해시셋과 조회 도구(RDS Query Tools)를 안내합니다.
- **ssdeep**: 유사 해시를 만들고 비교합니다.
- **YARA 의 pe 모듈**: `pe.imphash()` 로 가져오기 해시를 씁니다.
- **Sigcheck (Microsoft Sysinternals)**: 파일 해시를 보여 주고, 해시로 평판을 조회합니다.
- 도구마다 결과가 다르면 [도구 결과 교차 검증](../reporting/tool-validation.md) 을 봅니다.

## 함정과 한계

- **RDS 와 일치한 파일을 무해하다고 봅니다.** RDS 에는 악성으로 볼 수 있는 응용 프로그램 해시도 들어 있습니다.
- **RDS 에 없는 파일을 의심 파일로 봅니다.** 사용자 문서처럼 목록에 없는 것이 정상인 파일이 대부분입니다.
- **알고리즘이 다른 해시를 비교합니다.** 목록과 증거가 같은 알고리즘인지 먼저 봅니다.
- **뽑는 방식을 맞추지 않습니다.** 희소 스트림은 뽑는 방식에 따라 해시가 달라집니다(현장 관찰).
- **정확 일치가 없으니 같은 파일이 없다고 씁니다.** 한 바이트만 달라도 정확 일치는 실패합니다. 유사 해시로 한 번 더 봅니다.
- **유사 해시 점수를 비율로 씁니다.** 문서는 점수를 가중한 유사도로만 설명합니다.
- **유사 해시가 비슷하다고 같은 사람이 만들었다고 씁니다.** 같은 틀이나 같은 라이브러리를 쓴 파일도 비슷하게 나올 수 있습니다.

## 결과를 어떻게 해석하나

| 결과 | 말해 주는 것 | 말해 주지 못하는 것 |
|---|---|---|
| 정확 일치 | 두 파일의 내용이 바이트까지 같다는 것 | 이름·경로·시각이 같다는 것, 누가 그 파일을 옮겼는지 |
| RDS 일치 | 그 파일이 목록에 있는 알려진 소프트웨어 파일이라는 것 | 그 파일이 무해하다는 것 |
| RDS 불일치 | 목록이 그 파일을 모른다는 것 | 그 파일이 의심스럽다는 것 |
| 유사 해시 일치 | 도구가 두 파일을 비슷하다고 잰 것 | 한 파일을 고쳐 다른 파일을 만들었다는 것 |
| 가져오기 해시 일치 | 두 실행 파일의 가져오기 목록이 같다는 것 | 두 파일이 같은 계열의 프로그램이라는 것 |

- 해시는 파일 내용으로 계산합니다. 파일 이름과 파일 시스템 시각은 따로 확인합니다.
- 파일이 언제 어디서 들어왔는지는 [이 파일은 어디서 왔나](../../04-scenarios/activity/file-origin.md) 에서 찾습니다.

보고서에는 어떤 목록과 어떤 방법으로 대조했는지를 씁니다.

> 증거 `<경로>` 의 `<알고리즘>` 해시는 사건 자료 `<파일 이름>` 의 해시와 같다. 유사 해시 대조(ssdeep, `<판>`)에서 `<다른 경로>` 는 같은 사건 자료와 일치 점수 `<점수>` 로 나왔다. ssdeep 문서는 이 점수를 두 파일의 비슷한 정도를 가중해 잰 값으로 설명하며, 같은 내용의 비율로 설명하지 않는다.
