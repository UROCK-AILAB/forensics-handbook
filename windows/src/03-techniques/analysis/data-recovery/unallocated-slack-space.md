# 비할당 영역과 슬랙 (Unallocated·Slack Space)

## 한 줄 요약

비할당 영역 (Unallocated Space) 은 파일이나 파티션에 할당되지 않은 공간이고, 슬랙 공간 (Slack Space) 은 할당된 블록 안에서 쓰지 않는 부분입니다. 두 곳 모두 지운 파일 조각 같은 옛 데이터가 남을 수 있으며, 이 데이터는 비트 단위 이미지에만 담깁니다.

이 페이지는 [삭제 데이터 복구 (Data Recovery)](index.md) 의 하위 주제입니다. 여기서 찾은 데이터를 파일로 되살리는 법은 [파일 카빙 (File Carving)](file-carving.md) 과 [레코드 카빙 (Record Carving)](record-carving.md) 에 있습니다. 파일시스템 기록으로 되살리는 법은 [파일시스템 기반 복구 (Undelete: NTFS·FAT)](undelete-ntfs-fat.md) 에 있습니다.

## 언제 쓰나

- 파일시스템 기록으로 되살릴 수 없는 조각을 찾을 때 씁니다.
- 키워드나 서명 검색 범위를 파일 밖까지 넓힐 때 씁니다. 검색 방법은 [파일 내용 검색](../content-search/index.md) 에 있습니다.
- 숨긴 데이터를 찾을 때 씁니다. NIST SP 800-86 은 데이터가 숨을 수 있는 자리로 네 곳을 듭니다. NTFS 대체 데이터 스트림 (ADS), 파일 끝 슬랙, 빈 공간, 일부 하드디스크의 HPA(제조사용 영역) 입니다. 증거를 없애려 한 정황은 [증거를 없애려 했나](../../../04-scenarios/activity/anti-forensics/index.md) 에서 다룹니다.

## 무엇이 어디에 남나

> 그림 자리: 클러스터 네 개를 쓰는 파일 하나. 마지막 클러스터 안에서 파일 끝 뒤의 슬랙을 색으로 나누고, 그 옆에 어느 파일에도 속하지 않은 비할당 클러스터를 보여 주는 그림

| 공간 | 뜻 | 남을 수 있는 것 |
|---|---|---|
| 빈 공간 (Free Space) | 매체에서 파티션에 할당되지 않은 영역입니다. 할당되지 않은 클러스터·블록도 여기에 듭니다. | 예전에 그 자리에 있던 파일이나 볼륨 전체의 데이터 조각 |
| 파일 슬랙 (File Slack) | 파일에 잡힌 마지막 할당 단위에서 파일 끝 뒤로 남는 부분 | 지운 파일 조각 같은 옛 데이터 |
| 색인 슬랙 | NTFS 색인 노드에서 쓰는 항목 뒤의 나머지 공간 | 옛 데이터 또는 0 |
| EVTX 청크 빈 공간 | 이벤트 로그 청크 안의 빈 공간 | 옛 이벤트 레코드. [레코드 카빙](record-carving.md) 에서 다룹니다. |

NIST 용어 풀이는 빈 공간을 "매체나 메모리에서 할당되지 않은 영역" 이라고 적고, 슬랙 공간은 "할당 블록이나 메모리 페이지 안에서 쓰지 않는 부분" 이라고 적습니다.

### 파일 슬랙 계산

파일이 할당 단위보다 작아도 할당 단위 전체가 파일에 잡힙니다. NIST SP 800-86 의 예는 이렇습니다. 할당 단위가 32KB 이고 파일이 7KB 이면 32KB 가 모두 파일에 잡히고 남는 25KB 가 파일 슬랙입니다.

파일이 할당 단위 여러 개를 쓰면 마지막 단위에서 같은 계산을 합니다. 아래 숫자는 설명을 위해 정한 값입니다.

```
할당 단위 크기   = 4,096바이트
파일 크기        = 10,000바이트
필요한 단위 수   = 10,000 ÷ 4,096 을 올림 = 3
파일에 잡힌 크기 = 3 × 4,096 = 12,288바이트
파일 슬랙        = 12,288 − 10,000 = 2,288바이트 (파일 안 오프셋 10,000 부터)
```

### 파일시스템별 비할당 판단

| 파일시스템 | 판단하는 자리 | 비할당 값 |
|---|---|---|
| NTFS | $Bitmap (MFT 레코드 6번). 볼륨 클러스터마다 할당 여부를 적습니다. | 비트 0 |
| exFAT | 할당 비트맵. 비트 하나가 클러스터 하나이고, 최하위 비트부터 셉니다. | 비트 0. 1 은 할당된 클러스터입니다. |
| FAT12·FAT16·FAT32 | FAT 표 | 값 0. 다른 값의 뜻은 [파일시스템 기반 복구](undelete-ntfs-fat.md) 에 있습니다. |

## 절차

1. 비트 단위 이미지로 수집합니다. 파일·폴더를 복사하는 논리 백업에는 지운 파일과 슬랙의 옛 데이터가 담기지 않습니다. 이미지 방법은 [증거 획득](../../process-acquisition/evidence-acquisition/index.md) 에 있습니다.
2. RAID-0·RAID-5 처럼 줄무늬 (Striping) 로 묶인 볼륨은 모든 디스크를 이미지로 뜨고 RAID 구성을 다시 맞춰야 빈 공간과 슬랙까지 볼 수 있습니다.
3. 파티션에 할당되지 않은 영역을 찾습니다. 파티션 표를 읽는 법은 [파티션 구조](../../../01-foundations/disk-volume/mbr-gpt.md) 에 있습니다.
4. 볼륨마다 위 표의 자리를 읽어 비할당 클러스터 목록을 만듭니다.
5. 비할당 클러스터를 뽑아 파일로 저장합니다. 뽑은 파일의 오프셋이 이미지의 어느 클러스터였는지 대응표를 함께 남깁니다.
6. 파일마다 슬랙 범위를 계산해 뽑습니다. 이때도 원래 파일과 오프셋을 함께 적습니다.
7. NTFS 폴더 색인 블록에서 쓰는 항목 뒤 나머지 공간을 따로 봅니다. 해석은 [폴더 인덱스와 슬랙](../../../02-artifacts/filesystem/i30.md) 에 있습니다.
8. 뽑은 데이터에 키워드 검색, 파일 카빙, 레코드 카빙을 합니다.

## 도구

NIST SP 800-86 은 다음 도구를 듭니다.

- 빈 공간에서 데이터를 뽑아 파일로 저장하는 도구
- 헥스 편집기
- 슬랙 공간 전용 도구

디스크 이미지 하나에 슬랙과 빈 공간이 수 GB 들어갈 수 있고 그 안의 파일과 조각은 수천 개일 수 있어서 손으로 뽑기 어려우므로 도구를 씁니다. 도구마다 결과가 다르면 [도구 결과 교차 검증](../../reporting/tool-validation.md) 을 따릅니다.

## 함정과 한계

- 논리 백업만 받았다면 이 분석을 할 수 없으며, 이는 수집 단계에서 이미 정해집니다.
- 희소 구간은 비할당 영역도 슬랙도 아닙니다. 희소 구간은 데이터 런에 위치가 없는 구간이라서 이 구간의 0 은 디스크에서 읽은 바이트가 아닙니다.
- $UsnJrnl:$J 는 앞부분이 비어 있는 희소 스트림입니다. 구멍을 0 으로 채우면 논리 크기(수 GB)가 되고, 건너뛰면 실제 데이터만 남습니다. 두 결과는 크기와 해시가 다르므로 뽑은 방식을 적습니다(현장 관찰). $J 자체는 [USN 변경 저널](../../../02-artifacts/filesystem/usnjrnl.md) 에서 다룹니다.
- SSD 에서는 비할당 영역이 이미 비워져 있을 수 있습니다. [SSD TRIM과 복구 한계 (SSD·TRIM)](ssd-trim.md) 를 봅니다.

## 결과를 어떻게 해석하나

- 비할당 클러스터는 지금 어느 파일도 쓰지 않는 자리라서 거기서 나온 조각이 어느 파일의 것이었는지는 파일시스템 기록으로 바로 알 수 없습니다.
- 슬랙은 지금 파일의 마지막 할당 단위 안에 있지만 슬랙 바이트가 그 파일의 내용인 것은 아니므로 지금 파일과 슬랙 조각을 같은 파일로 묶어 쓰지 않습니다.
- 조각에는 쓴 시각이 따로 붙지 않으며, 조각 안에 형식이 스스로 적어 둔 시각이 있으면 그 값만 씁니다. 그런 예는 [레코드 카빙](record-carving.md) 에 있습니다.

**증명하는 것**

- 그 바이트가 이미지의 그 오프셋에 있었다는 것
- 그 자리가 수집 시점에 비할당이었거나 어느 파일의 슬랙이었다는 것

**증명하지 못하는 것**

- 그 조각이 어느 파일의 일부였는지
- 언제 쓰였고 언제 지워졌는지
- 누가 썼는지

보고서 문장 예: "이미지 오프셋 X\~Y 의 비할당 클러스터에서 문자열 Z 가 나왔다. 수집 시점에 이 클러스터는 어느 파일에도 할당되지 않은 상태였다. 이 데이터가 어느 파일의 일부였는지, 언제 쓰였는지는 파일시스템 기록에 없다."
