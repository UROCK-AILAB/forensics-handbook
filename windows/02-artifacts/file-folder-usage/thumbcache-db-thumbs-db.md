# 썸네일 캐시 (thumbcache_*.db·Thumbs.db)

## 한 줄 요약

썸네일 캐시 (thumbnail cache) 는 탐색기가 쓰는 미리 보기 그림을 모아 둔 파일입니다. Windows Vista 부터는 사용자 프로필 안의 `thumbcache_*.db` 파일에 그림이 모입니다. XP 에서는 폴더마다 숨김 파일 `Thumbs.db` 가 생겼습니다. 그림은 남지만, Windows 7 이후 형식에는 원본 파일의 이름과 시각을 담는 필드가 문서화돼 있지 않습니다.

## 무엇을 기록하나 · 왜 생기나

캐시 파일에는 미리 보기 그림이 항목 단위로 들어 있고, 항목 하나에는 항목 해시 (8바이트), 식별자 문자열, 그림 데이터가 들어갑니다. 데이터가 없는 항목도 있습니다.

Vista 이후에는 캐시 종류마다 파일이 따로 있고, 색인 파일 `thumbcache_idx.db` 가 항목 해시와 캐시 파일 안의 항목 위치를 모아 둡니다.

### 기록이 생기는 계기

XP 의 Thumbs.db 는 폴더를 미리 보기 (thumbnail) 보기로 볼 때 Windows 가 만듭니다. Vista 와 7 에서는 폴더마다 두던 파일이 사라지고 사용자 프로필의 중앙 데이터베이스로 옮겨졌습니다. 중앙 데이터베이스에 어떤 동작으로 그림이 들어가는지는 정확한 조건이 공개된 자료가 없어 실험으로 확인합니다. Windows 7 이후에도 조건이 맞으면 Thumbs.db 가 생기며, 조건은 아래 "위치와 버전별 차이" 에 정리했습니다.

## 위치와 버전별 차이

### 위치

| 파일 | 위치 | Windows |
|---|---|---|
| `thumbcache_*.db` | `\Users\<사용자>\AppData\Local\Microsoft\Windows\Explorer` | Vista 이후 |
| `Thumbs.db` | 미리 보기를 만든 폴더 안. 숨김 파일입니다 | XP. 7 이후는 조건에 따라 생깁니다 |

중앙 캐시는 사용자 프로필 폴더 안에 있어서 어느 계정의 캐시인지 가를 수 있습니다. 프로필 폴더와 계정의 짝은 [사용자 프로필 목록](../system-account/profilelist.md) 으로 확인합니다.

Windows 11 25H2 의 `%LOCALAPPDATA%\Microsoft\Windows\Explorer` 폴더에는 다음 파일이 있습니다.

- `thumbcache_16`, `_32`, `_48`, `_96`, `_256`, `_768`, `_1280`, `_1920`, `_2560`, `_custom_stream`, `_exif`, `_idx`, `_sr`, `_wide`, `_wide_alternate` (모두 확장자 `.db`)
- `thumbcache_1920`, `_2560`, `_custom_stream`, `_sr`, `_wide_alternate` 는 크기가 24바이트일 수 있습니다. 헤더만 있고 항목이 없는 파일입니다.
- 같은 폴더에 이름 규칙이 같은 `iconcache_*.db` 파일도 있습니다. iconcache 는 이 페이지에서 다루지 않습니다.

### 형식 버전

캐시 파일 헤더의 형식 버전 값으로 어느 Windows 에서 만든 파일인지 가릅니다.

| 형식 버전 | Windows |
|---|---|
| 20 | Vista |
| 21 | 7 |
| 30 | 8.0 |
| 31 | 8.1 |
| 32 | 10 · 11 |

Windows 11 25H2 의 thumbcache 파일은 형식 버전이 모두 `0x20` (32) 입니다.

### Thumbs.db 가 생기는 조건

| Windows | 조건 |
|---|---|
| XP | 폴더를 미리 보기 보기로 볼 때 만듭니다 |
| 7 | 평소 탐색기로 볼 때는 만들지 않습니다. 같은 폴더를 네트워크 경로 (예: `\\localhost\c$`) 로 보면 만듭니다 |
| 8 · 8.1 | 사용자 프로필 폴더 (`C:\Users\<사용자>\` 아래) 에서만 만듭니다. 다른 폴더도 네트워크 경로로 열면 만듭니다 |
| 10 · 11 | 공개 자료 없음 |

네트워크 폴더에서 Thumbs.db 를 막는 정책은 아래 "함정과 한계" 에서 다룹니다. 공유 폴더 흔적은 [공유 폴더·네트워크 드라이브](../network/network-shares-mapped-drives.md) 에서 봅니다.

## 구조

정수는 리틀 엔디언입니다.

### 캐시 파일 헤더 (24바이트)

| 오프셋 | 크기 | 내용 |
|---|---|---|
| 0 | 4 | 서명 `CMMM` |
| 4 | 4 | 형식 버전 |
| 8 | 4 | 캐시 종류 |
| 12 | 4 | 첫 캐시 항목의 오프셋. 항목이 없으면 0 |
| 16 | 4 | 첫 빈 캐시 항목의 오프셋 |
| 20 | 4 | 캐시 항목 수로 알려져 있지만 확실하지 않습니다 |

Windows 11 25H2 의 형식 버전 32 파일에서는 오프셋 12 뒤의 값이 이 표와 한 필드씩 어긋납니다.

- 오프셋 12 는 0 입니다.
- 오프셋 16 은 24 입니다. 실제 첫 `CMMM` 항목이 24 에서 시작합니다.
- 오프셋 20 은 파일 크기에 가까운 값입니다. 그 위치는 항목 경계 (`CMMM`) 입니다.

버전 32 에서 오프셋 16·20 의 정확한 뜻은 공개된 자료가 없습니다.

### 캐시 종류 값 (헤더 오프셋 8)

같은 값이라도 형식 버전마다 뜻이 다릅니다.

| 값 | 버전 20 · 21 | 버전 30 | 버전 31 | 버전 32 |
|---|---|---|---|---|
| 0 | 32 | 16 | 16 | 16 |
| 1 | 96 | 32 | 32 | 32 |
| 2 | 256 | 48 | 48 | 48 |
| 3 | 1024 | 96 | 96 | 96 |
| 4 | sr | 256 | 256 | 256 |
| 5 | | 1024 | 1024 | 768 |
| 6 | | sr | 1600 | 1280 |
| 7 | | wide | sr | 1920 |
| 8 | | exif | wide | 2560 |
| 9 | | | exif | sr |
| 10 | | | wide_alternate | wide |
| 11 | | | | exif |
| 12 | | | | wide_alternate |
| 13 | | | | custom_stream |

표의 이름은 `thumbcache_<이름>.db` 의 파일 이름과 맞춰 읽습니다. Windows 11 25H2 에서 `thumbcache_16` 은 0, `_96` 은 3, `_256` 은 4, `_1280` 은 6, `_1920` 은 7 로, 버전 32 열과 맞습니다.

### 캐시 항목 (버전 30 이후)

| 오프셋 | 크기 | 내용 |
|---|---|---|
| 0 | 4 | 서명 `CMMM` |
| 4 | 4 | 항목 크기. 서명까지 포함합니다 |
| 8 | 8 | 항목 해시. 해시 방식은 알려져 있지 않습니다 |
| 16 | 4 | 식별자 문자열의 크기 (바이트) |
| 20 | 4 | 채움 (padding) 의 크기 |
| 24 | 4 | 데이터의 크기 |
| 28 | 4 | 알 수 없음 |
| 32 | 8 | 알 수 없음 |
| 40 | 8 | 데이터 체크섬 (CRC-64) |
| 48 | 8 | 헤더 체크섬 (CRC-64). 앞 48바이트로 계산합니다 |
| 56 | 가변 | 식별자 문자열. UTF-16LE 이고 끝 문자가 없습니다 |
| 그 뒤 | 가변 | 채움 |
| 그 뒤 | 가변 | 데이터 (그림) |

앞 버전은 헤더가 다릅니다.

| 형식 버전 | 다른 점 |
|---|---|
| 21 | 헤더가 48바이트입니다. 식별자 문자열이 오프셋 48 에서 시작합니다. 헤더 체크섬은 앞 40바이트로 계산합니다 |
| 20 | 오프셋 16 에 파일 확장자 필드 (8바이트, UTF-16LE) 이 있습니다. 식별자 문자열은 오프셋 56 에서 시작합니다. 확장자 필드는 버전 21 에서 없어졌습니다 |

- 식별자 문자열은 64비트 ThumbnailCacheId 를 앞자리 0 없이 16진수로 쓴 값일 수 있습니다.
- CRC-64 의 다항식은 알려져 있지 않습니다. 조회표는 `thumbcache.dll` 안에 있습니다. 계산할 때 처음과 마지막에 -1 로 XOR 하지 않는다고 알려져 있지만, 같은 자료의 헤더 체크섬 필드 설명은 초기값을 -1 로 둔다고 해 서로 어긋납니다.
- 문자열 인코딩은 [문자 인코딩](../../01-foundations/value-decoding/utf-16le-utf-8-cp949.md) 에서 다룹니다.

Windows 11 25H2 캐시 파일의 예는 다음과 같습니다.

- `thumbcache_256.db` 한 개에 항목 2,433개가 끝까지 이어져 있습니다. 데이터 없는 항목이 972개, JPEG 가 1,010개, PNG 가 451개입니다.
- `thumbcache_96.db` 는 항목 429개 가운데 BMP 가 428개, 데이터 없는 항목이 1개입니다.
- 식별자 문자열은 32바이트 (16진 숫자 16자) 가 가장 많습니다. 16진수가 아니면서 더 긴 식별자도 있습니다.

### 색인 파일 thumbcache_idx.db

색인 파일의 서명은 `IMMM` 입니다. 버전에 따라 헤더 크기와 필드 위치가 다릅니다.

| 버전 20 · 21 (24바이트) | | 버전 30 이후 (28바이트) | |
|---|---|---|---|
| 오프셋 0 | 서명 `IMMM` | 오프셋 0 | 알 수 없음 (4바이트) |
| 오프셋 4 | 형식 버전 | 오프셋 4 | 서명 `IMMM` |
| 오프셋 8 | 알 수 없음 | 오프셋 8 | 형식 버전 |
| 오프셋 12 | 사용 중 항목 수 | 오프셋 12 | 알 수 없음 (8바이트) |
| 오프셋 16 | 전체 항목 수 | 오프셋 20 | 사용 중 항목 수 |
| 오프셋 20 | 빈 값 | 오프셋 24 | 전체 항목 수 |

Windows 11 25H2 의 색인 파일은 오프셋 4 에 `IMMM`, 8 에 `0x20` (32) 이 있어 버전 30 이후 표와 맞습니다. 예로 든 파일의 오프셋 20 은 2,926, 오프셋 24 는 6,464 입니다.

색인 항목 하나의 크기는 버전마다 다릅니다.

| 형식 버전 | 20 | 21 | 30 | 31 | 32 |
|---|---|---|---|---|---|
| 색인 항목 크기 (바이트) | 40 | 32 | 56 | 64 | 72 |

버전 32 색인 항목의 필드는 다음과 같습니다.

| 오프셋 | 크기 | 내용 |
|---|---|---|
| 0 | 8 | 항목 해시 |
| 8 | 8 | 알 수 없음. 플래그로 보입니다 |
| 16 | 14 × 4 | 캐시 항목 오프셋 14개의 배열 |

- 배열 원소 수 14 는 버전 32 캐시 종류 값의 개수 (0~13) 와 같습니다. 각 원소가 어느 캐시 파일인지는 캐시 종류 표로 읽습니다. 이 순서가 맞는지는 실제 데이터로 확인합니다.
- 배열의 오프셋은 캐시 파일 시작에서 센 32비트 값입니다. 0 은 설정되지 않음, -1 은 그 캐시 파일에 항목이 없음을 뜻합니다.
- 버전 32 의 오프셋 8 필드는 뜻이 알려져 있지 않고, 플래그로 보입니다. 알려진 플래그 표는 버전 20·21 색인 항목의 것입니다. 이 표에서도 `0x00000001` (데이터 없는 항목일 때 켜지는 것으로 보임) 은 확실하지 않고, 다른 값 (`0x2`, `0x200` … `0x80000000`) 은 뜻이 알려져 있지 않습니다.
- 버전 20 색인 항목에만 오프셋 8 에 마지막 수정 시각 (FILETIME) 필드가 있습니다. 그 뒤 버전에는 시각 필드가 문서화돼 있지 않습니다.

### Thumbs.db

Thumbs.db 는 Office 문서와 같은 형식인 OLE 복합 파일 (Compound File) 이고, 스트림을 꺼내는 방법은 [OLE 복합 파일](../../01-foundations/shell-document-formats/compound-file-binary.md) 에서 다룹니다. Windows 7 이후의 Thumbs.db 도 OLE 컨테이너이지만 Catalog 스트림이 없고 몇 가지가 바뀌었습니다.


- XP Thumbs.db 의 Catalog 스트림에 파일 이름과 시각이 들어 있다는 설명이 널리 쓰입니다. 그 구조와 스트림 이름 규칙은 실제 데이터로 확인해야 합니다.

## 증거로서 의미

| 증명하는 것 | 증명하지 못하는 것 |
|---|---|
| 이 사용자 프로필의 캐시에 이 미리 보기 그림이 저장된 적이 있습니다 | 원본 파일의 이름과 경로 (버전 21 이후) |
| 그림에 무엇이 보이는지 | 그림을 언제 만들었는지 (버전 21 이후) |
| 어느 캐시 종류 파일에 들어 있는지 | 사용자가 원본 파일을 열었는지 |
| Thumbs.db 가 있는 폴더라면, 그 폴더에서 미리 보기를 만든 적이 있습니다 | 원본 파일이 지금도 있는지 |
| | 그 계정 앞에 실제로 누가 앉아 있었는지 |

캐시 항목의 그림은 원본 파일이 아니므로, 원본은 파일 시스템에서 따로 찾습니다. 데이터 없는 항목은 그림이 없는 항목이라 무엇이 있었는지 말하지 못합니다. 캐시에 그림이 없다는 사실로 그 파일이 없었다고 단정하지도 않습니다. 정책으로 미리 보기를 껐거나 캐시를 비웠을 수 있기 때문입니다.

### 보고서 문장

아래 식별자와 그림 내용은 설명을 위해 만든 예입니다.

- 쓸 수 있는 문장: "사용자 A 프로필의 `thumbcache_256.db` 에 식별자가 `8f3c2a1b0d9e7f65` 인 항목이 있습니다. 이 항목의 데이터는 JPEG 그림이고, 그림에는 설계 도면이 보입니다. 이 캐시 형식에는 원본 파일 이름과 시각이 남지 않습니다."
- 쓰면 안 되는 문장: "사용자 A 가 설계 도면 파일을 열어 보았습니다."

## 시각 해석

| 시각 | 어디에 남나 | 무엇을 가리키나 |
|---|---|---|
| 색인 항목의 마지막 수정 시각 | 버전 20 (Vista) 색인 항목의 오프셋 8 | "마지막 수정 시각" 이라는 이름의 값입니다. FILETIME 형식입니다 |
| 캐시 파일 자체의 시각 | 파일 시스템 (MFT) | 캐시 파일이 바뀐 때. 항목 하나가 들어간 때가 아닙니다 |

버전 21 이후 캐시 파일과 색인 파일에는 원본 파일의 시각이나 캐시를 만든 시각 필드가 문서화돼 있지 않고, 캐시 파일의 파일 시스템 시각은 파일 전체에 하나뿐이라 항목마다 따로 시각을 알려 주지 않습니다. 그래서 시각은 다른 기록에서 찾습니다. 원본 파일의 시각은 [마스터 파일 테이블](../filesystem/mft.md) 에서, 폴더를 연 시각은 [셸백](shellbags/index.md) 에서, 파일을 연 시각은 [바로가기 파일](lnk.md) 과 [점프리스트](jump-lists.md) 에서 찾습니다.
- FILETIME 계산은 [시각 값 형식](../../01-foundations/value-decoding/filetime-unix-webkit-dos-ole.md) 에서 다룹니다.

## 함정과 한계

1. **캐시 종류 값을 다른 버전 표로 읽습니다.** 값 5 는 버전 30·31 에서 1024 이고, 버전 32 에서 768 입니다. 먼저 헤더의 형식 버전을 읽습니다.
2. **버전 32 파일 헤더를 문서 순서대로 믿습니다.** 오프셋 12~23 의 값은 구조 표와 어긋납니다. 항목은 `CMMM` 서명과 항목 크기로 하나씩 따라가며 확인합니다.
3. **24바이트 파일을 손상으로 봅니다.** 헤더만 있는 빈 캐시입니다.
4. **식별자를 파일 이름으로 읽습니다.** 식별자는 ThumbnailCacheId 의 16진수 표기일 수 있습니다. 파일 이름이 아닙니다. 이 값이 [윈도 검색 색인 DB](windows-search/index.md) 의 속성과 이어진다는 설명이 있지만, 굳어진 사실은 아닙니다.
5. **원본을 지운 뒤에도 그림이 남는다고 단정합니다.** Thumbs.db 는 원본 그림을 폴더에서 옮기거나 지워도 갱신되지 않습니다. thumbcache 도 그런지는 공개 자료가 없으므로, 실험으로 확인하기 전에는 보고서에 쓰지 않습니다.
6. **Thumbs.db 가 없으면 미리 보기를 안 봤다고 봅니다.** Windows 7 이후 로컬 폴더에서는 기본으로 만들지 않습니다. Windows 10·11 에서 만드는 조건은 공개 자료가 없습니다.
7. **체크섬 검증 결과를 그대로 믿습니다.** CRC-64 다항식이 알려져 있지 않습니다. 도구마다 검증 방식이 다를 수 있습니다.

### 설정과 지우기

미리 보기와 Thumbs.db 에 관한 정책은 사용자 구성 > Windows 구성 요소 > File Explorer 아래에 있습니다 (ADMX 파일 `Thumbnails.admx`).

| 정책 | 키 · 값 | 켜면 |
|---|---|---|
| Turn off the caching of thumbnails in hidden thumbs.db files | `Software\Policies\Microsoft\Windows\Explorer` · `DisableThumbsDBOnNetworkFolders` | 탐색기가 thumbs.db 를 만들지도, 읽지도, 쓰지도 않습니다. 이 정책은 네트워크 폴더 항목의 미리 보기를 숨김 thumbs.db 에 저장하는 설정입니다 |
| Turn off the display of thumbnails and only display icons on network folders | `Software\Microsoft\Windows\CurrentVersion\Policies\Explorer` · `DisableThumbnailsOnNetworkFolders` | 네트워크 폴더에서 아이콘만 보입니다 |
| Turn off the display of thumbnails and only display icons | `Software\Microsoft\Windows\CurrentVersion\Policies\Explorer` · `DisableThumbnails` | 로컬 폴더에서도 아이콘만 보입니다 |

- 이 세 정책을 MDM (Policy CSP) 으로 설정할 수 있는 버전은 Windows 10 2004·20H2·21H1 (KB5005101 이후) 과 Windows 11 21H2 이후입니다. 그룹 정책이 처음 나온 버전이 아닙니다.
- thumbcache 자체를 끄는 정책은 알려진 것이 없습니다.
- 캐시 파일을 지우거나 비운 흔적은 [마스터 파일 테이블](../filesystem/mft.md) 과 [USN 변경 저널](../filesystem/usnjrnl.md) 에서 봅니다.
- 지우기 전의 캐시는 [섀도 복사본 활용](../../03-techniques/analysis/volume-shadow-copy-analysis.md) 으로 찾습니다. 지운 캐시 파일의 조각은 [삭제 데이터 복구](../../03-techniques/analysis/data-recovery/index.md) 에서 다루는 방법으로 찾습니다.

## 직접 분석해 보기

### 헥스로 한 번

아래는 위 구조 표로 만든 예시입니다. 실제 데이터에서 뽑은 값이 아닙니다. `..` 은 줄인 바이트입니다.

먼저 캐시 파일 헤더입니다.

```
오프셋  00 01 02 03 04 05 06 07 08 09 0A 0B 0C 0D 0E 0F
0x00    43 4D 4D 4D 20 00 00 00 04 00 00 00 .. .. .. ..
0x10    .. .. .. .. .. .. .. ..
```

1. 0x00 의 `43 4D 4D 4D` 는 ASCII `CMMM` 입니다. 캐시 파일 서명입니다.
2. 0x04 의 `20 00 00 00` 은 32 입니다. Windows 10·11 형식입니다.
3. 0x08 의 `04 00 00 00` 은 4 입니다. 버전 32 표에서 4 는 256 입니다. `thumbcache_256.db` 의 헤더라는 뜻입니다.
4. 0x0C~0x17 은 버전 32 에서 뜻이 구조 표와 어긋나는 필드입니다. 여기서는 읽지 않고, 0x18 부터 항목을 찾습니다.

다음은 0x18 에서 시작하는 캐시 항목입니다. 오프셋은 항목 시작을 0 으로 셉니다.

```
오프셋  00 01 02 03 04 05 06 07 08 09 0A 0B 0C 0D 0E 0F
0x00    43 4D 4D 4D 58 08 00 00 .. .. .. .. .. .. .. ..
0x10    20 00 00 00 00 00 00 00 00 08 00 00 .. .. .. ..
0x20    .. .. .. .. .. .. .. .. .. .. .. .. .. .. .. ..
0x30    .. .. .. .. .. .. .. .. 38 00 66 00 33 00 63 00
0x40    .. .. .. .. .. .. .. .. .. .. .. .. .. .. .. ..
0x50    .. .. .. .. .. .. .. .. .. .. .. .. .. .. .. ..
```

5. 0x00 의 `CMMM` 은 항목 서명입니다.
6. 0x04 의 `58 08 00 00` 은 0x858 (2,136) 입니다. 서명부터 센 항목 전체의 크기입니다.
7. 0x08~0x0F 는 항목 해시입니다. 색인 파일 항목의 첫 8바이트도 항목 해시입니다. 색인 항목의 오프셋 배열이 이 항목의 시작 위치 (여기서는 0x18) 를 가리키는지 보고, 해시가 같은지로 한 번 더 맞춰 봅니다.
8. 0x10 의 `20 00 00 00` 은 32 입니다. 식별자 문자열이 32바이트, 곧 UTF-16LE 16자입니다.
9. 0x14 의 `00 00 00 00` 은 채움 크기 0 입니다.
10. 0x18 의 `00 08 00 00` 은 0x800 (2,048) 입니다. 그림 데이터의 크기입니다.
11. 0x28~0x2F 는 데이터 체크섬, 0x30~0x37 은 헤더 체크섬입니다.
12. 0x38 부터 식별자 문자열입니다. `38 00 66 00 33 00 63 00` 은 `8f3c` 입니다. 끝 문자가 없으므로 0x10 의 크기만큼만 읽습니다.
13. 그림 데이터는 0x38 + 0x20 + 0 = 0x58 에서 시작해 0x800 바이트입니다. 데이터 첫 바이트의 파일 서명으로 JPEG·PNG·BMP 를 구분합니다.
14. 0x58 + 0x800 = 0x858 로, 6단계의 항목 크기와 같습니다. 항목 시작에서 항목 크기만큼 가면 다음 항목의 `CMMM` 이 나와야 합니다. 안 나오면 손상이나 형식 차이를 의심합니다.

### 공개 도구로 한 번

- thumbcache 파일은 libyal 의 libwtcdb 가 다룹니다. libwtcdb 는 이 페이지의 구조 표를 정리한 문서를 함께 내는 공개 라이브러리입니다.
- Thumbs.db 는 vinetto (오픈소스, Python) 나 MiTeC Windows File Analyzer 로 볼 수 있습니다. OLE 복합 파일을 여는 도구로 스트림을 직접 꺼내도 됩니다.

도구를 쓸 때는 다음을 확인합니다.

- 형식 버전 32 의 캐시 종류 값을 제대로 이름으로 바꾸는지 확인합니다. 768·1280·1920·2560·custom_stream 파일을 옛 표로 읽지 않는지 봅니다.
- 데이터 없는 항목을 따로 표시하는지, 조용히 빼는지 확인합니다.
- 식별자 문자열을 그대로 보여 주는지 확인합니다. 16진수가 아닌 긴 식별자도 잘리지 않는지 봅니다.
- 도구가 보여 준 항목 수를 헥스로 따라간 항목 수와 맞춰 봅니다. 방법은 [도구 결과 교차 검증](../../03-techniques/reporting/tool-validation.md) 을 봅니다.

## 실습

NIST CFReDS 같은 공개 자료 가운데 사용자 프로필이 든 Windows 이미지를 골라 다음을 풀어 봅니다.

1. 이미지의 Windows 버전은 무엇입니까? thumbcache 파일 헤더의 형식 버전과 맞습니까?
2. `Explorer` 폴더에 thumbcache 파일이 몇 개 있습니까? 24바이트짜리 빈 캐시는 어느 것입니까?
3. 가장 큰 캐시 파일에서 첫 항목 세 개를 헥스로 따라가 봅니다. 항목 크기, 식별자, 데이터 크기를 표로 적어 봅니다.
4. 데이터 없는 항목과 그림이 있는 항목은 각각 몇 개입니까?
5. 그림 하나를 골라 파일 시스템에서 같은 그림의 원본을 찾아봅니다. 원본은 지금도 있습니까?
6. 이미지에 Thumbs.db 가 있습니까? 있다면 어느 폴더에 있고, OLE 스트림은 어떻게 생겼습니까?

실험용 가상 머신이 있으면 그림 파일이 든 폴더를 탐색기에서 미리 보기 보기로 열어 봅니다. 앞뒤로 캐시 파일을 떠서 어느 파일에 항목이 늘었는지 비교합니다. 원본을 지운 뒤에도 항목이 남는지 확인합니다. 결과에는 실험한 Windows 버전을 함께 적습니다.
