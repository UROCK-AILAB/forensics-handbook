# 메모장 탭 저장 파일 (Notepad TabState)

> 위치: 아티팩트 사전 > 파일·폴더 사용 흔적

## 한 줄 요약

Windows 11 메모장은 열린 탭과 저장하지 않은 내용을 앱 폴더의 작은 이진 파일에 자동으로 적어 둡니다. 한 번도 저장하지 않은 글도 이 파일에 남습니다. 메모장을 닫기 전에는 입력하고 지운 과정이 조각으로 남으므로, 화면에서 지운 글자까지 되살릴 수 있습니다. 창 파일에는 탭 순서와 창 위치가 남고, 설정 파일에는 최근 파일과 마지막 찾기 문자열이 남습니다.

이 페이지에서 "관찰" 이라고 적은 것은 Windows 11 25H2(빌드 26200), 메모장 11.2607.14.0 PC 한 대에서 파일 목록과 머리 바이트만 읽어 본 결과입니다. 메모장을 열거나 파일을 바꾸지 않았습니다. 한 대의 결과이므로 모든 PC 에 맞는다고 보장하지 못합니다.

## 무엇을 기록하나 · 왜 생기나

메모장은 11.2307.22.0 버전부터 세션 상태 (session state) 를 자동으로 저장합니다. 이 버전은 2023-08-31 에 Canary·Dev 채널에 먼저 나왔고, 9월 7일까지 Beta 채널로, 9월 19일까지 Release Preview 채널로 넓어졌습니다. (Microsoft, 2023)

이 기능이 켜져 있으면 메모장을 다시 열 때 전에 열려 있던 탭이 저장하지 않은 내용과 편집까지 함께 돌아옵니다. 그래서 메모장을 닫을 때 저장할지 묻는 창이 뜨지 않습니다. (Microsoft, 2023)

Microsoft 는 이 기능이 사용자 파일에는 영향을 주지 않으며, 탭을 닫을 때 저장할지 버릴지는 여전히 사용자가 고른다고 설명합니다. 앱 설정에서 이 기능을 끌 수 있습니다. (Microsoft, 2023)

탭을 다시 띄우려면 메모장이 탭 내용을 어딘가에 적어 두어야 합니다. 메모장은 세 가지 파일에 적습니다. (ogmini README)

- **탭 파일 (TabState)**: 탭마다 내용, 원본 파일 경로, 저장하지 않은 편집 조각을 적습니다.
- **창 파일 (WindowState)**: 창마다 탭 수, 탭 순서, 현재 탭, 창 크기와 위치를 적습니다.
- **설정 파일 (settings.dat)**: 최근 파일 목록, 마지막 찾기 문자열 같은 앱 설정을 적습니다.

## 위치와 버전별 차이

### 위치

세 파일 모두 사용자 프로필의 메모장 앱 폴더에 있습니다. 그래서 어느 계정의 메모장 기록인지 알 수 있습니다. (ogmini README·원고)

| 파일 | 위치 | 파일 이름 |
|---|---|---|
| 탭 파일 | `%LOCALAPPDATA%\Packages\Microsoft.WindowsNotepad_8wekyb3d8bbwe\LocalState\TabState\` | `<GUID>.bin`, `<GUID>.0.bin`, `<GUID>.1.bin` |
| 창 파일 | `%LOCALAPPDATA%\Packages\Microsoft.WindowsNotepad_8wekyb3d8bbwe\LocalState\WindowState\` | `*.0.bin`, `*.1.bin` |
| 설정 파일 | `%LOCALAPPDATA%\Packages\Microsoft.WindowsNotepad_8wekyb3d8bbwe\Settings\` | `settings.dat` |

- 탭 파일의 이름은 GUID 입니다. 같은 GUID 의 파일들이 탭 하나를 이룹니다.
- `settings.dat` 는 응용 프로그램 하이브 (application hive) 입니다. 레지스트리 편집기와 하이브 도구로 열 수 있습니다. 구조는 [UWP 앱 데이터 구조](../../01-foundations/app-mail-data/packages-settings-dat.md) 에서 다룹니다.
- 관찰에서는 `Settings` 폴더에 `settings.dat.LOG1`·`settings.dat.LOG2` 도 있었습니다. (확인 범위: Win11 25H2 한 대, 메모장 11.2607.14.0)

### Windows 버전

대상은 Windows 11 의 메모장(스토어 앱)입니다. README 는 아래 환경에서 형식을 확인했다고 적었습니다. (ogmini README)

| Windows 11 | 빌드 |
|---|---|
| 23H2 | 22631·22635 |
| 24H2 | 26100.4652 |
| 25H2 | 26200.6899 |

Windows 10 에서 같은 파일이 생기는지는 확인하지 못했습니다.

| 메모장 버전 | 달라진 점 | 근거 |
|---|---|---|
| 11.2307.22.0 | 세션 상태 자동 저장이 들어왔습니다 | Microsoft |
| 11.2407.9.0·11.2408.12.0·11.2409.9.0 | DFIR Review 원고가 확인한 버전입니다. 원고는 11.2408.12.0 을 기준으로 씁니다. 추가 옵션 블록에 알 수 없는 1바이트 두 개만 있습니다 | ogmini 원고 |
| README 확인 범위 11.2402.22.0 ~ 11.2507.26.0 | 추가 옵션 블록 끝에 서식 (Formatting) 1바이트가 더 있습니다. `settings.dat` 의 RecentFiles·FindString·ReplaceString·RewriteEnabled 값도 README 에만 나옵니다. 이 칸과 값이 들어온 버전은 확인하지 못했습니다 | ogmini README |
| 11.2607.14.0 (관찰) | 상태 파일의 TypeFlag 가 0x0E(14)였습니다. 문서의 10·11 과 다릅니다. 나머지 칸 순서는 문서와 맞았습니다 | 관찰 |

## 구조

아래 칸 이름과 순서는 ogmini 의 README 와 DFIR Review 원고를 따릅니다. 두 자료가 다른 곳은 따로 적었습니다.

### 공통 규칙

모든 파일은 서명 `4E 50`("NP") 으로 시작하고, 앞 바이트들의 CRC32 를 적어 무결성을 확인합니다.

숫자 칸 대부분은 uLEB128 이라는 가변 길이 형식으로, 바이트마다 아래 7비트가 값이고 맨 위 비트가 1이면 다음 바이트가 이어집니다. 앞 바이트가 낮은 자리이므로 예를 들어 `82 01` 은 2 + 1 × 128 = 130 이고, 0x80 보다 작은 값은 한 바이트입니다.

- 글자는 UTF-16LE 로 적습니다. 인코딩은 [문자 인코딩](../../01-foundations/value-decoding/utf-16le-utf-8-cp949.md) 에서 다룹니다.

### 탭 파일의 종류

| 종류 | 파일 | TypeFlag | 뜻 |
|---|---|---|---|
| 파일 탭 (File Tab) | `<GUID>.bin` | 1 | 디스크 파일을 열었거나 디스크에 저장한 탭입니다. 저장됨·저장 안 됨 상태가 있습니다. 저장 안 됨은 탭 이름 오른쪽의 점으로 보입니다 |
| 파일 없는 탭 (No File Tab) | `<GUID>.bin` | 0 | 한 번도 저장하지 않았고 파일에서 열지도 않은 탭입니다. 내용은 이 파일에만 있습니다 |
| 상태 파일 (State File) | `<GUID>.0.bin`, `<GUID>.1.bin` | 10(파일 없는 탭의 상태), 11(파일 탭의 상태) | 같은 GUID 의 `.bin` 에 대한 추가 정보입니다. 늘 있지는 않습니다 |

### 파일 탭

| 순서 | 칸 | 형식 | 뜻 |
|---|---|---|---|
| 1 | 서명 | 2바이트 | `4E 50` |
| 2 | Sequence Number | uLEB128 | 탭 파일에서는 늘 0 입니다 |
| 3 | TypeFlag | uLEB128 | 1 |
| 4 | FilePathLength | uLEB128 | 경로 길이. README 표는 바이트 수라고 적었지만, 같은 저자의 ImHex 패턴은 이 값만큼 UTF-16 글자를 읽습니다. 글자 수로 읽고 헥스로 확인합니다 |
| 5 | FilePath | UTF-16LE | 원본 파일의 전체 경로 |
| 6 | SavedFileContentLength | uLEB128 | 디스크에 저장된 텍스트 파일의 크기. 모든 변경을 저장했으면 0 |
| 7 | EncodingType | 1바이트 | 1 ANSI, 2 UTF-16LE, 3 UTF-16BE, 4 UTF-8 BOM, 5 UTF-8 |
| 8 | CarriageReturnType | 1바이트 | 1 CRLF, 2 CR, 3 LF |
| 9 | Timestamp | uLEB128 | Win32 FILETIME. 모든 변경을 저장했으면 0 |
| 10 | FileHash | 32바이트 | 디스크에 저장된 텍스트 파일의 SHA-256. 모든 변경을 저장했으면 0 |
| 11 | 알 수 없음 | 2바이트 | `00 01` |
| 12 | SelectionStartIndex·SelectionEndIndex | uLEB128 두 개 | 선택 영역의 시작과 끝 |
| 13 | 설정 블록 | 가변 | 아래 "설정 블록" 참고 |
| 14 | ContentLength | uLEB128 | 내용 길이 |
| 15 | Content | UTF-16LE | 탭 내용 |
| 16 | Unsaved | 1바이트 | 저장 안 됨 표시 |
| 17 | CRC32 | 4바이트 | 앞 바이트들의 CRC32 |
| 18 | 저장 안 된 버퍼 조각 | 가변 | 저장하지 않은 변경이 있을 때만 이어집니다 |

6·9·10번 칸은 모든 변경을 저장했으면 0 입니다. 값이 채워져 있으면 이 파일에 저장하지 않은 변경이 있다는 뜻입니다.

### 파일 없는 탭

칸 순서는 이렇습니다.

`4E 50` → Sequence Number(늘 0) → TypeFlag 0 → 알 수 없는 1바이트 `01` → SelectionStart·End → 설정 블록 → ContentLength → Content(UTF-16LE) → Unsaved 1바이트 → CRC32 → 저장 안 된 버퍼 조각

파일 경로, 해시, 시각 칸이 없습니다. 버퍼 조각의 변경은 메모장을 닫을 때 Content 로 합쳐집니다.

### 상태 파일

칸 순서는 이렇습니다.

`4E 50` → Sequence Number(uLEB128) → TypeFlag(10·11) → 알 수 없는 1바이트 `00` → BinSize(uLEB128) → SelectionStart·End → 설정 블록 → CRC32

- Sequence Number 는 갱신할 때마다 늘어납니다. `.0.bin` 과 `.1.bin` 가운데 값이 큰 쪽이 현재 파일입니다.
- BinSize 는 짝이 되는 `<GUID>.bin` 의 바이트 크기입니다.
- 관찰에서는 탭 두 개가 모두 `.bin`·`.0.bin`·`.1.bin` 세 파일이었습니다. `.1.bin` 은 둘 다 0바이트였습니다. 두 `.0.bin` 의 머리는 `4E 50 00 0E 00` 으로, TypeFlag 가 0x0E 였습니다. BinSize 는 짝 `.bin` 의 실제 크기와 같았습니다. (확인 범위: Win11 25H2 한 대, 메모장 11.2607.14.0)

### 설정 블록

| 칸 | 형식 | 뜻 |
|---|---|---|
| WordWrap | 1바이트 | 자동 줄 바꿈 |
| RightToLeft | 1바이트 | 오른쪽에서 왼쪽으로 쓰기 |
| ShowUnicode | 1바이트 | 유니코드 표시 설정 |
| MoreOptions | uLEB128 | 뒤따르는 추가 옵션의 바이트 수 |
| 추가 옵션 블록 | MoreOptions 바이트 | 아래 참고 |

추가 옵션 블록에는 알 수 없는 1바이트 두 개가 있으며, 이 두 바이트는 맞춤법 검사와 자동 고침 기능이 들어올 때 추가됐습니다. (ogmini README) README 는 그 뒤에 서식 1바이트를 적었는데, 1 서식 없음, 2 마크다운 서식, 3 마크다운 문법입니다. (ogmini README) 11.2408.12.0 기준인 원고에는 서식 칸이 없습니다. (ogmini 원고)

- 버전마다 칸 수가 다르므로 MoreOptions 값만큼 건너뛰어 다음 칸을 찾습니다. 관찰에서는 MoreOptions 가 3 이었고 뒤에 3바이트가 있었습니다. (확인 범위: Win11 25H2 한 대, 메모장 11.2607.14.0)
- WordWrap·RightToLeft·ShowUnicode 는 탭마다 따로 적습니다. WordWrap 은 앱 전체 설정도 따로 있습니다. (ogmini 원고)

### 저장 안 된 버퍼 조각 (Unsaved Buffer Chunk)

저장하지 않은 편집은 조각 하나에 한 동작씩 이어 붙습니다.

| 칸 | 형식 | 뜻 |
|---|---|---|
| Cursor Position | uLEB128 | 지우기·더하기가 시작된 위치 |
| Deletion Action | uLEB128 | 지운 글자 수 |
| Addition Action | uLEB128 | 더한 글자 수 |
| Added Characters | UTF-16LE | 더한 글자 |
| CRC32 | 4바이트 | 이 조각 하나의 CRC32 |

- 글자 하나를 입력하면 Addition 이 1 인 조각이 생깁니다. (ogmini 원고)
- 글자 하나를 지우면 Deletion 이 1 인 조각이 생깁니다. (ogmini 원고)
- 붙여 넣으면 붙인 글자 수만큼 Addition 이 적힙니다. (ogmini 원고)
- 덮어쓰기는 지우기와 더하기가 한 조각에 함께 적힙니다. (ogmini README·원고)
- 조각을 차례로 되짚으면 입력하고 지운 과정을 키로거처럼 재생할 수 있습니다. (ogmini README·원고)
- 메모장을 닫거나 파일을 저장하면 조각은 Content 로 합쳐져 사라집니다. (ogmini README·원고)
- 마크다운 서식 탭에는 버퍼 조각이 생기지 않습니다. (ogmini README)

원고에는 이런 사례가 나옵니다. 화면에는 장보기 메모만 보이던 탭이 있었습니다. 버퍼 조각을 되짚자 붙여 넣었다가 지운 복구 키가 되살아났습니다. (ogmini 원고)

### 창 파일

열린 메모장 창마다 창 파일이 생깁니다.

| 순서 | 칸 | 형식 | 뜻 |
|---|---|---|---|
| 1 | 서명 | 2바이트 | `4E 50` |
| 2 | Sequence Number | uLEB128 | 갱신 순번. 큰 쪽이 현재 파일 |
| 3 | BytesToCRC | uLEB128 | CRC32 까지의 바이트 수 |
| 4 | 알 수 없음 | 1바이트 | `00` |
| 5 | NumberTabs | uLEB128 | 탭 수 |
| 6 | 탭 GUID | 16바이트 × 탭 수 | 화면에 보이는 순서. 탭 파일 이름과 같은 GUID |
| 7 | ActiveTab | uLEB128 | 현재 탭 번호(0부터 셉니다) |
| 8 | TopLeft X·Y, BottomRight X·Y, Width·Height | 각 4바이트 부호 없는 정수 | 창 위치와 크기 |
| 9 | 알 수 없음 | 1바이트 | `00` |
| 10 | CRC32 | 4바이트 | 앞 바이트들의 CRC32 |
| 11 | 남는 공간 (slack) | 가변 | 예전 내용이 남을 수 있는 곳 |

- 창 파일은 크기가 줄지 않는 것으로 보이며, 탭을 닫으면 CRC32 뒤에 남는 공간이 생겨 거기서 예전 탭의 GUID 를 통째로 또는 일부 되찾을 수 있습니다. 탭을 여닫을수록 내용이 뒤섞이므로 늘 되찾는다는 보장은 없습니다. (ogmini README·원고)
- 탭을 창 밖으로 끌어 새 창을 만들면 새 창 파일이 생깁니다. 추가 창을 닫으면 그 창 파일은 지워지고, 마지막으로 닫은 창의 창 파일만 남습니다. (ogmini README·원고)
- 관찰에서는 NumberTabs 가 2 였습니다. 뒤이은 16바이트 두 개를 GUID 로 읽자(앞 세 칸은 리틀 엔디언) TabState 파일 이름 두 개와 정확히 같았습니다. (확인 범위: Win11 25H2 한 대, 메모장 11.2607.14.0) GUID 바이트 순서는 [윈도 식별자 형식](../../01-foundations/value-decoding/sid-guid-clsid-known-folder-id.md) 에서 다룹니다.

### settings.dat 값

값 형식은 값 끝에 붙은 표시로 가립니다. (ogmini README·원고)

| 표시 | 형식 |
|---|---|
| 0x5f5e104, 0x5f5e105 | 4바이트 부호 없는 정수 |
| 0x5f5e10b | 1바이트(참·거짓) |
| 0x5f5e10c | NULL 로 끝나는 문자열 |

조사에 쓸 만한 값은 이렇습니다. (ogmini README)

| 값 | 뜻 |
|---|---|
| RecentFiles | 쉼표로 나눈 최근 파일 목록. 가장 최근에 닫은 파일이 맨 앞입니다 |
| RecentFilesEnabled | 최근 파일 목록을 쓸지 정하는 설정 |
| FindString | 마지막으로 찾은 문자열 |
| ReplaceString | 마지막으로 바꾼 문자열 |
| GhostFile | 0 새 창으로 열기, 1 이전 세션 내용 열기(세션 복원 설정) |
| OpenFile | 0 새 탭, 1 새 창 |
| RewriteEnabled | AI 다시 쓰기 설정 |

값이 없으면 그 옵션을 기본값에서 바꾼 적이 없다는 뜻입니다. (ogmini README·원고)

## 증거로서 의미

### 증명하는 것

- **탭 내용.** 한 번도 저장하지 않은 글이 파일 없는 탭의 Content 에 남습니다. 디스크 어디에도 없는 글일 수 있습니다.
- **원본 파일 경로.** 파일 탭의 FilePath 는 이 탭과 이어진 파일의 전체 경로입니다. 그 파일을 메모장으로 열었거나 그 경로에 저장했다는 기록입니다.
- **저장하지 않은 변경.** SavedFileContentLength·Timestamp·FileHash 가 0 이 아니면 탭에 저장하지 않은 변경이 있었습니다. Timestamp 는 그 변경이 시작된 때를 알려 줍니다.
- **디스크 파일과의 대응.** FileHash 는 디스크에 저장된 텍스트 파일의 SHA-256 입니다. 디스크에 남은 파일과 해시를 맞춰 볼 수 있습니다.
- **편집 과정.** 버퍼 조각은 입력하고 지운 동작을 차례대로 보여 줍니다. 지금 화면에 없는 글자도 되살아납니다.
- **창과 탭 배치.** 창 파일은 탭 수, 탭 순서, 현재 탭, 창 크기와 위치를 알려 줍니다. 남는 공간의 예전 GUID 는 지금은 없는 탭이 있었다는 단서입니다.
- **여닫은 횟수의 단서.** 저장하지 않은 변경이 있는 탭은 메모장을 닫을 때마다 상태 파일의 Sequence Number 가 늘어납니다. 저장하지 않은 채 여러 번 여닫았다는 뜻입니다.
- **설정과 최근 기록.** `settings.dat` 는 최근 파일 목록과 마지막 찾기·바꾸기 문자열을 알려 줍니다. 값마다 바꾼 시각도 있습니다.
- **계정.** 파일이 사용자 프로필 아래에 있으므로 어느 계정의 메모장인지 알 수 있습니다.

### 증명하지 못하는 것

- **누가 입력했는지.** 계정까지만 알려 줍니다. 자판 앞의 사람은 다른 흔적으로 좁힙니다. 방법은 [그 시각에 PC 를 쓴 사람이 누구인가](../../04-scenarios/activity/user-attribution.md) 에서 다룹니다.
- **조각마다의 시각.** 버퍼 조각에는 시각 칸이 없습니다. 입력 순서는 알아도 각 입력의 시각은 모릅니다.
- **파일 없는 탭의 시각.** 파일 없는 탭에는 시각 칸이 없습니다. 언제 입력했는지는 파일 시스템 시각과 다른 흔적으로 좁힙니다.
- **디스크 파일의 지금 내용.** 파일 탭의 Content 는 탭의 내용입니다. 저장하지 않은 변경이 있으면 디스크 파일과 다릅니다.
- **메모장을 쓰지 않았다는 것.** 기능을 끌 수 있고, 메모장을 열 때 이제 없는 파일에 대한 탭·창 파일이 지워질 수도 있습니다. 파일이 없다고 사용하지 않았다고 말할 수 없습니다.
- **읽었거나 뜻을 알았다는 것.** 붙여 넣은 글이 남았다고 해서 사용자가 그 내용을 읽었다고 말할 수 없습니다.

보고서에는 "피의자가 복구 키를 적었다" 가 아니라 이렇게 씁니다. "A 계정의 메모장 탭 파일 `<GUID>.bin` 에 저장되지 않은 버퍼 조각이 있다. 조각을 차례로 되짚으면 32글자를 붙여 넣은 뒤 같은 32글자를 지운 기록이 나온다." 숫자는 설명을 위한 예입니다.

## 시각 해석

| 시각 | 언제 바뀌나 | 주의 |
|---|---|---|
| 파일 탭의 Timestamp | 저장한 뒤 첫 변경 때 값이 들어갑니다. 저장하면 0 이 됩니다 | 저장 전까지 이어진 변경으로는 바뀌지 않습니다. 메모장을 여닫아도 유지됩니다. 마지막 편집 시각이 아니라 저장하지 않은 변경이 시작된 시각입니다 |
| `settings.dat` 값의 마지막 8바이트 | 그 설정을 바꿀 때 | FILETIME 입니다 |
| 창 파일의 Sequence Number | 탭 열기·닫기, 탭 순서 바꾸기, 창 크기 바꾸기, 창 옮기기 | 시각이 아니라 순번입니다. 여러 탭을 한꺼번에 닫으면 한 번만 늘어납니다 |
| 상태 파일의 Sequence Number | 저장하지 않은 변경이 있는 탭이면 메모장을 닫을 때마다 | 변경 없는 탭이면 늘지 않습니다 |
| 파일 시스템 시각 | 파일을 다시 쓸 때 | 아래 관찰 참고 |

- Timestamp 는 Win32 FILETIME 형식입니다. 참고한 자료는 이 값이 UTC 인지 현지 시각인지 밝히지 않습니다. 같은 PC 의 UTC 기록과 맞춰 본 뒤 씁니다. 형식은 [시각 값 형식](../../01-foundations/value-decoding/filetime-unix-webkit-dos-ole.md) 에서 다룹니다.
- `.0.bin` 과 `.1.bin` 은 번갈아 갱신됩니다. Sequence Number 가 큰 쪽이 현재 것입니다. 상태 파일과 창 파일 모두 같습니다. (ogmini README·원고)

상태 파일은 탭의 상태에 따라 생기고 지워지는 때가 다릅니다. (ogmini README·원고)

| 탭의 상태 | 상태 파일이 생길 때 | 상태 파일이 지워질 때 | Sequence Number |
|---|---|---|---|
| 변경 없는 파일 탭 | 메모장을 닫을 때만 | 그 탭을 다시 활성화할 때 | 늘지 않습니다. `.1.bin` 은 비어 있습니다 |
| 저장하지 않은 변경이 있는 탭 | 메모장을 닫을 때, 합쳐 넣을 버퍼 조각이 없었을 때만 | 새로 변경하거나 저장할 때 | 메모장을 닫을 때마다 늘어납니다 |

관찰에서는 `.bin` 의 마지막 수정 시각과 `.0.bin`·`.1.bin` 의 마지막 수정 시각이 6일 차이 났습니다. 상태 파일 쪽이 더 늦었습니다. `.bin` 의 파일 시각만으로 마지막 메모장 사용 시각을 잡으면 안 됩니다. (확인 범위: Win11 25H2 한 대, 메모장 11.2607.14.0)

## 함정과 한계

- **메모장을 만지면 증거가 바뀝니다.** 원고는 이런 경우를 듭니다. (ogmini 원고)
  - 메모장을 열고 닫고 만지는 것만으로 탭 파일과 창 파일이 바뀝니다.
  - 메모장을 닫으면 버퍼 조각이 사라집니다. 입력했다 지운 비밀번호도 함께 사라집니다.
  - 메모장을 열면 이제 없거나 접근할 수 없는 파일(예: 빠진 USB 의 파일)에 대한 탭·창 파일이 지워질 수 있습니다.
  - 현재 탭을 바꾸거나 커서만 옮겨도 파일이 바뀝니다.
- **실행 중인 PC 에서는 메모장을 닫지 않습니다.** `TabState`·`WindowState`·`Settings` 폴더를 먼저 복사합니다. 내용을 보려고 증거 PC 에서 메모장을 열지 않습니다. 수집 순서는 [라이브 응답](../../03-techniques/process-acquisition/live-response/order-of-volatility.md) 에서 다룹니다.
- **빈 화면도 확인합니다.** 열린 메모장 화면이 비어 보여도 버퍼 조각에 되살릴 내용이 있을 수 있습니다. (ogmini 원고)
- **형식이 버전마다 바뀝니다.** 서식 칸은 원고에는 없고 README 에는 있습니다. 관찰한 메모장 11.2607.14.0 에서는 상태 파일의 TypeFlag 도 문서와 달랐습니다. 특정 버전에 맞춘 도구는 다른 버전을 잘못 읽을 수 있습니다. 결과가 이상하면 헥스로 확인합니다.
- **창 파일은 크기로 판단하지 않습니다.** 관찰에서는 크기가 더 큰 창 파일이 예전 것이었습니다. 현재 파일은 Sequence Number 로 가립니다. (확인 범위: Win11 25H2 한 대, 메모장 11.2607.14.0)
- **마크다운 서식 탭에는 버퍼 조각이 없습니다.** 조각이 없다고 편집이 없었다고 볼 수 없습니다.
- **남는 공간의 GUID 는 보장되지 않습니다.** 탭을 여러 번 여닫으면 예전 GUID 가 덮이거나 잘립니다.
- **CRC32 는 손상을 가리는 값입니다.** 조작을 막지는 못합니다. 누군가 내용을 고치고 CRC32 를 다시 계산하면 CRC32 만으로는 알 수 없습니다.
- **지우거나 기능을 끌 수 있습니다.** 사용자가 `TabState` 폴더를 지우거나 세션 저장을 끄면 탭 파일이 남지 않습니다. 예전 탭 파일은 볼륨 섀도 복사본에 남아 있을 수 있습니다. 방법은 [섀도 복사본 활용](../../03-techniques/analysis/volume-shadow-copy-analysis.md) 에서 다룹니다.
- **Windows 10 은 확인하지 못했습니다.**

## 직접 분석해 보기

### 헥스로 한 번

아래는 README 의 형식으로 만든 파일 없는 탭 예시입니다. 실제 검체에서 나온 값이 아닙니다. 새 탭에 `hi` 를 붙여 넣고, 한 글자를 지우고, 메모장을 아직 닫지 않은 상태를 가정했습니다. CRC32 값은 `??` 로 비워 두었습니다. 설정 칸과 알 수 없는 칸의 값도 예시로 넣은 것입니다.

```
오프셋  00 01 02 03 04 05 06 07 08 09 0A 0B 0C 0D 0E 0F
0x00   4E 50 00 00 01 00 00 01 00 00 03 00 00 01 00 00
0x10   ?? ?? ?? ?? 00 00 02 68 00 69 00 ?? ?? ?? ?? 01
0x20   01 00 ?? ?? ?? ??
```

1. 0x00 의 `4E 50` 은 서명 "NP" 입니다.
2. 0x02 의 `00` 은 Sequence Number 0 입니다.
3. 0x03 의 `00` 은 TypeFlag 0 입니다. 파일 없는 탭이므로 경로·해시·시각 칸이 없습니다.
4. 0x04 의 `01` 은 파일 없는 탭의 알 수 없는 1바이트입니다.
5. 0x05·0x06 은 선택 영역의 시작과 끝입니다.
6. 0x07~0x09 는 WordWrap·RightToLeft·ShowUnicode 입니다.
7. 0x0A 의 `03` 은 MoreOptions 입니다. 뒤 3바이트가 추가 옵션입니다.
8. 0x0B·0x0C 는 알 수 없는 두 바이트입니다. 0x0D 의 `01` 은 서식 없음입니다. 서식 없는 탭이므로 버퍼 조각이 생길 수 있습니다.
9. 0x0E 의 `00` 은 ContentLength 0 입니다. 메모장을 닫기 전이라 아직 Content 에 합쳐진 글자가 없습니다.
10. 0x0F 의 `00` 은 Unsaved 칸입니다. README 는 새 파일 없는 탭에서 이 값이 0 이라고 적었습니다. 0x10~0x13 은 여기까지의 CRC32 입니다.
11. 0x14 부터 첫 조각입니다. 위치 `00`, 지운 수 `00`, 더한 수 `02`, 더한 글자 `68 00 69 00`("hi"), 조각 CRC32 입니다.
12. 0x1F 부터 둘째 조각입니다. 위치 `01`, 지운 수 `01`, 더한 수 `00` 입니다. 더한 글자는 없고 조각 CRC32 가 바로 옵니다.

조각을 차례로 되짚습니다. 첫 조각으로 위치 0 에 두 글자가 들어가 `hi` 가 됩니다. 둘째 조각으로 위치 1 의 한 글자가 지워져 `h` 가 됩니다. 화면에는 `h` 만 보이지만 `hi` 를 붙여 넣은 기록이 남아 있습니다.

실제 파일에서는 몇 가지를 더 확인합니다.

- 값이 0x80 이상이면 uLEB128 이 두 바이트 이상입니다. 관찰한 창 파일의 Sequence Number 는 `82 01`(130)과 `81 01`(129)였습니다. 이 경우 `82 01` 쪽이 현재 파일입니다. (확인 범위: Win11 25H2 한 대, 메모장 11.2607.14.0)
- 상태 파일은 BinSize 가 짝 `.bin` 의 크기와 맞는지 봅니다.
- 창 파일의 GUID 를 탭 파일 이름과 맞춥니다. CRC32 뒤 남는 공간에서 16바이트 GUID 모양을 찾아봅니다.

### 공개 도구로 한 번

공개 도구의 예로 ogmini 의 Notepad State Library 가 있습니다. 이 저장소의 WindowsNotepadParser.exe 는 기본 위치나 지정한 폴더의 탭 파일과 창 파일을 CSV 로 냅니다. 버퍼 조각이 있으면 변경 과정을 GIF 로 만듭니다. 같은 저장소에 010 Editor 템플릿과 ImHex 패턴도 있습니다. (ogmini README)

도구가 확인한 메모장 버전과 증거 PC 의 메모장 버전을 맞춰 보고, 도구가 낸 탭 수와 폴더의 `.bin` 수도 맞춰 봅니다. 차이가 나면 헥스로 돌아갑니다. 방법은 [도구 결과 교차 검증](../../03-techniques/reporting/tool-validation.md) 에서 다룹니다.

`settings.dat` 는 복사본을 하이브 도구로 엽니다. 값 끝 8바이트의 FILETIME 을 따로 풉니다.

## 실습

이 기능이 들어간 공개 검체는 찾지 못했습니다. Windows 11 가상 머신을 하나 만들어 직접 시험합니다. 시험 전에 메모장 버전을 적어 둡니다.

1. 새 탭에 글을 입력하고 저장하지 않은 채 메모장을 닫습니다. `TabState` 에 어떤 파일이 생겼습니까? TypeFlag 는 무엇입니까?
2. 같은 탭에 글을 붙여 넣고 일부를 지웁니다. 메모장을 닫기 전에 탭 파일을 복사합니다. 버퍼 조각으로 편집 순서를 되짚을 수 있습니까?
3. 2번 뒤 메모장을 닫습니다. 버퍼 조각이 Content 로 합쳐졌습니까?
4. 텍스트 파일 하나를 열어 고치고 저장하지 않습니다. Timestamp 가 언제 채워졌습니까? 두 번째 변경 뒤에도 같습니까?
5. 4번 파일의 FileHash 와 디스크 파일의 SHA-256 이 같습니까?
6. 탭 세 개를 열었다가 하나를 닫습니다. 창 파일의 CRC32 뒤에 닫은 탭의 GUID 가 남았습니까?
7. 메모장을 여러 번 여닫으며 상태 파일의 Sequence Number 와 파일 시스템 시각을 적습니다. 두 값은 같이 움직입니까?
8. 찾기 창에 문자열을 넣은 뒤 `settings.dat` 의 FindString 과 그 값의 마지막 8바이트를 봅니다.
