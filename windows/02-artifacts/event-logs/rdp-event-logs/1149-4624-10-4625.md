# 들어온 접속: 인증 단계 (1149·4624 유형 10·4625)

## 한 줄 요약

원격 데스크톱 (Remote Desktop, RDP) 접속을 받은 컴퓨터에는 연결 단계와 인증 단계의 기록이 남습니다. 중심 이벤트는 RemoteConnectionManager/Operational 로그의 1149 와 보안 로그 (Security Log) 의 4624 유형 10·4625 입니다. 이 페이지는 세 이벤트의 칸과 서로 잇는 방법을 다룹니다. 1149 를 "인증 성공" 으로 읽어도 되는지는 [해석 함정](1149-nla-3-10.md) 에서 따로 다룹니다.

## 무엇을 기록하나 · 왜 생기나

들어온 접속은 네트워크 연결, 인증, 로그온, 끊김·다시 연결, 로그오프 단계로 나눠 볼 수 있습니다[1]. 이 페이지는 앞의 두 단계를 다룹니다. 다섯 단계 전체 표는 [허브](index.md) 에 있습니다.

| 이벤트 | 로그 | 단계 | 남는 때 |
|---|---|---|---|
| 1149 | RemoteConnectionManager/Operational | 네트워크 연결 | 원격 데스크톱 연결이 들어왔을 때. 메시지 문구는 "사용자 인증 성공" 입니다 |
| 4624 유형 10 | Security | 인증 | 원격 대화형 로그온 세션이 만들어졌을 때 |
| 4625 | Security | 인증 | 로그온에 실패했을 때 |
| 131 · 98 · 140 | RdpCoreTS/Operational | 연결 | 연결 시도, TCP 연결 성립, 사용자 이름이나 비밀번호가 틀려 연결 실패 |

- 네 로그 모두 접속을 받은 컴퓨터 (대상) 에 남습니다.
- 로그온 다음 단계인 세션 로그온·끊김·로그오프는 [세션 단계](localsessionmanager-21-25-4778-4779.md) 에서 다룹니다.

## 위치와 버전별 차이

- 원격 데스크톱 전용 채널의 파일 위치와 기본 크기는 [허브](index.md) 의 "채널 이름과 파일 경로" 표에 모았습니다.
- 보안 로그 파일의 위치는 [로그온·로그오프](../logon-events/index.md) 에서 다룹니다.
- 4624 는 로그온 감사 (Audit Logon) 하위 범주에 속합니다. 이 하위 범주가 켜져 있었는지는 [감사 정책과 로그 설정](../audit-policy-log-settings.md) 으로 확인합니다.

| Windows | 이 단계와 관련된 차이 |
|---|---|
| Vista · Server 2008 이후 | 위 단계 구분이 맞는 범위입니다[1]. XP 시절 이벤트는 다루지 않습니다 |
| 8.1 · Server 2012 R2 | 제한된 관리자 모드 (Restricted Admin Mode) 가 이때 생겼습니다 |
| 10 | 4624 이벤트 버전 2 에 제한된 관리자 모드 칸이 들어갔습니다 |
| 11 Home 빌드 26200 | 이 페이지의 1149·261·1158·131·98·140 메시지 원문은 이 빌드의 공급자 정의 기준입니다 |

4624 이벤트 버전 0·1·2 의 전체 변화는 [로그온·로그오프](../logon-events/index.md) 에서 다룹니다.

## 구조

### 1149

| 항목 | 값 |
|---|---|
| 공급자 | Microsoft-Windows-TerminalServices-RemoteConnectionManager |
| 채널 | Microsoft-Windows-TerminalServices-RemoteConnectionManager/Operational |
| 수준 | 정보 |
| 메시지 첫 줄 | `Remote Desktop Services: User authentication succeeded:` |

메시지 첫 줄 다음에 칸 세 개가 한 줄씩 나옵니다.

| XML 칸 이름 | 메시지에 보이는 이름 | 내용 |
|---|---|---|
| Param1 | User | 사용자 이름 |
| Param2 | Domain | 도메인 |
| Param3 | Source Network Address | 접속해 온 주소 |

메시지 원문은 Windows 11 Home 빌드 26200 의 공급자 정의 기준입니다. 메시지가 "User authentication was successful" 로 적힌 예도 있지만 칸은 같습니다[2]. 판마다 문구가 조금 다르므로 문구가 아니라 이벤트 ID 로 찾습니다.

같은 공급자의 다른 이벤트도 함께 봅니다.

| 이벤트 | 채널 | 메시지 원문 | 칸 |
|---|---|---|---|
| 261 | Operational | `Listener %1 received a connection` | listenerName. RDP-Tcp 같은 리스너 이름이 들어갑니다[2] |
| 1158 | Admin | `Remote Desktop Services accepted a connection from IP address %1.` | 주소 하나 |

1146·1147·1148 은 원격 제어 (Shadow) 세션의 시작·성공·실패 기록인데, 실제로는 드물게 보입니다[1].

### 4624 유형 10

4624 는 로그온 세션이 만들어질 때 남습니다. 유형 10 (RemoteInteractive) 은 터미널 서비스나 원격 데스크톱으로 이 컴퓨터에 원격 로그온한 경우입니다[3].

원격 데스크톱 조사에서는 유형 10 말고도 아래 유형이 함께 보입니다.

| 유형 | 이름 | Microsoft 정의 | 원격 데스크톱에서 보이는 때 |
|---|---|---|---|
| 3 | Network | 네트워크 로그온 | 네트워크 수준 인증 설정에 따라 유형 10 과 함께 남습니다. [해석 함정](1149-nla-3-10.md) 을 봅니다 |
| 7 | Unlock | 잠금 해제 | 이미 있던 세션에 다시 붙을 때 보입니다[1][4] |
| 10 | RemoteInteractive | 터미널 서비스·원격 데스크톱으로 원격 로그온 | 원격 데스크톱 로그온 |
| 12 | CachedRemoteInteractive | RemoteInteractive 와 같고, 내부 감사용 | 공개 자료 없음 |

원격 데스크톱 조사에서 읽을 칸은 아래와 같습니다.

| XML 칸 | 뜻 | 볼 점 |
|---|---|---|
| LogonType | 로그온 유형 | 10 이 원격 데스크톱 로그온입니다 |
| TargetUserName · TargetDomainName | 로그온한 계정과 도메인 | 1149 의 User·Domain 과 맞춰 봅니다 |
| TargetLogonId | 로그온 ID (Logon ID) | 같은 세션의 다른 이벤트 (4672 등) 를 이 값으로 묶습니다 |
| IpAddress | 원본 네트워크 주소 (Source Network Address). `::1`·`127.0.0.1` 은 이 컴퓨터 자신입니다 | 1149 의 원본 주소, LocalSessionManager 21 의 주소와 맞춰 봅니다 |
| IpPort | 원본 포트 (Source Port). 대화형 로그온은 0 입니다 | |
| WorkstationName | 로그온을 시도한 컴퓨터 이름 | |
| RestrictedAdminMode | 제한된 관리자 모드를 썼는지 | RemoteInteractive 세션에만 Yes 나 No 가 들어갑니다. 다른 유형은 `-` 입니다 |

- IP·포트·컴퓨터 이름 칸은 인증 방식에 따라 비어 있을 수 있습니다.
- 어느 방식에서 어느 칸이 비는지는 [로그온·로그오프](../logon-events/index.md) 에서 다룹니다.

### 4625

원격 데스크톱 로그온에 실패하면 보안 로그에 4625 가 남습니다. 실패 기록의 로그온 유형은 네트워크 수준 인증 (Network Level Authentication, NLA) 설정에 따라 달라지며, 어느 유형으로 찾아야 하는지는 [해석 함정](1149-nla-3-10.md) 에서 다룹니다.

실패는 상태 코드 (Status) 와 하위 상태 코드 (Sub Status) 로 나눕니다[1]. 비밀번호 만료 같은 실패는 정상 사용에서도 생기지만, 없는 사용자 이름으로 되풀이한 실패는 공격 쪽으로 봅니다.

- 코드 표는 [로그온·로그오프](../logon-events/index.md) 허브의 4625 페이지에 있습니다.

### RdpCoreTS/Operational 에서 함께 볼 이벤트

| 이벤트 | 메시지 원문 | 칸 |
|---|---|---|
| 131 | `The server accepted a new %1 connection from client %2.` | ConnType, ClientIP |
| 98 | `A TCP connection has been successfully established.` | |
| 140 | `A connection from the client computer with an IP address of %1 failed because the user name or password is not correct.` | IPString |

- 메시지 원문은 Windows 11 Home 빌드 26200 의 공급자 정의 기준입니다.
- 131 은 연결 시도 기록이고, 98 은 성공한 연결 기록입니다[4].
- 140 에는 주소 칸만 있고 사용자 이름 칸은 없습니다.
- 140 이 어느 Windows 버전부터 남는지, NLA 로 인증에 실패할 때만 남는지는 공개 자료가 없어 검체에서 확인합니다.

## 증거로서 의미

| 증명하는 것 | 증명하지 못하는 것 |
|---|---|
| 1149 가 있으면, 그 시각에 기록된 주소에서 이 컴퓨터로 원격 데스크톱 연결이 들어왔습니다. 사용자·도메인 칸에 적힌 값도 남았습니다 | 1149 한 건으로 로그온까지 끝났는지. [해석 함정](1149-nla-3-10.md) 을 봅니다 |
| 4624 유형 10 이 있으면, 그 시각에 이 계정의 원격 대화형 로그온 세션이 이 컴퓨터에 만들어졌습니다 | 그 계정을 쓴 사람이 누구인지 |
| 4625 가 있으면, 로그온 시도가 실패했고 실패 이유 코드가 남았습니다 | 기록된 주소의 컴퓨터에 사람이 앉아 있었는지. 중간에 다른 컴퓨터를 거쳤을 수 있습니다 |
| 140 이 있으면, 기록된 주소에서 온 연결이 사용자 이름이나 비밀번호가 틀려 실패했습니다 | 140 으로 실패한 사용자 이름. 이 이벤트에는 사용자 칸이 없습니다 |
| | 로그온 뒤 세션 안에서 무엇을 했는지 |
| | 기록이 없을 때 접속도 없었는지. 감사 설정, 로그 크기, 로그 삭제를 먼저 확인합니다 |

### 보고서 문장 예

아래 `< >` 는 자리표시입니다.

- 쓸 수 있는 문장: "RemoteConnectionManager/Operational 로그에 `<시각>` UTC 의 1149 기록이 있습니다. 사용자 칸은 `<계정>`, 원본 주소 칸은 `<주소>` 입니다."
- 쓸 수 있는 문장: "보안 로그에 같은 계정의 4624 유형 10 기록이 `<시각>` UTC 에 있습니다. 로그온 ID 는 `<값>` 입니다."
- 쓰면 안 되는 문장: "`<주소>` 에서 `<계정>` 으로 인증에 성공해 로그인했습니다." 1149 한 건만 근거로 이렇게 쓰지 않습니다.

## 시각 해석

- 시각이 어느 기준으로 저장되는지는 [허브](index.md) 의 "시각" 절을 봅니다.
- 4624 의 시각은 로그온 세션이 만들어진 때이고, 4625 의 시각은 로그온에 실패한 때입니다.
- 1149 가 자격 증명을 넣기 전에 남는지 뒤에 남는지는 NLA 설정과 얽혀 있어서 1149 의 시각을 곧바로 인증 시각으로 쓰지 않습니다. 자세한 내용은 [해석 함정](1149-nla-3-10.md) 에 있습니다.
- 한 번의 접속을 시각순으로 세울 때는 단계 순서 (1149 → 4624 → LocalSessionManager 21·22) 를 기준으로 삼습니다[1].
- 같은 사용자와 같은 주소로 기록을 묶은 뒤 시각을 비교합니다.

## 함정과 한계

1. **1149 를 "인증 성공" 으로 읽습니다.** 메시지 문구와 실제 뜻이 다르다는 설명이 있습니다. [해석 함정](1149-nla-3-10.md) 을 봅니다.
2. **로그온 실패를 4625 유형 10 에서만 찾습니다.** NLA 설정에 따라 실패 기록을 놓칠 수 있습니다. [해석 함정](1149-nla-3-10.md) 을 봅니다.
3. **유형 7 을 화면 잠금 해제로만 읽습니다.** 유형 7 의 정의는 잠금 해제 (Unlock) 입니다[3]. 그러나 원격 데스크톱으로 이미 있던 세션에 다시 붙을 때도 유형 7 이 보입니다[1][4]. 다시 연결한 기록은 [세션 단계](localsessionmanager-21-25-4778-4779.md) 의 25·4778 과 맞춰 봅니다.
4. **로그 파일이 없으면 접속도 없었다고 봅니다.** 채널이 켜져 있어도 파일이 없을 수 있습니다. 로그 크기와 함께 [허브](index.md) 에서 다룹니다. 로그를 지운 흔적은 [이벤트 로그 삭제 (1102·104)](../1102-104.md) 에서 찾습니다.
5. **감사 설정을 보지 않습니다.** 4624 는 로그온 감사가 켜져 있어야 남습니다. 검체마다 [감사 정책과 로그 설정](../audit-policy-log-settings.md) 으로 확인합니다.
6. **140 을 모든 실패의 기록으로 봅니다.** 140 이 남는 조건은 공개 자료가 없습니다. 실패는 4625 와 함께 판단합니다.

## 직접 분석해 보기

### 헥스로 읽을 때

EVTX 레코드를 바이트 단위로 읽는 법은 [이벤트 로그 형식](../../../01-foundations/database-log-formats/evtx-evt-etl/index.md) 에서 다룹니다. 이 페이지는 XML 보기와 명령으로만 따라갑니다.

### 공개 도구로 한 번

- 이벤트 뷰어에서 이벤트를 열고 "자세히" 탭의 XML 보기로 칸 이름과 값을 봅니다.
- Windows 에 들어 있는 PowerShell 의 Get-WinEvent 로 필요한 칸만 뽑을 수 있습니다. 아래 명령은 수집한 로그 사본에 씁니다.

```powershell
# 1149: 시각(UTC)·도메인\사용자·원본 주소
$rcm = '.\Microsoft-Windows-TerminalServices-RemoteConnectionManager%4Operational.evtx'
Get-WinEvent -Path $rcm -FilterXPath "*[System[EventID=1149]]" |
  ForEach-Object { '{0:o} {1}\{2} {3}' -f $_.TimeCreated.ToUniversalTime(), $_.Properties[1].Value, $_.Properties[0].Value, $_.Properties[2].Value }

# 4624 유형 10: 시각(UTC)·도메인\계정·원본 주소·로그온 ID
$sec = '.\Security.evtx'
Get-WinEvent -Path $sec -FilterXPath "*[System[EventID=4624] and EventData[Data[@Name='LogonType']='10']]" |
  ForEach-Object {
    $d = @{}
    ([xml]$_.ToXml()).Event.EventData.Data | ForEach-Object { $d[$_.Name] = $_.'#text' }
    '{0:o} {1}\{2} {3} {4}' -f $_.TimeCreated.ToUniversalTime(), $d.TargetDomainName, $d.TargetUserName, $d.IpAddress, $d.TargetLogonId
  }

# RdpCoreTS 131·140: 시각(UTC)·ID·칸 값
$core = '.\Microsoft-Windows-RemoteDesktopServices-RdpCoreTS%4Operational.evtx'
Get-WinEvent -Path $core -FilterXPath "*[System[(EventID=131 or EventID=140)]]" |
  ForEach-Object { '{0:o} {1} {2}' -f $_.TimeCreated.ToUniversalTime(), $_.Id, (($_.Properties | ForEach-Object Value) -join ' ') }
```

- 1149 의 `Properties` 순서는 Param1 (User), Param2 (Domain), Param3 (Source Network Address) 입니다.
- 다른 공개 EVTX 파서로 뽑았다면 한두 건을 XML 원문과 맞춰 봅니다. 방법은 [도구 결과 교차 검증](../../../03-techniques/reporting/tool-validation.md) 을 봅니다.
- 많은 로그를 규칙으로 훑는 방법은 [이벤트 로그 규칙 검색](../../../03-techniques/analysis/sigma-rules.md) 을 봅니다.

조사 흐름은 [원격 데스크톱 침입 확인](../../../04-scenarios/incident/rdp-intrusion.md) 과 [계정 탈취와 측면 이동](../../../04-scenarios/incident/credential-theft-lateral-movement/index.md) 을 봅니다.

## 실습

NIST CFReDS 같은 공개 검체 가운데 원격 데스크톱 접속을 받은 Windows 이미지를 골라 풉니다. 알맞은 검체가 없으면 시험용 가상 머신 두 대로 직접 접속해 기록을 만듭니다.

1. 1149 의 원본 주소는 무엇입니까? 같은 주소가 4624 유형 10 의 IpAddress 에도 있습니까?
2. 1149 마다 같은 사용자의 4624 유형 10 이 뒤따릅니까? 뒤따르지 않는 1149 는 몇 건입니까?
3. 4624 유형 10 과 가까운 시각에 같은 계정의 유형 3 기록이 있습니까?
4. 4625 가 있다면 로그온 유형은 3 입니까, 10 입니까? 상태 코드와 하위 상태 코드는 무엇입니까?
5. RdpCoreTS 131 의 ClientIP 와 1149 의 원본 주소는 같습니까?
6. 4624 유형 10 의 RestrictedAdminMode 칸에는 어떤 값이 있습니까?
