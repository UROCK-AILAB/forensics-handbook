# 해석 함정 (1149의 뜻·NLA·유형 3과 10 구분)

## 한 줄 요약

원격 데스크톱 (Remote Desktop, RDP) 기록에는 읽는 사람이 틀리기 쉬운 곳이 세 군데 있습니다. 1149 를 인증 성공으로 읽는 것, 네트워크 수준 인증 (Network Level Authentication, NLA) 설정을 보지 않는 것, 로그온 유형 3 과 10 을 따로따로 읽는 것입니다. 이 페이지는 세 함정이 왜 생기는지와 어떻게 피하는지 다룹니다.

## 무엇을 기록하나 · 왜 생기나

세 함정의 뿌리는 NLA 입니다. NLA 설정에 따라 인증이 일어나는 때가 달라집니다.

- Microsoft 문서는 NLA 를 RD 세션 호스트에 세션이 만들어지기 전에 사용자가 인증을 받도록 요구하는 인증 방식으로 정의합니다.
- NLA 는 원격 데스크톱 연결이 만들어지고 로그온 화면이 뜨기 전에 사용자 인증을 끝냅니다.
- 같은 문서는 NLA 의 장점으로 처음에 자원을 덜 쓰고 서비스 거부 공격 위험을 줄인다는 점을 듭니다.
- 인증이 일어나는 때가 달라지면 어떤 이벤트가 어떤 로그온 유형으로 남는지도 달라집니다. Ponder The Bits 는 NLA 설정에 따라 4624·4625 의 로그온 유형이 달라진다고 정리했습니다.

각 이벤트의 칸 구조는 [인증 단계](1149-4624-10-4625.md) 에서 다룹니다. 이 페이지는 해석만 다룹니다.

## 위치와 버전별 차이

### NLA 설정을 확인하는 곳

Microsoft 문서 (Windows Server 2008 R2 기준) 는 NLA 를 세 곳에서 설정한다고 적습니다.

1. 시스템 속성의 원격 탭
2. RD 세션 호스트 구성의 "Allow connections only from computers running Remote Desktop with Network Level Authentication"
3. 그룹 정책: `Computer Configuration\Policies\Administrative Templates\Windows Components\Remote Desktop Services\Remote Desktop Session Host\Security` 의 "Require user authentication for remote connections by using Network Level Authentication"

- 그룹 정책이 다른 설정보다 우선합니다.
- 클라이언트 쪽 요구 조건은 원격 데스크톱 연결 6.0 이상입니다.
- 클라이언트 OS 는 CredSSP 를 지원해야 합니다. 문서는 Windows 7, Vista, XP SP3 등을 예로 듭니다.

### 레지스트리에서 본 값

원격 데스크톱 받기가 꺼진 PC 한 대에서 아래 값을 봤습니다 (확인 범위: Windows 11 Home 빌드 26200).

| 키 | 값 |
|---|---|
| `HKLM\SYSTEM\CurrentControlSet\Control\Terminal Server\WinStations\RDP-Tcp` | UserAuthentication=1, SecurityLayer=2, PortNumber=3389, MinEncryptionLevel=2 |

- UserAuthentication=1 이 "NLA 필요" 라는 뜻인지는 확인하지 못했습니다.
- Windows 10·11 의 기본값이 NLA 켜짐인지도 확인하지 못했습니다.
- 검체에서 그룹 정책 쪽 값이 어느 레지스트리 경로에 남는지, 그 값이 위 값보다 우선하는지도 확인하지 못했습니다.
- 그래서 보고서에 NLA 설정을 쓰려면 검체와 같은 버전의 시험 PC 에서 먼저 확인합니다.
- 수집한 하이브 파일을 읽는 법은 [레지스트리 하이브 구조](../../../01-foundations/database-log-formats/registry-hive/index.md) 에서 다룹니다.

## 증거로서 의미

| 기록 | 증명하는 것 | 증명하지 못하는 것 |
|---|---|---|
| 1149 | 기록된 주소에서 원격 데스크톱 네트워크 연결이 이루어졌습니다 | 자격 증명이 맞았는지. 세션이 열렸는지 |
| 4624 유형 10 | 원격 대화형 로그온 세션이 만들어졌습니다 | 그 계정을 쓴 사람 |
| 4624 유형 3 | 네트워크 로그온 세션이 만들어졌습니다 | 그 로그온이 원격 데스크톱의 NLA 인증인지. 공유 폴더 접근 같은 다른 네트워크 로그온도 유형 3 을 남깁니다 |
| 4625 유형 3 | 네트워크 로그온이 실패했습니다 | 원격 데스크톱 로그온 실패인지. 같은 시각대의 다른 기록으로 확인합니다 |

## 함정과 한계

### 함정 1. 1149 를 "인증 성공" 으로 읽습니다

- 1149 의 메시지 문구는 사용자 인증에 성공했다는 뜻입니다. 문구는 [인증 단계](1149-4624-10-4625.md) 에 있습니다.
- Ponder The Bits 는 1149 가 대상에 인증 성공을 뜻하지 않는다고 적었습니다. RDP 네트워크 연결에 성공했다는 뜻일 뿐이라고 설명합니다.
- 같은 글은 1149 가 남는 때를 이렇게 설명합니다. 클라이언트에서 연결을 누르고 로그인 화면이 뜬 단계입니다. 자격 증명을 넣기 전입니다.
- 1149 에는 로그온 유형이나 성공 여부를 적는 칸이 없습니다. 칸은 사용자·도메인·원본 주소 세 개뿐입니다.
- NLA 는 로그온 화면이 뜨기 전에 인증을 끝냅니다. 그래서 "NLA 가 켜진 대상에서는 1149 가 인증을 통과한 뒤에만 남고, 꺼진 대상에서는 연결만으로 남는다" 는 설명을 흔히 볼 수 있습니다.
- 이번에 연 자료 가운데 이 설명을 직접 적은 곳은 없었습니다. 이 설명을 보고서에 쓰려면 시험 환경에서 먼저 확인합니다.

**피하는 법**

1. 1149 는 "원격 데스크톱 연결 기록" 으로 적습니다.
2. 로그온했는지는 같은 사용자·같은 주소의 4624 유형 10 과 LocalSessionManager 21 로 판단합니다.
3. 1149 뒤에 4624 유형 10 이 없으면 "연결 기록은 있으나 로그온 기록은 찾지 못했다" 까지만 씁니다.

### 함정 2. 로그온 실패를 4625 유형 10 에서만 찾습니다

- Ponder The Bits 는 NLA 가 켜져 있으면 원격 데스크톱 로그온 실패가 4625 유형 3 으로 남는다고 적었습니다.
- NLA 가 꺼져 있으면 유형 10 으로 남습니다.
- 그래서 유형 10 만 찾으면 NLA 가 켜진 대상에서 실패 기록을 놓칩니다.
- NLA 유형 3 실패 기록에 원격 IP 가 늘 남는지는 확인하지 못했습니다. 4624·4625 의 주소 칸은 인증 방식에 따라 비어 있을 수 있습니다 ([로그온·로그오프](../logon-events/index.md)).

**피하는 법**

1. 4625 는 유형 3 과 10 을 함께 뽑습니다.
2. 유형 3 실패는 같은 시각대의 원격 데스크톱 기록 (1149, RdpCoreTS 131·140) 과 맞춰 봅니다. RdpCoreTS 이벤트는 [인증 단계](1149-4624-10-4625.md) 에서 다룹니다.
3. 실패 이유는 4625 의 상태 코드로 나눕니다. 코드 표는 [로그온·로그오프](../logon-events/index.md) 에 있습니다.

### 함정 3. 유형 3 과 10 을 따로따로 셉니다

- Ponder The Bits 는 NLA 가 켜져 있으면 성공한 원격 데스크톱 로그온에서 4624 유형 3 이 먼저 남고 유형 10 이 뒤에 남을 수 있다고 적었습니다.
- 그래서 유형 3 과 10 을 따로 세면 한 번의 접속을 두 번으로 세게 됩니다.
- 반대로 유형 3 은 공유 폴더 접근 같은 다른 네트워크 로그온에서도 남습니다.
- 그래서 유형 3 한 건만 보고 원격 데스크톱 접속이라고 할 수 없습니다.

**피하는 법**

아래 순서는 Ponder The Bits 의 단계 표를 바탕으로 한 정리입니다. 한 자료에 그대로 적힌 절차는 아닙니다.

1. 4624 유형 10 을 찾습니다.
2. 같은 계정·같은 주소의 유형 3 이 바로 앞 시각에 있는지 봅니다. 있으면 두 기록을 한 번의 접속으로 묶습니다.
3. 같은 시각대의 1149 와 LocalSessionManager 21 에서 사용자와 주소를 맞춥니다.
4. 유형 10 이 뒤따르지 않는 유형 3 성공 기록은 다른 네트워크 로그온일 수 있습니다. 공유 폴더 접근 기록을 먼저 봅니다 ([공유 폴더 접근 (5140·5145)](../5140-5145.md)).

### 함정 4. 한 PC 에서 본 순서를 모든 PC 에 적용합니다

- Ponder The Bits 의 저자는 NLA 와 로그온 유형의 관계가 OS 버전과 설정에 따라 다르다고 적었습니다.
- 저자는 Windows 10 과 서버에서 시험 결과가 일정하지 않았다고도 적었습니다.
- 그래서 함정 2·3 의 규칙은 출발점입니다.
- 검체와 같은 버전·같은 설정에서 시험한 결과가 있으면 그 결과를 따릅니다.

## 직접 분석해 보기

### 헥스로 읽을 때

EVTX 레코드를 바이트 단위로 읽는 법은 [이벤트 로그 형식](../../../01-foundations/database-log-formats/evtx-evt-etl/index.md) 에서 다룹니다. 이 페이지는 명령으로만 따라갑니다.

### 공개 도구로 한 번

4624·4625 의 유형 3 과 10 을 한 번에 오래된 순서로 뽑으면 두 유형이 붙어 나오는지 볼 수 있습니다. 아래 명령은 Windows 에 들어 있는 PowerShell 의 Get-WinEvent 로 수집한 보안 로그 사본을 읽습니다.

```powershell
$sec = '.\Security.evtx'
$xp = "*[System[(EventID=4624 or EventID=4625)] and EventData[Data[@Name='LogonType']='3' or Data[@Name='LogonType']='10']]"
Get-WinEvent -Path $sec -FilterXPath $xp -Oldest |
  ForEach-Object {
    $d = @{}
    ([xml]$_.ToXml()).Event.EventData.Data | ForEach-Object { $d[$_.Name] = $_.'#text' }
    '{0:o} {1} 유형{2} {3}\{4} {5}' -f $_.TimeCreated.ToUniversalTime(), $_.Id, $d.LogonType, $d.TargetDomainName, $d.TargetUserName, $d.IpAddress
  }
```

- 이 결과를 [인증 단계](1149-4624-10-4625.md) 의 1149 명령 결과와 합쳐 시각순으로 정렬합니다.
- 유형 3 바로 뒤에 같은 계정·주소의 유형 10 이 붙는 묶음이 있는지 봅니다.
- 이 묶음이 보이는 것만으로 NLA 가 켜져 있었다고 단정하지 않습니다. 함정 4 를 봅니다.

## 교차 검증

| 함께 볼 기록 | 확인할 것 | 링크 |
|---|---|---|
| 1149 | 4624 와 같은 사용자·주소, 앞선 시각 | [인증 단계](1149-4624-10-4625.md) |
| LocalSessionManager 21 | 주소 칸의 원격 IP, 4624 유형 10 과 같은 사용자 | [세션 단계](localsessionmanager-21-25-4778-4779.md) |
| 공유 폴더 접근 | 원격 데스크톱과 관계없는 유형 3 을 걸러 냄 | [공유 폴더 접근 (5140·5145)](../5140-5145.md) |
| RDP-Tcp 키와 그룹 정책 | NLA 설정 | [레지스트리 하이브 구조](../../../01-foundations/database-log-formats/registry-hive/index.md) |

조사 흐름은 [원격 데스크톱 침입 확인](../../../04-scenarios/incident/rdp-intrusion.md) 을 봅니다.

## 실습

NIST CFReDS 같은 공개 검체 가운데 원격 데스크톱 접속을 받은 Windows 이미지를 골라 풉니다. 알맞은 검체가 없으면 시험용 가상 머신에서 NLA 를 켠 상태와 끈 상태로 한 번씩 접속하고, 비밀번호도 한 번씩 틀려 봅니다.

1. 4624 유형 10 마다 바로 앞에 같은 계정·주소의 유형 3 이 있습니까?
2. 4625 에서 유형 3 과 유형 10 은 각각 몇 건입니까?
3. 1149 가운데 같은 사용자·주소의 4624 유형 10 이 뒤따르지 않는 기록이 있습니까?
4. 대상의 RDP-Tcp 키에서 UserAuthentication 값은 무엇입니까? NLA 관련 그룹 정책 설정도 있습니까?
5. NLA 를 켠 가상 머신과 끈 가상 머신에서 1149 가 남는 시점이 다릅니까? 비밀번호를 틀렸을 때도 1149 가 남습니까?
6. 유형 3 성공 기록 가운데 원격 데스크톱과 관계없는 기록을 공유 폴더 접근 기록으로 골라낼 수 있습니까?
