# 화면 잠금·해제 (4800·4801)

> 위치: 아티팩트 사전 > 이벤트 로그 > [로그온·로그오프 (Logon Events)](/02-artifacts/event-logs/logon-events/index.md)

## 한 줄 요약

4800 은 사용자 세션이 잠긴 때를 Security 로그에 남깁니다. 4801 은 그 세션의 잠금이 풀린 때를 남깁니다. 두 이벤트는 기본 설정에서 감사하지 않으므로, 검체에 없는 경우가 더 흔합니다.

## 무엇을 기록하나 · 왜 생기나

- 4800 의 제목은 "The workstation was locked." 입니다.
- 4801 의 제목은 "The workstation was unlocked." 입니다.
- 공급자는 Microsoft-Windows-Security-Auditing 입니다.
- 채널은 Security 입니다.
- 두 이벤트는 감사 하위 범주 "기타 로그온/로그오프 이벤트 감사 (Audit Other Logon/Logoff Events)" 에 속합니다.
- 같은 하위 범주에 화면 보호기 시작·종료(4802·4803)와 원격 세션 다시 연결·끊김(4778·4779)도 들어 있습니다.
- Win+L 처럼 손으로 잠글 때 4800 이 남습니다.
- 한동안 입력이 없어 저절로 잠길 때도 4800 이 남습니다(Ultimate Windows Security 설명).
- 이벤트는 세션이 있는 그 컴퓨터의 Security 로그에 남습니다. 로컬 PC 와 도메인 컨트롤러에 남는 기록의 차이는 [기록이 남는 위치](/02-artifacts/event-logs/logon-events/pc.md) 에서 다룹니다.

## 위치와 버전별 차이

- 파일 위치는 `%SystemRoot%\System32\winevt\Logs\Security.evtx` 입니다.
- 4800·4801 은 Windows Vista·Server 2008 부터 있습니다.
- 이벤트 버전은 0 하나뿐입니다. Windows 10·11 에서도 필드 구성이 같습니다.

기본 감사 설정은 운영체제 종류에 따라 다릅니다. 아래 표는 Microsoft 의 권장 감사 정책 표를 옮긴 것입니다.

| 하위 범주 | 담는 이벤트 | 클라이언트 기본값 | 서버 기본값 |
|---|---|---|---|
| 기타 로그온/로그오프 이벤트 | 4800·4801·4802·4803·4778·4779 등 | 감사 안 함 (표의 기본값 칸이 비어 있음) | 감사 안 함 (표의 기본값 칸이 비어 있음) |
| 로그온 (Audit Logon) | 4624(유형 7 포함)·4625 | 성공 감사. Windows 10 1809 부터 실패도 감사 | 성공·실패 감사 |

- Microsoft 는 서버에서 "강화 권장안" 으로 기타 로그온/로그오프 이벤트의 성공·실패 감사를 켜라고 권합니다.
- 그룹 정책으로 이 하위 범주를 켠 PC 에서만 4800·4801 을 기대할 수 있습니다.
- 검체의 실제 감사 설정은 [감사 정책과 로그 설정](/02-artifacts/event-logs/audit-policy-log-settings.md) 에서 확인합니다.

## 구조

EVTX 레코드와 이진 XML 의 짜임은 [EVTX 파일 구조](/01-foundations/database-log-formats/evtx-evt-etl/file-header-chunk-record.md) 와 [이진 XML 해석](/01-foundations/database-log-formats/evtx-evt-etl/binary-xml-template.md) 에서 다룹니다. 이 페이지에서는 두 이벤트에 담기는 값만 봅니다.

System 부분의 값은 Microsoft 문서의 예시 XML 에서 옮겼습니다.

| 요소 | 값 | 뜻 |
|---|---|---|
| Provider | Microsoft-Windows-Security-Auditing `{54849625-5478-4994-A5BA-3E3B0328C30D}` | 보안 감사 공급자 |
| EventID | 4800 / 4801 | 잠금 / 해제 |
| Version | 0 | 이벤트 버전 |
| Task | 12551 | 기타 로그온/로그오프 하위 범주 |
| Keywords | 0x8020000000000000 | 감사 성공 |
| TimeCreated | UTC 시각 | 기록된 때 |

EventData 부분은 두 이벤트가 같습니다.

| 필드 | 형식 | 뜻 |
|---|---|---|
| TargetUserSid | SID | 잠금·해제를 요청한 계정의 SID |
| TargetUserName | 문자열 | 그 계정의 이름 |
| TargetDomainName | 문자열 | 도메인 이름. 로컬 계정이면 컴퓨터 이름 |
| TargetLogonId | HexInt64 | 로그온 세션 ID. 4624 와 잇는 열쇠 |
| SessionId | UInt32 | 잠기거나 풀린 세션의 번호. `query session` 의 ID 칸과 같은 값 |

- 이 이벤트에는 원본 IP 가 없습니다.
- 인증 방식과 프로세스 정보도 없습니다.
- Microsoft 문서 예시에서 한 세션의 4800 과 4801 은 TargetLogonId(0x759a9)와 SessionId(3)가 같습니다.
- SID 를 읽는 법은 [윈도 식별자 형식](/01-foundations/value-decoding/sid-guid-clsid-known-folder-id.md) 에서 다룹니다.

## 증거로서 의미

### 증명하는 것

- 기록된 때에 이 컴퓨터에서 이 계정의 로그온 세션이 잠겼습니다(4800).
- 기록된 때에 같은 세션의 잠금이 풀렸습니다(4801).
- 같은 TargetLogonId 의 4800 과 4801 사이가 그 세션이 잠겨 있던 구간입니다.
- 4801 은 그 계정으로 잠금 화면을 통과했다는 기록입니다.

### 증명하지 못하는 것

- 키보드 앞에 누가 있었는지는 알려 주지 않습니다. 계정 주인과 실제 조작한 사람을 잇는 근거는 [그 시각에 PC 를 쓴 사람이 누구인가](/04-scenarios/activity/user-attribution.md) 에서 모읍니다.
- 손으로 잠갔는지, 시간이 지나 저절로 잠겼는지는 구분하지 않습니다.
- 비밀번호·PIN·얼굴 인식 가운데 무엇으로 풀었는지는 적혀 있지 않습니다.
- 잠긴 동안 PC 에서 아무 일도 없었다는 뜻이 아닙니다. 예약 작업·동기화·다운로드처럼 사람 손이 필요 없는 일은 잠긴 동안에도 계속 돕니다.
- 4800 이 없다고 해서 잠그지 않았다는 뜻도 아닙니다. 감사가 꺼져 있으면 기록이 아예 생기지 않습니다.

### 보고서 문장 예

- 쓰지 않을 문장: "사용자 A 가 자리를 비웠다."
- 쓸 문장: "Security 로그에 계정 A 의 로그온 세션(Logon ID 0x…)이 YYYY-MM-DD hh:mm:ss(UTC)에 잠기고 hh:mm:ss(UTC)에 풀린 기록이 있습니다."

## 시각 해석

- TimeCreated 는 UTC 입니다.
- 저장 형식은 FILETIME 입니다. 읽는 법은 [시각 값 형식](/01-foundations/value-decoding/filetime-unix-webkit-dos-ole.md) 에서 다룹니다.
- 이벤트 뷰어는 보는 PC 의 시간대로 바꿔서 보여 줍니다. 검체 PC 의 시간대가 아닐 수 있습니다.
- 잠긴 시간의 길이는 같은 TargetLogonId 의 4801 시각에서 4800 시각을 빼서 구합니다.
- 시각은 그 PC 의 시계를 따릅니다. 잠긴 사이에 시계를 바꾸면 길이가 틀어집니다. [시간 변경 (4616)](/02-artifacts/event-logs/4616-kernel-general.md) 을 함께 봅니다.
- 현지 시각으로 옮길 때는 [시간대 설정](/02-artifacts/system-account/time-zone.md) 과 [시간대·시계 오차 보정](/03-techniques/analysis/timeline/time-normalization.md) 을 따릅니다.

## 함정과 한계

1. **기본값은 감사 안 함입니다.** 4800·4801 이 없으면 감사 정책부터 확인합니다. 로그온 감사는 기본으로 켜져 있어서, 4801 이 없어도 4624 유형 7 은 남아 있을 수 있습니다. 유형 7 의 뜻은 [로그온 유형 해석](/02-artifacts/event-logs/logon-events/logon-type.md) 에서 다룹니다. 로그온 감사에는 잠근 때를 알려 주는 이벤트가 없습니다.
2. **4624 유형 7 과 4801 의 Logon ID 를 같다고 보지 않습니다.** 4624 는 로그온 세션이 만들어질 때 남는 이벤트입니다. 4801 의 TargetLogonId 는 잠겼던 원래 세션을 가리킵니다. 두 기록은 계정과 시각으로 짝을 짓습니다. 세션을 잇는 법은 [로그온 세션 잇기](/02-artifacts/event-logs/logon-events/logon-id-4624-4634-4647.md) 에서 다룹니다.
3. **짝이 안 맞는 기록이 있습니다.** 4800 뒤에 4801 없이 로그오프(4647·4634)나 부팅 기록이 오면, 잠긴 채로 로그오프·재시작·전원 끊김이 있었을 수 있습니다. [켜짐·꺼짐](/02-artifacts/event-logs/power-on-off-events.md) 기록과 맞춰 봅니다. 4801 앞에 4800 이 없으면 앞부분 기록이 덮어써졌거나 감사를 도중에 켰을 수 있습니다.
4. **화면 보호기로 잠긴 경우를 따로 봅니다.** 화면 보호기가 걸렸다가 풀릴 때는 4801 대신 4803 이 남을 수 있습니다(Ultimate Windows Security 설명). 4802·4803 도 같은 하위 범주이므로 함께 뽑습니다.
5. **Logon ID 는 재부팅 사이에서만 고유합니다(Ultimate Windows Security 설명).** 여러 번의 부팅에 걸친 로그에서는 같은 값이 다른 세션일 수 있습니다. 짝은 한 부팅 구간 안에서만 짓습니다.
6. **원격 세션과 섞어 읽지 않습니다.** 원격 데스크톱 세션의 끊김·다시 연결은 4779·4778 로 따로 남습니다. SessionId 로 콘솔 세션과 원격 세션을 나눠 읽습니다. 자세한 내용은 [들어온 접속: 세션 단계](/02-artifacts/event-logs/rdp-event-logs/localsessionmanager-21-25-4778-4779.md) 에 있습니다.
7. **절전과 잠금이 겹치는 경우는 이 글에서 확인하지 않았습니다.** 절전에 들어갈 때와 깨어날 때 4800·4801 이 어떤 순서로 남는지는 검체에서 전원 기록과 나란히 놓고 확인합니다.
8. **지우기와 덮어쓰기에 약합니다.** 로그를 지우면 1102 가 남습니다. 이는 [이벤트 로그 삭제 (1102·104)](/02-artifacts/event-logs/1102-104.md) 에서 다룹니다. 감사를 끈 흔적은 [감사 정책과 로그 설정](/02-artifacts/event-logs/audit-policy-log-settings.md) 에서 찾습니다. 보관 크기가 차면 보관 설정에 따라 오래된 기록이 먼저 사라집니다.

## 직접 분석해 보기

### 헥스로 한 번

레코드를 찾는 단서는 두 가지입니다.

- EVTX 레코드는 서명 `2A 2A 00 00` 으로 시작합니다.
- 4800 은 16진수로 0x12C0 이므로 리틀 엔디언 바이트는 `C0 12` 입니다. 4801 은 `C1 12` 입니다.
- 이 두 바이트는 다른 자리에도 우연히 나오므로 후보를 좁히는 데만 씁니다.

이벤트 값은 레코드 안 템플릿 인스턴스의 값 배열에 있습니다. 값마다 4바이트 설명자가 하나씩 붙습니다. 설명자는 크기 2바이트, 값 형식 1바이트, 0x00 1바이트로 되어 있습니다(libevtx 명세). 값 형식 번호는 SID 가 0x13, UTF-16LE 문자열이 0x01, HexInt64 가 0x15, UInt32 가 0x08 입니다.

아래 바이트는 Microsoft 문서의 4800 예시 XML 값을 명세대로 옮겨 만든 예시입니다. 실제 검체에서 나온 값이 아닙니다.

```
값 설명자 (EventData 다섯 값만 보임)
1C 00 13 00    크기 28, 형식 0x13 SID         → TargetUserSid
?? 00 01 00    크기는 글자 수에 따라, 형식 0x01 → TargetUserName
?? 00 01 00    크기는 글자 수에 따라, 형식 0x01 → TargetDomainName
08 00 15 00    크기 8,  형식 0x15 HexInt64    → TargetLogonId
04 00 08 00    크기 4,  형식 0x08 UInt32      → SessionId

값 (SID·Logon ID·Session ID)
01 05 00 00 00 00 00 05 15 00 00 00 07 F2 1B CE
5A 2E 3B A9 B0 3F 1A 31 50 04 00 00
  → S-1-5-21-3457937927-2839227994-823803824-1104
A9 59 07 00 00 00 00 00
  → 0x759A9
03 00 00 00
  → 3
```

- SID 는 첫 바이트가 개정 번호(1)이고, 둘째 바이트가 하위 권한 개수(5)입니다.
- 다음 6바이트는 식별 권한이고 빅 엔디언입니다(5).
- 그 뒤로 하위 권한이 4바이트씩 리틀 엔디언으로 이어집니다.
- 실제 값 배열에는 System 부분에 들어가는 값도 함께 있을 수 있습니다. 그래서 EventData 값의 위치는 템플릿 정의를 보고 찾습니다.

### 공개 도구로 한 번

운영체제에 들어 있는 PowerShell 로 두 이벤트만 뽑을 수 있습니다. 화면 보호기 이벤트도 함께 뽑습니다.

```powershell
Get-WinEvent -Path .\Security.evtx -FilterXPath "*[System[(EventID=4800 or EventID=4801 or EventID=4802 or EventID=4803)]]"
```

- EvtxECmd, python-evtx 같은 공개 파서로도 같은 값을 뽑을 수 있습니다.
- Chainsaw·Hayabusa 같은 규칙 기반 도구로 여러 로그를 한꺼번에 훑을 수도 있습니다.
- 도구마다 TargetLogonId 를 16진수 문자열이나 10진수로 다르게 보여 줄 수 있습니다. 4624 와 짝을 지을 때는 표기부터 맞춥니다.
- 두 도구의 결과를 맞춰 보는 법은 [도구 결과 교차 검증](/03-techniques/reporting/tool-validation.md) 에서 다룹니다.

## 실습

1. 시험용 가상 머신에서 `auditpol /set /subcategory:"Other Logon/Logoff Events" /success:enable` 로 감사를 켭니다. 한국어 Windows 에서는 하위 범주 이름이 한국어로 표시되므로 `auditpol /list /subcategory:*` 로 이름을 먼저 확인합니다. Win+L 로 잠갔다가 풀고, 4800 과 4801 의 TargetLogonId 가 같은지 확인합니다.
2. 같은 때 남은 4624 유형 7 의 Logon ID 는 4801 의 TargetLogonId 와 같습니까, 다릅니까?
3. 암호를 건 화면 보호기가 걸린 뒤 풀면 4801 과 4803 가운데 무엇이 남습니까?
4. 공개 검체(NIST CFReDS 등)의 Security.evtx 에 4800·4801 이 있습니까? 없다면 감사 정책 때문인지, 기록이 덮어써진 탓인지 어떻게 가릅니까?
5. 잠긴 구간 안에 파일 변경 기록이 있다면, 보고서에 어떤 문장으로 쓰겠습니까?
