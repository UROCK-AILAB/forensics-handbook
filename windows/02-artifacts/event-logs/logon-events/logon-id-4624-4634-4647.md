# 로그온 세션 잇기 (Logon ID·4624~4634·4647)

> 위치: 아티팩트 사전 > 이벤트 로그 > [로그온·로그오프 (Logon Events)](index.md)

## 한 줄 요약

로그온 ID (Logon ID) 는 로그온 세션 하나에 붙는 16진 값입니다. 4624 는 세션이 만들어진 때를 남깁니다. 4647 은 사용자가 로그오프를 시작한 때를 남깁니다. 4634 는 세션이 끝난 때를 남깁니다. 세 이벤트를 로그온 ID 로 묶으면 한 세션의 처음과 끝을 이을 수 있습니다. 이 값은 같은 컴퓨터에서 다시 부팅하기 전까지만 겹치지 않습니다.

## 무엇을 기록하나 · 왜 생기나

세 이벤트 모두 공급자 `Microsoft-Windows-Security-Auditing` 이 `Security` 채널에 남깁니다. 공급자 GUID 는 `{54849625-5478-4994-A5BA-3E3B0328C30D}` 입니다.

| 이벤트 | 생기는 때 | 감사 하위 범주 | Task |
|---|---|---|---|
| 4624 | 로그온 세션이 만들어질 때 | 로그온 (Audit Logon) | 12544 |
| 4647 | 계정이 로그오프 기능으로 로그오프 절차를 시작할 때 | 로그오프 (Audit Logoff) | 12545 |
| 4634 | 로그온 세션이 끝나 더는 없을 때 | 로그오프 | 12545 |

- Microsoft 문서는 4647 뒤로 사용자가 시작하는 활동은 더 없다고 적습니다. 그래서 4647 도 로그오프 이벤트로 읽을 수 있습니다.
- 4634 는 로그오프를 시작했다는 기록이 아닙니다. 세션 자체가 사라졌다는 기록입니다.
- 사용자가 로그오프를 시작하면 보통 4647 과 4634 가 둘 다 보입니다.
- 4647 은 대화형 (Interactive)·원격 대화형 (RemoteInteractive) 로그온을 표준 방법으로 끝낼 때 더 흔합니다.
- 로그온 유형 숫자의 뜻은 [로그온 유형 해석](logon-type.md)에서 다룹니다. 이 페이지는 세션을 잇는 칸만 다룹니다.

## 위치와 버전별 차이

- 4624 는 접속을 받은 컴퓨터, 곧 세션이 만들어진 컴퓨터에 남습니다.
- 4634·4647 은 로그온 ID 로 같은 컴퓨터의 4624 와 짝짓습니다.
- 이벤트마다 어느 컴퓨터의 로그를 봐야 하는지는 [기록이 남는 위치](pc.md)에서 다룹니다.
- 로그 파일 형식은 [이벤트 로그 형식](../../../01-foundations/database-log-formats/evtx-evt-etl/index.md)에서 다룹니다.
- 이 이벤트들이 남도록 감사가 켜져 있었는지는 [감사 정책과 로그 설정](../audit-policy-log-settings.md)에서 확인합니다.

| 이벤트 | 이벤트 버전 | 최소 OS | 세션 잇기와 관련된 점 |
|---|---|---|---|
| 4624 | 0 · 1 · 2 | Vista · Server 2008 | 버전 2 (Windows 10) 부터 연결된 로그온 ID (Linked Logon ID) 와 관리자 권한 토큰 (Elevated Token) 칸이 있습니다 |
| 4647 | 0 | Vista · Server 2008 | `LogonType` 칸이 없습니다 |
| 4634 | 0 | Vista · Server 2008 | `LogonType` 칸이 있습니다 |

4624 의 버전별 칸 변화 전체는 [로그온 유형 해석](logon-type.md)의 표를 봅니다. 이 페이지의 칸 설명은 Microsoft 의 Windows 10 보관 문서를 따릅니다.

## 구조

### 세션을 잇는 칸

| 이벤트 | 칸 (XML 이름) | 뜻 |
|---|---|---|
| 4624 | `TargetLogonId` | 새로 만들어진 세션의 로그온 ID 입니다. 이벤트 뷰어에는 "New Logon" 절의 Logon ID 로 보입니다. 형식은 HexInt64 입니다 |
| 4624 | `TargetLinkedLogonId` | 짝을 이루는 로그온 세션의 값입니다. 짝이 없으면 `0x0` 입니다. 버전 2 부터 있습니다 |
| 4624 | `SubjectLogonId` | 로그온을 보고한 계정의 세션 값입니다. 새 세션의 값이 아닙니다 |
| 4624 | `LogonGuid` | 로그온 GUID (Logon GUID) 입니다. 도메인 컨트롤러의 4769, 같은 컴퓨터의 4648·4964 와 잇는 값입니다. 잡히지 않으면 모두 0 입니다 |
| 4647 | `TargetLogonId` | 로그오프를 시작한 세션의 로그온 ID 입니다 |
| 4634 | `TargetLogonId` | 끝난 세션의 로그온 ID 입니다 |
| 4672 | `SubjectLogonId` | 특수 권한이 붙은 세션의 값입니다. 4624 와 잇습니다 |
| 4648 | `SubjectLogonId` | 명시적 자격 증명을 넣은 쪽 세션의 값입니다. 4624 와 잇습니다 |

4672·4648 은 [명시적 자격 증명·특수 권한](4648-4672.md)에서 다룹니다. 로그온 GUID 로 도메인 컨트롤러 기록과 잇는 법은 [도메인 인증 이벤트](4768-4769-4776.md)에서 다룹니다.

### 4624 의 두 계정: Subject 와 New Logon

4624 한 건에는 계정 정보가 두 벌 들어 있습니다.

| 절 | XML 칸 | 뜻 |
|---|---|---|
| Subject | `SubjectUserSid`, `SubjectUserName`, `SubjectDomainName`, `SubjectLogonId` | 로그온을 보고한(요청한) 계정입니다 |
| New Logon | `TargetUserSid`, `TargetUserName`, `TargetDomainName`, `TargetLogonId` | 실제로 로그온한 계정입니다 |

- Microsoft 예시에서 Subject 는 SID `S-1-5-18`, 이름은 컴퓨터 이름 뒤에 `$` 가 붙은 값, `SubjectLogonId` 는 `0x3e7` 이었습니다.
- Microsoft 문서는 이 이벤트를 보통 SYSTEM 계정이 남긴다고 적습니다. 그래서 Subject 의 Security ID 가 SYSTEM 이 아니면 살펴보라고 권합니다.
- Subject 에 사용자 정보 없이 NULL SID `S-1-0-0` 만 들어가는 경우도 있습니다.
- 세션을 이을 때 쓰는 값은 New Logon 절의 `TargetLogonId` 입니다.

### 칸 목록

4624 버전 2 예시의 EventData 칸 순서는 아래와 같습니다.

```
SubjectUserSid, SubjectUserName, SubjectDomainName, SubjectLogonId,
TargetUserSid, TargetUserName, TargetDomainName, TargetLogonId,
LogonType, LogonProcessName, AuthenticationPackageName, WorkstationName,
LogonGuid, TransmittedServices, LmPackageName, KeyLength,
ProcessId, ProcessName, IpAddress, IpPort, ImpersonationLevel,
RestrictedAdminMode, TargetOutboundUserName, TargetOutboundDomainName,
VirtualAccount, TargetLinkedLogonId, ElevatedToken
```

4647 과 4634 는 칸이 적습니다.

| 이벤트 | EventData 칸 |
|---|---|
| 4647 | `TargetUserSid`, `TargetUserName`, `TargetDomainName`, `TargetLogonId` |
| 4634 | `TargetUserSid`, `TargetUserName`, `TargetDomainName`, `TargetLogonId`, `LogonType` |

- 4634 는 이벤트 뷰어에서 "Subject" 절로 보입니다. 그러나 XML 칸 이름은 `Target` 으로 시작합니다.
- `ElevatedToken`·`VirtualAccount`·`ImpersonationLevel` 은 XML 에 Yes/No 같은 글자로 들어 있지 않습니다. `%%1842`·`%%1843`·`%%1833` 같은 메시지 코드로 들어 있습니다.
- 메시지 코드와 글자의 대응표는 이번에 확인한 Microsoft 문서에 없습니다. 이벤트 뷰어처럼 메시지를 풀어 보여 주는 도구로 확인합니다.
- `ElevatedToken` 의 뜻은 [명시적 자격 증명·특수 권한](4648-4672.md)에서 다룹니다.

### Microsoft 예시 값

아래는 Microsoft 4624 문서의 예시(로컬 대화형 로그온)에서 이 페이지에 필요한 값만 옮긴 것입니다.

| 칸 | 값 |
|---|---|
| `TimeCreated SystemTime` | `2015-11-12T00:24:35.079785200Z` |
| `SubjectUserSid` | `S-1-5-18` |
| `SubjectLogonId` | `0x3e7` |
| `TargetLogonId` | `0x8dcdc` |
| `LogonType` | `2` |
| `AuthenticationPackageName` | `Negotiate` |
| `LogonGuid` | `{00000000-0000-0000-0000-000000000000}` |
| `TargetLinkedLogonId` | `0x0` |

이 예시에서는 로그온 GUID 가 모두 0 이었습니다. 이런 4624 는 로그온 GUID 로 다른 컴퓨터의 기록과 이을 수 없습니다.

## 증거로서 의미

| 증명하는 것 | 증명하지 못하는 것 |
|---|---|
| 기록 시각에 이 컴퓨터에 New Logon 계정의 세션이 만들어졌습니다 (4624) | 그 계정을 쓴 사람이 누구인지 |
| 그 세션에서 로그오프 절차가 시작됐습니다 (4647) | 세션이 있는 동안 사람이 앞에 있었는지 |
| 그 세션이 끝나 더는 없었습니다 (4634) | 끝 기록이 없는 세션이 계속 이어졌는지 |
| 같은 로그온 ID 의 4672 가 있으면, 그 세션에 특수 권한이 붙었습니다 | 세션 안에서 무엇을 했는지 |
| `TargetLinkedLogonId` 가 `0x0` 이 아니면, 짝을 이루는 세션이 있습니다 | 짝을 이룬 두 세션이 두 번의 로그온인지 |

보고서에는 기록이 말하는 만큼만 씁니다. 아래 시각과 계정은 설명을 위해 만든 예입니다. 로그온 ID 는 Microsoft 문서의 예시 값입니다.

- 쓸 수 있는 문장: "이 PC 의 Security 로그에 2024-03-15 00:10:02 UTC, 계정 `kim` 의 4624 가 있습니다. 로그온 유형은 2, 로그온 ID 는 0x8dcdc 입니다. 같은 로그온 ID 의 4647 은 08:55:40 UTC, 4634 는 08:55:41 UTC 에 있습니다. 두 시각 사이에 재부팅 기록은 없습니다."
- 쓰면 안 되는 문장: "김 씨가 00:10 부터 08:55 까지 PC 를 썼습니다."

두 번째 문장은 기록에 없는 사람과 사용 시간을 적습니다. 세션이 열려 있던 시간과 사람이 PC 를 쓴 시간은 다릅니다. 사용 시간은 [PC 사용 시간 재구성](../../../04-scenarios/activity/system-usage-time.md)의 흐름으로 따로 판단합니다.

## 시각 해석

- `TimeCreated SystemTime` 값은 끝에 `Z` 가 붙은 UTC 형식입니다.
- Microsoft 문서는 이 시각이 이벤트를 기록한 때인지, 일이 일어난 때인지 따로 밝히지 않습니다. 보고서에는 "기록 시각" 으로 적습니다.
- 이벤트 뷰어 같은 도구는 분석 PC 의 시간대로 바꿔 보여 줄 수 있습니다. 원래 값은 XML 에서 확인합니다. 값 형식은 [시각 값 형식](../../../01-foundations/value-decoding/filetime-unix-webkit-dos-ole.md)에서 다룹니다.
- 4624 에서 4634 까지는 세션이 있던 시간입니다. 사람이 자리에 있던 시간이 아닙니다. 세션 중간에 잠근 시간은 [화면 잠금·해제](4800-4801.md)에서 찾습니다.
- 4647 은 로그오프를 시작한 때이고, 4634 는 세션이 사라진 때입니다. 두 시각이 다르면 둘 다 적습니다.
- 시각은 이벤트를 남긴 컴퓨터의 시계를 따릅니다. 시스템 시각을 바꾼 기록은 [시간 변경](../4616-kernel-general.md)에서 찾습니다.
- 여러 컴퓨터의 기록을 한 줄로 세울 때는 [타임라인 작성](../../../03-techniques/analysis/timeline/index.md)을 봅니다.

## 함정과 한계

1. **Subject 의 로그온 ID 로 세션을 잇습니다.** 4624 의 `SubjectLogonId` 는 로그온을 보고한 계정의 값입니다. Microsoft 예시에서는 `0x3e7` 이었습니다. 새 세션의 값은 `TargetLogonId` 입니다.
2. **이벤트마다 칸 이름이 같다고 봅니다.** 4634·4647 은 세션 값을 `TargetLogonId` 에 둡니다. 4672·4648 은 `SubjectLogonId` 에 둡니다. 4634 는 화면에 "Subject" 로 보여도 XML 이름은 `TargetLogonId` 입니다. 도구가 칸 이름을 바꿔 보여 주면 XML 원문과 맞춰 봅니다.
3. **재부팅을 넘어 짝짓습니다.** Microsoft 문서는 로그온 ID 가 같은 컴퓨터에서 재부팅 사이에서만 겹치지 않는다고 적습니다. 부팅 구간을 먼저 나누고, 같은 구간 안에서만 짝짓습니다.
4. **다른 컴퓨터끼리 로그온 ID 를 맞춥니다.** 같은 값이라도 컴퓨터가 다르면 다른 세션입니다. 컴퓨터를 넘어 이을 때는 로그온 GUID 를 씁니다. 로그온 GUID 가 모두 0 이면 이 방법도 쓸 수 없습니다.
5. **짝을 이룬 4624 두 건을 두 번의 로그온으로 셉니다.** `TargetLinkedLogonId` 가 `0x0` 이 아니면 짝을 이루는 세션이 있다는 뜻입니다. 관리자 계정이 UAC 로 로그온할 때 이런 짝이 생긴다는 설명이 흔합니다. 이번에 연 Microsoft 문서에서는 이 설명을 확인하지 못했습니다. 두 레코드가 서로의 값을 가리키는지 직접 확인합니다.
6. **4647 이 없으면 이상하다고 봅니다.** 4647 은 대화형·원격 대화형 로그온을 표준 방법으로 끝낼 때 더 흔합니다. 다른 유형의 세션에 4647 이 없다는 것만으로 이상하다고 보지 않습니다. 세션의 끝은 4634 로 확인합니다.
7. **4634 가 없으면 세션이 계속 열려 있었다고 봅니다.** 끝 기록이 없는 이유는 이 로그만으로 가리지 못합니다. 감사 설정, 로그 덮어쓰기, 전원 끊김 가운데 무엇인지 다른 기록으로 확인합니다. 전원이 갑자기 꺼졌을 때 4634 가 남지 않는다는 설명은 흔하지만, 이번에 연 Microsoft 문서에서는 확인하지 못했습니다. 세션의 끝은 [켜짐·꺼짐](../power-on-off-events.md) 기록으로 메웁니다.
8. **사람이 아닌 계정의 세션을 셉니다.** Microsoft 의 4634 문서 예시는 `Window Manager` 도메인의 `DWM-1` (SID `S-1-5-90-1`) 계정 기록입니다. 세션을 셀 때는 SID 로 시스템 계정을 먼저 걸러 냅니다. SID 형식은 [윈도 식별자 형식](../../../01-foundations/value-decoding/sid-guid-clsid-known-folder-id.md)에서 다룹니다.
9. **로그온 유형으로 짝을 맞춥니다.** 4647 에는 `LogonType` 칸이 없습니다. 짝은 로그온 ID 로 맞추고, 유형은 4624 에서 읽습니다.

### 지우기와 조작

- **로그를 지웁니다.** 보안 로그를 지운 흔적은 [이벤트 로그 삭제](../1102-104.md)에서 찾습니다. 파일 안에 남은 지운 레코드는 [이벤트 로그 형식](../../../01-foundations/database-log-formats/evtx-evt-etl/index.md)의 하위 페이지에서 다룹니다.
- **감사를 끕니다.** 로그오프 감사를 끄면 4634·4647 이 남지 않습니다. 4624 만 있고 끝 기록이 하나도 없으면 [감사 정책과 로그 설정](../audit-policy-log-settings.md)을 먼저 확인합니다.
- **시스템 시각을 바꿉니다.** 세션의 시작과 끝 시각이 모두 바뀐 시계를 따릅니다. [시간 변경](../4616-kernel-general.md)을 함께 봅니다.
- 이런 흔적을 모아 읽는 순서는 [증거를 없애려 했나](../../../04-scenarios/activity/anti-forensics/index.md)에서 다룹니다.

## 직접 분석해 보기

### 잇는 순서

1. 이 컴퓨터가 언제 다시 부팅했는지 먼저 찾습니다. 부팅 기록은 [켜짐·꺼짐](../power-on-off-events.md)에서 다룹니다.
2. 4624 에서 `TargetLogonId`, `TargetUserName`, `LogonType`, `TargetLinkedLogonId` 를 적습니다.
3. 같은 부팅 구간 안에서 `TargetLogonId` 가 같은 4647·4634 를 찾습니다.
4. 같은 값이 `SubjectLogonId` 에 들어 있는 4672·4648 을 찾습니다. 이 기록들은 그 세션 안에서 생겼습니다.
5. `TargetLinkedLogonId` 가 `0x0` 이 아니면 그 값을 `TargetLogonId` 로 쓰는 4624 를 찾습니다. 두 기록이 서로를 가리키는지 봅니다.
6. 끝 기록을 못 찾으면 다음 부팅 전 마지막 기록과 전원 기록을 함께 적습니다.

> 그림 자리: 한 부팅 구간의 시간 축 위에 4624(로그온 ID 0x8dcdc) → 4672(같은 값) → 4647 → 4634 를 놓고, 재부팅 뒤 같은 값이 다른 세션에 다시 쓰이는 모습을 함께 보여 주는 그림

### 헥스로 한 번

EVTX 레코드에서 값이 어디에 어떤 바이트 순서로 놓이는지는 [로그온 유형 해석](logon-type.md)의 "헥스로 한 번" 에서 다룹니다. 여기서는 그 방식대로 로그온 ID 를 바이트로 옮겨 같은 세션의 레코드를 찾아갑니다.

아래는 Microsoft 문서의 예시 값을 형식대로 옮긴 예시입니다. 검체에서 뽑은 바이트가 아닙니다.

```
TargetLogonId  0x8dcdc  →  DC DC 08 00 00 00 00 00
SubjectLogonId 0x3e7    →  E7 03 00 00 00 00 00 00
```

1. 4624 레코드 안에서 `TargetLogonId` 값 8바이트를 찾습니다.
2. 같은 8바이트를 파일 전체에서 찾습니다. 걸린 자리가 같은 세션의 4634·4647·4672 후보입니다.
3. 걸린 자리마다 어느 레코드의 어느 칸인지 확인합니다. 같은 바이트가 다른 칸이나 관계없는 데이터에 우연히 들어 있을 수 있습니다.
4. 4634·4647·4672 의 해당 칸이 같은 8바이트 형식으로 저장되는지는 그 파일의 템플릿에서 확인합니다.
5. 예시의 `SubjectLogonId` `0x3e7` 처럼 보고한 쪽 계정의 값은 여러 4624 에 되풀이해 들어갈 수 있습니다. 이런 값으로 찾으면 걸리는 자리가 너무 많습니다.

### 공개 도구로 한 번

- 이벤트 뷰어에서 "자세히 → XML 보기" 를 열면 `<Data Name="TargetLogonId">0x8dcdc</Data>` 처럼 값을 바로 볼 수 있습니다.
- Windows 에 들어 있는 PowerShell 로 세 이벤트를 로그온 ID 별로 늘어놓을 수 있습니다. 아래는 사본 파일을 읽는 예입니다.

```powershell
Get-WinEvent -Path .\Security.evtx -FilterXPath "*[System[(EventID=4624 or EventID=4647 or EventID=4634)]]" -Oldest |
  ForEach-Object {
    $d = @{}
    ([xml]$_.ToXml()).Event.EventData.Data | ForEach-Object { $d[$_.Name] = $_.'#text' }
    [pscustomobject]@{
      TimeUtc   = $_.TimeCreated.ToUniversalTime()
      EventId   = $_.Id
      LogonId   = $d['TargetLogonId']
      Linked    = $d['TargetLinkedLogonId']
      User      = $d['TargetUserName']
      LogonType = $d['LogonType']
    }
  } | Sort-Object LogonId, TimeUtc | Format-Table
```

- 이 목록은 부팅 구간을 나누지 않습니다. 재부팅 시각을 따로 찾아 구간별로 나눈 뒤 짝을 봅니다.
- 한 세션만 볼 때는 `EventData[Data[@Name='TargetLogonId']='0x8dcdc']` 조건을 XPath 에 더합니다. 값은 XML 에 보이는 모양 그대로 적습니다.
- python-evtx, EvtxECmd 같은 공개 도구도 이 칸들을 뽑아 줍니다. 도구가 `SubjectLogonId` 와 `TargetLogonId` 를 어떻게 이름 붙이는지 XML 원문 한두 건과 맞춰 봅니다. 방법은 [도구 결과 교차 검증](../../../03-techniques/reporting/tool-validation.md)에서 다룹니다.
- 많은 기록을 규칙으로 훑는 방법은 [이벤트 로그 규칙 검색](../../../03-techniques/analysis/sigma-rules.md)에서 다룹니다.

## 실습

NIST CFReDS 같은 공개 검체 가운데 Windows 이미지에서 `Security` 로그를 꺼내 사본으로 풀어 봅니다.

1. 4624 가운데 사람 계정의 기록만 골라, 같은 로그온 ID 의 4634 가 있는 비율을 세어 봅니다.
2. 4647 이 있는 세션의 로그온 유형은 무엇입니까? 4647 없이 4634 만 있는 세션의 유형과 비교해 봅니다.
3. 짝이 없는 4624 를 골라, 그 뒤 첫 재부팅 시각과 비교해 봅니다.
4. 같은 로그온 ID 가 서로 다른 부팅 구간에 두 번 나오는지 찾아봅니다.
5. `TargetLinkedLogonId` 가 `0x0` 이 아닌 4624 두 건을 찾아 서로 가리키는지 확인합니다. 두 건의 관리자 권한 토큰 칸도 비교합니다.

직접 만든 Windows 10·11 가상 머신에서도 해 봅니다. 각 단계의 시각을 적어 둡니다.

1. 로컬 계정으로 로그온한 뒤 시작 메뉴에서 로그아웃합니다. 4647 과 4634 의 순서와 시각 차이를 봅니다.
2. 로그온한 채 가상 머신의 전원을 강제로 끕니다. 다시 켠 뒤 앞 세션의 4634 가 있는지 봅니다. 위 함정 7번의 답이 여기서 나옵니다.
3. 다른 가상 머신에서 공유 폴더에 접속했다가 창을 닫습니다. 유형 3 세션의 4634 가 언제 남는지 잽니다.
4. 관리자 계정과 일반 계정으로 한 번씩 로그온해 `TargetLinkedLogonId` 가 어떻게 남는지 비교합니다. 위 함정 5번의 답이 여기서 나옵니다.
