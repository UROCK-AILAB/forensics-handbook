# 위챗 (WeChat)

위챗은 Tencent 의 메신저이고, 대화 기록을 사용자 기기의 로컬 DB 에 암호화해 저장합니다[1]. PC 판의 폴더 구성과 DB 형식은 공개된 분석 자료가 없어 실제 데이터로 확인해야 합니다. 이 페이지는 알려진 설명과 실제 데이터로 확인할 항목을 정리합니다. 2026년 초 GitHub 에서 위챗 대화 DB 를 푸는 공개 도구 다수가 Tencent 의 요청으로 내려갔습니다.

## 무엇을 기록하나 · 왜 생기나

### 서비스 이름

위챗의 개발사이자 권리자는 Tencent 입니다. 중국 본토 서비스 이름은 Weixin 이고 해외 서비스 이름은 WeChat 이며, 두 서비스는 자매 서비스이고, 분석할 때는 두 이름을 모두 검색어로 씁니다.

### 로컬 대화 DB

위챗은 개인 대화와 미디어를 사용자 기기에 암호화된 형태로 저장합니다. 저장 방식은 Tencent 자체의 DB 방식이고, 대화 기록은 위챗 안의 로컬 DB 에 저장됩니다[1]. Tencent 는 자체 암호 알고리즘, 고유한 암호 키, 자체 DB 프로토콜로 이 DB 에 접근을 막고, 이 키는 사용자나 제3자에게 드러나지 않는다고 주장합니다[1].

Tencent 는 암호화된 대화 기록을 백업하고 옮기는 공식 도구를 제공합니다[1].

### 분석할 때의 뜻

- 대화 DB 는 암호문이라고 보고 시작합니다.
- 공식 백업·이전 기능을 썼다면 대화 기록이 다른 PC 나 기기로 옮겨졌을 수 있습니다.
- 대화 DB 를 풀지 못해도 받은 파일·사진, 설치·실행 흔적은 따로 볼 수 있습니다.

## 위치와 버전별 차이

### 알려진 위치

아래는 널리 알려진 설명이며, 이를 뒷받침하는 공개 분석 자료가 없어 분석 대상마다 직접 확인합니다.

| 판 | 알려진 설명 |
|---|---|
| 3.x | 기본 저장 폴더가 `Documents\WeChat Files\<wxid>\` 입니다 |
| 3.x | 그 아래 `Msg\` 에 연락처 `MicroMsg.db` 와 대화 `Multi\MSG<n>.db` 가 있습니다 |
| 3.x | `FileStorage\` 에 받은 파일과 사진이 있습니다 |
| 3.x | 사진 캐시 `.dat` 파일을 단순 XOR 로 가려 둡니다 |
| 3.x | 사용자가 저장 폴더를 바꾸면, 바꾼 경로를 적는 설정 파일이 `%APPDATA%\Tencent\WeChat\` 아래에 있습니다 |
| 4.x (Weixin 4.0 계열) | 저장 폴더 이름(`xwechat_files` 등)과 DB 구성이 3.x 와 다릅니다 |

- 알려진 바로는 3.x 와 4.x 의 구성이 크게 다릅니다(버전마다 확인 필요). 그래서 분석 대상의 버전부터 확인합니다.
- 공개 수집 정의 모음 KapeFiles 에는 위챗 항목이 없습니다(2026-09-23 기준)[2]. 자동 수집 목록만 돌리면 위챗 폴더를 빠뜨릴 수 있습니다.
- 저장 위치가 Windows 버전에 따라 다르다는 공개 자료는 없습니다.

### 찾는 법

1. [설치 프로그램](../system-account/uninstall.md) 에서 위챗(Weixin) 설치 여부와 버전을 봅니다.
2. [프리페치](../execution/prefetch/index.md) 와 [AmCache](../execution/amcache-hve/index.md) 에서 실행 파일 경로를 봅니다.
3. [마스터 파일 테이블](../filesystem/mft.md) 목록에서 `WeChat`·`Weixin`·`Tencent` 가 들어간 폴더를 찾습니다. 알려진 폴더 이름 `WeChat Files`·`xwechat_files` 도 검색합니다.
4. 저장 폴더는 사용자가 바꿀 수 있다고 알려져 있습니다. 문서 폴더에 없으면 다른 드라이브도 봅니다.
5. `%APPDATA%\Tencent` 아래에서 저장 경로를 적은 설정 파일이 있는지 봅니다.
6. 찾은 폴더의 이름·구성과 앱 버전을 함께 적습니다.

## 구조

DB 의 내부 구조는 공개 자료가 없습니다. 로컬 DB 가 SQLCipher 계열 형식이라는 설명이 흔하지만, Tencent 는 "자체 DB 방식" 이라고만 밝혔습니다[1]. 그래서 SQLCipher 라고 단정하지 않고 파일 앞머리부터 봅니다.

| 앞머리 모양 | 뜻 | 다음에 볼 페이지 |
|---|---|---|
| SQLite 헤더 문자열 | 평문 SQLite | [SQLite 데이터베이스](../../01-foundations/database-log-formats/sqlite/index.md) |
| 알아볼 서명이 없고 바이트가 고르게 흩어져 있음 | 암호문일 가능성이 큼 | [암호화 증거 다루기](../../03-techniques/analysis/encrypted-evidence/index.md) |

- 알려진 바로는 `<wxid>` 폴더 이름은 계정 식별자입니다(버전마다 확인 필요). 이 이름으로 계정을 추정합니다.
- 알려진 바로는 3.x 사진 캐시 `.dat` 은 단순 XOR 로 가려져 있습니다(버전마다 확인 필요). 그러면 파일 앞머리에 이미지 서명이 보이지 않습니다. 확장자와 앞머리만 보고 이미지가 아니라고 판단하지 않습니다.

## 증거로서 의미

| 증명하는 것 | 증명하지 못하는 것 |
|---|---|
| 위챗 폴더나 설정 파일이 있으면, 그 Windows 계정에서 위챗을 설치했거나 실행했습니다 | 누가 그 계정으로 앱을 조작했는지 |
| 계정 폴더가 여러 개면 이 PC 에서 여러 계정이 로그인했을 수 있습니다 | 폴더 이름만으로 계정 주인이 누구인지 |
| 받은 파일 폴더에 파일이 있으면 그 파일이 이 PC 에 있었습니다 | 대화 DB 를 풀지 못했을 때, 누가 그 파일을 보냈는지 |
| 실행 흔적이 있으면 그 시각에 위챗이 실행됐습니다 | 그 시각에 대화를 주고받았는지 |
| | 대화 DB 를 풀지 못했을 때 대화 내용. 대화가 없었다는 것도 말하지 못합니다 |
| | 이 PC 의 대화가 전체 대화라는 것. 공식 도구로 다른 곳에 옮겼을 수 있습니다 |

### 보고서 문장

아래 사용자 이름과 개수는 설명을 위해 만든 예입니다.

- 쓸 수 있는 문장: "사용자 A 의 문서 폴더 아래 위챗 저장 폴더에 계정 폴더 1개가 있습니다. 받은 파일 폴더에는 파일 37개가 있습니다. 대화 DB 는 암호문이어서 내용을 확인하지 못했습니다."
- 쓰면 안 되는 문장: "사용자 A 는 위챗으로 파일 37개를 받았습니다."

## 시각 해석

- 대화 DB 안 시각 열의 형식은 공개 자료가 없습니다.
- DB 를 풀 수 있으면 보낸 시각을 아는 시험 메시지로 형식을 맞춥니다. 후보 형식은 [시각 값 형식](../../01-foundations/value-decoding/filetime-unix-webkit-dos-ole.md) 에 있습니다.
- 받은 파일과 사진 파일의 시각은 파일 시스템 시각입니다. NTFS 는 이 시각을 UTC 로 적습니다.
- 받은 파일이 이 PC 에 처음 쓰인 때를 보려면 [마스터 파일 테이블](../filesystem/mft.md) 의 두 시각 묶음을 함께 봅니다. 파일을 옮기거나 복사하면 시각이 달라질 수 있습니다.
- 저장 폴더를 바꾼 경우 파일이 한꺼번에 옮겨졌을 수 있습니다. 여러 파일의 시각이 한 시점에 몰려 있으면 폴더 이동을 의심합니다.

## 함정과 한계

- **3.x 설명을 4.x 에 그대로 씁니다.** 폴더 이름과 DB 구성이 다르다고 알려져 있습니다. 버전부터 확인합니다.
- **SQLCipher 라고 단정합니다.** Tencent 는 자체 DB 방식이라고만 밝혔습니다[1].
- **기본 위치만 봅니다.** 저장 폴더를 바꿀 수 있다고 알려져 있습니다.
- **자동 수집 목록에 기댑니다.** KapeFiles 에는 위챗 항목이 없습니다[2]. 위챗 폴더를 따로 수집합니다.
- **`.dat` 사진을 깨진 파일로 봅니다.** 가림 처리 때문에 이미지 서명이 보이지 않을 수 있습니다.
- **공개 복호 도구가 늘 있다고 봅니다.** 아래 "공개 복호 도구 삭제" 를 봅니다.
- **앱을 지운 PC 에서 흔적이 없다고 봅니다.** 저장 폴더가 문서 폴더나 다른 드라이브에 남아 있을 수 있습니다. [USN 변경 저널](../filesystem/usnjrnl.md) 에서 지운 파일 이름도 찾습니다.

### 공개 복호 도구 삭제

Tencent 는 2026-01-08 자 요청서로 GitHub 에 위챗 대화 DB 를 풀고 추출하는 도구 저장소를 지워 달라고 요청했습니다. Tencent 는 2025-07-08 에도 같은 요청을 보냈지만 그때는 저장소가 내려가지 않았습니다[1]. GitHub 는 원 저장소를 포함해 포크까지 저장소 4,195개 네트워크 전체에 이 요청을 적용했고, 요청서 표에 이름이 적힌 저장소는 30여 개입니다[1]. 그래서 공개 복호 도구에 기대던 분석 방법이 막혔을 수 있습니다.

예전에 받아 둔 도구를 쓸 때는 도구 버전과 분석 대상의 앱 버전을 적습니다. 결과는 [도구 결과 교차 검증](../../03-techniques/reporting/tool-validation.md) 방법으로 확인합니다.

## 직접 분석해 보기

### 헥스로 한 번

대화 DB 후보와 사진 캐시를 헥스 편집기로 봅니다.

1. 대화 DB 후보의 앞 16바이트를 봅니다. SQLite 헤더 문자열이 보이면 평문 SQLite 입니다.
2. 헤더 문자열이 없으면 파일 여러 곳을 봅니다. 알아볼 문자열이 거의 없고 바이트가 고르게 흩어져 있으면 암호문일 가능성이 큽니다.
3. 같은 폴더에 `-wal`·`-shm`·`-journal` 같은 짝 파일이 있는지 봅니다. 짝 파일이 있으면 SQLite 계열일 가능성이 큽니다. 짝 파일도 함께 수집합니다.
4. `.dat` 사진 파일의 앞 몇 바이트를 봅니다. 이미지 서명이 보이지 않으면 가림 처리를 의심합니다.
5. 가림 처리가 XOR 이라면, 원래 형식의 서명 바이트와 가린 파일의 같은 자리 바이트를 XOR 하면 가림 값이 나옵니다. 이 값이 파일마다 같은지 봅니다.

### 공개 도구로 한 번

위챗 대화 DB 를 푸는 공개 도구 다수는 2026년 초 내려갔는데, 일반 도구로 나눠서 봅니다. 아래 도구는 예로만 듭니다.

| 도구 | 쓰임 |
|---|---|
| MFT 목록 도구 | 위챗 폴더와 파일 목록, 시각을 뽑습니다 |
| 헥스 편집기 | 파일 앞머리로 형식과 가림 처리를 구분합니다 |
| SQLite 뷰어 | 평문 SQLite 로 확인된 파일만 엽니다 |
| 파일 내용 검색 도구 | 받은 파일 폴더에서 사건 관련 문서를 찾습니다. 방법은 [파일 내용 검색](../../03-techniques/analysis/content-search/index.md) 에 있습니다 |

## 실습

Windows 가상 머신에 위챗 PC 판을 설치해 직접 시험하고, 시험 전에 앱 버전과 Windows 버전을 적어 둡니다.

1. 설치하고 로그인한 뒤 어느 폴더가 새로 생겼습니까? 폴더 이름은 `WeChat Files` 입니까, `xwechat_files` 입니까, 다른 이름입니까?
2. 대화 DB 로 보이는 파일의 앞 16바이트는 무엇입니까?
3. 사진을 받은 뒤 생긴 파일의 확장자와 앞머리는 무엇입니까? 이미지 서명이 보입니까?
4. 설정에서 저장 폴더를 바꿉니다. 바꾼 경로는 어느 파일에 남습니까? 옛 폴더에는 무엇이 남습니까?
5. 계정 두 개로 차례로 로그인합니다. 계정 폴더가 몇 개 생깁니까?
6. 앱을 제거한 뒤 저장 폴더와 설정 폴더에 무엇이 남습니까?
