# PC 를 초기화하거나 윈도를 다시 깔았나 (Reset·Reinstall)

Windows 10·11 의 PC 초기화 (Push-button reset) 는 OS 를 다시 만들면서 여러 폴더를 비웁니다. 무엇을 남기고 무엇을 지우는지는 고른 옵션에 따라 정해져 있습니다[1]. 이 페이지는 초기화한 PC 에서 무엇을 어디서 찾는지 다룹니다.

## 조사 질문

- 이 PC 를 초기화했습니까? 어느 옵션으로 했습니까?
- 초기화 전 기록 가운데 무엇이 남아 있습니까?
- 초기화나 재설치는 언제 했습니까?

## 먼저 확인할 것

| 확인할 것 | 이유 |
|---|---|
| Windows 버전 | 이 페이지의 초기화 동작은 Windows 10·11 기준입니다[1]. 드라이버와 앱을 되살리는 방식이 버전마다 다릅니다(아래 표). |
| 볼륨 구성 | OS 가 아닌 파티션의 파일은 "내 파일 유지" 에서 그대로 남습니다[1]. "모두 제거" 에서는 고른 범위에 따라 데이터 볼륨을 포맷합니다[1]. 볼륨마다 따로 봅니다. |
| `C:\Windows.old` | "내 파일 유지" 로 초기화한 뒤에는 옛 AppData 폴더를 여기서 볼 수 있습니다[1]. 언제 지워질지 모르니 보이면 먼저 확보합니다. |
| 사용자 | "내 파일 유지" 는 사용자 계정과 그룹 소속을 남깁니다[1]. 초기화 전 계정이 그대로 있을 수 있습니다. |
| 수집 범위 | OS 볼륨 전체, OS 가 아닌 볼륨, `C:\Windows.old`, 파일 히스토리 데이터를 확보합니다. |

## 초기화가 하는 일

새 OS 는 별도 복구 이미지가 아니라 구성 요소 저장소 (component store) `C:\Windows\WinSxS` 의 파일로 다시 만들고[1], 공장 상태가 아니라 업데이트된 상태로 되돌리며 설치된 업데이트는 모두 되살아납니다[1]. 드라이버와 앱을 되살린 상태는 Windows 버전마다 아래처럼 다릅니다[1].

| 되살리는 것 | Windows 버전 | 되살린 상태 |
|---|---|---|
| 드라이버 | Windows 11 | 초기화 시점에 설치돼 있던 드라이버 |
| 드라이버 | Windows 10 1709 부터 | 최신 드라이버 |
| 드라이버 | Windows 10 1709 전 | 가장 최근 릴리스·주요 업데이트를 설치할 때의 드라이버 |
| 미리 설치된 Windows 앱 | Windows 10 1809 부터 | 업데이트된 상태 |
| 미리 설치된 Windows 앱 | Windows 10 1809 전 | 공장 버전 |
| 미리 설치된 Windows 앱 | Windows 11 | 업데이트된 상태 |

## "내 파일 유지" (Keep my files) 로 초기화했을 때

이 옵션으로 초기화하면 폴더마다 아래처럼 됩니다[1].

| 구분 | 곳 |
|---|---|
| 새로 만들고 옛 내용을 남기지 않음 | `\Windows`, `\Program Files`, `\Program Files(x86)`, `\ProgramData`, 각 사용자의 `\AppData\Local`·`\AppData\LocalLow`·`\AppData\Roaming` |
| 옛 내용을 볼 수 있는 곳 | 옛 `\AppData` 폴더 → `C:\Windows.old` |
| 그대로 둠 | 파일 히스토리 버전 데이터, OS 가 아닌 파티션의 모든 파일·폴더 |

**남는 설정.** 아래 설정은 초기화 뒤에도 남습니다[1].

- 사용자 계정(로컬·도메인·Microsoft 계정)과 그룹 소속
- 도메인 설정, Windows Update 설정, 라이브러리 설정
- 잠금 화면 배경, 테마, 국가·언어 설정
- 무선 네트워크 프로필
- Windows 시작 화면에서 정한 설정
- 개인정보 설정(위치·카메라·마이크)

**앱.**

사용자가 받은 Microsoft Store 앱과 사용자가 설치한 데스크톱 프로그램은 남지 않지만[1], 제조사가 사용자 지정 프로비저닝 패키지에 담아 넣은 데스크톱 프로그램은 사용자가 지웠어도 공장 상태로 되살아납니다[1].

**개인정보 설정.** 초기화 뒤에는 "활동 기록을 이 장치에 저장" 설정이 기본으로 켜집니다[1].

**조사에서 뜻하는 것.**

- 이벤트 로그와 프리패치처럼 `\Windows` 아래에 있는 기록도 새로 만드는 범위에 듭니다. 위치는 [이벤트 로그 형식](../../../01-foundations/database-log-formats/evtx-evt-etl/index.md) 과 [프리패치](../../../02-artifacts/execution/prefetch/index.md) 에서 봅니다.
- 옛 `\AppData` 는 `C:\Windows.old` 에 남습니다[1]. 옛 `\Windows`·`\Program Files` 의 내용이 남았는지는 `C:\Windows.old` 안을 목록으로 만들어 확인합니다.
- 브라우저·메신저처럼 AppData 아래에 데이터를 두던 앱의 기록은 옛 AppData 에서 찾습니다.
- 무선 네트워크 프로필은 남으므로 초기화 전에 접속한 네트워크가 [Wi-Fi 프로필](../../../02-artifacts/network/wlan-profiles.md) 에 남아 있을 수 있습니다.
- OS 가 아닌 파티션과 파일 히스토리 데이터는 그대로 남습니다[1]. 초기화 전 자료를 찾는 첫 자리입니다.

## "모두 제거" (Remove everything) 로 초기화했을 때

볼륨이 여럿이면 모든 볼륨의 데이터를 지울지 Windows 볼륨만 지울지 고릅니다[1]. Windows 볼륨은 OS 를 다시 만들 파일이 그 안에 있기 때문에 포맷하지 않고[1] 사용자 데이터 파일을 하나씩 지우며[1], 모든 볼륨을 고르면 데이터 볼륨은 포맷합니다[1].

파일을 지우기만 할지 드라이브 데이터 지우기까지 할지도 고르는데, 데이터 지우기를 고르면 복구가 훨씬 어려워집니다[1]. 데이터 지우기는 일반 사용자용이며 정부·업계의 데이터 삭제 기준을 만족하지 않습니다[1]. 걸리는 시간은 드라이브 속도·파티션 크기·BitLocker 여부에 따라 다릅니다[1]. Compact OS 가 켜져 있었으면 초기화 뒤에도 켜진 채로 남습니다[1].

데이터 지우기를 고르지 않았을 때 지운 파일을 얼마나 되살릴 수 있는지는 실제 기기로 확인해야 합니다. [삭제 데이터 복구](../../../03-techniques/analysis/data-recovery/index.md) 로 시도해 보고 결과를 적습니다.

## 다시 설치했을 때

- OS 설치 시각은 [시스템 기본 정보](../../../02-artifacts/system-account/os-version-computer-name-install-date-shutdown-t.md) 에서 읽습니다.
- 로컬 계정을 만든 시각은 레지스트리에 직접 없습니다. 흔히 그 SID 의 NTUSER.DAT 생성 시각($STANDARD_INFORMATION)으로 추정합니다. NTUSER.DAT 가 없으면 OS 설치 시각을 씁니다. 보고서에는 추정값이라고 밝힙니다.
- "내 파일 유지" 초기화 뒤에도 계정은 남습니다[1]. 그래서 계정 생성 추정 시각과 OS 설치 시각이 크게 어긋날 수 있습니다.

## 분석 흐름

1. `C:\Windows.old` 가 있는지 봅니다. 있으면 안의 목록과 항목마다의 시각을 뽑습니다.
2. [시스템 기본 정보](../../../02-artifacts/system-account/os-version-computer-name-install-date-shutdown-t.md) 에서 OS 설치 시각을 읽습니다. 사용자마다 NTUSER.DAT 생성 시각을 뽑아 나란히 놓습니다.
3. [설치 프로그램](../../../02-artifacts/system-account/uninstall.md) 목록과 사용자 파일 쪽 흔적을 비교합니다. 사용자 파일은 남아 있는데 사용자가 설치한 프로그램이 없고 제조사 프로그램만 있으면 "내 파일 유지" 초기화를 의심합니다.
4. OS 가 아닌 볼륨과 파일 히스토리 데이터를 확보합니다.
5. 옛 AppData 에서 사용자별 앱 기록을 찾습니다.
6. "모두 제거" 가 의심되면 볼륨마다 따로 봅니다. Windows 볼륨은 포맷하지 않고 파일을 하나씩 지우므로[1], [지운 파일의 흔적 찾기](../deleted-file-traces.md) 를 따라 남은 흔적을 찾습니다.
7. 초기화 전후의 시각을 UTC 하나로 맞춰 [타임라인](../../../03-techniques/analysis/timeline/index.md) 으로 정리합니다. 초기화 전 기간에서 기록이 비는 곳은 빈칸으로 두고 그렇게 적습니다.

## 흔한 오판

1. **설치 프로그램 목록에 없으니 그 프로그램을 쓴 적이 없다고 봅니다.** 초기화는 사용자가 설치한 데스크톱 프로그램과 Store 앱을 남기지 않습니다[1].
2. **제조사 프로그램이 있으니 사용자가 지운 적이 없다고 봅니다.** 사용자가 지웠어도 초기화 때 공장 상태로 되살아납니다[1].
3. **업데이트 목록이 그대로이니 초기화하지 않았다고 봅니다.** 초기화는 설치된 업데이트를 모두 되살립니다[1].
4. **"활동 기록 저장" 설정이 켜져 있으니 사용자가 켰다고 봅니다.** 초기화 뒤에는 이 설정이 기본으로 켜집니다[1].
5. **무선 네트워크 프로필·잠금 화면·테마를 초기화 뒤에 설정했다고 봅니다.** 이 설정들은 "내 파일 유지" 초기화에서 그대로 남습니다[1].
6. **데이터 지우기를 기준에 맞는 완전삭제로 적습니다.** 데이터 지우기는 정부·업계의 데이터 삭제 기준을 만족하지 않습니다[1].
7. **계정 생성 추정 시각을 확정 시각으로 적습니다.** NTUSER.DAT 생성 시각은 추정 근거입니다.

## 보고서 문장 예

- 쓰지 않을 문장: "피조사자는 증거를 없애려고 PC 를 초기화했습니다."
- 쓸 문장: "C: 볼륨에 Windows.old 폴더가 있고, 그 안에 사용자 ○○ 의 옛 AppData 폴더가 있습니다. 현재 설치 프로그램 목록에는 ○○ 가 없지만, 옛 AppData 에는 ○○ 의 데이터 폴더가 있습니다. 이 기록은 이 PC 를 '내 파일 유지' 방식으로 초기화했을 가능성과 맞습니다. 초기화한 사람과 이유는 이 기록만으로 알 수 없습니다."
