# LM Studio (LM Studio)

LM Studio 는 언어 모델을 자기 컴퓨터에서 내려받아 대화하는 데스크톱 앱이고, 대화는 홈 폴더의 `.lmstudio\conversations` 에 JSON 파일로, 모델은 `.lmstudio/models` 아래 만든 사람과 모델 이름으로 나눈 폴더에 남습니다.

> 확인 날짜: 2026-09. 이 페이지는 공식 문서(2026-09-25 열람)만 근거로 썼습니다. LM Studio 를 깐 기기는 직접 관찰하지 않았고, 문서가 기준으로 삼은 앱 버전도 확인하지 못해서 버전 번호는 적지 않습니다.

## 무엇을 기록하나 · 왜 생기나

LM Studio 는 사용자가 앱에서 나눈 대화를 기기에 파일로 저장해 두었다가 다시 열 수 있게 하고, 대화를 폴더로 묶거나 끌어다 다른 폴더로 옮기는 기능도 둡니다. 대화를 복제하면 대화에 든 파일도 함께 복제한다고 문서에 적혀 있어서, 대화에 넣은 파일이 기기에 따로 저장된다고 볼 수 있습니다. 첨부 파일을 두는 폴더 이름은 확인하지 못했습니다. 프롬프트·첨부·생성물을 나눠 보는 기준은 [프롬프트·첨부·생성물 구분하기](../../01-foundations/concepts/prompt-attachment-output.md)를 따릅니다.

모델도 기기에 남습니다. 앱에서 받은 모델과 `lms import` 명령(문서가 실험 기능이라고 밝힌 것)으로 가져온 모델이 같은 모델 폴더에 들어갑니다.

대화가 LM Studio 서버로 가는지에 관한 문장은 대화 관리 문서에 없었고, 개인정보 처리방침은 이번에 열어 보지 않았습니다. 그래서 대화 원본이 기기에만 있다고도, 서버에도 있다고도 단정하지 않습니다. 서비스 쪽 저장의 일반 원리는 [AI 서비스의 데이터는 어디에 있나](../../01-foundations/storage-model/where-data-lives.md)에서 다룹니다.

문서는 모델이 대화 사이에 기억을 이어 가지 않고 그 대화의 내용과 시스템 프롬프트에 있는 것만 안다고 설명합니다. 모델이 어떤 사실을 답에 썼다면, 그 사실은 그 대화 안이나 시스템 프롬프트에 들어 있었다고 보고 대화 파일에서 찾습니다.

## 위치와 버전별 차이

| 경로 | 담긴 것 | OS 표기 |
|---|---|---|
| `%USERPROFILE%\.lmstudio\conversations` | 대화(JSON) | Windows(문서) |
| `~/.lmstudio/conversations/` | 대화(JSON) | macOS·Linux(문서) |
| `~/.lmstudio/models/` | 모델 폴더 기본 위치 | 문서가 `~` 로만 표기 |

모델 폴더는 문서가 OS 를 나누지 않고 `~/.lmstudio/models/` 로만 적었습니다. Windows 에서는 대화 폴더처럼 `%USERPROFILE%\.lmstudio` 아래에 있을 가능성이 크지만 문서 문장으로 확인하지는 못했습니다. 모델 폴더를 다른 곳으로 옮기는 방법, 설정 파일 이름과 키, 로그 폴더, 서버 모드의 포트도 이번에 확인하지 못했습니다. 기본 위치에 모델이 없으면 다른 폴더로 옮겼을 수 있다고 보고 큰 `.gguf` 파일을 디스크 전체에서 찾습니다.

LM Studio 는 자주 바뀌는 앱이고, 문서도 대화 JSON 의 구조를 믿지 말라고 적고 있습니다. 조사할 때는 앱 버전을 먼저 적고, 아래 구조는 2026-09 문서 기준으로 읽습니다.

## 구조

### 대화 파일

대화는 JSON 으로 저장하지만 문서는 "It is NOT recommended to edit them manually, nor to rely on their structure." 라고 적고 있습니다. 버전마다 구조가 바뀔 수 있다는 뜻이라서 이 페이지는 키 이름을 싣지 않습니다. 실제 검체에서는 그 버전에서 키 이름을 새로 읽고, 어느 버전에서 읽었는지를 기록에 함께 남깁니다.

앱 안의 대화 폴더가 `conversations` 아래 실제 폴더로 나뉘는지는 확인하지 못했습니다. 폴더 이름이나 대화 제목을 근거로 쓸 때는 파일 안의 값인지 파일 시스템 경로인지 나눠 적습니다.

### 모델 폴더

모델 폴더 안은 `만든 곳/모델/파일` 세 단계로 나뉩니다. 문서의 예는 아래와 같습니다.

```
~/.lmstudio/models/infra-ai/ocelot-v1/ocelot-v1-instruct-q4_0.gguf
```

가져오기 문서가 다루는 형식은 GGUF 뿐이고, 다른 형식의 모델을 어떻게 두는지는 이 문서에서 확인하지 못했습니다. 폴더 이름의 `만든 곳` 과 `모델` 은 사용자가 가져올 때 정할 수 있는 값일 수 있어서, 출처는 파일 헤더의 메타데이터로 다시 확인합니다. GGUF 헤더를 읽는 법은 [로컬 모델 파일](model-files.md)에서 다룹니다.

## 증거로서 의미

**증명하는 것.** `conversations` 아래 대화 파일이 있으면 그 사용자 계정의 LM Studio 에 그 대화가 저장되어 있었다고 쓸 수 있고, 파일 안에 든 글은 기록이 말하는 만큼 대화 내용의 근거가 됩니다. 모델 폴더에 파일이 있으면 그 모델이 그 디스크에 있었다고 쓸 수 있습니다.

**증명하지 못하는 것.** 대화 파일은 계정 폴더에 남을 뿐이라서, 그 대화를 누가 키보드로 쳤는지는 따로 밝혀야 합니다([그 대화를 한 사람이 누구인가](../../04-scenarios/attribution/user-attribution.md)). 대화 파일이 없다고 대화가 없었다고 보지 않고, 사용자가 지웠거나 다른 위치를 썼을 가능성을 함께 적습니다. 모델 파일이 있다고 그 모델로 대화했다는 뜻도 아니어서, 어떤 모델을 썼는지는 대화 파일 안에서 찾습니다. 대화가 외부로 나갔는지는 이번에 확인한 문서로 판단할 수 없습니다.

## 시각 해석

대화 JSON 안에 시각 값이 있는지, 있다면 UTC 인지 현지 시각인지는 확인하지 못했습니다. 파일 시스템 시각으로 보면, 대화 파일의 생성 시각은 대화를 처음 저장한 때에 가깝고 수정 시각은 마지막으로 다시 저장한 때에 가깝다고 볼 수 있지만, 앱이 대화를 언제 다시 쓰는지 문서로 확인하지 못했으므로 추정이라고 적습니다. 대화를 폴더 사이로 옮기거나 복제하면 파일 시각이 바뀔 수 있어서, 복제한 대화의 생성 시각을 원래 대화를 나눈 시각으로 읽지 않습니다. 모델 파일의 시각은 내려받거나 가져온 때에 가깝고 모델을 쓴 때가 아닙니다.

## 함정과 한계

- **구조 변경.** 문서가 스스로 구조에 기대지 말라고 적은 만큼, 한 버전에서 만든 파서를 다른 버전 검체에 그대로 돌리지 않습니다. 키가 없어서 값이 비어 나오면 내용이 없는 것인지 파서가 못 읽은 것인지 가립니다.
- **복제된 대화.** 복제하면 대화에 든 파일도 함께 복제되므로 같은 첨부가 여러 벌 나올 수 있고, 한 번 넣은 파일을 여러 번 넣었다고 세지 않습니다.
- **모델 폴더 위치.** 기본 위치에 없다고 모델이 없다고 보지 않습니다. 위치를 바꾸는 설정은 확인하지 못했으니 디스크 전체에서 `.gguf` 파일을 찾습니다.
- **서버 쪽 기록.** 서버로 가는 데이터가 있는지 확인하지 못했으므로, 서비스 회사에 기록을 요청할 수 있다고도 없다고도 쓰지 않습니다.

## 직접 분석해 보기

**헥스로.** 대화 파일을 헥스 보기로 열어 글자 칸에 JSON 이 그대로 보이는지 확인합니다. 글자로 읽히면 평문으로 저장된 것이고, 알아볼 수 없는 바이트만 이어지면 다른 저장 방식을 쓴다고 보고 그 버전에서 따로 확인합니다. 모델 파일은 첫 4바이트 `47 47 55 46`(글자로 `GGUF`)을 확인합니다.

**공개 도구로.** 사본에서 `jq` 같은 공개 도구로 대화 파일을 펼쳐 봅니다. 먼저 최상위 키 목록을 뽑아 그 버전의 구조를 확인하고, 그다음 찾는 낱말로 검색합니다. 파일 이름과 낱말은 만든 예시입니다.

```
jq 'keys' .lmstudio/conversations/sample-chat.json
grep -l "project-blue" .lmstudio/conversations/*.json
```

## 실습

공개 검체 가운데 LM Studio 가 든 것은 확인하지 못했습니다. 시험용 가상 머신에 직접 깔고 가짜 사용자 `labuser01` 로 대화를 몇 개 만든 다음, 아래 질문을 풀어 봅니다.

1. 대화 하나를 만들고 제목을 바꾼 뒤, `conversations` 폴더의 파일 생성·수정 시각은 어떻게 바뀝니까?
2. 가짜 문서 `sample-plan.txt` 를 대화에 넣고 대화를 복제하면, 그 문서는 디스크 어디에 몇 벌 남습니까?
3. 앱에서 대화를 폴더로 옮기면 파일 시스템 경로가 바뀝니까, 파일 안의 값만 바뀝니까?
4. 대화를 지운 뒤 파일이 어떻게 되고, 볼륨에서 되살릴 수 있습니까?
