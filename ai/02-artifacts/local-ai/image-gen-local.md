# 로컬 이미지 생성 도구 (Stable Diffusion WebUI·ComfyUI)

Stable Diffusion WebUI 와 ComfyUI 는 이미지 생성 모델을 자기 컴퓨터에서 돌리는 도구이고, 둘 다 만든 이미지 파일 안에 프롬프트와 시드 같은 생성 설정을 함께 넣어 저장합니다.

> 확인 날짜: 2026-09. Stable Diffusion WebUI 는 AUTOMATIC1111 판의 위키 "Features" 쪽, ComfyUI 는 저장소 README 를 근거로 썼습니다(둘 다 2026-09-25 열람). 두 도구 모두 기기에서 직접 관찰하지 않았고 문서가 기준으로 삼은 버전도 확인하지 못해서 버전 번호는 적지 않습니다.

## 무엇을 기록하나 · 왜 생기나

두 도구는 로컬에서 돌기 때문에 생성 기록이 서비스 회사 서버가 아니라 도구를 깐 폴더 안에 남습니다. 이미지에 넣어 둔 설정은 도구에서 다시 불러올 수 있고, 조사에서는 이 기능 덕에 이미지 파일 하나로 어떤 프롬프트와 모델로 만들었는지 따라갈 수 있습니다.

Stable Diffusion WebUI(이하 WebUI)는 프롬프트를 비롯한 생성 설정을 PNG 메타데이터의 텍스트 조각(text chunk)에 넣고, 이 기능을 "PNG info" 라고 부릅니다. 사용자가 결과 화면 아래의 Save 버튼을 누르면 이미지를 설정에서 정한 폴더에 따로 저장하고, 생성 설정을 그 폴더의 CSV 파일에 덧붙여 기록합니다. 파일 이름에 시드나 프롬프트 일부를 넣는 설정도 있어서, 메타데이터가 사라진 이미지에서도 파일 이름에 단서가 남을 수 있습니다.

ComfyUI 는 생성한 PNG 를 화면에 끌어다 놓거나 불러오면 그 이미지를 만든 워크플로 전체가 시드까지 되살아난다고 문서에 적고 있습니다. 워크플로는 모델·프롬프트·처리 단계를 이은 그래프라서 WebUI 보다 더 많은 설정이 이미지에 들어갈 수 있습니다.

ComfyUI 는 기본으로 오프라인에서 돌고, 사용자가 요청하지 않으면 핵심 부분이 아무것도 내려받지 않는다고 문서에 적혀 있습니다. 한편 유료 Comfy API 노드를 쓰는 워크플로라면 프롬프트가 외부 서비스로 나갈 수 있고, 이 노드는 `--disable-api-nodes` 로 끌 수 있습니다. API 노드가 어느 서버로 보내는지는 확인하지 못했습니다. 온라인 이미지 생성 서비스는 [Midjourney와 이미지 생성 서비스](../generative-media/image-generation.md)에서 다룹니다.

## 위치와 버전별 차이

### Stable Diffusion WebUI

WebUI 는 사용자가 저장소를 받은 폴더에서 돌리는 방식이라 고정 설치 경로를 문서에서 찾지 못했습니다. 아래 경로는 모두 그 설치 폴더 기준입니다.

| 경로 | 담긴 것 |
|---|---|
| `outputs/txt2img-images` 같은 생성 종류별 하위 폴더 | 만든 이미지(기본 출력 위치) |
| Save 버튼으로 저장하는 폴더(설정에서 정함)의 CSV 파일 | Save 버튼을 누른 이미지의 생성 설정(폴더·파일 이름은 확인하지 못함) |
| `styles.csv` | 저장해 둔 프롬프트 스타일 |
| `config.json` | 일반 설정 |
| `ui-config.json` | 화면 기본값(기본값·슬라이더 범위·체크박스) |

파일 이름은 "Images filename pattern" 설정이 정하고, 기본값은 `[seed]-[prompt_spaces]` 입니다. 쓸 수 있는 태그에는 `[seed]`, `[steps]`, `[cfg]`, `[width]`, `[height]`, `[sampler]`, `[model_name]`, `[prompt]` 가 있어서, 설정에 따라 파일 이름에 시드·단계 수·크기·모델 이름·프롬프트가 들어갑니다. 조사할 때는 `config.json` 에서 그 PC 가 쓰던 파일 이름 규칙을 먼저 확인하고 파일 이름을 읽습니다.

### ComfyUI

ComfyUI 는 Windows·macOS 데스크톱 앱과 Windows 휴대용 판(NVIDIA·AMD·Intel GPU 용)으로 배포합니다. 아래는 저장소 폴더 기준이고, 데스크톱 앱이 데이터를 어디에 두는지는 확인하지 못했습니다.

| 경로 | 담긴 것 |
|---|---|
| `models/checkpoints` | ckpt·safetensors 체크포인트 모델 |
| `models/vae` | VAE 모델 |
| `output` | 만든 이미지 |
| `input` | 입력으로 넣은 이미지 |
| `custom_nodes` | 추가로 깐 노드 |
| `temp` | 임시 파일 |
| `extra_model_paths.yaml`(저장소 맨 위에 예시 파일) | ComfyUI 폴더 밖의 모델 위치 |

`extra_model_paths.yaml` 이 있으면 모델을 ComfyUI 폴더 밖, 예를 들어 WebUI 모델 폴더에 두고 함께 썼을 수 있어서 이 파일에 적힌 경로를 따라가 봅니다. 저장한 워크플로를 두는 폴더와 로그 파일 이름은 확인하지 못했습니다. 출력은 16비트 PNG, 32비트 EXR, 10비트 AVIF 도 지원하지만, PNG 가 아닌 형식에 워크플로가 들어가는지는 확인하지 못했습니다.

## 구조

두 도구 모두 생성 설정을 PNG 안의 텍스트 조각에 글자로 넣습니다. WebUI 의 조각 이름, ComfyUI 가 프롬프트와 워크플로를 어떤 조각 이름으로 넣는지, WebUI 가 JPEG·WebP 로 저장할 때 EXIF 에 넣는지는 이번에 문서로 확인하지 못했습니다. 그래서 이 페이지는 조각 이름과 값의 짜임을 싣지 않고, 검체에서 직접 읽어 확인하는 방법을 아래 "직접 분석해 보기" 에 적습니다.

WebUI 의 CSV 기록은 문서가 "Click the Save button under the output section, and generated images will be saved to a directory specified in settings; generation parameters will be appended to a csv file in the same directory." 라고 적은 대로, Save 버튼을 누른 이미지만 저장 폴더에 모이고 그 설정이 같은 폴더의 CSV 에 덧붙는 방식입니다. 생성할 때마다 자동으로 쌓이는 기록이 아니고, 열 이름과 순서는 확인하지 못했습니다.

모델 파일인 safetensors 의 구조는 [로컬 모델 파일](model-files.md)에서 다룹니다.

## 증거로서 의미

**증명하는 것.** 출력 폴더의 이미지에 생성 설정이 들어 있으면, 그 설정으로 만든 이미지가 그 폴더에 저장되어 있었다고 쓸 수 있습니다. WebUI 의 CSV 에 줄이 있으면 사용자가 Save 버튼으로 그만큼 이미지를 저장한 기록이 있다고 쓸 수 있고, 이미지를 나중에 지웠어도 CSV 줄은 남을 수 있습니다. CSV 는 Save 버튼을 누른 이미지만 적으므로, 줄 수를 생성한 횟수로 읽지 않습니다. ComfyUI 의 `input` 폴더에 있는 파일은 입력으로 쓰려고 넣은 이미지라서, [딥페이크·합성 이미지를 만들었나](../../04-scenarios/misuse/deepfake.md) 같은 조사에서 원본 사진을 찾는 출발점이 됩니다.

**증명하지 못하는 것.** 메타데이터는 글자라서 누구든 고치거나 지울 수 있습니다. 메타데이터에 적힌 프롬프트로 그 이미지를 만들었다는 근거로 쓸 때는 CSV 기록, 출력 폴더 위치, 파일 시각과 맞는지 확인합니다. 메타데이터가 없는 이미지를 사람이 만든 이미지라고 보지도 않습니다. 이미지만 보고 AI 로 만들었는지 가르는 일의 한계는 [AI가 만든 글·이미지 판별의 한계](../../03-techniques/analysis/detection-limits.md)에서 다룹니다. 다른 기기에서 만든 이미지를 복사해 넣었을 수도 있어서, 출력 폴더에 있다는 사실만으로 그 PC 에서 만들었다고 단정하지 않습니다.

## 시각 해석

이미지 파일의 생성·수정 시각은 도구가 파일을 저장한 때에 가깝고, 복사하거나 옮기면 바뀝니다. 메타데이터나 CSV 에 생성 시각이 들어가는지는 확인하지 못했습니다. Save 버튼으로 저장한 폴더의 이미지들을 파일 시각 순서로 늘어놓고 CSV 줄 순서와 맞춰 보면, 지워진 이미지가 있던 자리를 가늠할 수 있습니다. 시각이 UTC 인지 현지 시각인지는 파일 시스템의 규칙을 따릅니다.

## 함정과 한계

- **설치 위치.** 두 도구 모두 사용자가 고른 폴더에 깔 수 있어서 기본 경로가 없습니다. `outputs`, `models`, `custom_nodes`, `styles.csv` 같은 이름을 디스크 전체에서 찾아 설치 폴더를 먼저 찾습니다.
- **메타데이터가 빠진 이미지.** 메신저나 편집 프로그램을 거치면 텍스트 조각이 빠질 수 있습니다. 메타데이터를 끄는 설정은 두 문서 모두에서 확인하지 못했으므로, 메타데이터가 없는 까닭을 설정 탓으로 단정하지 않습니다.
- **API 노드.** ComfyUI 워크플로에 API 노드가 있으면 프롬프트가 외부로 나갔을 수 있습니다. 워크플로 안의 노드 종류와 네트워크 기록을 함께 봅니다.
- **추가 노드.** `custom_nodes` 에 깐 노드는 저마다 따로 파일을 쓰거나 통신할 수 있고, 그 흔적은 이 페이지가 다루는 범위 밖입니다.
- **워크플로 되살리기.** 이미지를 ComfyUI 에 불러오면 워크플로를 되살리지만, 원본 증거가 아니라 사본을 격리한 분석 환경에서 엽니다.
- **출처 정보와 다름.** 여기서 말하는 생성 설정은 도구가 편의로 넣는 글자이고, 서명으로 위조를 가리는 출처 정보와 다릅니다. 출처 정보는 [AI 생성물의 출처 정보](../../01-foundations/concepts/c2pa-provenance.md)에서 다룹니다.

## 직접 분석해 보기

**헥스로.** 출력 폴더의 PNG 사본을 헥스 보기로 열고, 오른쪽 글자 칸을 따라 내려가며 사람이 읽을 수 있는 글자가 이어진 곳을 찾습니다. 압축하지 않은 텍스트 조각이면 프롬프트 낱말이나 시드 숫자가 글자 그대로 보이고, 그 앞 몇 바이트에 조각 이름이 붙어 있습니다. 거기서 읽은 조각 이름을 검체 기록에 적어 두면, 같은 도구로 만든 다른 이미지를 한꺼번에 찾을 때 검색어로 쓸 수 있습니다. 조각 이름이 도구·버전마다 무엇인지는 이번에 확인하지 못했으므로 검체에서 읽은 값을 씁니다.

**공개 도구로.** ExifTool 같은 공개 메타데이터 도구로 PNG 텍스트 조각을 한꺼번에 뽑습니다. 파일 이름은 만든 예시입니다.

```
exiftool -a -G1 outputs/txt2img-images/12345-sample-prompt.png
```

WebUI 의 "PNG info" 화면이나 ComfyUI 에 이미지를 불러와 읽는 방법도 있지만, 이때도 원본이 아닌 사본을 씁니다.

## 실습

공개 검체 가운데 두 도구가 든 것은 확인하지 못했습니다. 시험용 가상 머신에 직접 깔고 가짜 프롬프트 "a red bicycle on a sample street" 로 이미지를 몇 장 만든 다음, 아래 질문을 풀어 봅니다.

1. WebUI 에서 이미지 몇 장을 Save 버튼으로 저장한 뒤 하나를 지우면, CSV 에는 무엇이 남습니까? Save 버튼을 누르지 않은 이미지는 CSV 에 적힙니까?
2. 파일 이름 규칙을 바꾼 앞뒤로 만든 이미지의 파일 이름은 어떻게 다릅니까?
3. ComfyUI 로 만든 PNG 를 메신저로 보냈다가 다시 받으면, 텍스트 조각이 남아 있습니까?
4. `extra_model_paths.yaml` 로 WebUI 모델 폴더를 가리키게 하면, 어느 도구의 흔적에 모델 경로가 남습니까?
