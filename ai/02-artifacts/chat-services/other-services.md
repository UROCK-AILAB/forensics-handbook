# 그 밖의 서비스 (DeepSeek·Grok 등)

DeepSeek·Grok 처럼 따로 페이지를 두지 않은 대화형 AI 서비스를 한데 모아, 공개 자료로 확인한 수집 항목·보관 규칙·제공 형태와, 아직 확인하지 못해 검체에서 직접 가려야 할 빈칸을 같은 기준으로 적습니다.

> 확인 날짜: 2026-09. DeepSeek 은 공식 개인정보 처리방침(최종 수정 2026-05-06, 2026-09-25 열람)으로, Grok 은 위키백과(2차 자료, 2026-09-25 열람)로 확인했습니다. xAI 의 개인정보 처리방침은 열리지 않았습니다. 이 PC 의 기기 관찰에는 이 서비스들이 없어서 관찰로 확인한 경로·파일 이름이 없고, 앱 버전도 확인하지 못했습니다.

## 무엇을 기록하나 · 왜 생기나

조사에서는 대화 원본이 서버에 있는지 기기에 있는지부터 가립니다. 이 기준은 [AI 서비스의 데이터는 어디에 있나](../../01-foundations/storage-model/where-data-lives.md)에 있습니다. 두 서비스 모두 로컬 저장 위치(브라우저 저장소, 앱 폴더, 데스크톱 앱이 있는지)는 이번 조사에서 확인하지 못했습니다.

### DeepSeek

DeepSeek 의 개인정보 처리방침은 앱과 웹에 모두 적용되고, 쿠키 같은 일부 항목만 웹에 해당합니다[1]. 처리방침이 수집한다고 적은 사용자 입력은 텍스트, 음성, 프롬프트, 올린 파일, 사진, 피드백, 채팅 기록이고, 사용자가 올린 음성·사진에서 사람을 알아보려고 성문이나 얼굴 인식 정보를 뽑아내지는 않는다고 적혀 있습니다[1]. 기기 정보로는 기기 모델, 운영체제, IP 주소, 기기 식별자, 시스템 언어, 통신사, MCC/MNC, 연결 방식, 브라우저 종류, 앱 정보를 적었고, 네트워크 활동으로는 IP 주소, 쿠키, 고유 기기 식별자, 접속 로그를 적었습니다[1]. 서버 쪽에 이 값들이 있다는 뜻이라서, 서버 자료를 받으면 대화 내용뿐만 아니라 어느 기기·어느 IP 에서 접속했는지도 맞춰 볼 수 있습니다.

처리방침에는 "저희 서버는 중화인민공화국에 위치해 있습니다" 라는 문장이 있습니다[1]. 서버 쪽 자료를 요청할 때 어느 나라 절차를 거쳐야 하는지가 여기서 갈리고, 절차는 [서비스 회사에 대한 데이터 요청](../../03-techniques/acquisition/legal-requests.md)에서 다룹니다.

### Grok (xAI)

Grok 은 2023-11 에 X(옛 Twitter) 안의 기능으로 일부 사용자에게 먼저 공개됐습니다[2]. grok.com 웹과 iOS 앱은 2024-12 에 베타로 나와 2025-01-09 에 전 세계에 공개됐고, Android 앱은 2025-02-04 에 일부 지역부터 나왔습니다[2]. 비공개 대화(Private), 메모리, 애니메이션 동반자(2025-07), 이미지 생성 Aurora(2024-12-09), 영상 생성 Grok Imagine(2025-07-28) 같은 기능이 있어서[2], 흔적은 대화 글뿐만 아니라 생성한 이미지·영상으로도 이어질 수 있습니다. 생성물 흔적은 [Midjourney와 이미지 생성 서비스](../generative-media/image-generation.md)에서 다룹니다.

같은 Grok 을 X 앱 안에서도, grok.com 에서도, 전용 앱에서도 쓸 수 있어서 한 사용자의 흔적이 세 곳에 흩어질 수 있습니다. X 계정으로 쓴 Grok 대화가 X 데이터 내보내기(아카이브)에 들어가는지는 확인하지 못했습니다.

### 그 밖(Le Chat, Kimi, Qwen 등)

이번 조사에서 연 자료가 없습니다. 이런 서비스를 만나면 이 페이지의 표와 같은 칸(제공 형태, 수집 항목, 서버 위치, 보관 기간, 내보내기, 로컬 흔적)을 사건 당시의 처리방침으로 하나씩 채우고, 채우지 못한 칸은 "확인 못 함" 으로 남깁니다.

## 위치와 버전별 차이

| 항목 | DeepSeek | Grok |
|---|---|---|
| 확인한 제공 형태 | 앱과 웹(처리방침 적용 범위)[1] | X 안의 기능, grok.com 웹, iOS 앱, Android 앱[2] |
| 서버 위치 | 중화인민공화국[1] | 확인 못 함 |
| 대화·계정 보관 | 계정 탈퇴 때까지 또는 이용 목적을 이룰 때까지[1] | 확인 못 함 |
| 데이터 내보내기 | 현재 웹 버전에서만 가능[1] | 확인 못 함 |
| 계정 삭제 뒤 | 계정과 관련 콘텐츠·개인정보를 되살릴 수 없음[1] | 확인 못 함 |
| 로컬 저장 위치 | 확인 못 함 | 확인 못 함 |
| 앱 버전 | 확인 못 함 | 확인 못 함 |

DeepSeek 처리방침은 웹사이트 방문 기록을 통신 관련 법에 따라 3개월, 거래 기록을 소비자 보호 법에 따라 5년 보관한다고 적었지만[1], 어느 나라 법인지는 확인하지 못했습니다. en-US 주소를 열었는데 한국어 번역본이 나와서, 접속 지역에 따라 다른 언어판이 나오는 것으로 보이고 위 인용 문장은 한국어판 기준입니다. 사건에 쓸 때는 원문판을 따로 확보해 대조합니다.

로컬 흔적은 쓰는 형태에 따라 찾는 곳이 다릅니다. 웹으로 썼다면 [크롬 계열 브라우저](https://urock-ailab.github.io/forensics-handbook-windows/02-artifacts/browsers/chrome-edge-whale/index.html) 같은 브라우저 페이지를, 모바일 앱이면 [Android 앱 데이터 폴더 구조](https://urock-ailab.github.io/forensics-handbook-android/01-foundations/storage/app-data-layout.html)와 [iOS 로컬 백업](https://urock-ailab.github.io/forensics-handbook-ios/01-foundations/backups/local-backup/index.html)을 따르고, 수집 순서는 [기기에서 AI 흔적 모으기](../../03-techniques/acquisition/endpoint-triage.md)를 봅니다.

## 구조

두 서비스 모두 로컬 저장 구조는 확인한 자료가 없어서 쓰지 않습니다. DeepSeek 내보내기 파일의 형식도 확인하지 못했고, 받은 파일은 [계정 데이터 내보내기 형식](../../01-foundations/storage-model/data-export-formats.md)의 방법대로 파일 목록과 형식부터 적은 뒤 읽습니다.

## 증거로서 의미

**증명하는 것.** 서버 쪽 자료에는 처리방침이 적은 대로 채팅 기록과 함께 기기 정보·IP 주소·접속 로그가 있을 수 있어서, 확보하면 어느 기기에서 언제 접속해 무엇을 입력했는지를 서버 기록으로 보일 수 있습니다. 기기의 방문 기록·네트워크 기록은 그 기기가 그 시간대에 서비스와 통신했다는 기록입니다.

**증명하지 못하는 것.** 접속 기록만으로는 대화 내용을 알 수 없고, 기기에서 대화를 찾지 못했다고 대화가 없었다고 할 수 없습니다. DeepSeek 계정을 지운 뒤라면 처리방침대로 되살릴 수 없어서[1], 서버 쪽 원본이 없다는 사실이 삭제 시점을 알려 주지도 않습니다. 계정을 쓴 사람은 [그 대화를 한 사람이 누구인가](../../04-scenarios/attribution/user-attribution.md)의 방법으로 따로 좁힙니다.

## 시각 해석

기기 쪽 시각은 저장소마다 기준 시각과 단위가 달라서 형식 페이지에서 먼저 확인하고, 내보내기로 받은 서버 쪽 시각은 파일 안의 시간대 표기를 직접 봅니다. 두 서비스 모두 서버 기록의 시각 형식은 확인하지 못했습니다. 여러 출처의 시각을 한 줄로 세우는 방법은 [AI 사용 타임라인](../../03-techniques/analysis/timeline.md)에 있습니다.

## 함정과 한계

Grok 의 공유 기능으로 만든 대화 링크는 2025-08 에 Google 검색에 색인돼 누구나 볼 수 있게 됐다는 서술이 있습니다[2]. 공유 링크는 서버에 있는 공개 사본이라서, 공유 링크가 있다는 사실과 그 링크를 누가 봤는지는 따로 다뤄야 하고, 기기에서 링크 주소를 찾았다고 대화 본문이 기기에 있다고 볼 수도 없습니다.

비공개 대화(Private) 같은 기능을 쓴 대화가 서버에 얼마나 남는지는 확인하지 못했습니다. 이런 기능의 이름만 보고 "기록이 없다" 고 단정하지 말고, 사건 당시의 처리방침을 확보해 확인합니다. 보관·삭제의 일반 원리는 [대화 기록 보관 설정과 삭제](../../01-foundations/storage-model/retention-deletion.md)에 있습니다.

DeepSeek 내보내기는 처리방침 기준으로 웹에서만 되니[1], 앱만 쓰던 사용자라도 웹에 로그인해서 받아야 합니다. 내보내기를 받는 동작 자체가 계정에 새 흔적을 남길 수 있어서 [계정 데이터 내보내기로 수집](../../03-techniques/acquisition/export-collection.md)의 절차대로 기록을 남기며 받습니다.

## 직접 분석해 보기

**헥스로 한 번.** 캐시나 할당되지 않은 영역에서 서비스 도메인의 바이트를 찾습니다. 아래는 문자 인코딩 명세대로 만든 예시이고, 검체에서 뜬 바이트가 아닙니다.

```
만든 예시(인코딩 명세로 만든 바이트)
"deepseek.com"  UTF-8     64 65 65 70 73 65 65 6B 2E 63 6F 6D
"deepseek.com"  UTF-16LE  64 00 65 00 65 00 70 00 73 00 65 00 65 00 6B 00 2E 00 63 00 6F 00 6D 00
"grok.com"      UTF-8     67 72 6F 6B 2E 63 6F 6D
"grok.com"      UTF-16LE  67 00 72 00 6F 00 6B 00 2E 00 63 00 6F 00 6D 00
```

**공개 도구로 한 번.** 수집한 사본 폴더에서 ripgrep 으로 두 도메인이 들어간 파일을 추리고, 찾은 파일은 형식에 맞는 도구로 다시 엽니다. 경로는 만든 예시입니다. Grok 을 X 안에서 썼다면 X 주소만 남을 수 있어서, 도메인으로 찾지 못해도 사용하지 않았다고 쓰지 않습니다.

```sh
# 만든 예시 경로
CASE=/cases/case-0005/copy/laptop-erin
rg -a -l -e "deepseek.com" -e "grok.com" "$CASE"
```

## 교차 검증

기기 흔적은 [AI 서비스 도메인과 네트워크 기록](../network-enterprise/network-traces.md)과 시각을 맞춰 보고, 회사 PC 라면 [보안 제품이 남기는 AI 사용 기록](../network-enterprise/dlp-casb.md)과 [회사가 허용하지 않은 AI를 썼나](../../04-scenarios/data-leak/shadow-ai.md)로 이어 갑니다. 파일을 올렸는지가 쟁점이면 [기밀 자료를 AI에 넣었나](../../04-scenarios/data-leak/confidential-input.md)를, 지운 캐시에서 조각을 되살리려면 [대화 내용 되살리기](../../03-techniques/analysis/content-recovery.md)를 봅니다.

## 실습

공개 검체에 이 서비스들의 흔적이 들어 있는지는 확인하지 못했습니다. 시험용 기기와 시험 계정으로 풀어 봅니다.

1. DeepSeek 웹에서 시험 계정의 데이터 내보내기를 받아 파일 목록과 형식, 시각 표기를 적어 봅니다.
2. Grok 을 X 앱 안에서 한 번, grok.com 에서 한 번 쓰고, 두 경우의 브라우저·앱 흔적과 네트워크 기록을 비교합니다.
3. 처리방침에서 수집한다고 적은 기기 정보 가운데 내보내기 파일에 실제로 들어 있는 항목이 무엇인지 표로 비교합니다.
