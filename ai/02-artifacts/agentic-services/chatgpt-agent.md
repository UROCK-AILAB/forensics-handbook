# ChatGPT 에이전트 모드 (ChatGPT Agent)

ChatGPT 에이전트 모드는 ChatGPT 가 사용자 대신 웹 작업을 해 주던 기능이고, 작업이 사용자 PC 밖에서 돈다고 알려져 있어 기기에는 ChatGPT 화면을 쓴 흔적만 남고 작업 원본은 계정 서버 쪽에 있을 것으로 봅니다. 위키백과는 이 기능이 2026년 8월 초에 ChatGPT 에서 빠졌다고 적고 있어서, 지금은 지난 사용 기록을 조사하는 대상으로 봅니다.

> 확인 날짜: 2026-09-25. OpenAI 공식 문서(소개 글·도움말)는 이번 조사에서 열리지 않아(403) 내용을 보지 못했습니다. 연혁은 위키백과 한 쪽만 근거로 썼고, 실행 위치와 기기 흔적은 확인하지 못한 내용이라 "알려져 있다", "추정" 으로 구분해 적었습니다. 관찰한 Windows 11 PC(2026-09)에는 ChatGPT·OpenAI 앱 폴더가 없어서 로컬 경로를 관찰로 확인한 것은 없습니다.

## 무엇을 기록하나 · 왜 생기나

위키백과에 따르면 OpenAI 는 2025-01-23 에 앞선 브라우저 에이전트인 오퍼레이터 (Operator) 를 공개했습니다. 오퍼레이터는 웹 브라우저를 조작해 양식 입력, 온라인 주문, 예약 같은 일을 스스로 하는 기능으로 소개됐고, 처음에는 미국의 ChatGPT Pro 구독자에게 제한 공개로 열렸습니다. Plus·Team·Enterprise 로 넓힐 계획이 있었다고 적혀 있지만, 실제로 넓혔는지는 위키백과에 나오지 않습니다.

그 뒤 오퍼레이터 기능은 ChatGPT 에이전트로 옮겨 갔고, 위키백과는 오퍼레이터가 2025-08-31 에 종료됐고, ChatGPT 에이전트도 2026년 8월 초에 미리 알리지 않고 ChatGPT 에서 빠졌다고 적습니다. 두 날짜 모두 공식 문서로 다시 확인하지 못했습니다. ChatGPT 에이전트가 처음 나온 날짜(2025-07 로 알려져 있음)와 쓸 수 있는 요금제도 이번에 확인하지 못했습니다.

조사에서 따질 흔적은 세 가지입니다. 사용자가 에이전트에게 내린 작업 지시, 에이전트가 작업하며 보여 준 단계와 화면, 에이전트가 만든 결과물입니다. 이 세 가지가 어디에 저장되는지는 공식 문서로 확인하지 못했지만, 작업 지시가 ChatGPT 대화 안에서 오간다는 점에서 먼저 ChatGPT 계정의 대화 기록을 찾아봅니다.

## 위치와 버전별 차이

### 작업이 도는 곳

ChatGPT 에이전트는 OpenAI 쪽 가상 컴퓨터(원격 브라우저·터미널)에서 작업을 실행한다고 알려져 있지만, 이번 조사에서 공식 문서로 확인하지는 못했습니다. 이 설명이 맞다면 에이전트가 방문한 사이트의 방문 기록·쿠키·다운로드는 사용자 PC 의 브라우저 프로필에 남지 않고, 사용자 기기에는 ChatGPT 대화 화면(웹 브라우저나 ChatGPT 앱)을 쓴 흔적만 남는다고 추정합니다.

사용자 PC 의 실제 브라우저를 조작하는 에이전트는 흔적이 전혀 다르게 남습니다. ChatGPT Atlas 의 에이전트 모드처럼 사용자 브라우저를 직접 움직이는 경우는 [브라우저를 조작하는 AI](browser-agents.md)에서 따로 다룹니다.

### 기기별 흔적

| 쓴 곳 | 기기에 남을 것으로 보는 흔적 | 확인 상태 |
|---|---|---|
| 웹 브라우저 | ChatGPT 사이트 방문 기록, 캐시, 쿠키 | 원리 추정. 이번에 따로 확인하지 않음 |
| Windows·macOS 데스크톱 앱 | 앱 데이터 폴더의 캐시·설정 | 저장 위치·형식 확인 못 함. 관찰 PC 에 앱 폴더 없음 |
| Android·iOS 앱 | 앱 데이터 폴더 | 확인 못 함 |
| 계정 서버 | 작업 지시, 에이전트가 보인 단계·화면, 결과물 | 확인 못 함(원격 실행 구조라면 원본은 여기) |

ChatGPT 앱과 웹의 일반 저장 구조는 [ChatGPT](../chat-services/chatgpt/index.md)에 있고, 이 쪽에서는 되풀이하지 않습니다. 데스크톱 앱이 크롬 계열 엔진 위에서 돈다면 저장 원리는 [Electron·웹뷰 앱의 저장 구조](../../01-foundations/storage-model/electron-webview.md)를 따릅니다.

### 확인하지 못한 세부

에이전트가 쓰는 도구 구성(화면을 보는 브라우저, 글자만 읽는 브라우저, 터미널, 외부 서비스 연결), 사용자가 도중에 조작을 넘겨받는 방식, 중요한 동작 전에 확인을 구하는 방식, 에이전트용 쿠키·로그인 정보를 지우는 설정이 있다고 알려져 있습니다. 오퍼레이터의 스크린샷·대화 보관 기간이 90일이라는 설명도 있습니다. 이 항목들은 모두 이번 조사에서 근거를 찾지 못해 조사 결론의 근거로 쓰지 않습니다. 결과 파일(슬라이드·표 등)이 어디에 저장되는지도 확인하지 못했습니다.

## 구조

공식 문서와 기기 관찰 모두로 로컬 저장 형식을 확인하지 못해 이 쪽에는 파일 구조를 적지 않습니다. 계정 데이터 내보내기 파일의 일반 형식은 [계정 데이터 내보내기 형식](../../01-foundations/storage-model/data-export-formats.md)에 있지만, 에이전트 작업 대화가 내보내기에 들어가는지는 확인하지 못했습니다.

## 증거로서 의미

**증명하는 것.** 사용자 PC 의 브라우저 기록이나 ChatGPT 앱 흔적은 그 계정으로 ChatGPT 를 연 시간대를 보여 줍니다. 계정 서버에서 받은 대화 기록에 에이전트 작업 지시가 있다면, 그 계정에서 그런 지시를 입력한 기록이 있다는 데까지 말할 수 있습니다.

**증명하지 못하는 것.** 원격 실행 구조라면 사용자 PC 의 브라우저 기록만으로는 에이전트가 어떤 외부 사이트에 들어가 무엇을 눌렀는지 알 수 없습니다. 반대로 사용자 브라우저에 어떤 사이트 방문 기록이 없다고 해서 에이전트가 그 사이트에서 작업하지 않았다고 결론 낼 수도 없습니다. 에이전트가 한 주문·예약의 실제 결과는 상대 사이트의 계정 기록이나 결제·예약 확인 메일에서 확인합니다.

보고서에는 "이 시간대에 이 계정으로 ChatGPT 화면을 쓴 기록이 있고, 서버 기록에 이런 작업 지시가 있다" 처럼 기록이 말하는 만큼만 씁니다.

## 시각 해석

사용자 PC 에 남는 브라우저 방문 기록의 시각은 사용자가 ChatGPT 화면을 연 시각이고, 원격 실행 구조라면 에이전트가 외부 사이트에 접속한 시각과 다를 수 있습니다. 브라우저 기록의 시각 형식과 기준 시각은 [크롬 계열 브라우저](https://urock-ailab.github.io/forensics-handbook-windows/02-artifacts/browsers/chrome-edge-whale/index.html)(Windows 판)에 있습니다.

서버 기록과 내보내기 파일의 시각이 UTC 인지, 작업 단계마다 시각이 붙는지는 확인하지 못했습니다. 기기 쪽 시각과 서버 쪽 시각을 한 줄로 합칠 때는 [AI 사용 타임라인](../../03-techniques/analysis/timeline.md)의 방법을 따릅니다.

## 함정과 한계

첫째, 위키백과 외에는 근거가 없습니다. 연혁 날짜, 오퍼레이터 종료와 에이전트 제거 시기, 요금제는 조사 시점에 공식 문서로 다시 확인해야 합니다.

둘째, 오퍼레이터와 ChatGPT 에이전트, Atlas 에이전트 모드는 이름이 비슷하지만 작업이 도는 곳이 다를 수 있습니다. 사용자가 "에이전트로 했다" 고 말하면 어느 기능을 썼는지부터 가립니다. 사용자 브라우저를 직접 조작하는 기능이었다면 방문 흔적이 사용자 프로필에 섞여 남습니다([브라우저를 조작하는 AI](browser-agents.md)).

셋째, 원본이 서버에 있다면 기기에서 지운 흔적과 서버 기록이 따로 움직입니다. 사용자가 대화를 지우거나 보관 설정을 바꿨을 때 어떻게 되는지는 [대화 기록 보관 설정과 삭제](../../01-foundations/storage-model/retention-deletion.md)를 봅니다.

넷째, 에이전트가 외부 웹 페이지의 글을 읽고 움직이는 구조라서, 사용자가 시키지 않은 동작이 기록에 보이면 페이지에 숨은 지시가 원인일 수도 있습니다. 이런 사고의 분석은 [프롬프트 인젝션 사고 분석](../../03-techniques/analysis/prompt-injection.md)에 있습니다.

## 직접 분석해 보기

**헥스로.** 에이전트 모드만의 로컬 파일 형식을 확인하지 못해서 헥스로 따라갈 대상이 없습니다. 기기에서 볼 수 있는 흔적은 일반 브라우저 기록이고, 기록 파일은 SQLite 라서 파일 머리와 페이지 구조는 [SQLite 데이터베이스](https://urock-ailab.github.io/forensics-handbook-windows/01-foundations/database-log-formats/sqlite/index.html)(Windows 판)의 헥스 설명을 따릅니다.

**공개 도구로.** 사본으로 뜬 브라우저 기록 파일을 SQLite 를 여는 공개 도구(예: DB Browser for SQLite)로 열고, ChatGPT 사이트 방문 줄을 시간순으로 뽑아 사용 시간대를 잡습니다. 그다음 계정 데이터 내보내기나 서비스 회사 자료로 같은 시간대의 대화 기록을 맞춰 봅니다. 수집 절차는 [계정 데이터 내보내기로 수집](../../03-techniques/acquisition/export-collection.md)과 [서비스 회사에 대한 데이터 요청](../../03-techniques/acquisition/legal-requests.md)에 있습니다.

## 실습

에이전트 모드 흔적을 담은 공개 검체는 이번 조사에서 찾지 못했습니다. 조사용 계정과 가상 머신으로 직접 시험 환경을 만들어 아래 질문을 풀어 봅니다.

1. 에이전트에게 공개 웹 사이트 한 곳을 열어 요약하라고 시킨 뒤, 가상 머신의 브라우저 기록에 그 사이트 방문이 남는지, ChatGPT 사이트 방문만 남는지 확인합니다.
2. 같은 작업 뒤 계정 데이터 내보내기를 받아, 작업 지시와 에이전트가 보인 단계가 내보내기 파일에 들어 있는지 확인합니다.
3. 작업 도중 브라우저를 닫았을 때 작업이 서버에서 이어지는지, 대화 기록에 어떤 시각이 남는지 봅니다.
