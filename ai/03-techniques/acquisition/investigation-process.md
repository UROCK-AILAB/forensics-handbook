# 조사 절차 (Investigation Process)

AI 서비스의 기록은 회사 서버, 사용자 계정, 사용자 기기 세 곳에 나뉘어 있고 곳마다 지워지는 시점이 달라서, 어느 쪽을 먼저 확보할지 정한 다음 휘발성 순서와 보관 연속성 기록을 지키며 모읍니다.

> 확인 날짜: 2026-09. 수집 원칙은 RFC 3227 [1], 서비스별 보관 기간은 각 회사 공식 문서 [2][3][4](2026-09-25 열람)를 따릅니다. ChatGPT 의 보관 기간은 조사할 때 OpenAI 공식 도움말에서 확인합니다. 보관 기간과 기능은 자주 바뀌므로 조사 때마다 회사 문서를 다시 확인합니다.

## 언제 쓰나

기밀 자료를 AI 에 넣었는지, 에이전트가 기기에서 무엇을 실행했는지, 문제의 글이나 이미지를 AI 로 만들었는지처럼 AI 서비스 사용이 사건의 한 부분일 때 이 절차로 시작합니다. 사건 유형별로 무엇부터 볼지는 [기밀 자료를 AI에 넣었나](../../04-scenarios/data-leak/confidential-input.md), [AI 에이전트가 무엇을 실행했나](../../04-scenarios/agents/agent-actions.md) 같은 조사 시나리오에 따로 정리되어 있고, 이 페이지는 그 모든 시나리오에 앞서 증거를 어떤 순서로 확보할지만 다룹니다.

## 절차

### 1. 조사 질문과 범위를 정합니다

어느 서비스를 어느 계정으로, 어느 기기에서 썼는지 먼저 목록으로 만듭니다. 같은 서비스라도 웹 브라우저, Windows·macOS 데스크톱 앱, Android·iOS 앱, 명령줄 개발 도구, 기기 안에서 도는 로컬 모델에 따라 기록이 남는 곳이 다르고, 서비스마다 어디에 무엇이 있는지는 [AI 서비스의 데이터는 어디에 있나](../../01-foundations/storage-model/where-data-lives.md)에 정리되어 있습니다. 개인 계정인지 회사 계정인지도 이 단계에서 가립니다. 회사 계정이면 조직 쪽에 감사 기록이 있는지도 확인하고, [Claude 기업용 감사 로그](../../02-artifacts/network-enterprise/claude-enterprise.md)나 [ChatGPT 기업용 감사 기록](../../02-artifacts/network-enterprise/chatgpt-enterprise.md) 같은 페이지를 함께 봅니다.

### 2. 기록이 어디에 있는지 나눕니다

| 위치 | 얻는 방법 | 자세한 절차 |
|---|---|---|
| 사용자 기기 | 기기에서 앱 폴더·설정·기록 파일을 수집 | [기기에서 AI 흔적 모으기](endpoint-triage.md) |
| 사용자 계정 | 계정 주인이 서비스의 내보내기 기능으로 받음 | [계정 데이터 내보내기로 수집](export-collection.md) |
| 회사 서버 | 법적 절차에 따라 회사에 요청 | [서비스 회사에 대한 데이터 요청](legal-requests.md) |

대화 원본이 서버에만 있는 경우도 있습니다. 아래 Claude Code 의 동작은 Claude Code 공식 문서 [2]를 따릅니다. Claude Code 를 웹에서 쓰는 클라우드 세션은 기본적으로 Anthropic 이 관리하는 가상 머신에서 돌고, 저장소도 그 격리된 가상 머신에 복제해 작업합니다. 작업이 사용자 기기에서 일어나지 않으므로 대화 원본은 서버에만 있고, 사용자가 클라우드 세션을 지우면 그 세션의 이벤트 데이터가 영구히 지워집니다. 조직이 클라우드 세션을 자체 서버 환경에서 돌리도록 설정했다면 실행은 그 조직의 인프라에서 일어나므로, 조직 쪽에 무엇이 남는지도 확인합니다. 원격 제어(Remote Control) 세션은 실행은 사용자 기기에서 하지만, 연결되어 있는 동안에는 기기 사이 동기화를 위해 세션 기록이 Anthropic 서버에도 저장됩니다.

### 3. 무엇부터 확보할지 정합니다

서버 기록은 보관 기간이 짧은 경우가 있어서, 회사에 보존을 요청할지 계정 내보내기를 먼저 받을지를 조사 초기에 정합니다. 회사 공식 문서 [2][3][4](2026-09-25 열람)에 적힌 보관 기간은 다음과 같습니다. 보관 설정을 바꾸는 방법과 삭제 동작은 [대화 기록 보관 설정과 삭제](../../01-foundations/storage-model/retention-deletion.md)에서 다룹니다.

| 서비스 | 조건 | 보관 기간 |
|---|---|---|
| Claude Code (Anthropic) | 소비자 계정, 모델 개선 사용을 허용하지 않음 | 30일 |
| Claude Code (Anthropic) | 소비자 계정, 모델 개선 사용을 허용함 | 5년 |
| Claude Code (Anthropic) | 상업 계정(Team·Enterprise·API) | 기본 30일, 자격 있는 Enterprise 조직은 보관하지 않도록(ZDR) 설정 가능 |
| Claude (Anthropic 개인정보 처리방침) | 사용자가 지운 대화 | 바로 지우고 30일 안에 백엔드에서 제거, 안전 검토 대상으로 표시된 대화는 더 오래 보관 |
| Gemini 앱 (Google) | 기본 설정 | 18개월 뒤 자동 삭제(3개월·36개월·자동 삭제 안 함으로 바꿀 수 있음) |
| Gemini 앱 (Google) | 임시 채팅, "활동 유지"를 끈 상태의 채팅 | 계정에 72시간 보관 |
| Gemini 앱 (Google) | 사람이 검토한 채팅 | 활동을 지워도 최대 3년 보관 |

기기 쪽 기록도 저절로 지워질 수 있습니다. Claude Code 공식 문서 [2]에 따르면 Claude Code 는 세션 기록을 `~/.claude/projects/` 아래에 평문으로 두고 기본 30일 동안만 보관하며, 이 기간은 `cleanupPeriodDays` 설정으로 바꿉니다. 다만 Claude 데스크톱이나 Cowork 에서 시작했거나 마지막으로 이어 간 세션은 기본적으로 이 제한을 받지 않습니다. 확보가 늦어지면 기기 기록부터 사라질 수 있어서, 기기를 손에 넣었다면 기기 수집을 미루지 않습니다.

### 4. 기기가 켜져 있으면 휘발성 순서를 따릅니다

RFC 3227 [1]은 사라지기 쉬운 것부터 모으라고 하고, 그 순서를 레지스터·캐시, 라우팅 표·ARP 캐시·프로세스 표·커널 통계·메모리, 임시 파일 시스템, 디스크, 원격 로깅·모니터링 자료, 물리 구성·네트워크 구성도, 보관 매체로 적습니다. 이 순서를 따르면 AI 앱이 실행 중일 때도 메모리 수집이 디스크 수집보다 앞섭니다. 메모리에서 대화를 되살리는 방법은 [대화 내용 되살리기](../analysis/content-recovery.md)에서 다룹니다.

같은 문서는 수집이 끝나기 전에 시스템을 끄지 말고, 네트워크를 그냥 끊으면 증거를 지우는 장치가 작동할 수 있다고 경고합니다. 그래서 네트워크를 끊기 전에 화면과 실행 중인 프로세스를 먼저 기록해 둡니다.

### 5. 곳마다 수집합니다

2단계 표의 세 페이지를 따라 기기, 계정, 회사 순으로 수집합니다. 계정 내보내기와 회사 요청은 모두 계정 주인의 동의나 법적 권한이 먼저 있어야 하고, 잠금 해제나 보안 우회로 계정에 들어가는 방법은 이 핸드북에서 다루지 않습니다.

### 6. 보관 연속성을 기록합니다

RFC 3227 [1]은 누가 언제 어디서 증거를 발견하고 수집했는지, 누가 언제 어디서 다루고 검사했는지, 누가 어느 기간 어떻게 보관했는지, 넘겨줄 때 언제 어떻게 넘겼는지를 적으라고 합니다. AI 조사에서는 여기에 앱 버전과 수집 날짜를 더 적습니다. AI 앱은 자주 바뀌어서 같은 파일 이름이라도 버전마다 담긴 키가 다를 수 있습니다. 수집한 파일은 받은 즉시 해시를 계산해 기록하고, 이후 분석은 사본으로 합니다.

아래는 기록 한 줄을 어떻게 적는지 보여 주려고 새로 만든 예시이고, 이름과 값은 모두 지어낸 것입니다.

```text
2026-09-12 10:20 KST | 수집자: 분석관 김가상 | 대상: 노트북 TEST-PC-07, 사용자 demo-user
수집물: .claude 폴더 논리 수집본 claude_demo.zip | SHA-256: (계산 값) | 앱 버전: (수집 시 확인한 값)
보관: 증거 보관함 B-3 | 인계: 2026-09-12 15:00 분석관 이예시에게 전달
```

### 7. 분석으로 넘깁니다

서버·계정·기기에서 모은 기록은 시각대가 서로 다를 수 있어서 [AI 사용 타임라인](../analysis/timeline.md)에서 한 줄로 맞춥니다. 결과를 적는 방법은 [AI 관련 포렌식 보고서](../reporting/forensic-report.md)에 있습니다.

## 도구

RFC 3227 [1]은 조사 대상 시스템 안의 프로그램을 믿지 말고 보호된 매체에 담아 간 도구를 쓰라고 하고, 모든 파일의 접근 시각을 바꾸는 프로그램(문서의 예는 tar·xcopy)을 돌리지 말라고 합니다. 디스크 전체가 필요하면 쓰기 방지 장치와 이미지 도구를 쓰고, 폴더만 가져올 때는 시각 정보를 보존하는 수집 도구를 씁니다. 해시는 Windows 의 `certutil -hashfile 파일 SHA256` 이나 PowerShell `Get-FileHash`, macOS·Linux 의 `shasum -a 256` 으로 계산할 수 있습니다. 수집 도구마다 시각 정보를 어디까지 보존하는지는 도구 문서에서 확인합니다.

## 함정과 한계

서버 보관 기간이 지나면 회사에도 줄 자료가 없을 수 있고, 조직이 보관하지 않도록 설정했다면 처음부터 서버에 남지 않습니다. 기기 기록도 자동 정리 기간이 지나면 사라지고, Anthropic 이 관리하는 가상 머신에서 돈 클라우드 세션은 처음부터 기기에 원본이 없습니다.

기기에서 모은 파일에는 인증 토큰이 들어 있을 수 있습니다. Windows 11 에서 관찰한 Claude Code 폴더에는 `.credentials.json` 이 있었고 그 안에 `accessToken`·`refreshToken` 키가 있었습니다(확인 범위: Windows 11, 2026-09). 수집물은 비밀 자료로 보관하고, 토큰으로 계정에 들어가지 않습니다. 토큰이 남는 곳은 [API 키와 토큰이 남는 곳](../../01-foundations/storage-model/api-keys-tokens.md)에서 다룹니다.

기기에 무엇이 남는지는 서비스와 앱, 앱 버전마다 다릅니다. 수집할 경로는 각 서비스 페이지에서 확인하고, 그 페이지에 적힌 확인 범위(OS·앱 버전·날짜)와 검체가 다르면 검체에서 경로가 있는지부터 확인합니다.

## 결과를 어떻게 해석하나

기록을 어디서 얻었는지에 따라 증명할 수 있는 범위가 다릅니다. 기기에 기록이 없다고 해서 그 서비스를 쓰지 않았다고 결론 내릴 수 없는데, 자동 정리로 지워졌거나 클라우드 세션처럼 처음부터 기기에 원본이 없었을 수 있어서입니다. 계정 내보내기나 회사 제출 자료는 요청한 시점에 서버가 보관하던 것만 담고, 그 전에 지웠거나 보관 기간이 지난 대화는 들어 있지 않을 수 있습니다. 세 곳의 기록이 서로 맞으면 사용 사실을 더 단단히 말할 수 있고, 어긋나면 그 차이가 지우기나 설정 변경의 단서가 됩니다. 누가 그 대화를 했는지는 기록만으로 정해지지 않으니 [그 대화를 한 사람이 누구인가](../../04-scenarios/attribution/user-attribution.md)를 함께 봅니다.
